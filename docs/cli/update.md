# `openclaw update`

更新 OpenClaw，并在 stable/extended-stable/beta/dev 频道之间切换。

如果你是通过 **npm/pnpm/bun** 安装的（全局安装，没有 git 元数据）， 更新会走 [更新](/install/updating) 中描述的包管理器流程。

更新检查、候选演练、激活 Doctor 和验证从其有效服务命令和 `NODE_OPTIONS` 继承托管网关的 Node 堆控制。命令行堆控制优先。空服务 `NODE_OPTIONS` 保留调用 shell 提供的堆控制，同时仍然清除继承的预加载和调试器标志。这需要在已安装的更新程序中进行修复；较旧的更新程序无法从其暂存的候选程序继承它。

在 Windows 上，更新会在暂存或更改状态之前检查网关计划任务的主体和运行级别。当前帐户的每用户 `LeastPrivilege` 任务可以从非提升的终端（包括 UAC-filtered 管理员终端）进行更新。即使网关已停止，另一个帐户（包括 SYSTEM）的任务、需要最高权限的任务或真正的任务计划程序查询拒绝也需要 **提升的终端**（以管理员身份运行）。未解决的或组主体遵循本机权限检查。任务查找有自己的 60 秒冷启动限制，每个 `schtasks` 命令有 15 秒限制；停止的操作命名检查或命令，而不是使用更新的完整超时。

如果任务计划程序拒绝在更新准备期间禁用自动启动，则 OpenClaw 会使用相同的提升终端和手动更新指南报告 `windows-task-elevation-required`。明确拒绝会使任务保持不变，因此不会尝试自动启动恢复；在更换安装之前仍然需要禁用防护装置。

服务定义刷新可识别解析为相同 SID 的 Windows 帐户别名。不同的或未解决的帐户仍然受到保护，不会被自动修复。

如果服务检查不可用，则当实时网关锁识别出相同的安装时，包更新会在更换之前被拒绝。在 Windows 上，当无法读取其命令行包标识时，活锁 PID 就足够了。公开原因为`gateway-stop-unverified`。通过任务计划程序、其原始终端或 `openclaw gateway stop` 停止网关，然后重新运行 `openclaw update`。没有实时锁定的更新仍然在所有平台上继续。此准入检查需要更新的已安装更新程序。

对于全局 npm 安装，手动恢复路径为 `npm i -g openclaw@<target> --allow-scripts=openclaw`、`openclaw doctor --fix`、`openclaw gateway restart`。如果任务计划程序拒绝访问，请将 `<target>` 替换为预期版本并从提升的终端运行服务 repair/restart。 OpenClaw 打印此替代方案；它不会自动运行它。每用户启动文件夹安装不需要提升此检查。较旧安装的更新程序会保留其先前的行为，直至被替换；使用提升路径或手动路径进行首次升级。

系统包管理器拥有的安装会在 npm 暂存或网关关闭之前跳过 OpenClaw- 托管更新。如果所有权检查失败，则继续更新并发出警告；只有确认的所有权匹配才会跳过更换。丢失的包管理器可执行文件被报告为不可用，没有数据库恢复说明。对于 pacman（包括基于 Arch 的发行版），请使用 `sudo pacman -Syu` 或 AUR 帮助程序进行更新。对于 FreeBSD，使用所属的 pkg 或 Ports 部署。然后通过其服务所有者重新启动网关。较旧的更新程序必须首先通过系统包管理器接收此修复程序；候选者无法修复在暂存之前失败的更新程序。

自定义 npm 前缀（例如 `~/.npm-global`）可从 npm 的配置前缀和安装的 OpenClaw 启动器中识别。 `~/.npmrc` 中配置的前缀不需要匹配的 `NPM_CONFIG_PREFIX` 环境变量。如果无法识别所有者，CLI 会在其指南中包含检查的包、前缀和启动器路径以及包管理器检查结果。安装检查还报告根、Git 元数据、`node_modules` 布局和服务单元目标（或未检查的原因）。无法识别的根目录会跳过目标预检并发出命令来定位所属安装。

在暂存之前停止的旧更新程序无法使用此修复。对于已知的 npm 安装，请明确为该更新提供其配置的前缀：`NPM_CONFIG_PREFIX="$(npm prefix -g)" openclaw update`。

未检测到程序包管理器所有者的安装会记录 **skipped** 更新，成功退出，并使网关保持运行状态。对于 Docker/container 映像，拉取或构建新映像并使用相同的 state/config 挂载重新创建容器。对于独立或提取的 tarball 安装，请使用原始方法重新安装； Yarn 全局安装必须使用 Yarn 进行更新。 CLI 显示下一步操作。现有配置文件也会将其记录在更新历史记录中，并将其作为 `run.origin.nextAction` 包含在 JSON 中。使用 `--json`，新的配置文件会向 stderr 发出指导，并且不会为跳过的更新创建状态数据库。这些非结果不会运行回滚验证或提供更新失败报告。

## <a id="usage"></a> 用法

```bash
openclaw update
openclaw update status
openclaw update repair
openclaw update cleanup --dry-run
openclaw update wizard
openclaw update --channel extended-stable
openclaw update --channel beta
openclaw update --channel dev
openclaw update --tag beta
openclaw update --dry-run
openclaw update --no-restart
openclaw update --yes
openclaw update --accept-capabilities
openclaw update --json
openclaw --update
```

`openclaw --update` 会重写为 `openclaw update`（对 shell 和启动器脚本很有用）。

在数据库架构检查之前，无效配置报告 `invalid-config`。不可读的配置文件或失败的配置加载步骤会报告 `config-read-failed`，并带有可识别的文件系统错误代码（如果可用）。对于支持的包目标，候选人在私人部署后做出决定；参见[考生自有入场](#candidate-owned-admission)。本地诊断识别无效字段并建议 `openclaw doctor --fix`，然后更正任何剩余错误。试运行将此指导保留在其 JSON `notes` 中，而不更改配置。公共故障报告保留拒绝的架构区域，例如 `gateway.*`，同时隐藏操作员定义的键和拒绝的值。当所选软件包版本与已安装版本匹配时，准入仍然运行；无操作决策是在验证所选工件和实时安装之后做出的。切换通道时，Doctor 可以准备支持的遗留字段的只读投影，以进行数据库检查。每个投影都与其原始配置字节和包含文件保持绑定。如果托管服务使用另一个配置文件，则调用者和服务投影保持独立；检查调用者不会重写其配置。引导式恢复会在稍后成功更新后识别已保存的配置失败，并仍然验证已安装的运行时和网关准备情况。

2026.9.4 更新程序将此情况报告为 `database-schema-preflight`，并且即使在解析 npm 目标后也可以显示 `mode: unknown`。在另一次更新或试运行替换最新历史记录之前，运行 `openclaw update status --json` 并检查 `lastRun.origin.nextAction` 和 `lastRun.target` 记录的原因和目标。候选版本无法修复在暂存之前拒绝的已安装更新程序；重试之前更正配置。

没有准入修复的更新程序首先在 2026.7.2-beta.5（包括 2026.6.34–2026.6.35 和 2026.7.33–2026.7.35 扩展稳定产品线）中发布，在使用 `plugins.load.paths: plugin path not found` 进行暂存之前也会拒绝；恢复丢失的自定义插件目录或在重试之前删除其配置的路径。 `openclaw doctor --fix` 可以修复已识别的捆绑路径别名并保留不相关的自定义路径。

更新准入将其父任务丢失的孤立 `task_delivery_state` 行识别为可修复。当它可以获得Doctor的所有权围栏时，它会在创建更新历史记录之前运行相同的[保留优先恢复](/reference/database-schemas/integrity-and-recovery#doctor-reports-orphan-task-delivery-rows)。恢复及其账本条目一起提交；该条目记录行数和恢复目录。实时网关所有者、只读存储或失败的保存会阻止修复并报告 `openclaw doctor --fix` 作为下一步操作。其他外键违规和结构损坏仍拒绝入场。 `--dry-run` 报告可修复情况，但不恢复行或为拒绝的预览创建更新分类帐条目。

安装的 2026.9.4 更新程序在更新自身之前无法使用此恢复。如果它因数据库完整性错误而拒绝，请手动安装纠正版本并运行 `openclaw doctor --fix`。

服务恢复和清理完成后，失败的更新和修复尝试进入 [ 恢复分类 ](/cli/update#recover-a-failed-update)。在移交所有权或报告完成之前，预检和最终确定会加入承认的命令清理。如果清理无法确认工作已停止，则更新程序将保留任何获得的所有权和恢复工件，并跳过自动服务补偿和修复。检查 `openclaw update status` 并在重试之前解决挂起的执行。修复仅解决属于其医生的本机命令。另一位博士保留的命令被记录为外国监护，其博士 PID，不会使完整的博士感到不安。当任何实时命令声明存在时，安装替换仍然被阻止。如果保留生成的命令的保管失败，Doctor 会保留其进程标识并在解决其保留之前停止该命令。没有记录身份的保留仍然会阻止恢复；重复修复并不能证明它已停止。经过验证的回滚不会自动启动分类：上一代再次运行，并且报告将失败的检查保留为原因。交互式更新提供了 diagnose/report 菜单，默认选择 **Exit**。拒绝或取消会保留失败更新的非零退出状态。 JSON、非交互式、`--yes` 和托管服务切换调用在回滚后不会提示。

更新完成会在退出之前打印终端结果和本地 Markdown 报告路径，包括意外故障。失败的运行使面向回滚的诊断 JSON 保持在已发布的 8 KiB 限制内。该文件链接了一个单独的工件，其中包含每个单独限制的医生发现； Markdown 报告还保留完整的清单。 JSON 输出包括`reportPath`；报告写入失败会打印警告并保留更新结果。

当另一个进程持有状态数据库写入器时，更新驱动程序会提供其工作支持的阶段和进度写入最多两分钟以获取写入器。当事务开始时，这种延长的等待就结束了；网关和其他呼叫者保留正常的五秒预算。仅进度收据最多等待一秒，然后发出警告并继续，而不声明已保存的收据。如果预算到期，则需要编写报告可操作的争用。此修复程序必须存在于已安装的更新程序中，以保护其运行的下一个更新。

Exit 始终等待已接受的状态操作、挂起的数据库打开以及实时工作线程引用的解决。结算后，retained-worker 本机关闭和线程终止有 10 秒的报告宽限期。 Expiration 记录警告并继续等待实际的 Native 退休；它不会放弃工人或强制进程退出。保留的运行时将保持所有权，直到退休解决，然后仍然可用于以后的清理。命令的记录结果将被保留。此保护属于已安装的更新程序：安装包含修复程序的版本可使其执行该版本的下一次更新。

在更新替换这些文件之前，可执行文件 CLI 会保留其共享状态和工作清理代码。较早安装的开发版本可以成功完成更新，然后在 CLI 清理期间以 `ERR_MODULE_NOT_FOUND` 退出。将`openclaw update status`与新安装的CLI进行检查，以区分退出失败和记录的更新结果；安装的驱动程序在执行下一次更新之前需要修复。

较新的软件包保留已发布的 2026.10.1 更新程序的清理入口点，包括其原始的待处理队列，以便第一次升级可以正常完成。这种兼容性涵盖已发布的包，而不是任意的开发构建文件名。

在替换包时，从安装内部进行更新会使捕获的路径锚定到调用目录。更新程序为后台工作人员保留有效的工作目录，并在原始目录仍然存在时恢复原始目录。此保护也属于已安装的更新程序；新候选人无法更改旧驱动程序的工作目录。

当网关处理请求时仪表板更新失败时，网关会记录一条警告，其中包含公开原因和安全错误摘要。成功和有意的无操作更新日志保持不变。这仅影响网关日志记录，而不影响已安装的更新程序、回滚或仪表板 RPC 响应。

最终交互式更新失败后，**诊断更新失败**和**报告更新失败**是单独的选择。报告首先显示确切的已清理问题正文，并默认确认 **No**。确认后，OpenClaw 在创建问题之前通过静默只读请求检查 GitHub CLI 的活动 `github.com` 帐户。回退和待定结果在本地保留经过净化的报告；已确认的问题仅保留其持久问题 URL。如果 CLI 丢失、身份验证不可用或 GitHub 拒绝上传，OpenClaw 会将清理后的报告保留在本地并返回到上一个操作菜单。修复问题，然后选择“**报告更新失败**”并再次确认以重试相同的报告，或者在浏览器中选择“**报告”**，以使用浏览器的GitHub帐户进行查看和提交。当准备好的报告适合预先填写的链接并且没有不确定的上传待处理时，可以选择浏览器；它不需要 GitHub CLI。已完成的更新和医生检查不会重新运行。准备或提交错误也会返回到菜单。不确定的上传保持待处理状态：**检查报告状态** 查找现有问题而不创建另一个问题，并且不提供浏览器切换。成功提交、显式退出、取消保留其正常行为；诊断仅在明确选择时运行。在Control UI中，中断的预创建准备在其本地预留过期后变得可重试。在不确定的创建结果之后，OpenClaw 检查是否有与确切报告匹配的问题。如果既没有经过验证的问题 URL 也没有明确的拒绝，则报告将保持待处理状态，并且没有重播链接，因为问题可能已经存在。 `--yes`、`--json`、非交互式运行和托管服务切换从不提交报告。

对于已承认的更新，意外异常会在更新历史记录中保留有界的、经过编辑的错误标识和源位置，以及迄今为止已完成的操作以及已解决的安装和目标事实。失败报告包括启动操作和所有者记录的回滚结果。失败的步骤在报告正文和问题标题中使用稳定标识符，例如 `candidate-state-snapshot`、`candidate-doctor-lint` 和 `post-install-verify`；命令参数和私有路径仍然经过编辑。快照错误标识活动数据库、执行批准或插件阶段。模式检查失败将识别的工作错误代码和原因放在私有源上下文之前，包括警告行之后的原因，因此它们可以在编辑后幸存下来。保存的诊断行省略路径及其尾随文本，包括文件名本身可能包含空格或引号的带引号的路径。完成的数据库快照并不能保证后面的插件路径可读；检查失败阶段指定的源路径和文件系统错误。安装或目标解析过程中的失败会使该解析步骤保持可见。较旧的更新程序进程无法恢复它们已丢弃的详细信息；由较新的代码生成的报告仅包含处理故障的更新程序记录的事实。

托管更新会在更新历史记录中保留已完成的子项的拒绝原因和失败详细信息，即使其通知已被使用。设置→更新读取相同的记录事实。对于 `update-recovery-pending`，检查保留的激活诊断并遵循其准确的恢复命令；最初的回收所有者仍然决定修复或报废是否安全。未产生可用结果的子项将报告为 `managed-service-handoff-failed`。服务停车前的拒绝不会影响服务网关。

Npm 安装失败会在更新历史记录和审阅的报告中记录已识别的错误代码（或 `unknown`）以及经过清理的 `npm ERR!` / `npm error` 行摘录。现有历史格式最多保留5行，每行200 UTF-8字节；权限指南保留其中一项。在记录摘录之前，会对主路径、凭据和经过身份验证的注册表 URL 进行编辑。对于 `EACCES` 或 `EPERM`，选中 `npm prefix -g` 并以对该前缀具有写入权限的安装帐户运行更新。对于 `ENOSPC`，前缀和 npm 缓存卷上的可用空间。对于 `E404` 或 `ETARGET`，检查配置的注册表和请求的版本或标签。生成的报告包括适用的下一步。已经运行的旧更新程序无法从其候选包中获取此诊断捕获。

在 Windows 上，临时锁定的实时包可以阻止更新程序将其重命名到其备份位置。更新程序以有限回退方式重试 `EPERM`、`EBUSY` 和 `EACCES`（16 次尝试，最多等待 57.75 秒），将每次重试记录为警告。如果重命名仍然失败，则失败会命名两个路径并将已安装的包保留在原处。关闭保存该安装的进程并在重试之前检查其权限。此保护属于已安装的更新程序；新的候选者无法将其添加到已经运行的旧更新程序中。

## <a id="immutable-release-installations"></a> 不可变的发布安装

明确采用的 Linux 安装可以使用 `openclaw update` 准备和激活密封释放。它的根包含 `releases/<full-commit-sha>` 和选择运行代的 `current` 符号链接。仅匹配的目录布局并不授予更新所有权。

准备工作一次性解决官方`main`，或者接受精确的`--sha <40-hex-commit>`，构建偏离路径，验证并密封候选者，并记录其准备工作。准备工作失败导致服务一代原地踏步；已经存在的目标会跳过构建。现有的收养记录仍仅供准备。本机激活需要在安装的控制数据库中记录明确的 `adopt-immutable --enable-activation` 同意。没有 `openclaw.json` 选项启用它。 `--no-restart` 仅为该调用保留启用的安装准备。

不可变的准备需要单独采用的构建帐户和工具链。构建帐户必须与运行时帐户不同，没有补充组，并且与记录的数字标识匹配。更新程序运行依赖项安装并构建受限制的 systemd 服务，该服务具有私有主目录、临时目录、内存限制和任务限制。其环境不包括运行时帐户的凭据，其文件系统视图保护运行时状态、服务定义和现有版本。更新程序会等待整个构建 cgroup 停止，然后再将新一代复制并密封为 root。

构建存储准入和运行时帐户的 write/quota 探针单独运行。失败的准入、安装、构建或流程结算检查会使现有服务和 `current` 指针保持不变。不确定的工艺沉降会保留构建划痕以供检查。没有采用的构建标识的安装仍然可以检查状态，重用已经准备好的一代，并检测已经存在的目标；准备新目标报告了未采用的情况。构建身份采用是为了本机不可变更新推出而进行的，尚未作为 `openclaw.json` 设置或 CLI 标志公开。

`--drain-timeout <seconds>`独立设置不可变的消耗预算`--timeout`，它保留了canary/readiness阶段预算。默认消耗预算来自现有的重启延迟策略（300秒）。准备就绪后，排水立即完成；在预算结束后，本地暂停所有者可以中断正常工作，同时保留未解决的写入保管权。对于一个30-第二个排水管，使用`--drain-timeout 30`。该标志在可变安装上被拒绝。在本机服务检查之后，更新程序要求网关在原来的暂停状态下提交关闭。过期或恢复的暂停会拒绝该切换。一旦提交，主机拥有单向关闭权；当本机停止等待调度时，恢复和租约到期无法重新开放入场。稳定启动器在启动网关之前读取相同的激活记录。停止和指针发布阶段阻止主管替代者承认工作；原生所有者明确授权发布后启动。

启用后，本机更新程序会通过网关暂停所有者耗尽资源，停止旧服务，在受保护的激活记录下发布 `current`，启动选定的生成，并验证其进程、构建、经过身份验证的运行状况、HTTP 就绪情况、插件和通道。构建和安装工作不在切换范围内。启动响应 `status: "starting"`，包括代理数据库检查，使准备等待时间保持在有限的预算范围内。不确定的检查保留恢复记录；它并不构成失败。候选人创作的附加启动配置迁移需要匹配的配置审核证据和保留的策略。其他配置或状态身份更改拒绝完成。

负载减慢更新速度；它不会建立激活失败。对于使用捆绑的托管发布控制器的部署，在运行隔离模型标记之前，接受会等待代理数据库准入、关键启动 sidecar 和响应主线程。可配置的验证预算默认为十分钟。在选定的网关证明准备就绪、响应能力和未更改的进程身份后，标记分派超时可以在该预算内重试相同的幂等性密钥。回滚接受需要同样的耐心。崩溃、错误的构建或身份、腐败、错误的标记回复、失败的健康检查或在预算到期之前从未解决的准备情况仍然是真正的失败。

验证激活会废弃操作记录。当保护状态保持兼容时，真正的激活失败可能会恢复密封的前身；回滚保留可恢复的记录。此切片不会回滚迁移的数据库或收集发布目录。仅支持匹配数据库模式合约；不兼容的迁移要求拒绝在耗尽之前激活。金丝雀排练会在切换前针对孤立的副本启动候选者，保留候选者本身在启动时必须迁移的输入。它不会预先修复 Doctor 的输入。此激活中不会运行实时 Doctor 或可选的 NOCOW 重写。实时准备就绪后，更新程序会在所选网关服务时针对新的私有副本重复仅启动金丝雀，然后验证相同的实时 PID 并在完成激活之前再次启动。这是金丝雀证明；它不会调度模型标记转弯。 JSON 区分准备 （`prepared`） 和激活 （`succeeded`、`rolled-back`、`pending` 或 `error`）。 `pending`、`rolled-back` 和 `error` 返回非零退出状态。

`openclaw update --dry-run` 报告不可变目标，无需采用、准备或发布。 `openclaw update status` 包括当前和准备好的生成身份和激活启用。其不可变收据字段也可在 `--json` 中的 `update.immutable` 下使用：

- `prepared` 标识密封的候选者，而不是接受的激活。
- `activation` 识别保留恢复：操作 ID、阶段、前一个和候选 SHA、可选 `failure` 以及使用记录的外部 Node 和保留助手的确切 `recoveryCommand`。显示已知的故障原因代码；其他存储的错误文本替换为 `details-withheld`。
- `lastActivation` 为历史验证：操作 ID、`outcome`、`selectedSha` 和 `verifiedAtMs`。文本状态标签 `succeeded` 为 **accepted**，`rolled-back` 为 **restored**；恢复可用性并不代表候选人成功。其可选的`gateway`包含经过验证的`version`、`buildId`、`pid`和`bootId`。没有这些字段的旧收据仍然可读。

这些事实来自安装记录，因此新的 CLI 观察者可以在更新程序退出后读取它们。他们不会探测当前进程或授予激活权限。即使 `lastActivation` 记录已恢复的可用性或较旧的已接受更新，保留的 `activation` 仍处于等待恢复状态。

不可变准备不会切换存储的通道并拒绝 `--tag` 等包目标。 `--sha` 仅适用于采用的不可变安装。网关 `update.run` 仍需要 root 安装所有者在网关服务 cgroup 之外运行 CLI；它不会提升聊天请求。 `update repair` 将不可变恢复定向到 `update recover`。

在不可变激活停止服务网关之前，更新程序会预热候选者的 Node 编译缓存，作为其最终发布路径上的服务帐户。这会在不启动服务器的情况下导入网关图。现有的 build-ID 缓存命名空间和禁用缓存设置仍然适用；预热失败是建议性的，普通冷启动仍然可用。考生排练保持其独立的、禁用缓存的环境。可变包更新不会预热：暂存路径在激活期间发生变化，并且在最终路径再次编译会在停机期间增加工作量。

不可变状态和试运行也解释了迁移覆盖范围。 JSON 在状态中暴露 `immutableCoverage`，在试运行中暴露 `coverage`。报告清单默认、配置的外部和注册的代理存储，包括缺少的路径和注册表的原始路径别名。它报告已声明的插件迁移资源以及未声明资源的警告。外部路径被识别；他们的存在并不能建立候选人移民支持。

对于已准备好的目标，检查会比较当前包、候选包和准备收据架构合同，并根据该目标显示每个商店的架构版本。诸如代理模式 24 → 25 之类的交叉指出了不可变激活在耗尽之前拒绝它的原因。未准备好的 SHA 具有 **unknown** 目标覆盖率：检查不会获取、构建或引导它。匹配的模式版本不是物理模式、备份、迁移或激活就绪证明；插件迁移覆盖范围仍然未知。

实时库存使用所采用服务的有效环境和配置。如果无法读取这些内容，报告将保留可用的准备事实并解释库存缺口。作为安装所有者运行检查以获得完整的服务可见性。数据库检查使用私有草稿副本保留实时 SQLite 工件，这些副本随后会被处理；大型商店可能会使这种只读检查变得昂贵。它不会迁移数据、写入配置、启用激活或停止服务网关。

服务网关必须支持承诺的暂停切换。新的 CLI 无法将该功能添加到旧的正在运行的进程中。对于第一次本机激活，请让现有安装所有者准备并激活包含此功能的一个桥接版本。仅在过渡期间保留其采用准备。桥接正常且之前的更新程序已稳定并停止调度后，从服务版本启用本机激活：

```bash
sudo /usr/bin/node /opt/example/current/dist/index.js update adopt-immutable \
  --root /opt/example \
  --service example.service \
  --account openclaw \
  --state-dir /var/lib/example \
  --config /etc/example/openclaw.json \
  --runtime /usr/bin/node \
  --previous-updater-stopped \
  --enable-activation
```

仅在前一个更新程序已解决并停止调度后才以 root 身份运行采用。该确认不会为您停止另一个更新程序。采用验证现有的 systemd 单元、固定的非 root 服务帐户、显式有效的 state/configuration 路径和可选的 `--profile`、外部 Node 可执行文件，并在记录所有权之前密封当前一代。现有的 systemd 环境文件通过本机服务读取器读取。不支持具有不同文件系统根、动态帐户或命令行配置文件覆盖的服务。本机激活需要 cgroup v2，以便更新程序可以验证旧服务及其后代是否已停止。采用永远不会编辑或重新启动服务。省略`--enable-activation` 仅用于准备采用。要启用早期仅准备采用，请使用标记重新运行原始采用命令；安装和服务标识仍然必须匹配。对于现有所有者激活桥接的仅准备采用，显式启用会在验证密封代和实时桥接过程后协调所选代。它保留了前身并保留了所有其他安装绑定。精确打包的 v1 启动器以原子方式备份和升级；自定义或修改的启动器将被保留并被拒绝。已启用的记录从不接受外部指针更改。

在服务 cgroup 之外，以 root 身份准备并激活下一代经过审核的一代。它必须与执行本机切换的桥接版本不同：

```bash
sudo /usr/bin/node /opt/example/current/dist/index.js update --sha <candidate-sha> --no-restart
sudo /usr/bin/node /opt/example/current/dist/index.js update --sha <candidate-sha> --drain-timeout 30
sudo /usr/bin/node /opt/example/current/dist/index.js update recover --root /opt/example
```

在耗尽之前，激活会在安装同级控制目录的 `recovery-<sha>` 路径下为每个源 SHA 准备一份其调用运行时的独立密封副本。其`recovery.mjs`启动器使用采用的外部Node和相同的本机恢复所有者。在没有候选者或私有部署检查的情况下，它仍然可以执行。切换期间没有运行时复制或构建。

`update recover --root <installation-root>` 在继续之前协调保留的指针和服务效果。它验证健康的选定候选者或恢复的前任者，并废弃该记录而无需再次重新启动。如果 `current` 需要恢复，请从保留的不可变能力生成中运行它。待处理和回滚结果还会打印精确的 `Recovery:` 命令，并在 JSON 中包含 `recoveryCommand`。当发布目录不可用时使用该独立助手；保留其控制目录和密封运行时。 `--timeout <seconds>` 边界准备状态观察； `--json` 返回结果和收据行，而不将散文混合到标准输出中。恢复也接受`--drain-timeout`；它仅适用于必须停止不健康服务的情况。健康的恢复永远不会耗尽或重新启动服务过程。在恢复等待期间保留记录和保留的版本。如果恢复重试已停止的候选并确认另一个启动失败，它将使用与激活相同的受保护前置回滚。候选人仍在开始或不确定的检查仍悬而未决。如果更新程序在关闭提交后中断，网关仍会完成关闭。保持独立的恢复命令可用：恢复会观察supervisor是否重新启动前任或服务停止，然后再采取其他操作。丢失的切换回复永远不会授权盲目的本机停止或回退到旧的可逆切换。

更新程序崩溃后，恢复可以修复安装控制或其本机执行程序租约中的热 SQLite 回滚日志。它首先验证私有恢复副本并获取当前所有权，然后再允许 SQLite 修复源。普通更新和状态读取不会执行该修复。修复仅准备的元数据永远不会启用激活。

[不可变更新设计](/reference/team-immutable-update-design#three-proposed-prs)记录了准备、激活和恢复合同。安装不可变版本后，现有已发布的更新程序需要明确采用；候选代码无法更改较旧安装的更新程序的行为。

## <a id="candidate-owned-admission"></a> 考生自有入场

对于包管理器更新，`openclaw update` 私下暂存所选包一次，然后让该候选者决定是否可以更新实时安装。注册表目标和显式工件（例如 `--tag ./openclaw.tgz`）使用相同的流程。该阶段可重复用于验证、金丝雀排练和激活；拒绝或预突变失败会将其删除并保留已安装的软件包和服务网关。在准入和包验证之后，匹配的安装版本和工件构建标识仍然是无操作的，除非更新需要替换安装方法或单独的服务根。临时候选者将被删除而不激活它。

当需要替换时，更新程序会在更改已安装的软件包之前保留其正在运行的工作文件。 Linux OverlayFS 安装使用私有副本，因此硬链接复制无法使保留文件的身份检查无效。其他支持的文件系统保留硬链接快速路径和复制回退。

SQLite 只读工作线程通过安装后验证使用保留的生成，即使在包管理器删除了以前的包路径之后也是如此。更新程序在返回之前加入这些工作人员。它记录已完成的运行时预测，以便由下一个符合条件的更新或 `openclaw doctor --fix` 进行清理，因此递归删除不会延迟最终结果后的命令退出。清理会保留投影，而另一个 OpenClaw 进程可能仍会使用它们。已安装的较旧更新程序（包括 2026.9.6）仍运行其原始工作启动代码；安装更正的候选者无法修复第一跳。

当仅保留被忽略的 `node_modules` 目录时，源更新会保留已停用的工作区依赖项链接。旧版安装的更新程序在 `updater-runtime-retention` 处失败，需要在重试之前在其运行代码中进行此更正；新的候选人无法修复之前的步骤。

运行时保留不包括全局模块目录中更新程序拥有的包备份，包括指向源签出的备份符号链接。较旧安装的更新程序（例如 `2026.9.6`）仍然可以遵循保留的 `.openclaw.package-backup-*` 链接，并因主机拥有的插件链接错误而拒绝更新。在重试之前，将该历史链接保留在全局模块目录之外，保持其已解析的目标不变。不要删除其源签出或移动属于活动或未解决的更新的备份。

安装的更新程序会在运行其挂起的生命周期脚本之前读取候选者的 `package.json`。 `openclaw.updateAdmissionProtocol: 1`发布内部准入命令。读取此标记不会执行候选代码。在候选准入过程开始之前，托管服务预检仍会在已安装的更新程序中运行。

相同的发布元数据可以声明`openclaw.databaseEngines: ["sqlite", "postgres"]`。该可选字段不会更改 `updateAdmissionProtocol: 1` 或其比较规则。缺失字段表示 `["sqlite"]`。当物理锚点显示任何已安装的存储使用 PostgreSQL 时，已安装的驱动程序会在突变之前检查所选包或 Git 目标是否有 `postgres`。缺少它的目标会被 `database-engine-preflight` 拒绝：在更新之前使用当前兼容的二进制文件反向移植到 SQLite，或者保留当前版本。参见[数据库引擎](/reference/database-engines)； port 命令保持禁用状态，直到满足其发布先决条件。 SQLite-only安装保留现有的进入路径并且不需要现场。候选人准入不能覆盖此已安装驱动程序保护。

| 所有者                                | 检查和操作                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 候选人拥有（通过 `update admit`） | 使用候选架构配置 read/validation（候选 Doctor preserves/handles 的缺失路径样式问题为 `admit` + 警告）、针对显式安装根的数据库架构预检、插件可用性预检。 Node 发动机比较仅供参考（`ok` 或 `warn`），不能拒绝入场。 |
| 安装自有（不变）          | 运行 admission/ledger、执行器租赁、托管服务预检 （ownership/ancestry）、Node 运行时 selection/provisioning、目录权限、npm/pnpm 生命周期策略、staging/verify/canary/swap/post-core.                                                                                                                       |

候选人使用相同的选定配置文件、状态目录、配置路径和环境以只读方式检查实时安装。它不获取租约、写入历史记录、运行 Doctor 修复、启动网关或接收更新执行权限。因此，丢失的自定义 `plugins.load.paths` 条目可能会产生准入警告，同时保留配置的路径和插件配置字节。入场并不承诺修复这条道路。

当候选人的 Doctor planner 生成完全有效的配置时，旧插件配置（例如 Discord 的嵌套 `dm.policy` 和 `dm.allowFrom`）会被承认并带有警告。准入检查预计的数据库目标，同时保留原始配置和状态字节。正常的更新时间Doctor仍然拥有保存修复、备份和回滚的权利。

有效的 `admit` 判决仅替换其报告的候选人拥有的检查。已安装的 Node 预检始终运行以进行软件包更新，包括在出现信息性 Node 警告后选择或私有配置兼容运行时。有效的 `refuse` 判决通过通常的突变前错误和 JSON 输出来报告候选人的原因和下一步行动。历史记录在 `candidate-admission` 步骤中记录检查。安装的更新程序在接纳后继续拥有更新，包括每个变更。

如果标记不存在或无效，更新程序将使用其已安装的准入检查并记录 `update-admission-unsupported-target`。如果候选者超时、崩溃或未返回有效的协议 1 判决，它将记录 `update-admission-fallback` 并使用相同的已安装检查。这些警告仅供参考；安装的检查确定更新是否继续。当历史记录压缩到 128 步或 16 KiB 限制时，这两个警告步骤都会保留其标识、状态和时间戳。可以压缩警告文本以适应该限制。这不需要迁移，也不会改变录取决定。

使用 `--admission installed` 强制安装检查。默认选项为`--admission auto`；该选项没有环境变量形式。 `--dry-run` 始终使用已安装的检查，并且不会暂存包或调用候选人准入。 Git/source 更新保持现有流程。

`openclaw update admit` 是一个内部命令，隐藏在帮助中。 Supervisor 将 `--context <absolute-path>` 传递给私有模式 0600 上下文文件；此命令路径和所需参数选择准入子模式。该命令发出一份 JSON 文档，其中包含 `protocol`、`verdict`、`reasons`、`warnings` 和 `facts`，其中包含 candidate/installed 版本、候选者声明时的 `nodeEngines` 要求以及命名检查结果。它退出 `0` 表示准入，`3` 表示拒绝，或 `2` 表示内部错误而没有有效的判决。它通过退出 `2` 拒绝继承的更新权限变量，从而允许主管回退。它不执行托管服务祖先检查。默认准入预算为 120 秒，并遵循金丝雀超时预算分辨率。

运行 JSON 包括 `run.admission` 和 `owner: "candidate"` 或 `"installed"`，以及可选的 `protocol`、`candidateVersion`、`checks` 和 `fallbackReason`。账本将此元数据存储在其现有来源 JSON 中； `run.origin.candidateAdmission` 保留有限制的、经过编辑的判决，包括所有记录的原因和警告。较旧的历史记录可以省略准入元数据。

准入元数据是诊断性的，当恢复收据使用完整的历史预算时，可以从历史记录中省略。

仅当安装的更新程序已支持此切换时，此切换才有效。在登台之前拒绝的旧更新者不能使用新候选者的判断；首先遵循该已安装版本的恢复指南。

## <a id="database-capture-and-recovery"></a> 数据库捕获和恢复

更新保留每个商店的物理引擎。在数据库突变之前，安装的更新程序会保留现有的精确 SQLite 捕获并将每个 PostgreSQL 存储捕获为未经消毒的 SQLite 导出映像及其匹配的锚点和格式 2 清单。这些私有恢复捕获保留了规范数据、瞬态行和分配事实；普通的经过清理的用户备份无法替代它们。恢复收据记录了物理引擎和存储身份。

PostgreSQL 捕获在更新的独家维护所有权下运行。回滚验证捕获，恢复新拥有的 PostgreSQL 命名空间，并通过现有恢复所有者发布匹配的锚点。它会保留迁移的命名空间，直到确认恢复为止。如果由于捕获或所有权或提交结果不确定而状态发生变化，自动恢复将停止并保留两者以进行恢复。部分恢复使网关保持停止状态。 SQLite 捕获和恢复保留其现有行为；更新永远不会反向移植或默默地更改引擎。这些保护必须已存在于已安装的更新程序中：安装候选更新程序不会改进其父驱动程序。

## <a id="runtime-retention-failures"></a> 运行时保留失败

**立即修复：** `host-owned-plugin-link` 表示依赖项符号链接到达 OpenClaw- 拥有的文件，更新程序无法安全地将其保留为独立插件依赖项。当包替换删除旧文件时​​，保留可以保护正在运行的更新程序和恢复工作程序。不要跳过此检查。

检查本地故障输出中的链接和目标。保留源文件和恢复备份。对于当前安装，请要求插件维护者将私有主机文件依赖项替换为 `openclaw/plugin-sdk/*` 导入或单独打包的依赖项。如果链接是意外的，请使用相同的配置文件、服务帐户、状态和配置运行 `openclaw triage`，以在移动或删除任何内容之前诊断其所有者。

较旧安装的更新程序可能会遇到上述历史包备份或退役工作区情况。安装的更新程序在替换之前执行保留：选择正确的候选更新程序无法修复第一步。仅移动已识别的非活动历史备份链接；不要移动活动或未解决的更新的备份或删除其源签出。

修复链接后，重试更新。使用报告的验证和恢复结果来确定之前的网关是否仍在服务；仅拒绝保留并不能确定服务健康或恢复。

## <a id="gateway-recovery-verification-failures"></a> 网关恢复验证失败

**立即修复：** 服务停止或就绪检查失败意味着更新未验证服务网关。使用相同的配置文件和帐户检查 `openclaw gateway status --deep`。该报告标识了观察到的服务状态、版本不匹配、准备失败以及可用的插件诊断。没有这些事实的准备期限并不能确定启动原因。

一旦目标版本和构建正在运行且 HTTP 就绪情况良好，通道连接或探测错误就会发出警告。更新成功并且包备份保留正常进行。每个警告都会命名通道；运行`openclaw channels status --probe`或`openclaw health --json`进行诊断。仅通道警告并不会使重新启动变得不安全。

保留恢复备份并检查更新程序打印的重新启动日志。请遵循其恢复说明；如果它说重新启动不安全，请保持网关停止并运行 `openclaw triage` 来修复安装。状态迁移后不要单独恢复代码。如果报告显示网关仍在启动，请检查其进度，而不是重复重新启动它。

## <a id="automation-and-ssh"></a> 自动化和SSH

对于另一台主机上的授权更新，请使用目标安装的所属帐户和非交互式 SSH 命令：

```bash
ssh -T user@gateway-host 'openclaw update --yes' </dev/null
```

检查 `openclaw` 是否解析为该帐户的 SSH 环境中的预期安装。当定位命名配置文件时，在 `update` 之前添加现有的全局 `--profile <name>`。

单独的活动聊天会话并不能阻止显式更新。 `--yes` 跳过确认和可选的 shell 完成提示。如果没有它，普通升级仍然可以通过管道输入运行，但需要确认的操作（例如降级）会立即失败。当 stdin 不是终端时，故障报告菜单和分类同意提示不会等待输入。 `--yes` 不授予执行批准或接受更改的插件功能。

更新托管其自己会话的网关的代理应使用 `gateway` 工具的 `update.run` 操作（如果可用）。 SSH 配方适用于另一台主机；验证目标不是同一个网关。正常的执行批准和部署所有权仍然适用。

## <a id="native-service-commands-during-updates"></a> 更新期间的本机服务命令

更新程序通过目标 CLI 启动的本机服务安装、重新启动和停止命令在其子进程稳定下来时保留原始更新所有者。其所有者退出或失去租约的命令无法启动另一个本机突变或提交其挂起的配置更改。当注册的子进程或其进程组仍处于活动状态时，新的更新仍会被排除。

目标运行时必须支持这种所有权切换。在停止网关或激活其替代品之前，候选验证会检查支持情况。缺少目标 CLI 或没有支持的较旧目标将被拒绝；更新程序不会调用旧的运行时安装程序作为替代。授权安装根更改单独绑定目标 CLI，同时保留原始更新所有者。更新拥有的命令还拒绝非托管 restart/stop 和分离重新启动或无法保留此所有权的 Windows 启动文件夹后备。普通用户调用的 `openclaw gateway` 命令保留其现有行为。

在 Windows 上，功能检查保持活动状态，直到更新程序完成绑定其进程身份。如果 Windows 无法提供进程创建时间戳，则更新程序将保留由实时父级建立的标识或使用子级记录的启动器标识，并在运行历史记录和诊断日志中发出警告。不同的观察到的身份仍然拒绝切换。仍然支持使用 `InteractiveToken` 的计划任务；这不需要存储任务密码。

此目标-CLI 保护并不涵盖每个 Doctor 或插件子项或包突变之前的进程内服务准备。

计划任务自动启动暂停后，在安装突变之前取消会在退出前恢复它，同时保留对原始更新所有者和任务身份的检查。此保护属于已安装的更新程序；安装包含修复程序的版本可以使其执行该版本的下一次更新。

## <a id="options"></a> 选项

核后修复 Doctor 和 `openclaw update finalize` 的运行没有单独的每个 Doctor 截止日期，除非操作员提供 `--timeout`。新的核心后处理会独立于其内部步骤余量接收操作员选择。较旧的目标保留其现有的津贴和截止日期行为。

当省略 `--timeout` 时，当前的 CLI 和 RPC 最终确定不会添加聚合激活期限。明确的运营商限制和继承的激活津贴仍然适用；旧的或未被识别的切换保留其现有的有限期限行为。检查、所有权许可、准备情况、恢复和清理保留其自身的界限。显式 `--timeout <seconds>` 提供从更新准入到激活、准备和恢复的总体预算，包括本机服务命令。过期报告 `update-activation-timeout` 或待恢复；它不会启动另一个恢复阶段。杰出作家保留所有权，直至达成和解。

验证激活或回滚后，过时的包和启动器备份树共享五分钟的清理预算。过期会保留剩余的备份并记录其路径作为警告，而不会撤消已验证的安装。清理会检查文件系统操作之间的预算，并等待已在进行的操作解决，因此停滞的存储可以延长清理等待时间。所有权和路径身份失败与清理到期仍然不同。

稍后验证的程序包激活还会废弃在更新开始之前捕获的历史程序包备份。符号链接停用仅删除链接；源结帐保持不变。失败的更新和回滚会保留这些历史备份，并且单独保留的数据库快照会保留其自己的恢复生命周期。

具有匹配 lint 检查的可选 Doctor 检查可以在重新启动的网关准备就绪后运行。目标 Doctor 报告其实际推迟的检查；更新程序针对更新的安装和当前配置运行这些检查。较旧的更新父母或目标将这些检查保留在 Doctor 内。如果目标未提供可用的报告，则更新程序会记录建议，而不是声称重启后检查已完成。在从较旧的更新程序进行第一次升级时，即使目标运行内联检查，保留的父级仍然可以报告其自己的重新启动后检查警告。

插件后配置验证和准备情况检查使用 Doctor 完成后测量的共享和代理数据库大小，包括 WAL 文件。当省略 `--timeout` 时，核心后插件安装和更新工作没有默认截止日期；明确的操作员限制和老年呼叫者津贴仍然适用。明确的 `--timeout` 仍然是这些检查和迁移最终确定的总体预算。较旧的继承激活限额使用测量的数据库大小、观察到的候选启动和插件计数。汇总到期报告 `update-activation-timeout` 并保留所有权直至作者和解；它不授权回滚或重新启动。使用 `openclaw update status` 和 Doctor 进行康复指导。

对于全局软件包安装（npm、pnpm 或bun），`--no-restart` 仅跳过更新程序的托管重新启动。当其观察程序检测到替换的安装时，正在运行的网关会自行重新启动，因为旧的运行时可能会在包交换期间丢失所需的块。在发布之前，更新程序会打印此警告并将其包含在 JSON 更新历史记录中。它无需等待启动即可检查观察到的网关版本；不可用的准备状态或尚未切换的版本会使软件包更新成功并出现警告。被另一个进程阻止或移交给新模式的状态验证将推迟到候选者。保留恢复备份并在启动完成后运行 `openclaw update status` 和 `openclaw doctor`。不相关的更新失败保留其故障诊断。

对于 Git 签出和不可变的仅准备更新，`--no-restart` 将激活留给操作员。正在使用的 Git 运行时受到保护，不会被替换；该标志不授权覆盖正在运行的网关仍需要的文件。准备好激活它时，通过安装的服务所有者重新启动。使用更改的插件成功更新后，最终报告会提醒您重新启动以激活它们，包括核心版本也发生更改的情况。

交互式更新显示阶段转换、当前步骤和经过的时间。这些阶段与 Control UI 匹配：请求、暂存、验证、激活、重新启动、验证和完成。当输出通过管道传输或捕获到日志中时，会打印无动画的进度，并在步骤运行时每 30 秒报告一次经过的时间。更新、验证和回滚不需要推理或模型认证。模型验证结果仍然是警告。无人值守更新（`--yes`、`--json` 或无 TTY）永远不会启动修复代理。在失败的结果和更新清理后，他们保存分类诊断并打印 `openclaw triage --run --update-result <path>` 以进行明确的选择修复。托管切换和前台 `gateway run` 启动失败也仅收集诊断信息。交互式更新保留了**诊断更新失败**菜单和同意提示。分类不会更改记录的更新结果。来自旧更新程序的报告仍可能包含 `repairing` 阶段。失败的步骤包括来自两个输出流的最终诊断；超时被明确标记。最终报告包括结果、记录的阶段持续时间、失败的步骤、验证事实和恢复指南。 `--json` 保持标准输出机器可读，并且不打印进度步骤或运行进度观察器。 Progress 通过可重用的只读工作连接观察已提交的账本行，而不是重复复制共享状态。这适用于固定更新程序启动的更新；已发布的较旧更新程序会保留自己的进度读取器，直到被替换为止。状态检查和快照进度是建议性的：暂时满的进度管道可以省略更新，而不会中断底层工作。其他输出错误仍然会导致受影响的操作失败并保留其诊断报告。

当没有更新活动时，`openclaw update status` 使用记录的开始时间标记保存的结果 `Last recorded update`，因此历史结果与当前更新活动不同。

从开发签出切换到软件包时，更新程序会替换 npm 的安装链接，并保持外部签出不变。如果激活失败，恢复该链接及其启动器不会验证可变签出的运行时。恢复未经验证且不授权自动重启；在重新启动之前检查检查和恢复报告。

对于没有运行时数据库的配置文件，较旧的 npm 目标会在更新程序记录历史记录之前初始化其兼容状态。所选版本的 Doctor 在激活之前运行，包括 npm 的安装挂钩已创建数据库时。现有数据库保留降级保护。当更新程序可以读取共享状态时，目标发布预检还会检查已配置、停用和注册的自定义代理存储，并在更改安装或停止网关之前命名每个不兼容的存储。比更新程序可以读取的更新的状态保留单个安装兼容构建或恢复备份拒绝。

在候选验证期间，Doctor 会从复制的配置中留下仅簿记版本、向导和迁移标记，以便较旧的更新程序不会将它们误认为是所需的配置修复。没有端点更改的 Webhook 完成记录在排练状态中。真实配置迁移仍在运行；激活后正常配置写入记录候选者的版本和迁移元数据。

如果数据库模式预检由于配置无效而无法检查配置的路径，则其拒绝列出配置文件和无效字段。运行 `openclaw doctor --fix` 以修复已失效或无法识别的字段，更正任何剩余错误，然后重试更新。预检保持配置不变。

带有临时 OpenClaw 配置文件的新配置文件第一阶段的显式封装规格。更新程序在承认对所选配置文件进行更改之前，会检查分阶段运行时声明的架构和 Node 要求。没有声明模式支持的工件将被拒绝，而不创建配置文件的运行时数据库。准备工作使用原始包规范和拥有的包管理器。

新配置文件 `--dry-run` 使数据库不存在并且不记录运行。对于包目标，它使用与实际更新相同的运行时规划器检查确切目标的 Node 要求。当没有可用的运行时时，文本输出和 JSON `notes` 报告 `Would refuse update`，或者当更新程序可以将其拥有的托管服务刷新为兼容的 Node 时报告 `Would replace`。预览仍然成功退出，并且不安装包或更改服务。如果无法解析包元数据，请使用确切发布的 `--tag` 重试；失败的目标选择不会使用更新程序的架构初始化配置文件。元数据故障保留检测到的更新模式以及注册表查找、dist 标记解析、版本不匹配、模式声明或 Git 目标检查的特定故障事实。摘要和`openclaw update status --json`包括原因和下一步；有界故障报告包含相同的公共描述，而无需发布本地路径或注册表响应文本。在安装候选更新程序之前，现有更新程序无法获得这些诊断信息。

`--dry-run --json` 报告 `currentVersion` 中包和 Git 安装的已知安装版本，包括选择转换为 Git 的已保存开发通道。如果目标版本未解析，`targetVersion` 仍为 `null`，并且附加 `targetVersionReason` 字段解释了原因。已解决的目标忽略此字段。文本预览还显示已安装的版本并解释未解决的目标。

`--yes` 还会跳过可选的 shell 完成设置提示。现有的完成配置文件和缓存仍会在需要时进行修复；在新的 shell 配置文件中安装完成仍然是一个交互式选择。

`--tag` 仅更改此软件包更新。即使在一次性测试版安装之后，保存的 `update.channel` 仍会继续管理以后的前台和自动更新。使用 `--channel` 更改该策略。

对于显式包工件，在排练或激活之前，将根据私下暂存的包版本检查配置的插件可用性。 `--dry-run` 不会暂存工件并报告此检查仍处于待处理状态。

托管更新切换会保留选定的工件，包括当前的重复项，因此目标检查会使用该工件的数据库架构和运行时要求。

对于源签出，`--dry-run` 预览更新流程，无需获取 Git 引用或检查工作树更改。真正的更新在修改结帐之前会检查未提交的更改。使用 `openclaw update status` 检查当前分支、版本和更新可用性。

<Note>
在 Nix 模式 （`OPENCLAW_NIX_MODE=1`） 下，禁用变异 `openclaw update` 运行。更新此安装的 Nix 源或 flake 输入；对于 nix-openclaw，请使用代理优先 [Quick Start](https://github.com/openclaw/nix-openclaw#quick-start)。 `openclaw update status` 保持只读。 `openclaw update --dry-run` 无需更改安装即可预览流程。仅当配置文件已具有运行时数据库时，它才会记录跳过的运行。
</Note>

<Warning>
降级需要确认，因为旧版本可能会破坏配置。 如果安装已经将会话迁移到 SQLite，请在启动旧的基于文件版本之前恢复已归档的旧版转录工件。请参见 [Doctor：在会话 SQLite 迁移后降级](/cli/doctor#downgrading-after-session-sqlite-migration)。
</Warning>

## `update wizard`

交互式流程，用于选择更新通道并确认之后是否重启 Gateway（默认会重启）。在没有 git 检出版本的情况下选择 `dev` 会提供创建一个的选项。

通道选择器读取本地安装标识，而不检查 Git 新鲜度或依赖项。当您应用更新时，这些检查就会运行；首先使用 `openclaw update status` 检查可用性。

| 标志                    | 默认值 | 描述                                                  |
| ----------------------- | ------- | ------------------------------------------------------------ |
| `--timeout <seconds>`   | 取消设置   | 可选的总体更新预算（以秒为单位）。                   |
| `--accept-capabilities` | `false` | 在更新期间接受经过审查的插件功能更改。 |
