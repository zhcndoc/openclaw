# `openclaw worker`

`openclaw worker` 是网关拥有的启动器在准备好的云或配对节点工作环境中启动的受限运行时入口点。它不是用于手动工人注册的通用命令。

网关通过注册节点的经过身份验证的连接安装匹配的 OpenClaw 捆绑包。工作线程启动器使用准备好的分配启动此命令，并且工作线程通过其自己经过身份验证的出站 WebSocket 作为专用 `worker` 角色连接回网关。

## <a id="launch-contract"></a> 启动合约

该命令从标准输入中准确读取一个有界 JSON 发射包络线。信封包含网关工作端点、铸造的工作凭证、捆绑包和协议身份、所有者纪元、单个分配的会话和轮次，以及为该轮次授权的确切工作人员本地工具名称。网关在移交之前根据当前策略解析此最终工具集；原始配置和计划所有者身份永远不会进入工作人员信封。该凭据永远不会通过命令行参数接受，并且此页面有意不提供凭据或手工编写的信封示例。

节点管理程序使用私有托管入口点，该入口点可以允许连续进入同一环境，同时保留后台进程。每个回合仍然会收到一个新的有界信封、网关连接和工具权限。上面的独立命令仍然是单轮入口点。

停止节点工作线程环境会取消挂起的准入，并尝试清理其工作区进程、托管工作线程和持久启动所有者。一个清理所有者的失败不会跳过其他清理所有者。这些尝试完成后，停止报告清理错误；清理尚未确认的启动将保留其容量预留，直到恢复成功。当 Stop 等待跟踪的工作人员清理工作完成时，同一环境不能允许再次转弯。如果初始化失败，独立清理仍然可以完成，但节点不会通告空闲容量，直到初始化成功。当失败转向清理记录终端放置时，会话描述将刷新到 `failed` 并包含恢复原因，而不是保留 `draining`。

在当前的Linux和macOS节点主机上，启动日志标识了worker的进程所有者；应用程序 `worker.mjs` 作为其子应用程序运行。所有者在应用程序崩溃后幸存下来，并在释放容量之前保留嵌套命令清理。节点主机重新启动后，恢复会短暂观察该确切所有者，而不会终止其清理观察者。未完成的清理会保留其插槽，而其他空闲插槽仍然可用。节点管理程序继续观察清理情况，并在记录的沿袭完成和物理进程树消亡后自动返回槽。关闭监督者放弃并加入其观察，而不释放未完成的所有权。状态、启动重播和取消共享相同的恢复，同时保留回合收据；已完成的回合结果保持不变。这种保护需要更新的节点主机以及当前的工作包；单独更新网关不会替换旧节点的监督路径。

启动必须适合每个完整序列化形式的 25 MiB：节点调用事件和托管工作线程输入行，包括节点的连接端点。网关会在需要时修剪旧的完整回合，而不丢弃最新的提供者重放检查点。如果该重播单元无法容纳，则在切换之前回合会失败，并显示可见的重试指令。托管行限制不包括其最后的换行符；独立的标准输入计算每个字节。

如果信封无效、凭证被拒绝、捆绑包或协议功能不匹配或者会话和所有者纪元不再是当前的，则拒绝入场。丢失、重复或未知的工具名称也会使信封失效。操作员应通过云工作人员编排器启动工作人员，而不是直接调用此入口点。

如果准入耗尽其 120 秒重试预算，则终端错误包括尝试计数、网关主机和端口（或本地套接字路径）以及上次失败。 `connect failed`表示WebSocket没有打开；检查可达性和 TLS。 `no hello within deadline` 表示已打开，但网关未完成工作人员准入。可重试的录取拒绝保留其原因。这些有界的、经过凭据编辑的详细信息出现在节点启动日志和转向错误中。

在创建每个容器之前，容器启动会重新验证固定的守护进程身份。此检查允许繁忙的守护进程有 30 秒的时间；超时仍然会导致启动失败并命名该命令。更改的守护进程身份仍然是一个硬故障。

## <a id="runtime-boundary"></a> 运行时边界

该进程运行标准的嵌入式 agent 循环，但后端受限：

- `read`、`write`、`edit`、`apply_patch`、`exec` 和 `process` 代码工具在 Gateway 发起的 turn 授权中存在时，会在 worker 工作区本地运行。 空授权会以无工具方式运行模型。
- Model 调用默认使用网关推理代理。显式配置的配对设备配置文件可以选择具有节点配置模型配置和外部范围代理身份验证的 [worker-local inference](/gateway/cloud-workers/native-inference)；未加载网关身份验证配置文件。
- Transcript 写入使用 gateway transcript-commit RPC。
- 流式传输和工具生命周期更新使用 gateway live-event RPC。
- 只接受已分配的 session 和 turn。

工作模式不会启动通道、网关 HTTP 表面或超出指定会话工具集的插件自动启动。它使用一次性状态目录。代理工作人员没有模型提供者凭据，并且工作人员 `exec` 不会读取或投影网关秘密存储。显式选择的本地推理工作人员将其节点授予的不透明身份验证值保存在运行时内存中。外部托管人必须将实际的提供商密钥保存在不受信任的工作负载之外；工作进程不是同一用户凭证隔离边界。当网关的有效共享 GitHub 身份可用时，工作人员会在其私有启动信封中收到一个回合绑定访问令牌。令牌在一次性状态目录内的私有每轮配置文件中具体化，在下一次绑定之前删除较早的配置文件，并在删除该目录时进行清理。密封的工人发射器将其绑定到每个 `exec` 子项。 Worker主机上必须安装GitHub CLI；该捆绑包包括启动器，而不是 `gh`。

物化技能文件是与工作状态及其 GitHub 凭证分开的私有目录中的临时轮次输入。他们的目录范围仅限于会话和工作区，每个技能路径都使用一个简短的可读名称及其名称、来源和经过验证的内容的摘要。未更改的交付以固定的提示顺序重新创建相同的路径，因此后面的轮次可以重用提供者的提示前缀并读取先前轮次的引用，而无需重写记录历史记录。改变的技能内容获得了新的路径。 Worker 通过清理持有文件系统锁；另一个实时转弯无法取代其输入，并且崩溃恢复只能回收一个绝对死去的所有者。每轮删除失败记录 `Materialized skill cleanup failed`。 Node Claude 技能会话单独报告 `Node Claude skill session cleanup failed` 用于临时创意工坊配置。这些有限的、经过编辑的警告标识可能保留的文件。等到工作线程或会话及其拥有的进程停止后，再检查权限并手动删除报告的目录。完成转弯并不意味着受管理的工人已经停止。这些文件系统删除失败会保留原始的成功、错误、取消或超时，而不会重播工作或声明删除成功。工作线程状态删除（包括 GitHub 凭证清理）在失败时仍会拒绝。进程耗尽、权限撤销、数据库关闭和传输或 MCP 关闭保留其现有的故障行为。无效的技能完整性或传递限制仍然会拒绝回合。

工作人员通过有界引导加载程序加载工作区 `AGENTS.md`，并将网关提供的系统指令作为文字文本附加。它不会从工作区或代理状态目录中发现 `SYSTEM.md` 或 `APPEND_SYSTEM.md`。

worker-to-worker session dispatch 在此模式下不暴露。放置和 dispatch 仍由网关负责： 操作员可以通过 Gateway dispatch 一个现有的本地、managed-worktree session，而 worker 进程不能自行 dispatch 自己或另一个 worker。

准备好的作业携带转录上下文、接受的基本叶、提交序列和实时事件光标。在工作人员 WebSocket 重新连接时，该进程会使用相同的凭证和所有者纪元重新接纳，保留已接受的转录库，重播其未确认的实时事件尾部，并使用相同的身份重新附加正在进行的推理轮次。如果流式增量丢失，则终端推断消息具有权威性。取代所有者纪元会隔离该进程并导致干净退出。

`stale-base-leaf` 转录本拒绝会导致当前运行失败。工作模式不会针对不同的叶子重试被拒绝的序列，因此不会产生重复的提交；该运行中任何尚未提交的内存尾部都会丢失。重新启动属于 [placement](/gateway/cloud-workers/placement-and-machine-selection)，它必须从网关的权威记录和提交分类账中创建新的分配。同样，网关进程重新启动会终止挂起的推理轮次并出现提供者错误；只有工作线程 WebSocket 重新连接才能重新附加到活动的同进程推理流。

网关在确认之前保持推理准入，并在发布终端消息之前保持完成。网关关闭和会话生命周期消耗也加入了接受的提供者和存储工作，包括在取消开始时仍在等待的准入。如果本机存储结算未知，则网关会保留该故障，并且不会重试终端写入或重放受影响的推理身份。在报告故障之前，独立关闭清理仍在运行。

有关封闭工作人员 RPC 表面的信息，请参阅 [ 网关协议 ](/gateway/protocol/handshake#worker-role-and-closed-protocol)，有关架构和安全模型的信息，请参阅 [ 云工作人员](/gateway/cloud-workers)。
