## <a id="goals"></a> 目标

- 按 HTTP 请求重试，而不是按多步骤流程重试。
- 仅重试当前步骤，以保持顺序。
- 避免可能产生重复效果的重复操作。

## <a id="defaults"></a> 默认值

这些默认值适用于通道发送。模型请求使用下面的恢复策略。

| 设置       | 默认值   | 适用于                                                             |
| ------------- | --------- | ---------------------------------------------------------------------- |
| 尝试次数      | 3         | 下面的每个信封                                                   |
| 抖动        | 0.1 (10%) | 下面的每个信封                                                   |
| 最短延迟     | 400 ms    | 共享通道包络：Telegram 和任何无覆盖的通道 |
| 最短延迟     | 500 ms    | Discord 发送和 Discord REST 调用                                   |
| 最大延迟上限 | 30000 ms  | 共享信道包络和 Discord 发送                          |
| 最大延迟上限 | 300000 ms | Discord REST API 来电                                                 |

这些是按请求的信封。 Discord 网关 WebSocket 重新连接环路是独立的，不使用它们：它允许最多 50 次重新连接尝试，并从 2000 毫秒指数级回退到 30000 毫秒上限，没有抖动。

## <a id="behavior"></a> 行为

### <a id="model-providers"></a> 模型提供方

在显示终端错误之前，代理会自动从临时速率限制、过载和提供程序故障中恢复。每次连续中断允许最多尝试 10 次速率限制；其他暂时性故障允许在 90 秒重试窗口内重试八次。成功完成的模型响应会重置重试计数、退避和中断窗口，因此故障之间的有用模型工作不会耗尽以后中断的恢复。仅部分流、失败的响应和工具活动不会重置这些预算。外部恢复环路防护也仅在成功完成模型响应后才会重置；现有的每次尝试超时和任何独立的外部截止日期均保持不变。正在进行的转弯可能会超过一次尝试的总预算。退避大约从一秒开始，呈指数增长，并增加抖动以分散并发重试。提供者节奏（包括 `retry-after`、`retry-after-ms` 和“请在……后重试”提示）设置最短等待时间，甚至超过 30 秒的退避上限。用户取消和独立施加的整个运行期限仍然会阻止恢复。

在 HTTP 429 响应上，耗尽的令牌、项目令牌或请求存储桶也会贡献其配额重置等待。 OpenClaw 采用最长的适用重置和显式重试提示。云工作人员将此时间与缩短的错误文本分开保存；可用配额和非 429 响应不会引入配额重置等待。这不会更改本机harness传输或添加共享配额准入。

恢复继续现有的记录，并指示保留已完成的工作并在决定是否重复之前检查中断的操作。它可以在工具活动或部分输出后恢复节流，而无需重新提交原始用户请求。该运行在等待期间显示一个瞬态重试指示器，并且仍然可以取消。恢复的尝试不会留下持续存在的助理错误；只有终端故障才会保留一个错误。计费失败、身份验证错误和提供商拒绝不使用此暂时重试预算。

空错误正文不会使永久性 HTTP 客户端错误可重试。 Bodyless `400` 和 `422` 响应浮出水面，无需静默错误重新提交；具有已识别的瞬时重试证据的客户端错误仍然遵循现有的恢复策略。空的成功响应保留其单独的响应修复重试。

在嵌入式运行时中，当最新批次中的每个工具都有记录的结果并且所有工具执行都已解决时，工具活动后的模型空闲超时也会使用此恢复。下一次尝试保持工具可用于完成任务，包括处理记录的工具故障。等待批准、异步工具活动、有意的工具终止、取消和运行截止日期仍然会阻止这种继续。已完成的操作不会重新提交。

由于格式错误的服务器发送事件 JSON 而失败的 OpenAI SDK 流也符合有界瞬时恢复的条件；任意 JSON 解析和请求模式失败都不会。从记录的工具结果继续恢复，而不是重新运行已完成的操作。

在其终止事件之前结束的响应流也符合瞬态恢复的条件，包括当工具调用仍未完成时。部分工具参数永远不会被执行。具有不一致工具调用标识的完整响应不符合断开连接的流的资格。在事件框架内结束的 Gemini 或 Vertex AI 流具有相同的资格；畸形的 JSON 的整个框架则不会。

即使提供商尚未关闭 HTTP 响应，也会立即发送已完成的响应回复。 OpenClaw 在后台丢弃最多 64 KiB 的尾随字节，持续时间最多为 250 毫秒，因此可以重用已完成的连接。尾随事件永远不会添加输​​出或工具调用。取消和网关关闭可以阻止流失。

如果在生成工具调用时响应请求达到其输出令牌限制，嵌入式运行器也会在承认的工具稳定后自动从记录的结果继续。它保持相同的模型和帐户，保留已完成的操作，并且从不执​​行部分参数。此延续共享重试计数预算和现有超时控制，但不共享 90 秒的中断窗口：生成完整响应可能需要比这更长的时间。其单独的一次连续限制适用于整个运行，并且不会因成功的模型响应而重置。取消、待批准、活动的异步工作和有意的工具终止仍然会停止继续。提供商拒绝和未知的不完整答复原因不符合资格。

用尽的订阅、每日、每周或每月使用窗口将直接转至符合条件的身份验证配置文件或模型后备。单独的 `Retry-After` 值不会建立使用窗口耗尽：临时限制仍然遵循提供者在保存的 `retry.provider.maxRetryDelayMs` 之前的最短等待时间（默认 60 秒）。对于重放安全尝试，比该上限长的速率限制下限会停止相同配置文件重试，并遵循现有的身份验证配置文件轮换和模型回退策略，即使没有配置模型回退也是如此。如果没有剩余合格的配置文件或模型，OpenClaw 会显示速率限制错误，而不是等待发言权。配置文件引脚仍然限制凭证选择。重放不安全的尝试继续尊重发言权； `maxRetryDelayMs: 0` 禁用上限。

[ 模型故障转移控制器](/concepts/model-failover#model-fallback) 拥有此恢复预算。一旦耗尽，OpenClaw 就会遵循符合条件的身份验证配置文件或模型回退路径，或者显示最终失败。终端速率限制错误解释了在没有完成模型响应的情况下用尽了多少次自动重试，而不是仅显示提供程序的最后一次重试延迟提示。在将终端故障返回到 OpenClaw 之前，本机harness可能会在内部重试各个请求；这些内部重试与 OpenClaw 的持续预算是分开的。

ChatGPT SSE 错误将 HTTP 状态和 `Retry-After` 保留在一起，因此即使瞬态 HTTP 响应的消息或提供程序代码不熟悉，它仍然可以重试。 ChatGPT 传输在流式传输之前单独为 `websocket_connection_limit_reached` 重新连接一次；这不是 SSE HTTP- 响应重试。

对于保留内部重试的 SDK 调用，基于不锈钢的 SDK（例如 Anthropic 和 OpenAI）可以在可重试响应上接收 `retry-after-ms` 或 `retry-after`（`408`、`409`、`429`、和 `5xx`）。当等待时间超过 60 秒时，OpenClaw 注入 `x-should-retry: false`，以便 SDK 立即返回控制。使用 `OPENCLAW_SDK_RETRY_MAX_WAIT_SECONDS=<seconds>` 覆盖此 SDK-only 上限。将其设置为 `0`、`false`、`off`、`none` 或 `disabled`，让这些 SDK 调用尊重长时间的 `Retry-After` 内部睡眠。

中文的配额耗尽提示也遵循相同策略，包括 MiniMax Token Plan 的 `已达到 Token Plan 用量上限`、z.ai 的 `已达到每周/每月使用上限`，以及 `额度已用尽` / `配额已用尽`。临时的 `请求过于频繁` 限流仍使用同一模型的重试预算。

### <a id="managed-git-operations"></a> 托管Git操作

在命令的原始超时内延迟一秒后，共享 Git 运行程序会重试暂时的 `fetch` 和 `ls-remote` 故障一次。这包括不完整的对象传输、连接重置、临时 DNS 故障和瞬时 HTTP 错误。托管项目克隆使用相同的策略，并在重试之前删除失败的部分签出。取消会停止重试，并在下次尝试之前再次检查工作区或发布权限。每次计划的重试都会写入 `git/network` 警告，其中包含操作、尝试计数、延迟和退出代码。它省略了命令参数、存储库 URL 和原始 Git 输出。

身份验证失败、缺少存储库或引用、本地存储故障、进程终止和用尽的命令超时不会重试。此运行程序不会重播 `push` 和 `pull`：失败的连接可能会跟随已接受的写入，因此发布会保留其现有的远程结果协调。此策略不会包装由代理或安装脚本运行的任意 Git 命令。

### Discord

- 对速率限制错误（HTTP 429）、请求超时、HTTP 5xx 响应，以及临时性传输失败（例如 DNS 查询失败、连接重置、套接字关闭和 fetch 失败）进行重试。
- 优先使用 Discord 的 `retry_after`，否则使用指数退避。
- 如果无法读取错误响应正文，则收到的 HTTP 状态和速率限制标头仍会控制重试。永久拒绝 `401`、`403` 和 `404` 不会重试。
- 消息编辑、删除、固定和取消固定以相同的方式重试。只有在先前的尝试因丢失响应而失败后，发现消息已消失的删除才算完成。

### Telegram

- 通过内置传输，新的文本消息和富文本消息使用新的 HTTP 连接，避免了初始预览、回复和终端错误的陈旧保持活动套接字。轮询、编辑和控制请求保留连接池。这会向每条新短信添加连接握手。
- 这些文本发送可能会创建重复项，因此仅当 Telegram 通过洪水控制 （429） 拒绝请求或传输证明请求未启动时，它们才会重试。发送后重置、超时或丢失响应仍然不明确且不会重播。
- 可安全重复的操作（包括预览编辑）可以重试暂时性网络故障和 HTTP 5xx 响应，而无需替换现有消息。
- 优先使用 `retry_after`，否则使用指数退避。
- HTML/Markdown 解析错误不会重试；第一次尝试时会回退为纯文本。

## <a id="configuration"></a> 配置

Discord 和 Telegram 频道的重试时间是内置的，无法在 `openclaw.json` 中配置。

嵌入式运行时的现有会话设置 `retry.provider.maxRetries` 会覆盖其恢复重试预算； `0` 禁用重试，并且速率限制仍限制为每次连续中断的总尝试次数为 10 次。这是嵌入式会话设置，而不是 `openclaw.json` 密钥，并且它不配置本机harness请求重试。自动恢复不需要新配置。

## <a id="notes"></a> 说明

- 重试按请求生效（消息发送、媒体上传、反应、投票、贴纸）。
- 复合流程不会重试已完成的步骤。

### <a id="durable-outbound-delivery"></a> 耐久外向交货

网关在启动时检查一次未完成的外向交货。新的持久队列在数据库事务提交后唤醒恢复。当未完成的交付仍然存在时，恢复会不断重试，并在队列为空时停止唤醒；空闲网关不会轮询空的出站队列。

持久出站队列具有单独的传递尝试预算。当交付使用生产者声明时，预订会在收取尝试费用之前检查确切的所有者及其租约。过期或被替换的索赔不会花费剩余预算；恢复可以在重试之前获得新的声明。

生产者租约持续 60 秒，并在所有者处于活动状态时每 20 秒更新一次。这可以容忍短暂的网关停顿；消失的生产者的恢复要等到其最后一个租约到期。

租约到期不会删除发送已开始的证据。这些条目在重播之前仍然需要进行协调，并且未替换的所有者可以记录较晚的结果，而无需授权另一次发送。
