# 会话搜索

`sessions_search` 会搜索你自己过往会话中的用户和助手文本。每个结果都
包含一个 `sessionKey`、时间戳、角色以及一段简短的匹配摘录。在需要查看上下文时，
将返回的 `sessionKey` 传给 `sessions_history`。

## 可见性和输出

搜索使用与 `sessions_history` 相同的会话可见性规则。在应用结果限制之前，会移除调用方可见会话树之外的结果。当启用 spawned-session 可见性时，沙箱化代理仍然仅限于它们自己创建的会话。

摘录在返回给模型之前会被编辑。结果还受到数量、摘录长度以及总响应大小的限制。

## 索引生命周期

OpenClaw 将全文索引存储在每个 agent 的 SQLite 数据库中，与转录记录行并列。
新的用户和助手消息会在持久化它们的同一事务中被索引，因此索引不会落后于实时对话；工具结果、推理块和图像被排除在外。
只有转录的活动分支可被搜索。

早于索引生成的转录（例如通过 `openclaw doctor` 导入的会话）以及
其活动分支已被回退的会话，会在下一次搜索开始时通过后台协调进行重新索引。
因此，带有 `indexing: true` 的响应可能是不完整的；请在索引完成后重试。
删除会话会在同一事务中移除其索引条目。

当前搜索使用 SQLite 的 Unicode 单词分词器，并移除变音符号。
用于 CJK 子串匹配的三元组分词是未来的改进方向。

## 会话搜索 vs. 记忆搜索

对于原始会话记录中的精确单词或短语，请使用 `sessions_search`。对于持久化记忆文件和语义召回，请使用
[`memory_search`](/concepts/memory-search)。实验性的会话记忆语料库是这种精确转录搜索的语义补充。
