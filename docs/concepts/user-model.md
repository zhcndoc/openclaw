`USER.md` 是代理工作区中可选的用户模型工件。它以指令的形式存储稳定的偏好、沟通风格、关系以及当前项目上下文，以便指导未来的会话。

OpenClaw 在会话开始时会将 `USER.md` 与 `MEMORY.md` 一起加载。它有一个单独的小型启动预算，并且在长时间运行的会话中，后续轮次会拾取对它的编辑。如果该文件不存在，启动将继续进行而不受影响。

## <a id="personal-user-files-on-a-shared-gateway"></a> 个人的USER共享网关上的文件

单用户网关仅使用代理工作区的根目录`USER.md`，可编辑于**代理 → 文件**。他们不公开个人指令编辑器或聊天工具，接受个人文件API请求，或加载每个配置文件的第二个`USER.md`。现有的每个配置文件文件在磁盘上保持不变，不会自动合并到根文件中。

仅当网关使用现有的多用户身份策略具有至少两个不同的、未合并的个人配置文件时，个人文件才可用。共享的所有者个人资料不算作单独的人。名单更改后，重新连接Control UI更新其宣传的功能；服务器在每次读取和写入时重新检查当前策略。

打开 **设置 → 个人资料 → 个人说明**，在“设置”侧栏的现有代理选择器中选择一个代理，然后保存您的首选项。您可以使用经过身份验证的配置文件和 `operator.read` 创建或编辑您自己的个人 `USER.md`；不需要管理员或一般写入权限。编辑器始终使用登录者，而不是当前打开的聊天的所有者。它无法编辑他人的文件或共享默认值。

您还可以要求任何经过身份验证的网关聊天会话中的代理更新您的个人说明，包括由项目工作树支持或由其他人拥有的会话。 `personal_instructions` 工具读取或更新所选代理配置工作区中的 **请求者的** 文件；会话所有者、任务目录和模型提供的配置文件 ID 永远不会选择写入目标。它在保存其内容哈希之前读取当前文件。没有经过实时身份验证的请求者的匿名或自主运行不能使用此异常。正常的工具政策仍然适用；常规文件系统访问未更改。在多用户网关上，token/password 或设备令牌共享所有者登录可编辑该共享所有者配置文件的文件；使用个人登录将不同人的文件分开。

保存检查您加载的版本。如果其他编辑器更改了文件，请保留草稿的副本并重新加载，然后再次保存。与共享工作区编辑器一样，针对独立主机端编辑器的冲突检测是尽最大努力；避免同时对同一文件进行 UI 和主机进程编辑。个人说明必须符合 4,000 个字符的引导程序预算；较低的配置预算和现有的出处检查仍然适用。不要存储秘密。编辑器支持本地代理工作区；远程托管的代理工作区报告显式错误，而不是编写不同的网关本地文件。

保留工作空间根目录 `USER.md` 以实现共享默认值。个人偏好位于 **agent 工作区** 中的 `users/<canonical-profile-id>/USER.md`，而不是任务的 Git 工作树。对于手动主机端编辑，从网关经过验证的 profile/People 数据中获取持久配置文件 ID；请勿使用显示名称、GitHub 登录名、电子邮件或粘贴到消息中的个人资料 ID。这使用现有的会话所有权和创建记录；无需更改架构或配置。

每个会话选择 **one 个人 `USER.md`**：首先是指定的人类所有者的文件，否则是经过身份验证的人类创建者的文件。代理或系统分配不会阻止创建者回退。对于符合条件的外部聊天回合，OpenClaw 首先加载共享文件，然后加载选定的个人文件。个人文件补充而不是取代共享文件，覆盖冲突的共享用户首选项，而不是项目规则或安全策略。无论工作空间目录的名称如何，工作空间根 `USER.md` 都保持共享。

没有托管推理中继的 Codex 连接仅使用共享工作区首选项：它们忽略所选的个人覆盖，因为本机线程指令可以由子代理继承。托管中继连接保留仅限家长的个人配置文件传送。请参阅 [Codex 工作区引导文件](/plugins/codex-harness-reference/workspace-bootstrap-files#skills-persona-and-memory-without-a-managed-relay)。

文件将在稍后的回合中刷新。重新分配会话会更改下一个新回合的个人上下文，而不是正在运行的回合。另一个参与者可以在正常权限和队列规则下进行引导，而无需切换个人上下文。来自多人的排队和收集的消息保留会话的选择；当前发件人未选择其他文件。配置文件合并选择幸存的主 ID；自己将首选项移动到该目录。 OpenClaw 不合并文件或创建达析报告。

丢失文件或丢失合格人员身份仅使用共享默认值。没有配置文件 ID 的人工分配不会回退给创建者。显示标签、频道发件人 ID、未知来源创建者 ID 和代理所有者无法选择个人文件。内部事件和委派任务不会自动继承个人资料。子代理引导程序仍然仅包含其现有允许的项目指令。共享的本地所有者配置文件代表使用该身份的所有连接，而不是单独的人；在团队网关上使用单人登录。

个人文件使用现有的受保护读取和内存来源检查。不接受符号链接别名。每个个人文件必须完全符合 4,000 个字符的 USER 预算（或按 file/remaining 配置的较低总预算）；否则，它会被省略并带有警告，而不是部分注入。共享文件保留其现有限制。现有的特定于harness的引导程序抑制仍然适用：例如，嵌入式运行程序的 `contextInjection: "never"` 和 `continuation-skip` 设置以及轻量级引导程序模式。使用默认的 `always` 模式在稍后的回合中刷新会话选择的个人指令。本地嵌入式、通用 CLI 和本机 Codex 引导路径支持此选择。 ACP 代理、实时会话和远程工作执行无法从此功能中获得按人选择。

这是 **提示选择，而不是文件系统保密**。工作区工具、可信插件、共享记录和之前生成的响应可以暴露其他上下文。重新分配会话或更改参与者不会删除对话历史记录。不要在这些文件中存储机密。

## <a id="gateway-profile-and-github-credit"></a> 网关配置文件和GitHub信用

您的经过身份验证的网关配置文件与 `USER.md` 是分开的。打开**设置→个人资料→身份**设置在网关上向其他人显示的显示名称和头像。当 GitHub 帐户经过验证时，自定义 OpenClaw 头像仍然具有权威性。配置文件标头遵循您的实时用户身份，包括从其他浏览器清除的名称，即使配置了多个代理也是如此。未识别的连接保留默认代理预览。

经过身份验证的用户可以使用 `operator.read`、`operator.sessions.read` 或其隐含的 write/admin 范围读取自己的个人资料，即使共享人员名册不可用也是如此。刷新并重新连接读取当前经过身份验证的配置文件。编辑姓名、头像或信用偏好仍需要 `operator.write`；会话访问权限不会授予配置文件编辑或对其他配置文件的访问权限。个人资料图像下载保留其单独的读取权限，并且可能会显示仅限会话访问的缩写。

单用户网关为身份不明的操作员连接提供一个持久的本地所有者配置文件，在设备和选项卡之间共享，包括设备令牌重新连接。网关主机帐户的全名填充未设置的显示名称。保存的名称永远不会被覆盖。如果没有可用的全名，边栏和个人资料标题将显示 **Owner**，直到您设置名称。不使用登录名。所有者配置文件没有电子邮件，并且不会更改权限或身份范围。它不能与个人配置文件合并或分配操作员角色。使用个人身份登录以执行这些操作。如果早于 v2026.9.2 的构建将所有者配置文件合并到人员中，则连接将保持未识别状态并记录修复提示。运行`openclaw doctor --fix`，然后重新连接以恢复所有者身份。此人保留其电子邮件、角色和 GitHub 身份。

配置 `gateway.roles` 时，身份不明的操作员仅通过令牌或密码身份验证接收所有者配置文件。其他连接需要配置文件支持的登录来获取个人身份。 Node、临时连接和综合连接不会收到所有者配置文件。

当网关的身份验证配置允许所有者归属时，网关会在启动期间在接受请求之前准备其共享所有者配置文件。连接重用已承认的配置文件并接收提交的名称更改，而无需重新读取存储。如果配置文件准备失败，启动会记录一条警告，并且连接准入会重试。

Control UI 在人员侧边栏、活动卡、会话查看者和人员组中将此状态标记为 **共享所有者**。该卡说明这不是个人登录。其连接和活动详细信息仍然可见。您在“个人资料”页面上保存的姓名未更改。

在 macOS 上，未保存头像的所有者使用网关主机帐户的用户图片。在 **设置 → 个人资料 → 身份** 中上传头像会覆盖该默认设置。图片保留为本地进程缓存的默认值，而不是保存的配置文件上传。在macOS中更改后重新启动网关。这仅适用于共享所有者配置文件，不适用于使用自己身份登录的人员。 Unavailable pictures fall back to initials。

通过 Cloudflare Access 和 Tailscale Serve 支持 GitHub- 支持的登录。对于 Cloudflare Access，网关仅在使用标准 Access 电子邮件标头和所需的 Access 断言标头成功进行 `trusted-proxy` 身份验证后才接受身份丰富。它调用访问身份端点并要求返回的电子邮件与经过身份验证的代理主体匹配。帐户 ID 来自 GitHub 身份提供商，或来自显式配置的 [ 受信任的 OIDC 声明 ](/gateway/cloudflare-access#verified-github-credit-through-oidc)。然后，它会解析来自该数字帐户 ID 的当前已验证的 GitHub 登录。对于 Tailscale 服务，网关通过 GitHub 解析经过验证的 GitHub- 支持的 Tailscale 登录。两个路径都记录不可变的数字帐户 ID 以及当前验证的登录。

没有可信 GitHub 声明的 OIDC 将保留仅电子邮件登录和任何现有的链接身份。受信任的 OIDC 丰富功能保留了现有电子邮件配置文件的角色并保存了共同作者首选项；冲突的身份需要明确的管理员链接，而不是自动合并或电子邮件重新分配。

对于新的配置文件或未设置的显示名称，OpenClaw 更喜欢来自已验证的 GitHub 帐户的公共名称。当 GitHub 没有时，它使用登录提供商的名称。仅当保存的名称与当前验证的 GitHub 登录（包括大小写）完全匹配时，才会升级已保存的名称。所有其他保存的名称保持不变，包括自定义名称和以前采用的全名。这将在下次通过登录、重新连接或重试查找的配置文件刷新成功进行身份同步时生效。现有配置文件不会在后台迁移中重命名。

**GitHub account** 行是只读的。通用可信代理、令牌、密码和未经身份验证的连接无法声明 GitHub 帐户，并且代理或工具 GitHub 凭证绝不会用于此身份。公共 GitHub 帐户查找使用网关配置的 `gateway.controlUi.github.token` 或其进程 `GH_TOKEN` / `GITHUB_TOKEN`（未配置凭证时），以避免较小的匿名 API 配额。该凭证仅验证 API 请求。登录提供商仍会确定该人的身份。转发的 Cloudflare 访问断言是连接范围的：OpenClaw 不会保留、导出、记录或将其公开给 UI 或模型。

Cloudflare 访问帐户查找会自动共享有界的内存中 GitHub 元数据缓存 15 分钟，由不可变帐户 ID 和 API 凭证键入。并发查找共享一个 GitHub 请求。过期条目使用 ETag 进行条件刷新（如果可用）。经过身份验证的 `304 Not Modified` 响应不会消耗 GitHub 的主要配额。每个新连接或经过身份验证的 HTTP 请求仍会检查 Cloudflare 访问权限，并且本地配置文件权限使用当前操作员角色。缓存不存储访问断言或角色决策。 Tailscale 用户名查找保持新鲜，因为用户名可以重命名或重新分配。

什么时候[操作员角色](/gateway/operator-scopes#named-operator-roles)配置完毕后，身份验证完成前WebSocket连接被承认。如果验证不可用，连接将返回可重试的配置文件验证错误以及恢复指南。GitHub明确确定了速率限制。在可重试期间GitHub停电，已验证Cloudflare电子邮件和不可变帐户ID可以重复使用他们现有的个人资料。一个Tailscale GitHub仅当配置文件经过验证时，登录才能重用其现有配置文件GitHub帐户仍然具有确切的登录信息。首次用户必须完成验证才能获得基于角色的访问权限。

在 GitHub 速率限制上，网关在使用受影响的凭证和配额存储桶的请求之间共享冷却时间。耗尽搜索配额不会阻止配置文件查找。辅助限制可以使用该凭证暂停其其他 GitHub REST 读取。进一步的 API 请求暂停，直到 GitHub 的 `Retry-After` 截止日期，或者当剩余配额为零时其主要重置截止日期。二级限制无 `Retry-After` 暂停 60 秒。 Control UI 重新连接会遵守该延迟并保留其正常退避，因此打开另一个选项卡不会重新启动针对耗尽存储桶的 GitHub 请求。如果冷却后验证仍然不可用，请要求管理员检查配置的服务凭证和共享其配额的其他工作负载。

如果没有操作员角色，身份查找将在WebSocket登录，因此连接状态和其他与身份无关的读取仍然可用。配置文件和会话工作等待查找。相同的经过验证的绑定在可重试期间继续工作GitHub停电。否则，一个Cloudflare or GitHub速率限制或网络故障，返回可重试的不可用性；一个GitHub速率限制命名其原因并进行GitHub的重置期限。它不会公开可变别名或删除以前验证的帐户。稍后的请求、连接或配置文件刷新将重试查找。GitHub登录重命名通过数字帐户 ID 进行协调，因此个人资料历史记录和首选项始终与一个人相关。

管理员可以通过 `users.linkEmail` 或 `users.merge` 显式链接属于同一个人的配置文件。完成的配置文件合并将保留所有经过验证的 GitHub 帐户及其登录别名。任一帐户都会解析同一个人、头像、偏好和提及收件箱。目标配置文件保留其主 GitHub 帐户以用于公共身份和 Git 信用；未经验证的目标继承源主目标。通过辅助帐户登录不会改变该选择或其信用偏好。人们永远不会通过匹配名称而自动合并。

主账户使用现有配置文件表中的可为空字段，而不提升数据库架构版本。 **降级风险：** 没有架构版本冲突会阻止旧版本使用此状态。他们的单帐户作者可以放弃辅助帐户链接或再次拆分此人。重新升级不会重建废弃的链路；管理员必须明确地重新链接配置文件。 Keep a backup before downgrading。

Public commit metadata is a separate choice. **Git 合著者信用值** 默认为经过验证的帐户。它将已验证帐户的公共 GitHub noreply 地址添加到从共享会话创建的提交中。 OpenClaw 绝不会为此功能请求或存储私人 GitHub 电子邮件。不相关、未链接的 GitHub 帐户使用自己的个人资料和信用偏好，因此重复使用登录电子邮件或用户名不会继承他人的选择。通过链接的辅助帐户登录会保留主要配置文件的主要帐户和信用首选项。

当您的经过身份验证的配置文件在代理运行之前提示会话时，从该运行创建的提交将收到您的确切信息`Co-authored-by`拖车。提交并拉取请求，然后明显地归功于参与该会话的人员。已验证的个人资料参与者GitHub启用的身份和 Git 共同作者信用符合资格。远程身份、代理、机器人和配置的主要 Git 作者均被排除。贡献者按记录的贡献总额排列，最高的排在第一位。领带使用最早的已知配置文件输入，已知时间之后的历史时间未知，然后不可变GitHub帐户 ID。这些尽力而为的聚合并不是精确的生命周期提示计数。合并后的个人资料的贡献仍保留在其幸存的经过验证的帐户中。新参与者的准入和面向模型的信用输出的上限分别为32。修复可以保留更大的历史记录。

在子任务开始之前，委派的任务会保留原始会话的人工贡献者配置文件 ID 的单独快照。嵌套代表团将快照向前推进，最多 32 个独特的配置文件，在添加直接来源参与者之前保留继承的贡献者。这不会创建儿童参与、增加提示计数或授予访问权限。稍后加入源的人员不会添加到现有子快照中。在使用时，OpenClaw 将继承的信用与直接子贡献结合起来，并检查当前经过验证的 GitHub 身份和信用偏好。每个GitHub账户到账一次；直接贡献者保留其通常的顺序，其次是按快照顺序继承的贡献者。普通侧边栏父链接不会转移学分。

参与会话后的信用，包括同一源对话中的早期工作。当工作需要不同的贡献者集时，请使用单独的源对话。验证通道到配置文件的链接和对单个任务的归因是单独的功能。

快照在会话重置后仍然存在，并随子会话一起消失.隐身会话不会保留它或发布信用。没有快照的现有委派会话不会自动回填。这使用可选的会话元数据，无需数据库架构迁移；旧版本不使用它，并且可以在重置会话时丢弃它。

当某个会话有某人要归功于时，其系统提示会列出一次确切的预告片。它告诉代理将它们添加到从会话中进行的提交中。 Codex 运行时在其开发人员指令中收到相同的块。当没有人值得赞扬时，就不会添加任何内容，而隐身会话永远不会带来荣誉。网关发布代理直接在其生成的提交和拉取请求中应用相同的信用。当网关公开外部 HTTPS 会话 URL 时，拉取请求将以指向该确切团队会话的链接结束。拖车不通过进程或 shell 环境导出。直接 Git 命令仍然是普通的 shell 执行。 OpenClaw 不会替换 `git` 或安装存储库挂钩。因此，遵循系统提示指令的代理是执行边界。

关闭 **Git 合著者信用** 会停止未来运行的归因。网关管理的发布还会在每次挂起的提交、推送或拉取请求写入之前检查贡献者身份和同意情况。如果在发布期间资格发生变化，它会在下一次写入之前停止，并要求您在再次请求发布之前查看记录的效果。它不会重写已经包含公共预告片的提交。

## <a id="merging-duplicate-profiles"></a> 合并重复的配置文件

网关目录方法 `users.list` 需要 `operator.read`。其可选的 `githubAccountIds` 过滤器可接受最多 500 个唯一的正安全整数。响应保留 `profiles` 并添加 `githubProfiles`，仅包含请求的已验证帐户 ID 及其主要的、非合并的 `profileId` 匹配项。缺少的 ID 没有匹配项；其他关联帐户不予退还。省略过滤器将保留普通目录响应。此查找读取现有的身份绑定；它不会链接帐户或授予访问权限。

使用 [`openclaw users`](/cli/users) 列出个人资料 ID 并合并属于同一个人的重复个人资料。 Both linking and merging require `operator.admin`。

```bash
openclaw users list
openclaw users merge <duplicate-profile-id> --into <surviving-profile-id>
```

当您想要移动一个电子邮件别名时，请使用 `openclaw users link-email <email> --to <profile-id>`。仅当以前的配置文件丢失最后一封电子邮件时，它才会合并该配置文件。当您想要合并整个副本（包括没有电子邮件别名的配置文件）时，请使用 `users merge`。网关方法为 `users.merge`、`sourceProfileId` 和 `targetProfileId`。

幸存者保留其角色、显示名称和主要身份；没有经过验证的主 GitHub 帐户的目标将继承源主帐户。电子邮件别名、提供商身份和频道链接会跟随幸存者。保存幸存者获胜的偏好键；仅源密钥的传输上限为现有配置文件限制。个人模型帐户转移，而幸存者现有的提供商选择（包括明确的断开连接）获胜。幸存者保存的GitHub连接状态也获胜；如果不存在，它将继承源连接。仅当幸存者没有已保存的头像时才会转移。个人`USER.md`文件不合并；自行将其内容移至幸存配置文件的目录中。

退役的个人资料仍然是直接指向幸存者的别名。合并到副本中的早期个人资料也直接指向幸存者。两个 ID 必须存在且不同，并且目标必须是当前的、未合并的配置文件。两个配置文件都不能共享**所有者**。重复相同的合并会成功，而无需再次移动任何内容。如果源现在指向不同的配置文件，则请求将失败并识别当前的幸存者。

历史记录保留其原始配置文件 ID：记录、创建者、分配者、贡献者、审核上下文、批准出处、发布收据和会话参与者不会被重写。解析个人资料别名的读者仍然可以显示幸存的人。这不会转移先前捕获的权限：绑定到已停用配置文件的特权工作将被拒绝，并需要新的授权请求。连接身份、状态和权限在合并后刷新；受影响的连接可能需要重新连接。

## <a id="channel-identity-links"></a> 渠道标识链接

管理员可以证明稳定通道发送者属于现有网关配置文件。该链接包括通道、配置的通道帐户和发送者的本机 ID。 Display names， usernames， and `session.identityLinks` do not establish this association。

所有三种网关方法都需要`operator.admin`：

| 方法                        | 参数              | 结果                                    |
| ----------------------------- | ----------------------- | ----------------------------------------- |
| `users.linkChannelIdentity`   | `profileId`, `identity` | 主要配置文件 ID 和保存的身份 |
| `users.listChannelIdentities` | `profileId`             | 该配置文件的 `links`                  |
| `users.unlinkChannelIdentity` | `profileId`, `identity` | `removed`                                 |

例如，Discord 用户的 `identity` 对象为：

```json
{
  "channelId": "discord",
  "accountId": "team-bot",
  "senderId": "100000000000000001"
}
```

使用准确配置的帐户ID和不可变的发送者ID。相同的发件人ID在另一个帐户上是不同的绑定。重复相同的链接是安全的。已由另一个配置文件拥有的链接必须首先显式取消与该配置文件的链接。取消链接还会检查预期的配置文件，因此过时的请求无法删除其他人的绑定。所共享的**所有者**个人资料不是一个人，无法接收这些链接。

链接遵循显式配置文件合并和幸存的配置文件's current role. 链接不会重命名或合并人员， rewrite transcript attribution， assign session ownership， or change session visibility. 权限解析分别检查受信任的传入发件人和链接的人员's current authority。

当前有效操作员角色包括 `operator.admin` 的每个链接发件人会自动接收通道所有者权限，同时任何角色所需的人员访问授权仍保持活动状态。角色名称并不重要，并且不需要额外的 `gateway.auth.identityScopes` 授予。如果未配置操作员角色，则由匹配的管理身份范围授予来提供此权限。配置的非管理员角色可以防止这种回退。删除链接、降级人员或删除角色的管理范围会撤销继承的权限。在待处理的特权操作生效之前重新检查权限；已接受的操作完成所需的清理。显式 `commands.ownerAllowFrom` 条目保持独立。请参见 [ 操作员范围](/gateway/operator-scopes)。

托管更新通过暂存和停放网关之前所需的授权检查保留原始的人员访问权限。一旦停放被接受，本机更新程序就拥有该更新的完成或恢复，同时配置文件、角色和配置检查保持最新状态。重新启动的保单服务或更新的邀请不会授权对原始拨款的新请求。看[重新开始交接](/cli/update/how-updates-run#restart-handoff)。

通道策略和显式命令允许列表仍然适用，包括本机命令。外观配置文件的更改不会取消授权请求；更改其身份链接或角色需要新的请求。

这些记录使用现有的共享状态身份表，而不更改其架构版本. 旧版本忽略通道绑定命名空间； 降级会禁用此识别，而不会将链接转换为登录帐户. 升级不会猜测或回填通道身份. 再次升级后，管理员可以通过相同的方法检查和删除链接。

### <a id="assign-to-me-from-a-channel"></a> 从频道分配给我

使用 `users.linkChannelIdentity` 将发件人链接到其现有配置文件。对于 Slack，请使用 `channelId: "slack"`、配置的帐户 ID 以及确切的本机用户 ID（例如 `senderId: "U0123456789"`）。直接套接字模式和签名验证的 HTTP 传送可验证发送者的身份；中继传递则不然。 Discord 已验证的本机发件人使用相同的配置文件分辨率。

下一个经过验证的消息回合包括主要配置文件 ID 和当前显示标签，作为每回合对话信息中主机生成的字段。系统提示在请求者之间保持稳定。例如，有效角色包括 `operator.admin` 的链接人员可以询问“将此会话分配给我”。代理可以呼叫 `sessions`，并将 `action: "assign_owner"`、`ownerType: "human"` 和 `ownerId` 设置为该可信配置文件 ID。粘贴到消息中的姓名、电子邮件和 ID 并不能确定请求者。

链接的非管理员发件人还会接收请求者元数据。在现场承认代理轮流期间，`sessions`工具暴露`assign_owner`对于这些发件人；设置，reset/delete，并且全局组控制仍然需要所有者权限。运营商与`operator.write`还为它们创建或分配的会话保留单独的存档、恢复和停止控制，以接受会话访问检查。当新生成的可见会话开始由代理拥有时，代理可以将其分配给受信任的请求者配置文件并使用以下命令验证存储的所有者`sessions_list`。这改变了责任，而不是创建者归属或访问权限。未链接或断言的发件人不会收到请求者配置文件：首先链接经过验证的发件人，而不是根据名称或粘贴进行猜测ID。取消链接将在后续回合中生效，无需重新启动。

## <a id="github-connections"></a> GitHub 连接

打开**设置 → 个人资料 →GitHub连接**连接**My GitHub**不改变共享的**系统GitHub**帐户。两个帐户及其连接状态仍然可见。查看这些连接不需要选择代理或配置默认代理。连接凭证不会更改您已验证的GitHub登录身份、显示名称、头像、Git 共同作者信用偏好，或OpenClaw权限。

My GitHub需要经过身份验证的持久网关配置文件，包括本地所有者配置文件。已确定的运营商`operator.read`即使没有管理或一般写入访问权限，也只能管理自己的连接。使用所有者配置文件的共享秘密设备共享该连接。对团队使用单人登录。系统和每个代理连接仍需要更改`operator.admin`。

1. 为我选择****并连接GitHub。对于已确定的管理员来说，这是默认目的。**对于系统来说**是一个明确的替代方案。
2. 自行打开显示的 `github.com/login/device` 链接并批准一次性代码。网关验证帐户并将凭据保留在浏览器响应和代理上下文之外。
3. 使用前请检查已连接的帐户。个人连接使用设备授权。现有的 PAT 替代方案仍然可用于管理员管理的共享连接。

### <a id="publish-with-your-account"></a> 使用您的帐户发布

旁边的账户箭头**发布PR**仅当共享帐户和个人帐户都可用时才会出现。其紧凑的菜单显示帐户名称和所选帐户；有效共享帐户仍为默认帐户。仅使用共享帐户，使用**发布PR**直接地。仅与**My GitHub**， 这**发布为@account**按钮明确选择该帐户并请求一键发布；仅靠发现永远不会选择个人凭证。如果同一个帐户通过两条路由连接，菜单会单独标记它们。个人发布需要与协调的工作树或接受的存储库检查点进行空闲会话。

支持网关运行环境中现有的`gh`登录；连接 **My GitHub** 是可选的，不会取代该登录。在浏览器计算机上登录不会自动验证远程网关。当没有可选择的发布帐户时，该行会区分丢失的凭据、失败或速率受限的帐户验证以及不受支持的会话工作区。请遵循显示的恢复指南，而不是因验证或工作区故障而重新连接。会话范围的共享发布需要具有受支持的 GitHub 源的会话拥有的工作树或存储库工作区；普通代理 `git` 和 `gh` 命令与此发布资格检查保持独立。

编辑器显示未发布的分支更改或 PR 行。新的更改取代了早期的 PR 历史记录，包括在同一分支上合并后所做的更改。仅当发布空闲且帐户选择已解锁时才会显示帐户箭头。发布恢复保留在未发布的分支行内。当 PR 行可见时，恢复会单独显示，因为会话发布尝试不一定属于任何列出的 PR。失败的尝试使用折叠的 **Publication attempts failed** 披露；展开它以检查原始帐户、错误和恢复操作。当 OpenClaw 验证失败的共享尝试的已接受更改已在匹配的 PR 中发布时，它会停止提供过时的故障作为恢复 - 即使在重新加载或开始后续工作之后也是如此。历史收据保持不变，仍然可以明确读取。未发布或未经验证的更改仍会失败；刷新收据绝不会重试发布。待定状态和确认详细信息仍处于扩展状态。成功发布会显示紧凑的 PR 链接，直到 GitHub 元数据提供正常的 PR 行；它不添加单独的出版卡。

如果网关在接受第一个发布请求之前拒绝所选帐户，请选择 **刷新发布**，检查当前帐户，然后再次显式发布。未知的结果会导致原始帐户和请求被锁定。对于共享发布，**刷新发布**使用原始调用密钥查找收据；没有找到收据并不能证明该请求从未运行过。 **重试发布**重播相同的请求，而不重复其效果。它不会切换帐户或开始新的出版物。

发布状态在聊天之间的导航中保留下来，包括卸载非活动聊天窗格时。显示同一聊天的拆分窗格共享其发布进度并重试。页面最多保留32当前经过身份验证的网关连接内的发布尝试。在满负荷的情况下，现有的重试仍然可用。驳回已完成的PR行，或选择**选择新出版物**在一次失败的尝试之后，在开始另一次尝试之前。只读操作员可以忽略观察到的已完成结果，而无需发布或确认任何内容。

共享的发布进度来自 Gateway 拥有的收据。 **检查状态**读取记录的结果而不再次执行发布。收据更改通过现有会话事件流刷新 UI，并在活动请求后面合并突发；恢复该事件订阅还会刷新任何待处理的观察。重新加载或重新连接会发现当前会话和工作区的最新适用共享收据，包括离线时错过的完成情况。忽略已完成的 PR 行或在失败后选择新发布会确认当前演示文稿的终端接收，因此刷新不会立即恢复它。已完成的共享请求可以从网关恢复，而不是保留屏幕外的浏览器操作。个人收据和确认书仍对其经过验证的原始所有者具有约束力。

排队的共享发布还保留请求者、其原始权限上限以及接受请求时所需的任何访问授权。过期或撤销的来宾访问权限会阻止进一步的 GitHub 写入，包括重新启动后。新的邀请或后来的员工角色不会授权旧的客人请求。保存的工作、现有 PR 和单独授权的请求保持不变。 The Gateway can still record a GitHub result accepted before access ended；不可用的回读会使原始结果等待协调。

对于由访问授权支持的请求，将某人的原始电子邮件别名移动到另一个配置文件也会终止发布权限。恢复别名不会恢复旧的请求。请求后添加的显示更改和别名（包括后来的删除）不会取消。

没有此请求者绑定的较旧的未完成共享请求需要新的授权发布请求。首先检查其录制或未确认的 GitHub 效果。已发布的收据仍然可读，并且仍在启动的插件会推迟恢复，直到可以检查其原始授权为止。

挂起的会话删除会阻止发布操作，而不丢弃原始请求。删除失败可重试恢复。确认删除将取消该尝试。该页面会在重新加载或连接更改时清除该内存。配置文件、会话访问和工作区更改也会取消受影响的浏览器状态；他们从不重新定位现有的网关请求。

共享发布还支持会话创建者的 `operator.sessions.write`。当网关在自有会话的托管工作树或存储库工作区中识别出受支持的 GitHub 目标时，仅会话调用方可以使用 **Publish PR**，而无需访问更广泛的 PR 列表。单纯的对话或项目文件夹本身并不能提供发布。网关在发布之前重新检查工作区、未发布的工作、当前访问权限和工作流程限制。刷新或重新连接后共享结果仍然可见。

个人发布和确认需要 `operator.write` 和当前访问权限才能更改会话。单独连接您的帐户不会授予任何权限。

个人 GitHub 是网关代理的发布连接，而不是会话范围的 shell 身份。普通代理 `git`/`gh` 命令、模型启动的发布以及存储库预览和发现将保留其现有的凭据行为。 OpenClaw 云工作人员使用共享执行身份，而不是您的个人连接。对于仅限存储库的会话，完成当前回合并等待其接受的 Git 规范化检查点。个人出版物在工作人员空闲时或停止后可用，无需网关结帐。在个人发布之前，来自网关工作树的远程会话仍然需要 **Stop 云工作人员…**。有关共享代理执行，请参阅 [`tools.github`](/gateway/config-tools#tools-github)。

网关将个人出版物绑定到您经过身份验证的配置文件、所选帐户以及接受的工作树快照或存储库检查点。其他参与者的消息无法切换该帐户或授权以后使用您的连接进行工作。如果帐户变得不可用或工作区发生更改，发布将通过恢复操作停止，而不是回退到系统或本机凭据。

网关重新启动后，未完成的个人发布需要您的明确确认才能继续。确认重用原始请求。它检查已创建的提交、推送的分支或拉取请求，因此丢失的响应不会盲目地重复该操作。更改的连接或不兼容的工作区需要新的、明确选择的操作。对于仅限存储库的会话，即使后续轮次已完成，确认也会保留原始检查点。它从不默默地发布那些后来的变化。

存档的会话不提供个人出版物确认。取消存档会话以恢复有效的待定确认；记录的出版结果仍然可见。

如果确认无法访问其状态存储，网关会报告可重试的不可用结果以及存储原因。如果保留了工作区排除，则响应会命名其记录的持有者和租赁纪元。呼叫者取消单独报告，并且不会触发自动重试。重试使用原始请求和接受的检查点。

### <a id="disconnect-and-reconnect"></a> 断开并重新连接

断开“我的 GitHub”连接会删除其可用的本地凭据，并防止未完成的个人工作使用该连接。重新连接会创建一个新选择，即使对于同一个 GitHub 帐户也是如此。旧请求不会自动获取新授权。断开连接不会重写已发布的提交或撤销 GitHub 上的应用程序授权。需要时在 GitHub 的应用程序设置中单独撤销该授予。

个人连接共享网关现有的可信主机边界。它们阻止其他参与者通过个人 GitHub API 使用您的连接。它们不会将凭证与管理员或不受限制地访问网关 OS 帐户的代码隔离。请参阅 [ 操作员范围 ](/gateway/operator-scopes) 和 [ 网关安全性 ](/gateway/security)。

## <a id="profile-appearance-preferences"></a> Profile外观偏好

当 Control UI 连接绑定到经过身份验证的网关配置文件时，OpenClaw 会存储每个配置文件的主题、主题模式和强调色。它们位于共享状态数据库中现有的 `user_preferences` 表中。这些选择在不同设备上跟随该人，而不会改变同一网关上其他人的外观。

配置文件主题和主题模式首选项会覆盖其网关范围的 `ui.prefs` 设置，否则会回退到活动主题的默认设置。插件主题使用命名空间 ID，例如 `space-pack/xenovessel`。通过代理创建的个人主题定义存储在同一配置文件首选项存储中，并跨浏览器遵循配置文件。 `theme` 工具和外观共享一个目录和选择所有者。插件热重载更新目录和连接的浏览器，无需重新启动网关。不可用的插件主题会暂时呈现为 Claw，同时保留其保存的选择。传统的tweakcn导入是个例外：它们的调色板保留在导入它们的浏览器中，并且永远不会自动上传。选择本地导入永远不会遵循配置文件。重音优先级是配置文件的 `ui.accent` 首选项、网关范围的 `ui.prefs.accent`、`ui.seamColor`，最后是活动主题的默认重音。在外观中选择不同的主题会清除配置文件字体覆盖并存储 `ui.accent: "theme"`，显式选择主题调色板而不继承网关强调色。恢复默认设置仅清除配置文件首选项。所有者配置文件首选项遵循跨设备的所有者。没有配置文件的连接保留网关范围的外观行为。语言和聊天首选项继续使用网关配置。个人导航使用如下所述的配置文件首选项存储。

## <a id="personal-navigation-preferences"></a> 个人导航偏好

对于具有写入访问权限的经过身份验证的配置文件，Control UI 将侧边栏快捷方式引用及其顺序存储在现有 `user_preferences` 表中的 `ui.railShortcuts` 下。这些首选项跨设备遵循该配置文件，而无需重新安排其他人的导航。它们独立于会话的共享元数据，并且不授予对引用的会话、仪表板、插件或人员的访问权限。

浏览器保留设备特定的几何形状和瞬态呈现。没有保存快捷方式的配置文件以空导轨开始。阅读首选项永远不会导入共享导航或固定会话，只有用户编辑才能写入快捷方式首选项。升级后，旧的侧边栏顺序和引脚将被忽略，导轨开始为空。旧值仍被存储；新首选项下保存的快捷方式保持不变。只读连接或没有持久配置文件的连接上的导航更改保留在浏览器本地，而不是写入共享服务器配置。参见[导航导轨](/web/control-ui/sessions-and-sidebar#navigation-rail)。

会话所有者过滤器针对每个网关和配置文件单独存储在浏览器中。没有保存选择的配置文件以 **My 会话** 开头；没有持久配置文件的未解析身份和连接显示 **所有所有者**。选择**涉及我**、**的所有所有者**，或者某人直接更改该所有者过滤器。

## <a id="write-directives%2C-not-observations"></a><a id="write-directives-not-observations"></a> 编写指令，不要写观察

每条记录都有一行元数据，后面跟着一条祈使式指令：

```md
<!-- observed: 2026-07-27 | status: active -->

- Prefer concise progress updates during implementation work.
```

使用这些规则：

- 以 `Always`、`Never` 或 `Prefer` 这样的祈使式开头。
- 记录观察到该偏好的日期。
- 状态只使用 `active` 或 `superseded`。
- 每条指令只保留一个行为要求。
- 只存储能提升协助效果的细节。不要把文件变成档案袋。

PrefEval 发现，即使有检索和提示，在更长的对话中，偏好遵循也会急剧下降（[arXiv:2502.09597](https://arxiv.org/abs/2502.09597)）。将稳定的偏好重述为指令，可以在智能体使用它的那个时点明确预期行为。

## <a id="supersede-in-place"></a> 原地取代

当偏好发生变化时，请更新其现有部分。不要在文件的其他位置再追加第二条处于激活状态的指令。

之前：

```md
<!-- observed: 2026-05-10 | status: active -->

- Prefer detailed explanations for every code change.
```

之后：

```md
<!-- observed: 2026-05-10 | status: superseded -->

- Prefer detailed explanations for every code change.

<!-- observed: 2026-07-27 | status: active -->

- Prefer concise implementation summaries unless more detail is requested.
```

将被取代的条目保留在其替换条目旁边，以便当前指令明确无误。 HorizonBench 报告称，系统经常在用户更改后选择最初规定的首选项 （[arXiv：2604.17283](https://arxiv.org/abs/2604.17283)）。仅追加的矛盾历史记录重现了这种故障模式。

## <a id="choose-the-right-file"></a> 选择合适的文件

| 信息                                                                      | 存储到                                    |
| -------------------------------------------------------------------------------- | ---------------------------------------------- |
| 稳定的偏好或沟通风格                                         | `USER.md`                                      |
| 会改变对用户提供帮助方式的关系或活跃项目事实 | `USER.md`                                      |
| 持久的非个人资料事实、决策或经验教训                                    | `MEMORY.md`                                    |
| 详细观察或持续上下文                                          | `memory/YYYY-MM-DD.md`                         |
| 事件触发的未来行动                                                  | [常备意图](/concepts/standing-intents) |
| 精确时间或重复性行动                                                   | [计划任务](/automation/cron-jobs)        |

## <a id="keep-it-compact"></a> 保持简洁

`USER.md` 具有固定的 4,000 个字符引导程序上限，小于一般每个文件的预算。 `agents.defaults.bootstrapMaxChars` 和 `agents.entries.*.bootstrapMaxChars` 设置只能降低 `USER.md` 的此上限；他们无法提高它。配置文件指南旨在保持指令大小，因此它不会将项目规则或持久事实排除在共享即时预算之外。

当`USER.md`接近上限时：

1. 删除陈旧的被取代的条目（将替换保留在旧条目旁边，以便当前指令保持明确）。
2. 将不会改变您应如何获得帮助的持久事实和教训转移到 `MEMORY.md` 中。
3. 将详细的观察结果和运行项目上下文移至日常 `memory/YYYY-MM-DD.md` 文件中。
4. 使用 [ 常设意图 ](/concepts/standing-intents) 进行事件条件的未来操作，因此触发器在没有完整细节的情况下保持注入状态。

`MEMORY.md` 在符合条件的私有会话中的正常每个文件预算下注入工作区引导程序 - 子代理、cron、组和通道会话省略根内存，并且没有可信来源的内存被过滤掉（请参阅 [ 内存来源](/concepts/memory-provenance)）。每日内存文件是按需检索的，因此移动到每日内存的细节仍然可以访问，而无需花费始终注入的 `USER.md` 预算。当固定上限限制 `USER.md` 时，`openclaw doctor` 会命名上限并建议压缩文件。如果共享总预算也限制了注入，Doctor 会保留减少总引导内容或调整 `bootstrapTotalMaxChars` 的建议。
