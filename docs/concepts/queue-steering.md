当会话运行处于活动状态且队列模式为 `steer`（默认，无需配置）时收到正常提示时，OpenClaw 会尝试将该提示发送到活动运行时，包括在工具执行期间。 OpenClaw 和本机 Codex 应用程序服务器harness以不同的方式实现交付细节。

本页介绍在 `steer` 模式下，普通入站消息的队列模式 steering。对于 `followup` 或 `collect` 模式，普通消息会跳过此路径，并等待当前活动运行完成。关于显式的 `/steer <message>` 命令，请参见 [Steer](/tools/steer)。

较旧的后续操作不会禁用稍后输入的转向。在早期的转向尝试稳定后，OpenClaw 尝试针对主动运行的每个新转向。运行时拒绝的消息仍按其原始顺序排队；接受的转向进入主动转弯。

## <a id="runtime-boundary"></a> 运行时边界

转向不会中断已在运行的工具调用。助理消息的工具调用是一个承诺的计划，直到其中一个开始执行：

1. 助手请求工具调用。
2. 在顺序模式下，OpenClaw 启动第一个可执行调用而不检查转向。从该助理消息开始调用后，OpenClaw 在以后的每个调用之前进行检查，包括异步解析、验证和预执行挂钩之后。
3. 正在运行的调用完成。如果此后有待处理的 steer，则会跳过尚未开始的顺序尾部调用。
4. 在并行模式下，OpenClaw 一起准备和发起呼叫，无需转向检查点。等待转向永远不会跳过并行批次。
5. 每个跳过的调用都会按照助理源顺序接收配对工具 start/end 事件和合成结果 （`Skipped to process an incoming message.`）。结果告诉模型该工具未运行，Control UI 将其标记为 **Skipped**。
6. 在任一批次稳定后，OpenClaw 在停止挂钩或下一个模型调用之前检查转向。它会在工具结果之后、下一次 LLM 调用之前附加精确的耗尽转向消息。

这使得每个请求的工具调用与结果配对，而不会在任何工具执行之前丢弃新请求的计划。

内部更新（包括子代理完成报告）也使用此引导边界。这些更新可以从聊天记录中隐藏，并且不会出现在用户消息队列中。因此，跳过的工具并不一定意味着用户消息正在等待；代理在决定下一步调用哪些工具之前处理传入的更新。

在内置运行时中，每个引导的用户输入都会按顺序获得自己交付的答案。即使转向跳过了待处理的工具，后来的答案也不会取代先前输入的完整答案。

在保留另一个输入的同时记录转向接收可以保持活动转弯的运行。接受的输入保持顺序并到达下一个可用的模型边界。

引导通道回复将该消息的引用或转发上下文携带到模型输入中。引用的内容仍然是对话数据；命令和待决问题的答案使用传入的文字文本。纯文本转录条目也保留文字输入。

本机 Codex 应用程序服务器harness公开 `turn/steer` 而不是 OpenClaw 运行时的内部转向队列。 OpenClaw 对配置的安静窗口进行批处理排队提示，然后发送单个 `turn/steer` 请求，其中包含按到达顺序收集的所有用户输入。 Codex 的上游轮次调度程序拥有其工具调度并在模型边界排出待处理的输入； OpenClaw 不会向该运行时添加每个工具的抢占。副本提交确认持久性，而不是稍后的模型请求已读取输入。

插件拥有的 CLI 运行时在通过 `registerMessageInjection` 提供输入接收器时接受转向（请参阅 [CLI 后端插件](/plugins/cli-backend-plugins)）。本地 Claude 后端通过其持久流 JSON 进程支持纯文本输入。这适用于 `messages.queue.mode: "steer"`、通道队列覆盖、每会话 `/queue steer` 和显式 `/steer` （`/tell`），无论存储的队列模式如何。会话设置优先于通道设置，通道设置优先于全局模式；默认为 `steer`。

OpenClaw 在记录接受和用户记录之前等待 Claude 的输入生命周期确认。本机调度确定文本是加入当前答案还是在同一附加 OpenClaw 运行中启动另一个本机答案；转向不承诺单一答案或中断正在运行的工具。在初始提示提交之前、最终确定之后、在没有输入生命周期支持的运行时上，或者当本机拒绝未使用的输入时，正常队列回退仍然可用。已使用的输入不会重播。图片及不兼容的权限仍需后续输入； node/process 替代方案无法从此插件功能中获得文本控制。

Codex review 和手动压缩回合会拒绝同回合 steering。当运行时无法在 `steer` 模式下接受 steering 时，OpenClaw 会等待当前运行完成后再开始提示。

在没有本机挂钩准入的 Codex 安装上，当本机子代理生成可用时，另一个人的消息将作为后续消息排队，而不是引导活动轮。如果线程的策略已经禁用本机生成，包括 ChatGPT 令牌共享和仅报告委派，其他人仍然可以控制正在运行的轮次。

一旦 OpenClaw 回合完成或移交，即使清理仍在运行，新提示也会等待下一个回合。当前回合内的重试和压实仍然可以接收转向。当模型请求失败而受控消息仍在等待时，该消息不会接管轮次：OpenClaw 重试或回退原始消息，并且受控消息随后按自己的顺序运行。

## <a id="tool-launch-boundaries"></a> 工具启动边界

OpenClaw 在整个助手消息中跟踪工具是否实际启动：

- 在助理消息中的任何工具启动之前，转向不能跳过顺序调用。仅验证或策略拒绝并不算作执行开始。
- 已运行的顺序调用完成。等待转向可以跳过未启动的顺序尾部，让模型在转向可见的情况下重新考虑。
- 并行批次永远不会跳过转向调用。准备好的呼叫一起启动，并在批次稳定后检查转向。
- Streamed 工具批次和同一助手消息结束时的任何剩余调用共享此启动状态。在较早的调用开始后，可以跳过后面的顺序批处理；稍后的并行批次仍在运行。
- 记录保持仅追加且结构成对：助手工具调用、真实或合成的工具结果，然后是引导用户消息。

跳过转向的工具不会触发故障警告。即使跳过稍后的调用，真正的工具故障仍然可以报告。

停止已经在运行的工作，与重定向未来的工作是不同的意图。当最新消息应中止当前运行而不是对其进行引导时，请使用 `/queue interrupt`（或 `/stop`）。

## <a id="modes"></a> 模式

| 模式        | 活跃运行行为                                    | 后续行为                                                                      |
| ----------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| `steer`     | 在可以的时候将提示 steer 到活跃运行时。 | 如果 steering 不可用，则等待活跃运行结束。                      |
| `followup`  | 不 steer。                                        | 在活跃运行结束后稍后运行已排队的消息。                               |
| `collect`   | 不 steer。                                        | 在去抖窗口之后，将兼容的已排队消息合并为一次后续回合。 |
| `interrupt` | 中止活跃运行，而不是 steering 它。          | 在中止后开始处理最新消息。                                           |

具有单独持久入口准入的消息（包括 Discord 和 Telegram 消息）与批处理不兼容：`collect` 将它们保留为单独的后续回合。兼容网关 `chat.send` 输入仍然可以组合。请参见 [ 队列模式](/concepts/queue#queue-modes)。

## <a id="burst-example"></a> 突发示例

如果在代理执行工具调用时有四个用户发送消息：

- OpenClaw 保留运行时配置的引导排空模式和 FIFO 顺序。逐条处理的消费者会将后续消息留到之后的边界；`all` 消费者会将排队的 FIFO 批次一起注入。Codex 会将其静默窗口期间收集的消息作为一个批次的 `turn/steer` 接收。
- 与`/queue collect`一起，OpenClaw不转向。它会等到活动运行结束，然后在去抖窗口之后创建后续轮次，仅组合兼容的排队消息。
- 使用 `/queue interrupt` 时，OpenClaw 会中止活动运行，并启动最新消息，而不是进行引导。

## <a id="scope"></a> 范围

引导始终针对当前活动的会话运行。它不会创建新会话、不会更改活动运行的工具策略，也不会按发送者拆分消息。在多用户频道中，传入的提示已经包含发送者和路由上下文，因此下一次模型调用可以看到每条消息的发送者。

可见用户轮流通过`agent` RPC还可以接收兼容的转向系统。带有可选回复的直接后台轮询会将新的人工消息排队等待可以提供所需答案的后续轮询。这包括子代理完成和命令公告：当转向被拒绝时，消息会在公告及其清理完成后自动运行。输入保持排队状态，并且在等待期间仍然可以取消。

具有相同权限的不同登录人员可以引导彼此的活动回合，包括从不同的浏览器或重新连接后。该回合保留其原始所有者的权限、工具绑定和批准目标。个人工具（`screen` 和 `theme`）代表一位指定人员。当多人转向时，智能体必须通过该人的验证`requester_profile.id`为`user`来选择要改变谁的视图或外观，并询问是否不清楚。每条经过身份验证的 Control UI 消息都在代理的用户角色对话上下文中包含其请求者经过验证的配置文件 ID。当几个人已经转向时，会话工具和 `sessions_spawn` 也会使用请求者经过验证的 `requester_profile.id` 作为 `user`。会话访问和衍生子权限使用该人的权限。与会话中稍后的轮次一样，引导轮次使用会话的选定模型帐户。多人轮次中未选择的会话呼叫只能将所有者的权限用于该轮次自己的会话；其他目标和会话范围内的发现需要请求者的 `requester_profile.id` 为 `user` 的会话工具。没有 `user` 选择器的个人指令和其他个人设置无法从多人驾驶的转弯中读取或更改。该人应该轮流询问新的 Control UI 消息。对于混人轮流中的 Crabbox 打开和展示请求，创建不带 `presentation` 的环境，然后使用 `screen` 和 `desktop_show` 或 `portal_show`，其 `environmentId`，请求者的 `requester_profile.id` 为 `user`。不同的权限（角色范围、会话访问上限、沙箱要求、允许的代理、模型访问、访问授权或工具策略）将消息作为后续消息排队；对执行策略、工作区或绑定工具的更改也可能需要跟进。

自动凭证轮换和模型回退也保留活动轮换。新的输入可以引导这一方向，同时所选模型保持不变，仍然允许回退，并且当前权限匹配。选择或锁定模型、固定不同的帐户或更改工具权限可能需要后续操作。待决问题的答案仍归问题的原始所有者所有。

[Personal `USER.md` context](/concepts/user-model#personal-user-files-on-a-shared-gateway) 遵循会话指定的人类所有者，否则是其经过身份验证的人类创建者。具有相同权限的另一个参与者可以在不切换个人上下文的情况下进行引导，并且收集的消息保持相同的会话选择。重新分配在下一个新回合生效；它不能取代跑步回合的个人指示。个人上下文选择不会授予工具权限或更改批准目标。

发送轮次完成后，接受的跨会话引导会保留所选发送者的源权限。访问撤销仍然可以在提交副本之前阻止输入。

可见消息或发送确认并不意味着活动运行时已消耗它。当接受的消息正在等待工作程序设置或工作区同步时，Control UI 会显示特定通知。在回合创建其工作树或准备其运行时时发送的转向在该回合中保持待处理状态。一旦运行时准备就绪，OpenClaw 就会检查它是否可以接受输入。如果回合结束或无法接受，则该消息将保持排队等待后续消息。等待后续轮次的消息出现在编辑器上方的队列中，包括当网关将无法引导的消息排队时。它们在重新连接时一直保留在那里，直到被消耗或取消，而不会再次发送。

当转向回落到后续时，由 `chat.send` 返回的 `runId` 仍然是该输入的公共标识。队列接纳并没有完成它。当后续执行完成时，其终止事件到达，并包含该执行的成功、失败或取消结果。 `collect` 批次使用该批次的结果来完成每个消耗的输入的 `runId`。在消费之前被拒绝、取消或丢弃的输入（包括队列溢出）会立即收到其最终结果。接受到活动转弯的转向在收到其抄本后仍会完成输入的 `runId`，但不会完成活动转弯。

当你希望消息默认进入队列而不是引导当前活动运行时，请使用 `followup` 或 `collect`。当最新提示应替换活动运行时，请使用 `interrupt`。

## <a id="canceling-a-pending-steer"></a> 取消待处理的转向

授权网关客户端可以在传递开始之前使用 `chat.abort({ sessionKey, runId })` 撤回仍在 OpenClaw 运行时的转向队列或后续队列中等待的消息。使用该消息的 `chat.send` 返回的 `runId`。这将撤回该消息，而不停止活动运行或重试它作为后续操作。

一旦交付开始，取消不能保证撤回或撤消已完成的工作。如果无法确认交付，OpenClaw 会报告不确定性并保留输入而不重播。不确定的转向接收不会停止活动运行或其运行工具。使用 `/stop` 显式停止该工作。

## <a id="debounce"></a> 去抖

内置的队列去抖适用于排队的 `followup` 和 `collect` 投递。在使用原生 Codex harness 的 `steer` 模式下，它还会设置发送批量 `turn/steer` 之前的静默窗口。OpenClaw 的主动转向不使用去抖计时器；在工具启动和模型边界处，它会根据运行时配置的转向排空模式按 FIFO 顺序排空。
