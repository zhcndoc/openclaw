OpenClaw 首先是一个个人代理。开箱即用时，你发送给它的每一条直接消息——无论来自 Telegram、WhatsApp、iMessage、Slack 私信、Web 应用，还是其他任何地方——都会进入**一个滚动会话**：主会话。你可以在手机上提问，再从笔记本电脑上继续跟进，代理在两个地方都拥有相同的上下文。只有一个大脑，而这就是它思考的地方。

在幕后，主会话是一个普通会话，其标准密钥为 `agent:<agentId>:main`（例如 `agent:main:main`）。后缀是固定的；自定义 `session.mainKey` 值将被忽略。它的特别之处在于，默认的 DM 范围将所有直接消息折叠到其中，并且系统的其余部分将其视为代理的根：心跳唤醒它，后台工作向它报告，其他地方的活动流向它。

## <a id="home"></a> 首页

在 Web 应用程序中，主会话是 **Home** 页面 - 侧边栏中的第一个条目。顶部的身份行是您的代理（单击它可显示代理菜单）；家是你与它交谈的地方。分叉主要对话的会话出现在 **Threads** 下，群聊出现在 **Groups** 下，coding/CLI 会话出现在 **Coding** 下。

### <a id="talk-to-home-while-working"></a> 工作时与家通话

在侧边栏页脚中选择 **Talk to your Home Agent**（或按 `Cmd/Ctrl+Shift+H`）以打开当前页面旁边的主页。辅助侧边栏可以停靠在右侧或底部。它遵循在侧边栏的代理切换器中选择的代理，因此只有一处可以更改代理。 **Ask OpenClaw** 在同一侧栏中保留单独的系统维护对话。

该扩展坞使用您真实的家庭对话，包括其历史记录、工具、批准和消息队列。 **打开主页完整页面**在主区域打开该对话并暂时隐藏其停靠栏以避免重复作曲家。

展开 **Working on** 以检查下一条消息附带的小参考快照：当前页面以及工作会话、工作区和可见文件路径（如果可用）。在工作区域中选择文本并使用 **Attach 所选文本** 以包含有界摘录。使用 **删除工作上下文** 来发送而不带快照。它成为发送消息的一部分，并通过排队和重试保持不变；斜杠命令不包含它。引用不会授予归属代理对其他代理的会话或文件的额外访问权限。

## <a id="what-flows-into-the-main-session"></a> 什么会流入主会话

主会话不仅仅是聊天记录；它是你的代理的世界汇聚之处：

- **新会话。** 默认情况下，创建会话会在其代理的主页对话中对系统通知进行排队，其中包含会话密钥和可用标题、创建者和创建源。 Home 在下一个回合或预定的心跳中看到它；创建不会触发额外的唤醒。设置 `session.notifyOnCreate: false` 以选择退出。主页本身、草稿、隐身会话、隐藏的内部会话和计划的 cron 运行都被排除在外。重置或重新打开现有会话不会发送另一个创建通知。待处理的创建共享一个有限的内存摘要，为提醒和其他事件留下队列容量。摘要保留最近的会话元数据，并在已满时忽略较旧的条目；它不会订阅 Home 未来的活动。
- **群组活动。** 在 `session.groupScope: "per-group"`（默认）下，群组和房间会话保持隔离，而主会话会自动监视它们。活动以紧凑通知的形式排队——每个对话合并，每条消息不会唤醒一次——代理在下次运行时会看到它们：在您的下一条消息或预定的心跳上。在`tools.sessions.visibility: "all"`（默认）下，主会话可以跨网关使用[会话工具](/concepts/session-tool)，跨代理访问受`tools.agentToAgent`管理，默认情况下处于打开状态；它的系统提示名称监视组，以便它知道最近的活动发生在哪里。
- **后台工作。** 子代理和派生会话会把结果回报给启动它们的会话，因此代理从 Home 发起的工作会回报到 Home。
- **心跳。** 计划的心跳会以主会话为目标，这会在你没有写任何内容时，也能把队列中的通知转化为感知。

## <a id="memory-across-resets-and-conversations"></a> 重置和会话之间的记忆

滚动对话受模型上下文窗口的限制，因此连续性来自其周围的多层机制：

- `MEMORY.md`，即代理精心整理的长期记忆，会在每个新会话中加载。日常笔记（`memory/YYYY-MM-DD.md`）可按需搜索， 并且在 `/new` 或 `/reset` 之后会重新预热最近的笔记。在压缩之前， 代理会将持久事实刷新到日常笔记中，这样长对话就不会无声地丢失它们。
- **跨会话记忆回忆** 允许代理回忆其其他私有会话中的内容。在个人设置中——全局 `session.dmScope` 解析为 `main` 且没有每个绑定的 DM 覆盖——它默认启用；任何已配置的 DM 隔离都会将其关闭，除非你显式选择启用。 参见 [Memory configuration](/reference/memory-config)。

## <a id="a-rolling-session-with-durable-history"></a> 一个带有持久历史记录的滚动会话

主会话会通过重置和压缩向前滚动，而不是让模型一次性承载其全部历史：

- 默认情况下不会自动重置；压缩会在保持滚动会话的同时，将活动上下文限制在边界内。每日重置和空闲重置都是可选功能（参见 [会话管理](/concepts/session)）。在 `/new` 和 `/reset` 时，结束对话的尾部内容会保存到每日记忆笔记中，下一次会话会重新注入最近的笔记。重置会分配一个新的在线会话 id，但会让之前的 SQLite 对话记录在同一个主会话键下保持可搜索。
- 当对话接近上下文窗口时，压缩会对其进行总结并在原处继续——对话记录历史仍保留在会话存储中。
- 会话列表显示的是当前在线对话，而不是其背后每个历史会话 id。
- 当每个代理存储的物理数据库、WAL 和会话工件超出磁盘预算时（`session.maintenance.maxDiskBytes`，默认 `10gb` — 请参阅 [ 会话维护](/reference/session-management-compaction/maintenance)），OpenClaw 将最旧的未引用历史记录提取到经过验证的在删除其数据库行之前压缩存档。直播、路由和飞行中的会话从来都不是预算的牺牲品。

## <a id="when-you-want-isolation-instead"></a> 何时改为使用隔离

共享主会话是默认的正确选择，适用于只有你与其对话的代理。如果有多人可以给你的代理发送消息，请隔离私信：

```json5
{
  session: {
    dmScope: "per-channel-peer",
  },
}
```

通过隔离范围，每个发送者都有自己的会话，并且交叉会话记忆调用默认关闭。群组观看仍然由 `session.groupScope` 独立控制：`per-group` 保持环境主会话可见性，而 `main` 将房间直接置于主要对话中。 `openclaw security audit` 在检测到多个发件人时建议使用 DM 隔离。 [会话管理](/concepts/session)和[通道路由](/channels/channel-routing)中涵盖了完整范围矩阵、身份链接和每路由覆盖。

默认情况下，组和房间使用单独的会话。要使选定的受信任团队房间成为滚动主对话的一部分，请在其路由绑定上设置 `bindings[].session.groupScope: "main"`。这会更改会话密钥和共享上下文；提及门控和回复路由仍然使用原始房间。请参见 [ 会话管理](/concepts/session#group-and-room-routing)。
