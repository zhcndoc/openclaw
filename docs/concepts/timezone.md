OpenClaw 将时间戳标准化，使模型看到的是一个 **单一参考时间**，而不是混杂的提供方本地时钟。时区会出现在三个位置上，各自有不同的用途：

## 三个时区位置

| 表面           | 它显示的内容                                                                                              | 默认                               | 通过以下方式配置                                         |
| ---------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------ |
| 消息信封       | 包装传入的渠道消息：`[Signal +1555 Sun 2026-01-18 00:19:42 PST] hello`                         | 主机本地                            | `agents.defaults.envelopeTimezone`                     |
| 工具负载       | 渠道 `readMessages` 风格的工具返回原始提供方时间以及规范化的 `timestampMs` / `timestampUtc` | 始终包含 UTC 字段             | 不可配置；保留提供方原生时间戳 |
| 系统提示词     | 一个带有 **仅时区** 的小型 `Current Date & Time` 区块（不包含时钟值，以保证缓存稳定）      | 如果未设置 `userTimezone`，则使用主机时区 | `agents.defaults.userTimezone`                         |

系统提示词有意省略实时钟表，以便在多轮对话中保持提示词缓存稳定。当代理需要当前时间时，它会调用 `session_status`。

## 设置用户时区

```json5
{
  agents: {
    defaults: {
      userTimezone: "America/Chicago",
    },
  },
}
```

如果未设置 `userTimezone`，OpenClaw 会在运行时通过 `Intl.DateTimeFormat().resolvedOptions().timeZone` 解析主机时区（不写入配置）。`agents.defaults.timeFormat`（`auto` | `12` | `24`）控制信封和下游界面中的 12 小时/24 小时显示，而不是系统提示部分。

## 信封时区值

`agents.defaults.envelopeTimezone` 接受：

- `"local"`（默认）或 `"host"` - 主机机器的时区。
- `"utc"` 或 `"gmt"` - UTC。
- `"user"` - 解析后的 `agents.defaults.userTimezone`（如果未设置，则回退到主机时区）。
- 任何显式的 IANA 时区字符串，例如 `"Europe/Vienna"`。

## 何时覆盖

- **当你需要在不同区域的主机之间保持稳定时间戳时，使用 `"utc"`**，或者为了与 UTC 对齐的诊断/日志输出保持一致。
- **当你希望无论网关主机运行在哪个时区，都让信封与已配置的用户时区保持一致时，使用 `"user"`**。
- **当网关主机位于一个时区，但信封应始终以另一个时区显示，且不受主机迁移影响时，使用固定的 IANA 时区**。
- **当时间戳上下文对会话没有帮助时，将 `envelopeTimestamp` 设置为 `"off"`**。这会从信封、直接的代理提示前缀以及嵌入的模型输入前缀中移除绝对时间戳。
