OpenClaw 将时间戳标准化，使模型看到的是一个 **单一参考时间**，而不是混杂的提供方本地时钟。时区会出现在三个位置上，各自有不同的用途：

## 三个时区位置

| 界面位置           | 显示内容                                                                                              | 默认值                               | 配置方式                                         |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------ |
| 消息封装 | 封装入站频道消息：`[Signal +1555 周日 2026-01-18 00:19:42 PST] 你好`                         | 如果未设置 `userTimezone`，则使用主机时区 | `agents.defaults.userTimezone`                         |
| 工具负载     | 频道 `readMessages` 风格的工具返回提供商的原始时间，以及规范化的 `timestampMs` / `timestampUtc` | 始终提供 UTC 字段             | 不可配置；保留提供商原生时间戳 |
| 系统提示词     | 包含本地日期和时区的易变“时间上下文”块；精确时间仍由工具提供      | 如果未设置 `userTimezone`，则使用主机时区 | `agents.defaults.userTimezone`                         |

日期和时区位于系统提示词缓存边界之下，因此日期更替不会使稳定前缀失效。提示词会有意省略实时钟表；当代理需要精确的当前时间且 `session_status` 可用时，它会调用该工具。

## 设置用户时区

```json5
{
  agents: {
    defaults: {
      userTimezone: "America/Chicago",
    },
  },
}
```

如果未设置 `userTimezone`，OpenClaw 会在运行时通过
`Intl.DateTimeFormat().resolvedOptions().timeZone` 解析主机时区，而不会写入配置。相同的
解析时区也会用于消息信封、排队的系统事件、提示词中的本地日期以及心跳活动时段。

时钟显示遵循主机操作系统和区域设置的偏好。没有单独的 12 小时制或 24 小时制配置项。

有关提供商示例和已用时间格式，请参阅[日期与时间](/date-time)。
