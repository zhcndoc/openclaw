驻留意图是一种基于事件条件的指令，例如“当提到发布候选版本时，提醒我确认回滚负责人”。OpenClaw 将其存储在所属代理的 SQLite 数据库中，并在符合条件的交互式回复之前进行检查。

驻留意图是一种前瞻性记忆。它们记住当触发条件出现时该做什么；它们不是为某个时钟时间安排工作。

## <a id="choose-the-right-intention-tier"></a> 选择合适的意图层级

| 意图   | 用途                                      | 示例                                              |
| ----------- | ---------------------------------------- | ---------------------------------------------------- |
| 基于时间  | [计划任务](/automation/cron-jobs) | “提醒我星期五 9 AM”                           |
| 基于事件 | 持续意图                          | “当 Alice 提到发布时，询问回滚事宜” |
| 目标愿望  | 带有复查日期的 Markdown              | “在本季度改进发布检查清单”         |

将目标愿望放在 `MEMORY.md`、项目笔记或其他受维护的 Markdown 文件中，并明确写明复查日期。它们既不是定时任务，也不是事件触发器。

## <a id="create-an-event-based-intent"></a> 创建基于事件的意图

常设意图是所有者主导的记忆。经`commands.ownerAllowFrom`认可的频道所有者可以使用`intent`工具创建、列出或取消频道；其他发件人不会收到该工具。经过身份验证的 Gateway/Control UI 管理员和本地 CLI 可以检查和取消现有意图，但创建需要经过身份验证的通道和发送者身份。如果其中一个缺失，OpenClaw 会拒绝创建并要求操作员从经过身份验证的通道对话中重试。

让代理创建该意图，并清楚地命名事件：

```text
When someone mentions the launch checklist, remind me to confirm the rollback owner.
```

代理使用带有描述和触发关键词的 `intent` 工具。它还可以将该意图限定为某个对话频道标识符或发送者标识符，设置过期时间，减少或增加触发预算，或者更改冷却时间。

默认范围是当前频道和发送者。显式 `anywhere` 或 `anyone` 范围仍然需要创建发送者身份：匹配的挂钩无法在以后的通道轮流中安全地强制执行无发送者所有者主体。

默认值是刻意设置得较为保守的：

- 冷却时间：24 小时
- 最大触发次数：3
- 过期时间：90 天

`intent` 工具接受 `maxFires` 和 `cooldownSeconds` 的整数或数字字符串。 `maxFires` 必须为正； `cooldownSeconds` 可能为零。分数、负值和非数字字符串将被拒绝，并出现整数类型错误。

对于具体的时钟时间，代理应使用现有的计划任务路径，而不是创建常驻意图。

## <a id="how-matching-works"></a> 匹配工作原理

在符合条件的用户回合中，OpenClaw 对武装意图执行基于规则的 FTS 关键字预过滤。仅当至少一个配置的触发器条目中的每个术语依次出现时，候选才会触发。 OpenClaw 还在一个同步事务中根据权威的 SQLite 行重新检查通道范围、发送者范围、到期时间、冷却时间和火力预算。每轮匹配扫描最多 256 个范围内的 FTS 候选者，因此嘈杂的触发器集无法阻止回复路径。

匹配路径中不会发生模型调用。命中后，主回复会接收到一个有界的隐藏上下文块：

```text
Standing intent (created 2026-07-27): Confirm the rollback owner.
```

匹配器递增 `fire_count`，记录 `last_fired_at`，并在其显式生命周期中移动意图。发射的意图只有在冷却后才会再次武装。当其火力预算耗尽时，它变为 `done`；当其到期时，它变为 `expired`。网关的插件调度程序在下一个已知的截止日期运行到期和冷却维护。创建或更改意图会刷新该截止日期；当没有活动意图时，不会运行定期数据库检查。重新启动后启动会处理逾期的截止日期。

如果提示钩子在匹配等待数据库准入时超时，则其延迟完成不会消耗火灾。内存核心需要主机的每个处理程序 `hookInvocation` 功能，并在常驻意图写入之前对其进行检查。不受支持的主机会跳过匹配而不消耗意图，并通过现有的挂钩错误策略记录 `prompt hook invocation support is required; intent matching skipped`。共享数据库打开，其他活动调用者正常继续。

TriggerBench 发现，随着上下文增长，预期召回会衰减，并可能漂移为一种始终提醒的启发式方法（[arXiv:2606.23459](https://arxiv.org/abs/2606.23459)）。结构化匹配和触发预算使召回与对话上下文无关，同时限制误报。

## <a id="list-and-cancel"></a> 列出和取消

当你想检查待处理意图的状态、范围、过期时间或触发次数时，请让代理列出这些意图。

取消始终是显式的。请让代理取消某个特定意图；存储的行会移动到 `cancelled`，并且不再能够触发。OpenClaw 绝不会从普通对话中推断取消。ProEvent 报告称，主动系统经常过度反应，并且难以处理事件取消（[arXiv:2607.17701](https://arxiv.org/abs/2607.17701)），因此取消是持久状态，而不是模型判断。

## <a id="lifecycle-states"></a> 生命周期状态

| 状态       | 含义                          |
| ----------- | -------------------------------- |
| `pending`   | 已存储但尚未激活         |
| `armed`     | 符合匹配条件            |
| `fired`     | 已匹配，正在等待冷却 |
| `done`      | 触发预算已耗尽            |
| `cancelled` | 已明确取消             |
| `expired`   | 已达到过期时间                   |

持续意图存储在 `agents/<agentId>/agent/openclaw-agent.sqlite` 中。它们不会添加配置键，也不会创建旁路文件。
