多用户模式允许多个受信任的人操作同一个 OpenClaw 代理。它添加了会话所有权、参与者历史记录、现场状态和所有者过滤。然后，团队可以知道谁开始工作、谁现在负责以及谁参与了工作。

## <a id="trust-boundary"></a> 信任边界

任何能够操作某个代理的人都可以让它执行该代理能够执行的任何操作。会话所有权、侧边栏中的可见性以及在线状态指示器都是可用性功能，而不是安全边界。

如果人们不得访问彼此的会话、工具、凭据或文件，请为他们提供单独的代理或单独的 gateway/host 信任边界。不要依赖所有者头像或过滤器进行隔离。

具有 `operator.admin` 的经过身份验证的 Control UI 管理员可以 [ 以对话方式管理该网关上的任何自动化 ](/automation/cron-jobs#conversational-management)，包括从另一个通道或由另一个人创建的作业。该权限来自已承认的管理员轮次，无需将通道身份与网关配置文件进行匹配。它不会传输作业的创建者属性或计划执行策略。

## <a id="world-readable-session-links"></a> 世界可读的会话链接

对经过身份验证的人员的可见性和公共记录访问是分开的。在 **Shared**、**Read-only**、**Suggest** 和 **Draft** 之间更改会话控制登录人员。这些设置都不会创建公共链接。

会话创建者或网关管理员可以显式启用 **公共访问**。任何拥有普通线程 URL 的人都可以在不登录的情况下阅读现有和未来的对话文本，而工具、推理、文件、图像、小部件、隐藏消息和内部元数据仍然被排除在外。 **登录** 使用此人的现有权限返回到同一线程。指定不同的所有者并不转移发布权限。禁用公共访问会阻止匿名读取；再次启用它可以使相同的正常 URL 可读。之前撤销的令牌链接仍然无效，并且无法撤回下载的副本。有关用户流程，请参阅 [ 公开共享会话](/web/control-ui/sessions-and-sidebar#share-a-session-publicly)；有关安全和部署合同，请参阅 [ 公共会话记录 ](/web/urls#public-session-transcripts)。

## <a id="the-three-ownership-layers"></a> 三层所有权

每个会话最多可进行三层归因：

- **Creator**（不可变）：新会话在创建路径时记录一次写入`createdActor`，可以证明是谁造成的。人类创作者保留其来源：经过验证的网关配置文件、频道发送者或未知的历史归因。只有配置文件创建者才能接收隐式创建者访问权限，包括通过经过验证的配置文件合并。匹配的渠道、代理或系统 ID 无法识别该人的身份。即使所有者发生变化，共享和可见性权限仍保留在创建者身上。
- **Owner**（可分配）：当前负责会话的人员或代理，采用 GitHub 问题受让人的风格。它默认属于创建者，并且可以随时重新分配。分配记录了重新分配的人员和时间。侧边栏头像、所有者过滤器和人员排序都遵循当前所有者。
- **Participants**（历史记录）：经过身份验证的人员、通道发送者以及其接受的输入针对会话的请求代理。会话自己的代理和被动观看者永远不会被记录。每场新身份入场限制为 32 条记录。修复可以保留更大的现有历史。参与情况会在后台尽力记录，因此不会延迟回合。

返回会话行时，网关配置文件显示名称和头像将从当前配置文件解析。代理参与者根据配置的代理身份进行解析。参与者聚合不存储显示标签，因此重命名配置文件或代理会更新所有权 UI，而无需重写参与者历史记录。

## <a id="assigning-an-owner"></a> 分配所有者

在 Control UI 中，会话上下文菜单（kebab 或右键单击侧边栏行，以及聊天标题上的相同菜单）提供：

- **分配给我**：您自己负责会话。
- **分配给…**：选择任何注册人员或配置的代理，包括离线人员和未拥有会话的人员。当您打开菜单时，选项会刷新，并且不依赖于会话过滤器或存档状态。

代理可以重新分配所有权[`sessions`工具](/concepts/session-tool#managing-session-settings-and-groups)，包括在工具政策允许的情况下非所有者代理轮流。这些轮流接收分配操作。经认可的操作员`operator.sessions.write`还可以要求代理重命名他们通过仅标签补丁创建的会话；其他会话设置，reset/delete，全球集团控制仍然受到限制。默认沙箱公开仅标签重命名和单独的`sessions_create`这些非所有者作家的工具。创建保留其角色的代理、工作空间和会话访问限制；它不授予对其他人会话的访问权限。明确的沙箱允许名单和拒绝仍然适用；明确允许`sessions`保留调用者权限允许的操作。运营商与`operator.write`只能存档或恢复他们创建的会话。他们可以停止他们创建或分配的会话，但须接受会话访问检查。使用`action: "assign_owner"`和`ownerType` （`"human"` or `"agent"`） 和`ownerId`。默认情况下，它的目标是当前会话，或者通过以下方式的另一个可见会话`sessionKey`。

存档和恢复需要创建者或网关管理员 （`operator.admin`），包括升级后的现有会话。非创建者的指定所有者将不再获得这些权限。如果创建者不可用，或者会话没有可用的配置文件创建者，管理员可以从会话菜单存档或恢复它。重新分配所有者不会更改归档权限。

两条路径均调用网关方法 `sessions.assignOwner` （`operator.write`）。分配需要已识别的呼叫者（经过身份验证的网关配置文件或受信任的代理身份），并通过会话可见性进行授权。代理所有者 ID 必须命名已配置的代理。分配后，头像工具提示从“创建者”切换为“拥有者”。

重新分配所有者会更改责任和显示。指定人员还会在稍后符合条件的轮次（包括其他参与者的轮次）中选择会话的 [ 个人说明](/concepts/user-model#personal-user-files-on-a-shared-gateway)。这是即时选择，而不是模仿：它不会替换请求者的身份或特权、转移共享权限（保留在创建者手中）或授予或删除访问权限。个人指示不是保密界限；不要在其中存储秘密。

创建者源遵循计划的作业和继承的创建策略。所需的沙箱是一种限制，而不是配置文件身份的证据。失去其创建者来源的历史自动化保留其归属和内容，但不会收到猜测的个人资料授权。管理员可以管理他们的共享或创建新的、明确归属的会话。分配所有者并不会修复创建者权限。升级前请参阅 [Creator 命名空间迁移](/reference/database-schemas#creator-namespace-migration)。

## <a id="per-person-model-accounts"></a> 每人模型账户

每个人都可以登录其网关配置文件的模型帐户。他们启动的新会话更喜欢该帐户而不是默认网关。可用的提供程序和登录方法来自网关的提供程序插件。选择帐户并不能保证每次都会向该帐户计费。

有两种登录方式：网关识别**您**，然后提供商授权**您的模型帐户**。 CLI 和 Web UI 在所选网关上使用相同的个人帐户存储。共享服务器不会将个人登录转换为共享凭据。 System/agent 凭证是一个单独的范围，通过运行 OpenClaw 安装的计算机上的 `models auth` 进行管理。

### <a id="account-concepts"></a> 账户概念

有四个独立的部分：

| 片            | 含义                                                                                         |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| 已保存的帐户    | 您的网关配置文件拥有的凭证。您可以为一个提供商保留多个帐户。             |
| 新聊天默认 | 您的新聊天首选该提供商的已保存帐户。更改它不会重新固定现有聊天。 |
| 聊天选择   | 该帐户已选择用于一次聊天。其他人和叉子保留该选择。                |
| 登录尝试  | 临时的、可取消的操作。在登录成功之前，不会保存任何帐户。                       |

### <a id="adding-an-account"></a> 添加帐户

打开**设置→个人资料→关联帐户**，选择**添加帐户**，然后选择提供商和登录方法。添加帐户需要与 `operator.write` 建立已识别的连接。

- **Anthropic** 接受用于个人设置的 API 密钥，而不是 Claude 订阅令牌。
- **OpenAI** 提供 API 密钥、ChatGPT/Codex 浏览器登录和设备代码登录。
- **Grok （xAI）** 提供 API 密钥和设备登录。

选择器仅显示为该网关上的个人帐户启用的提供程序方法。按照其说明并使用受保护的输入作为凭据或授权代码。浏览器回调可以在输入打开时完成。保持配置文件连接打开，直到报告结果。保存凭据与验证成功的模型请求是分开的。

添加帐户之前，请检查 **Gateway**、**Person** 和 **Scope： Personal** 行。帐户所有权遵循网关分配的配置文件，而不是未保存的显示名称编辑。单用户连接可以使用耐用的 **Owner** 配置文件。使用该配置文件的每台设备都共享其帐户。要区分共享服务器上的人员，请使用网关的身份承载端点。如果未分配配置文件，该部分将解释缺少的内容并链接到 **连接设置**，而不是显示凭据输入。浏览器身份不会转移到 CLI。参见[个人账户CLI设置](/cli/models#personal-model-accounts)。

该页面列出了带有友好标签的已保存帐户，并标记了新聊天默认值。选择另一个已保存的帐户以更改默认值，而无需再次登录。 **加载更多** 继续浏览更大的帐户列表。 **使用网关默认值进行新聊天** 清除个人默认值。保存的帐户仍然可用。

该页面将确切的登录操作报告为待处理、已连接、已取消、已过期或失败。 **Cancel** 要求网关取消该操作，包括已在运行的交换。断开连接、失去权限或重新启动网关可防止未完成的登录启动另一个提供程序请求或保存凭据。重新连接后开始新的登录。刷新个人资料身份不会中断帐户控制。

### <a id="choosing-an-account-for-a-chat"></a> 选择聊天帐户

在 **新会话** 或现有聊天中打开模型菜单。展开 **Account** 类别，为所选提供商选择您已保存的帐户之一。当 **Automatic** 没有符合条件的模型时，帐户选择器仍然可用。在新会话中，选择帐户可以在发送第一条消息之前预览符合条件的模型。该选择适用于您创建的会话，也可用于在按“开始”之前准备 [ 草稿标题准备](/web/control-ui/sessions-and-sidebar#new-session-names)。它不会更改您的新聊天默认值或保存的模型首选项。更改帐户会放弃旧的标题建议。在现有聊天中，它会更改该聊天的选择。

帐户控件显示其他人的个人帐户的个人级别标签，而不是其私人电子邮件、提供商帐户标签或帐户 ID。该标签描述了选择，而不是帐单收据：配置的共享故障转移帐户仍然可以使用。

聊天状态和模型列表将选定的个人凭证标识为 **个人帐户**，而不暴露其私有标签、电子邮件或帐户 ID。

### <a id="cli-and-custodian"></a> CLI 和托管人

CLI 通过 [`openclaw models accounts`](/cli/models#personal-model-accounts) 使用相同的网关操作。运行 `openclaw models accounts login` 选择提供程序和方法，或直接提供 `login <provider> --method <id>`。使用 `list` 检查已保存的帐户。每个命令都会显示所选的网关、已验证的人员和个人范围。它针对的是该人，而不是 `--agent` 或操作系统用户名。

Ask OpenClaw（托管人）需要管理员访问权限和工作配置的推理路由。要求它管理您的个人模型帐户，或输入 `model accounts`。在 Control UI 中，它打开 **设置 → 配置文件 → 连接帐户**。在终端中，它给出 CLI 命令。如果托管人不可用，请开设**关联账户**或直接使用CLI。切换本身不会发生任何变化。在受保护的控件或隐藏的终端提示中完成登录，而不是在对话中。委派的代理请求无法打开或完成人工登录流程。

### <a id="where-credentials-are-stored"></a> 凭证的存储位置

凭证和选定的链接一起保存在共享状态数据库（网关状态目录下的 `state/openclaw.sqlite`）中的私有身份范围记录中。没有第二个帐户数据库或 JSON sidecar。待处理的登录操作仅存在于网关内存中。凭证不会添加到共享或代理本地身份验证存储中、复制到全局运行时快照中或包含在自动帐户轮换中。重新连接仅替换该人拥有的凭据。对于 ChatGPT，仅匹配工作区是不够的：提供者还必须识别同一用户。管理员链接的共享帐户永远不会被个人重新连接覆盖。

管理员仍然可以通过 CLI（`openclaw models auth login --provider openai --profile-id openai:alice`，请参阅 [OAuth](/concepts/oauth)）创建共享配置文件，并将其与 `users.linkAuthProfile` 链接。附加现有共享凭据是管理员决定。 `users.unlinkAuthProfile` 仍然是 self 或 admin，并且 `users.listAuthLinks` 返回没有机密的链接元数据。个人凭证不能链接到其他人的个人资料。

### <a id="pin-and-default-rules"></a> Pin 和默认规则

使用 `operator.sessions.write` 创建您自己的会话会应用您保存的新聊天默认值（如果可用），否则使用网关的配置选择。这包括在您当前认可的操作员权限下代表您使用 [`sessions_create`](/concepts/session-tool#creating-an-independent-session) 的代理。代理可以使用保存的默认值，而无需获得选择其他个人帐户或管理您的帐户的权限。显式个人帐户选择和对新聊天默认设置的更改仍然需要经过 `operator.write` 身份验证的人员。创建保留适用的实时呼叫者、配置文件和角色检查。

当链接的人员创建会话时，OpenClaw 捕获其默认值作为该会话的身份验证选择。该选择具有与 `/model ...@profile` 引脚相同的强度。这发生在发送初始消息之前，包括当创建和第一条消息是单独的请求时。首先按轮流准入创建的会话捕获该准入时的默认值。 pin 是 **session-sticky**：进入该会话的其他人使用其选定的帐户，分叉继承它。显式的 `/model ...@profile -s` 引脚优先于链接。新鲜的个人选择必须属于经过认证的制作者。知道他人的帐户 ID 并不意味着有权选择它。代理和渠道发起的转向不会创建个人链接。合格的 `sessions_create` 路径可以捕获已接纳人员对新会话的现有默认值；它不会创建或更改该默认值。对于使用 OpenClaw 的身份验证回退规划器的运行时，如果固定帐户失败，同一提供商的有序共享配置文件仍将保留故障转移候选者。这与显式引脚的行为相匹配。 Claude CLI 需要其选择的帐户，并且在无法使用该帐户时不会替代共享配置文件或其本机登录。

**对新聊天使用默认网关**、CLI、`clear-default` 和 API `users.unlinkAuthProfile` 仅影响将来的会话。更改默认值不会重新固定现有聊天，包括使用共享凭据取消固定的聊天。采用或分叉现有聊天不会应用当前参与者的默认设置，并且更改提供商不会默默地选择他们的个人帐户。展开模型菜单中的 **Account** 类别以进行显式选择。清除默认值既不会删除已保存的凭据，也不会撤销提供者令牌。如果现有会话必须停止使用它，请与提供者一起撤销它。链接和现有会话凭据遵循经过验证的配置文件合并，但合并不会逆转幸存配置文件上的显式取消链接。

这是在一个信任域内进行帐户选择的便利，而不是与管理员或作为网关 OS 用户运行的代码隔离。在兼容降级时，较旧的版本不会发现个人凭据作为共享默认值。在恢复支持版本之前，个人帐户选择不可用。

## <a id="finding-sessions-by-owner"></a> 按所有者查找会话

当所有权可见时，侧边栏的会话过滤器菜单将获得 **Owners** 部分：

- **所有所有者** 显示所有内容（默认）。
- A 特定人员或代理显示他们当前拥有的会话。
- **涉及我** 显示您拥有的、已提示的或已明确提及的会话。发送的提及会立即添加会话，包括当您离线时；收件箱关闭和过期不会将其删除。该过滤器由网关根据完整的参与者历史记录进行评估。它仅与您经过身份验证的个人资料身份匹配。频道本机发件人 ID 仅供显示且从不匹配，因此数字频道 ID 不会与您的个人资料冲突。

在会话菜单中使用 Involving me**中的**Hide 仅从您自己的过滤列表中隐藏会话。普通活动不会将其带回来，但新的明确提及却可以。该会话在 **All Owner** 下仍可发现，其中 **Show in Involving me** 会恢复它。这些选择遵循您在浏览器和网关重新启动时登录的配置文件；他们不会存档会话或更改其他人的列表。

**涉及我** 需要登录的网关配置文件。当加载的会话有多个所有者时，**Group by Person** 会为每个当前所有者创建一个部分。 **Owners** 排序模式按名称对这些所有者组进行排序。

## <a id="reading-the-avatars"></a> 读取头像

Control UI 在视觉上保持所有权和存在感清晰：

- 会话行上的实体所有者头像在该会话的生命周期内是永久的，并且始终显示当前所有者。当所有者未连接时，它会稍微变暗。
- 当其他人或代理提示会话时，行头像变为**pair-stack**。主人留在前面。要么是其他单个参与者从后面偷看，要么是 **+N** 计数总结了几个。聊天标题显示所有者芯片以及最多四个头像的参与者面孔。所有者被排除在参与者显示之外。
- 环形或半透明的存在头像显示当前正在连接或正在观看的人。它们来自现场存在，而不是所有权，并在观众离开时消失。所有者或参与者化身已经显示的人不会在该表面的实时查看器中重复。按 **+N** 计数汇总的参与者仍然可以单独显示为实时查看者。
- 在 **Group by Person** 下，当该人已连接时，部分标题中的所有者头像会显示一个小绿点。一旦他们闲置几分钟，它就会消失，并在他们离开时消失。您自己的部分从未显示过。

当几个人观看同一场会话时，文字记录还会在作曲家上方显示实时打字指示器。输入 Control UI 的人将其草稿文本流式传输到已发送消息气泡的较软版本中，具有相同的发件人身份、紧随作者编辑位置的插入符号以及 **Typing · not sent** 标签。当作者编辑较长的草稿时，有界预览会保留空格和换行符并跟随插入符号。其他打字员会显示一个三点气泡，并带有相同的未发送标签。草稿是短暂的存在。他们从不坚持。他们从不输入会话记录或模型的上下文。在打字员暂停或发送后不久，它们就会消失。

当加载的会话列表包含少于两个不同的所有者身份并且没有会话记录外部参与者时，OpenClaw 会隐藏所有所有权和所有者过滤器镶边。因此，单用户网关看起来没有变化。

## <a id="people-cards"></a> 人物卡

单击或点击侧边栏的 **Online** 部分中的人员以打开其活动页面。将鼠标悬停或聚焦该行以打开其信息卡。 **查看活动**在卡片中打开相同的页面。不合格的查看者没有个人资料活动页面，因此单击或点击他们的行只会打开卡片，其中包含连接详细信息和可见的观看会话。

活动页面显示每个不同的 app/platform 描述一次，因此多个匹配的浏览器选项卡不会重复相同的设备元数据。展开 **下面的** 连接详细信息 **立即查看** 以了解分组连接计数、报告的 host/platform、IP 地址、时区以及可用位置或输入新近详细信息。计数描述连接，而不是物理设备。单独的选项卡保留自己的观看会话状态；合并显示不会合并这些连接。

在**Group by Person**下，另一个人的部分标题中的头像和姓名打开同一张卡。 V 字形仍然使该部分塌陷。未连接的所有者会收到一张标记为 **Offline** 的卡片，其中仅包含他们最近的会话和活动链接。

该卡片显示该人连续连接的时间、报告的 app/device 上下文和时区，以及该在线期间最后观察到的活动。打开不同的会话、键入和发送新消息均算作活动。连接心跳和代理响应不会。 **尚未观察到** 表示尚未记录符合条件的活动，而不是该人不活动。这些时间事实是短暂的，并会在用户的最终连接关闭或网关重新启动后重置。

人员状态与具有读取访问权限的操作员共享（`operator.read`，也由 `operator.write` 或 `operator.admin` 暗示）。这些读者可能会看到其他人的在线和活动时间以及报告的时区，无论该人是否正在观看会话。 Node 和仅配对连接既不接收状态清单也不接收其活动驱动事件。这不会改变跨读取器 IP 可见性或为所有网关元数据提供隔离。参见[谁可以看到存在](/concepts/presence#who-can-see-presence)。

**正在查看**和**最近会话**使用独立于侧边栏所有者的有界、访问范围的会话列表、**涉及我**和状态过滤器。打开卡片会刷新已配置代理的列表；它仅包括活动会话。最近的会话要求查看者和所有者或创建者具有相同的记录配置文件身份。匹配原始 ID 是不够的。它们并不是一个人贡献的完整历史。会话更新时间描述的是会话，而不是该人最后一次操作的时间。连接描述和时区是客户端报告的提示，而不是经过验证的物理位​​置。

网关还使用 `sessions.list` 可见性规则、跨连接快照、状态 RPC 响应和事件来过滤每个收件人的观看会话引用。隐藏或缺失的引用将被省略，没有计数或占位符。打开某人的卡绝不会借用该人的会话访问权限。

## <a id="reactions"></a> 反应

在Control UI中，您可以对任何保存的提示或助理回复做出反应，包括您自己的提示和其他人的提示。做出反应需要已确定的作者有权发送到会话或在会话中提出建议。其会话角色仅允许查看的操作员无法做出反应。每个可以阅读会话的人都可以看到其反应芯片、计数和反应器名称，并在会话开放时进行实时更新。

代理在下一回合中将每个提交的添加和删除作为单独的 `System:` 行接收，使用与通道反应相同的事件机制。添加、删除、添加相同的反应队列按顺序三个通知；重复一个不会改变任何事情的动作不会引起任何通知。反应永远不会唤醒代理或创建通知。它们与记录分开存储，因此反应不会重写消息。永久删除消息也会删除其反应并释放其在会话反应限制中的空间。重置会话会启动新的转录实例，而不会出现前一个实例的反应。

对通道来源提示的反应也会反映到该通道，作为机器人在通道支持它们时的反应。跳过或失败的通道镜像不会消除 Control UI 反应。在机器人对每条消息保留一个反应的频道（例如 Telegram 机器人和 WhatsApp）上，频道会显示最近镜像的表情符号。删除表情符号会保留频道中最新剩余的 Control UI 表情符号；删除最后一个表情符号会清除通道反应。对助理回复的反应不会被镜像，因为抄本不保留其传递的频道消息 ID。有关调色板和切换控件，请参阅 [ 聊天反应 ](/web/control-ui/chat#reactions)。

## <a id="mentioning-people"></a> 提及人

在文字记录中，选定的提及内容会在原始名称旁边显示一个小的内联头像。丢失的照片使用缩写。徽章省略了可见的 `@`，而复制的文本保留了它。

在正常的 Control UI 聊天中，输入 `@` 并按人员的显示名称（包括空格）或任何链接的经过验证的 GitHub 句柄进行搜索，然后从选择器中选择人员。作曲家显示 **将通知** 以及您选择的收件人。每条消息最多可以选择十次提及。在不选择人员的情况下键入或粘贴 `@name` 会发送普通文本，并且不会通知任何人。 **删除提及** 清除收件人选择，同时保留消息文本。

使用 Up/Down 在人物之间移动，使用 Home/End 跳转到第一个或最后一个结果，然后使用 Enter 或 Tab 插入选定的提及。 Escape 关闭选择器。在 `@` 之后立即键入空格也会将其关闭，因此独立的 `@` 及其后面的散文仍保持普通文本。将光标移到活动提及之外也会关闭选择器。键入的名称中的空格仍会搜索该全名。过滤会保留所选人员（当他们仍然匹配时）。选择器重复使用同一作曲家中同一搜索的最新结果，包括在关闭它或开始另一次提及之后。五分钟后，它会在后台刷新缓存的结果，而不隐藏您已经可以选择的人员。切换会话、配置文件或连接会清除该缓存。超过 30 分钟的结果将被丢弃。选择器显示未缓存搜索的占位符，无人匹配时显示空消息，如果没有可用缓存结果的搜索失败，则显示 **Retry**。 **将通知**在加载时或照片不可用时重复使用所选人员的照片，并带有姓名首字母。

选定的提及在文字记录中呈现为不同的人物参考。将鼠标悬停、聚焦或点击参考以打开侧边栏中使用的相同信息卡：当前名称和头像、观察到的状态和连接详细信息、可见的观看和最近会话以及活动​​链接。原始消息标签和复制的文本保持不变。卡片遵循明确的配置文件合并；普通未选中的`@name`文本不会成为人参考。

选择器包括有资格读取会话的已知网关配置文件，包括离线的人员。其在线指示器只是连接提示，并非资格要求。使用持久的网关配置文件登录以使用人工提及。提及会增加个人发现参与，而不是作者参与或 Git 贡献者信用。它从不添加会话成员身份、更改可见性或授予访问权限。网关在创建和显示收件人时会重新检查收件人的当前访问权限。

提及适用于普通消息、排队或引导输入以及新会话（包括远程放置的会话）的第一条消息。它们在隐身、目标、目录、仅建议、命令发送或终端启动模式下不可用。如果切换到不支持的模式后仍然保留选定的提及，则作曲家会阻止发送。它要求您删除它们，或返回正常聊天。它不会默默地丢弃选定的收件人。

## <a id="mentions-inbox"></a> 提及收件箱

打开 **Inbox → Mentions** 以查看跨可访问代理发送到您登录个人资料的消息。打开提及会打开其会话而不将其关闭。选择 **Dismiss** 以从收件箱中删除该条目。该更改在连接的浏览器中遵循相同的配置文件，而不会删除聊天消息。

提及和解雇在网关重新启动和升级后仍然有效。条目保留其原始标识符和到期时间：**最多 7 天**，每个配置文件最多有 **100 个条目** 和 **10,000 个网关**。较旧的条目可以通过容量限制提前驱逐。刷新或重新连接会重新加载保留的收件箱，而不会重新发送旧的浏览器警报。不会扫描旧的转录消息来重建丢失的条目。

个人参与和 hide/show 选择存在于逻辑会话节点上的私有元数据中，与收件箱保留无关。重置和会话重定位保留它们；删除会话会删除它们，并且分叉不会继承它们。不会扫描现有的转录消息来回填参与。最后提交的提及位置可以防止重播旧消息以撤消后来的隐藏选择，即使在收件箱条目过期后也是如此。

收件箱及其重播簿记使用共享数据库的现有机器状态记录，没有 SQLite 架构更改。提及注释保留在现有消息 JSON 中，通知首选项使用现有首选项记录。请参阅 [ 收件箱存储和保留](/reference/database-schemas#mentions-inbox)。

收件箱无需浏览器通知权限即可运行。对于远离 Control UI 时的可选警报，请启用 **Someone在 [Notifications](/web/notifications#receive-human-mention-alerts) 中提及我**。有关发送和重试合约，请参阅 [WebChat](/web/webchat#human-mention-delivery)。

## <a id="agent-spawned-sessions"></a> 代理生成的会话

在由几个人引导的轮次中，`sessions_spawn` 需要 `user`（请求者经过验证的 `requester_profile.id`），并且子进程使用该人保留的权限进行操作。此选择不会更改会话的模型帐户或下面的创建者和所有者规则。

代理使用 `sessions_spawn` （`visible: true`） 创建的会话通常保留请求代理作为其不可变的创建者。相反，所需的沙箱会保留父级创建者的出处作为隔离策略。如果活动的人类请求者与请求会话的经过验证的人类所有者相匹配，则新的可见子级会将该人分配为其初始所有者。即使沙箱策略保留了人类创建者的出处，不同的所有者、未链接的请求者或系统触发的生成也会明确将请求代理指定为所有者。侧边栏显示当前所有者的个人资料或配置的代理身份，而不是内部会话密钥。分配遵循相同的 [ 所有者和个人上下文规则 ](/concepts/multi-user#assigning-an-owner) ；共享和可见性的权力仍然取决于创建者。

接受的生成结果兼作收据。它包括子会话密钥、运行 ID、直接 Control UI `sessionUrl` 以及命名存储所有者的 `owner` 记录。当 Control UI 禁用时，`sessionUrl` 被省略。当代理在聊天频道中确认生成时，它将会话 URL 放在第一行，将 `Owner: <label>` 放在第二行。然后您可以打开会话并一目了然地查看谁负责。仅当职责再次移动时，才使用 **分配给我** 或 `sessions` 工具。有关生成生命周期，请参阅 [Sub-agents](/tools/subagents)。

## <a id="identity-scoped-convenience-state"></a> 按身份限定的便利状态

当连接具有持久化的 Gateway 配置文件时，新会话偏好设置和选择器最近使用记录会跟随该用户跨浏览器同步。偏好设置仍按代理区分，而最近使用记录仅根据该用户创建的会话生成。没有持久化身份的连接会保留浏览器本地偏好设置，并根据已加载的会话列表生成最近使用记录。

单用户网关为身份不明的运营商提供一份共享的所有者配置文件，包括设备令牌重新连接。配置 `gateway.roles` 后，这仅适用于 token/password 连接。使用该配置文件的设备共享其身份和偏好。使用按人登录来区分人员。请参阅 [ 网关配置文件 ](/concepts/user-model#gateway-profile-and-github-credit)。

此状态提高了连续性。它不是授权或隔离边界。操作员范围仍然控制操作，共享网关仍然是会话、工具、凭证和文件的信任域。

## <a id="drafts"></a> 草稿

将会话作为草稿启动，以便在您发布之前，其他人不会看到正在进行的工作。草稿永远不会对管理员隐藏，他们会看到其他人的草稿带有褪色的幽灵标记。这是一个协调功能，而不是安全边界。

目录列表和进度更新重新检查每个收件人的当前会话可见性。缓存的提供程序结果不会保留对已成为草稿或隐身会话的访问。采用的线程仍然绑定到其原始会话实例和插件所有权。删除并重新创建会话密钥不会将旧线程转移给新的创建者。目录读取和更改还会在提供程序枚举之后重新检查存储的会话。

## <a id="turn-attribution"></a> 回合归因

尽最大努力转向发件人归因。转向可以将输入合并到活动回合中，因此记录不能始终将每个人的贡献表示为单独的回合。参与者的历史记录是由演员发起的，而不是他们说的。

参与者身份与显示名称和授权是分开的。经过身份验证的网关配置文件、OpenClaw 代理和远程发件人即使 ID 匹配，也仍然不同。通道插件在可以证明的情况下提供远程身份域和标识符类型。否则，OpenClaw 保留未解决的观察结果。它不会根据发件人 ID、本地帐户标签或 UUID 形状猜测配置文件。配置文件合并通过现有配置文件别名进行解析。接受的输入会更新已保留的当前配置文件行，或者在不存在当前行时更新保留的别名，即使在 32 条记录准入限制下也是如此。历史行保留其原始 ID。这不会重写成绩单或其他代理数据库。

个人资料参与记录接受外部编写的输入，包括接受的主动转向转向和针对会话的交互式输入。 Synthetic 运行、内部消息以及机器人或环境工作不会建立个人资料活动。参与者记录是一个聚合，而不是精确的重放安全生命周期输入计数。重置会保留逻辑会话的参与者。删除会话会删除它们，即使保留了转录档案也是如此。

正常的准入限制是每个逻辑会话 32 个身份。现有身份可以在该限额内继续做出贡献。修复会保留已经保留的较大历史记录，而不是丢弃它们。四头像标题只是一个预览：网关在分页和预览截断之前评估人员过滤器。活动报告关联的会话，包括验证的创建或分配的责任，而不是声称会话新近度是一个人的最后输入。有限的历史记录和截断的结果被认为是不完整的。

schema-18 迁移首先在 v2026.8.1 中发布，保留历史成员资格和记录的贡献聚合。早期的编写者可以合并配置文件和通道时间戳，因此模糊的第一个和最后一个输入时间变得未知。后来接受的输入建立了新的上次记录，但无法恢复首次输入时间。不运行文字记录、显示名称或基于 UUID- 的回填。请参阅 [ 数据库架构](/reference/database-schemas#participant-identity-migration)。

新的转录消息将合格的发件人身份与显示名称分开。只有合格的个人资料发件人才能获得个人资料肖像、人员活动链接或登录人员的识别，并且只有他们的消息才会清除该个人资料的键入指示器。匹配的通道发送器 ID 是不够的。写入挂钩可以编辑发件人身份，但不能将其替换为其他可信身份。建议归属可识别建议的作者，而不是接受建议的操作员。

较旧的或其他不合格的消息保留其保存的文本和发件人标签，并使用姓名缩写而不是推断的个人资料肖像，并且没有人员活动链接。当发送者和来源标签都没有被记录时，聊天和回复预览使用标签“消息”，没有头像，而是当前查看者的姓名或肖像。 Markdown 导出同样不会假设未归属的输入是由查看者编写的。这适用于现有历史记录，而不更改其存储的消息。 OpenClaw 不会重写这些消息或根据 UUID、个人资料查找或参与者历史记录重建其作者。这可以从真正由个人资料创作的旧消息中删除个人资料呈现，因为它没有记录足够的证据来证实该事实。成绩单归属、参与者​​聚合和基于创建者的访问决策仍然是单独的合同。归属和参与永远不会授予会话访问权限。

通过 Cloudflare Access 或 Tailscale Serve 支持的 GitHub- 登录会自动验证 **设置 → 配置文件 → Identity** 下的人员的 GitHub 帐户。公共 `Co-authored-by` 信用仍然是单独的 **Git 合著者信用** 切换，默认情况下对于经过验证的帐户处于打开状态。归因使用该偏好加上持久的配置文件参与以及委派工作时捕获的贡献者快照。继承的信用并不建立儿童的参与、个人活动、所有权或访问权。显示名称和四人脸堆投影不是身份证据。请参阅 [ 用户模型 ](/concepts/user-model#gateway-profile-and-github-credit) 了解隐私、资格、界限、帐户更改和禁用未来信用。
