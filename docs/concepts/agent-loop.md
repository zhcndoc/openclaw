Agent 循环是按会话串行执行的运行流程，它将一条消息转换为动作和回复：接收、上下文组装、模型推理、工具执行、流式传输、持久化。

## <a id="entry-points"></a> 入口点

- Gateway RPC：`agent` 和 `agent.wait`。
- CLI: `openclaw agent`.

## <a id="run-sequence"></a> 运行顺序

1. `agent` RPC 验证参数，解析会话（`sessionKey`/`sessionId`），持久化会话元数据，并立即返回 `{ runId, acceptedAt }`。
2. `agentCommand` 执行该轮：解析模型 + thinking/verbose/trace 默认值，加载 skills 快照，调用 `runEmbeddedAgent`，并在嵌入式循环尚未发出时补发一个 **lifecycle end/error**。
3. `runEmbeddedAgent`：通过每个会话和全局队列序列化运行，解析模型+身份验证配置文件，构建OpenClaw会话，订阅运行时事件，流式传输assistant/tool增量，强制当前模型尝试的超时（在到期时中止该尝试），并返回有效负载和使用元数据。对于 Codex 应用程序服务器转向，本机 Codex 拥有提供者活跃度和确切的 `turn/completed` 结果；安静期和辅助输出不会结束回合。
4. `subscribeEmbeddedAgentSession` 将运行时事件桥接至 `agent` 流：工具事件至 `stream: "tool"`、辅助增量至 `stream: "assistant"`、生命周期事件至 `stream: "lifecycle"` （`phase: "start" | "finishing" | "end" | "error"`）。
5. `agent.wait` 等待 `runId` 上的最终结果并返回 `{ status: ok|error|timeout, startedAt, endedAt, error? }`。网关 RPC 运行时还会等待其终端重放负载被发布，因此终端等待结果后的重复请求可以重放该结果。

对于嵌入式OpenAI响应回合，`response.completed`完成一个模型响应。如果提供者发送 `end_turn: false`，则即使完成的响应仅包含文本，循环也会请求另一个响应。现有的取消、主机停止决定和故意工具终止仍然适用。

每个完整或不完整的Responses响应还在保存的辅助消息的`diagnostics`中携带`openai_responses_terminal`条目。它将 `eventType` 和提供商的 `endTurn` 信号记录为 `true`、`false`、`"absent"` 或 `"invalid"`，而不保留格式错误的值。将其与消息的 `stopReason` 和文本阶段一起阅读。这些每个响应的事实会在同一运行中的后续响应中保留下来，并且不需要原始流日志记录。它们记录提供商信号，而不是主机停止或取消是否阻止继续。没有此诊断的旧消息无法确定提供者是否忽略了该信号。

等待结果还包含运行的 `terminalReply` 以及 `terminalReceipt`（如果可用）。带有 `sourceReplyDelivered: true` 的收据确认外部源对话已收到最终答复。 A2A 公告使用该事实，而不是使用显示历史镜像作为交付证据。

当提供程序在分派之前拒绝格式错误的工具调用时，内置运行程序可以在早期工具解决后从当前记录继续执行一次。当每次失败都携带主机证据表明执行从未开始并且其结果已经先于当前回合中被拒绝的响应时，早期失败的工具不会阻止此继续。可能导致副作用的故障、未完成的工具和异步工作仍然会阻止它；延续不会重播原始任务或增加重试预算。

## <a id="queueing-and-concurrency"></a> 排队与并发

运行按会话密钥（会话通道）进行序列化，并且可以选择通过全局通道进行序列化，从而防止 tool/session 竞争。消息通道选择为该通道系统提供数据的队列模式 （steer/followup/collect/interrupt）；请参见 [ 命令 Queue](/concepts/queue)。

在流式传输开始前，已获准的运行会记录其持久化的 `activeWriterRunId` 声明。每次追加或重写转录内容时都会提供 `expectedWriterRunId`，同步提交事务会验证它是否仍与当前活动声明匹配。因此，被取代的运行无法提交过时的转录数据。SQLite 写入队列会按代理对变更进行排序，而 Gateway 状态目录锁则防止另一个 Gateway 或 `openclaw agent --local` 进程同时拥有同一个状态目录。

## <a id="session-and-workspace-preparation"></a> 会话和工作区准备

- 工作区已解析并创建；沙箱运行可能会将其重定向到沙箱工作区根目录。
- 技能已加载（或从快照中重复使用），并注入环境和提示词中。
- 嵌入式全局、插件和项目设置在每个会话中准备一次，并在轮流中重复使用。配置或插件更改、工作区或代理目录更改以及会话重置会刷新该快照。对 `settings.json` 的直接编辑在新会话或重置会话中生效。身份验证和模型运行时保留在此设置缓存之外；特定于模型的压实限制和尝试本地设置对于每一轮都保持新鲜。
- Bootstrap/context 文件被解析并注入到系统提示符中。
- 会话记录目标和写入器声明已在开始流式传输之前准备就绪。之后的重写、压缩和截断会使用同一个事务内写入器声明围栏。

## <a id="prompt-assembly"></a> 提示词组装

系统提示词由 OpenClaw 的基础提示词、技能提示词、引导上下文以及每次运行的覆盖项构建而成。模型特定的限制和压缩预留 token 会被强制执行。有关模型所看到的内容，请参见[系统提示词](/concepts/system-prompt)。

## <a id="hooks"></a> 钩子

OpenClaw 有两个进程内钩子系统：

- **内部挂钩**：用​​于命令和生命周期事件（例如`command:new`）的`HOOK.md`脚本。
- **插件挂钩**：agent/tool生命周期和网关管道内键入的`api.on(...)`处理程序，例如`before_tool_call`。

[HTTP webhooks](/automation/cron-jobs#webhooks) 是独立的：它们接受触发工作的外部请求，而不是订阅代理循环事件。

### <a id="internal-hooks-(gateway-hooks)"></a><a id="internal-hooks-gateway-hooks"></a> 内部钩子（Gateway 钩子）

- **`agent:bootstrap`**: 在系统提示词最终确定之前，构建 bootstrap 文件时运行。可用于添加或移除 bootstrap 上下文文件。
- **命令挂钩**：核心发出`command:new`、`command:reset`和`command:stop`。其他命令名称不会自动成为挂钩事件。

参见 [钩子](/automation/hooks) 了解配置与示例。

### <a id="plugin-hooks"></a> 插件钩子

这些钩子在 agent 循环或 Gateway 流水线内部运行：

| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

- `before_tool_call`: `{ block: true }` 是终态并会停止低优先级处理器。`{ block: false }` 是无操作，不会清除先前的阻止。

## <a id="streaming"></a> 流式传输

- Assistant 增量会从代理运行时作为 `assistant` 事件流式输出。
- 已在提供者事件队列中等待的相邻文本追加可以在代理传递之前合并。这不会增加缓冲延迟；快照、内容块更改、推理、工具和终端事件保持独立的边界。
- 块流式传输可以在 `text_end` 或 `message_end` 上发出部分回复。
- 推理流式传输可以是单独的流，也可以是块回复。
- 序列化的 XML 工具调用（包括 GLM `arg_key` 有效负载和 `invoke`/`parameter` 块）对流式传输和最终回复隐藏。不明确的标签前缀等待更多文本；已完成的文字解释和 Markdown 代码示例仍然可见。隐藏卷影副本不会再次执行它。
- 有关分块和块回复行为，请参阅 [流式传输](/concepts/streaming)。

## <a id="tool-execution"></a> 工具执行

工具参数在执行之前根据工具的架构进行验证。在参数恢复期间，分支已接受的 `anyOf` 和 `oneOf` 值将保留其原始值和类型。例如，即使同级整数字段需要从 `"2"` 转换为 `2`，字符串 ID `"00123"` 仍保留为字符串。仅当没有分支接受原始值时，恢复才会尝试分支转换；完整的模式仍然强制执行诸如 `oneOf` 排他性之类的约束。

- Tool start/update/end 事件在 `tool` 流上发出。
- 在 logging/emitting. 之前，对 Tool 结果的大小和图像有效负载进行清理
- 会跟踪消息工具发送，以抑制重复的助手确认。
- A 确认对当前源对话的最终发送、回复、线程回复或轮询会结束自动和消息工具传递模式下的运行循环。对当前源消息进行显式 `final: true` 的附加反应也会结束它。进度操作 （`final: false`）、其他地方的反应、删除和未经确认的操作不会。

## <a id="reply-shaping"></a> 回复整形

最终载荷由助手文本（加上可选推理）、内联工具摘要（在详细且允许时）以及模型出错时的助手错误文本组成。

- 终端生产者仅识别修剪为大写 `NO_REPLY` 的整个结尾，记录终端回复事实，并在交付前删除静默模型文本。消费者转发准备好的有效负载，而无需再次解析文本。
- 消息工具的重复项会从最终载荷列表中移除。
- A 确认对当前源的最终消息传递工具回复仍​​然是提供商重试期间的完成证据。仅进度、失败、部分、试运行和其他目标发送不满足该要求。新接受的引导输入需要它自己的答案。
- A 后备工具错误警告仅在运行因工具故障而结束时才会出现，否则用户将得不到任何回复。该防护是不可配置的；面向用户的回复（包括已由消息传递工具发送的回复）可防止出现警告。

入场设置默认回复期望。即使需要回复，外部直接、组和通道轮流也可以使用仅令牌 `NO_REPLY` 明确完成。子代理、私人完成、Control UI 聊天和其他需要结果的内部会话需要完整的当前源最终结果；只追求进步的镜子永远无法满足这一义务。参见[无声回复](/concepts/messages#silent-replies)。

一场空荡荡的决赛并不意味着沉默。当有界恢复仅通过推理或空输出耗尽时，OpenClaw 记录失败的结果。已承认的用户请求会收到一条简短的系统通知，表明未返回任何答案，而不是历史上捏造的助理答案。后台和内部轮流记录故障，而不将通知发布到聊天中；现有的分类故障和警报路径保持不变。当重试之间发生压缩时，这也适用。单独的空格和零宽度字符不算作可见的答案。

如果所需答复回合在完全解决的工具批次后结束而没有组合答案，则 OpenClaw 可以进行无工具最终确定通过。早期的工具错误、工具前的进度以及被取代的、未送达的确认不算作最终答案。对于嵌入式外部转弯，仅当当前源 `final: false` 文本发送属于最后一个工具批次并且转弯随后以空或静默结束时，才可以算作结算时的答案。需要结果的内部转弯仍然需要实际完成的最终结果。任何后续的工具工作，包括异步进度发送之后的工作，仍然会获得最终确定通过。此遍使用已确定的结果并且不重复已完成的工具。即使最终确定产生了答案，致命的自动化失败（包括拒绝执行）仍然是失败。

即使在已解决的刀具故障之后，明确以 `NO_REPLY` 结束的外圆车削也不需要最终完成路径。故障仍被记录。 `NO_REPLY` 会丢弃本回合写入的所有未发送的内容，因此请在静默结束之前发送确认。

当模型返回空的最终结果时，Node 工作人员轮流使用相同的固定工具恢复。工作人员提出一项无需工具的后续请求。如果该请求也没有返回答案，则该回合报告失败。启动仍在运行的后台命令的工作进程以显式状态及其进程会话 ID 结束；它并不声称他们的结果是完整的。

确认的交付可防止重复生成。待交付或继续工作保留完成所有权，而不标记为已交付；被拒绝的发送、未刷新的延迟文本和丢失的传递回调都不是传递证明。 `NO_REPLY` 不会撤回已发送的文本。待处理的工具、接受的子运行和已生成的工作保留其现有所有者，并且助手错误和中止并不是故意的沉默。

提示段诊断属性 attachment/context 会阻止并独立于用户文本生成入站元数据。仅包含这些块的提示不需要尾随用户文本来完成回复处理。

## <a id="compaction-and-retries"></a> 压缩和重试

在 Control UI 聊天中，恢复保留在工作指示器旁边，而不是为每次失败的尝试创建消息。同模型重试状态包括其尝试次数和退避显示的绝对重试时间。重新连接到活动运行时，模型回退转换仍然可用。

一旦恢复失败，聊天就会显示一条运行失败通知。有用的部分文本和媒体与该通知分开。尝试失败的诊断保留在原始记录中；显示历史记录通过运行标识折叠它们，而不是通过比较错误文本。

当 OpenAI 响应请求在生成工具调用时达到其输出限制时，内置harness将完成已接受的工具并根据其记录的结果进行重试。未完成的调用永远不会执行。恢复使用现有的有界会话重试预算，并且仍然可以取消；拒绝和不一致的终端响应不符合此延续条件。

当空的 `length` 响应没有留下已完成或待处理的回复时，它也符合资格。内置工具使用通常允许的工具继续现有的转录，因此它可以完成诸如控制后台 `exec` 进程之类的工作。此延续保留已完成的操作并使用相同的重试预算。部分答案和有意静默的 cron 结果保留了现有的处理方式；确认的上下文溢出仍然使用压缩。

自动压缩会发出 `compaction` 流事件，并且可以触发重试。重试时，内存中的缓冲区和工具摘要会重置，以避免重复输出。参见 [压缩](/concepts/compaction)。

## <a id="event-streams"></a> 事件流

- `lifecycle`：由 `subscribeEmbeddedAgentSession` 发出（并且在 `agentCommand` 中作为回退机制）。
- `assistant`：来自代理运行时的流式增量。
- `tool`：来自代理运行时的流式工具事件。

发布明确的生命周期 `end` 或 `error` 后，事件所有者会抑制该执行的后续客户端生命周期事件，包括中止清理期间的模型更新和重复终端。可重试的尝试错误使生命周期保持开放状态。聊天中止将其直接终端保留为 `aborted: true` 和呼叫者的停止原因（例如 `rpc`、`restart` 或 `timeout`）。中止所有者在调用取消侦听器之前保留该终端。相同的发布决策涵盖代理框架、聊天决赛、进度快照和会话生命周期通知。执行结算和清理继续独立于事件发布。

对于已完成的 `chat.send` 回合，客户可以在收到聊天 `final` 后立即请求压缩、分叉或倒回。在改变会话之前，这些请求会加入已发布回合的剩余成绩单和入场清理中。竞争实时转弯仍会返回主动运行错误。生命周期交付在侦听器运行之前捕获注册，稍后的聊天终端发布将保留生产者的原始注册。在侦听器回调期间重用运行 ID 无法使其替换终端。

网关将生命周期和工具 start/terminal 事件投影到有界的、仅限元数据的 [audit 分类账](/cli/audit) 中。此投影记录出处和结果代码，而不从 transcript/runtime 路径复制提示、消息、工具参数、工具结果或原始错误。

## <a id="chat-channel-handling"></a> 聊天通道处理

助理增量缓冲到聊天 `delta` 消息中。终端生命周期事件生成聊天 `final`、`error` 或 `aborted` 消息。最终取消和超时事件立即完成，包括运行时将其报告为 `phase: "error"` 时。可重试的错误会保留 15 秒的宽限期，以便回退或重新启动同一运行。一旦外部执行所有者完成其尝试，它就会发布 `executionSettled: true`。网关在没有重试宽限的情况下使用该事实，包括从未到达模型或发出后备步骤的准备失败。对于网关RPC运行，`agent.wait`在需要结算后也加入终端重播发布。未标记的超时和裸中止观察保留其现有的等待层重试处理。

在模型回退和临时确认重试中，Cron 尝试完成情况仍然是 `finishing`；工人`finishing`事件不要求执行结算。已完成的执行事实在 cron 记账之前被捕获，但只有在执行结束后才会发布最终结果。新的尝试在准备之前清除了之前的结果。稍后的工作流程错误或中止无法重新分类已完成的执行； cron 持久性、交付和屈服父延续保留其单独的结果。

当父任务正在等待时，产生的结束不会提交最终结果。如果调度失败，网关仍会发布并保留该失败以用于聊天重播和对话历史记录。

聊天错误等待终端会话持久性，包括任何失败通知，因此立即历史记录重新加载包括记录的失败。成功和中止的聊天终端不会等待此写入。如果持久性失败，网关会记录写入失败并仍然传递实时聊天错误。

历史记录使运行保持活动状态，而其终端会话写入处于挂起状态。一旦写入成功，历史记录和会话活动就会显示记录的结束时间和持续时间，而无需等待重试宽限期。

实时快照的范围仅限于其辅助消息。更正可以缩短或清除当前预览，而不会删除较早的消息。挂起的文本在终止事件之前被刷新；调整实时更新不会延迟工具执行或脚本写入。

运行持续时间元数据属于当前运行，包括模型启动前准备失败的情况。在 Control UI 已完成工作汇总中，独立发送具有单独的运行时间边界：失败的轮次和下一次发送之前的空闲时间不属于下一轮工作的一部分。转向仍然与其目标运行相关联，而不是被视为独立的重试。

对于聊天完成流，重复或减少使用快照会保持连接处于活动状态，但不会重置模型进度截止日期。仅前进提示、完成、总计或推理令牌计数才算作使用进度；更改计费元数据不会使停滞的请求保持活动状态。

内置 OpenClaw 工具将当前模型尝试的执行截止日期发布到队列。当尝试超时时，配置的回退可以在中断的尝试解决后以新的预算开始。用户取消会停止整个运行，包括回退。批准等待会暂停未使用的尝试预算；解决所有待批准的问题后将恢复相同的预算。压缩可以获得一个有限的宽限期。来自 `ask_user` 的问题不会暂停尝试的执行预算。对于 `0`，没有配备执行计时器，但提供程序活跃度、停止和有界中止清理仍然适用。独立的后工具完成有自己的截止日期和取消控制，而不是从已完成的尝试继承回调。

终端超时是失败的转弯，而不是成功完成。聊天和命令结果保留其超时说明；早期的工具错误不会取代该解释或重新启动已经最终超时的回合。这包括工具执行期间没有最终有效负载或接受的延续时的超时。压缩失败标签不会将未完成的工具超时转变为暂停运行；完成的工具结果保留在记录中。早期的工具警告和推理输出不算作完整的答复。安静或收集模式的孩子不会抑制超时，除非另一个延续拥有回复；单独接受孩子并不能保证分娩。向另一个对话发送的进度和消息未完成当前源回复。故意产量保留其现有的公认工作语义。工具媒体在超时期间保留在结果中；仅靠文物并不能完成回复。

取消会立即撤销运行的工具和批准权限。其接受的终端簿记仍然通过生命周期所有者进行结算，因此停止和重新启动取消可以记录会话结果和任何适用的失败通知。替换的会话、候选运行时或网关生命周期无法重用该终端编写器。生命周期所有者在终端写入器接受的写入完成后退休。

模型空闲和提供者 HTTP 行描述内置 OpenClaw 模型路径。 Codex 拥有其本机流截止日期和网络重试。本地终端准确收到后，OpenClaw 允许两分钟进行本地结算。在单独有界中止清理之后，排队的投影获得五秒的耗尽宽限。两个窗口都不会根据进度重置。当执行预算不受限制时，这些清理限制仍然适用。请参阅 [Codex 超时](/plugins/codex-harness-reference#timeouts)。

harness清理会刷新前台工作结束之前接受的轨迹事件，包括重新启动取消期间接受的轨迹事件。它不能在生命周期结束后接受新事件，也不能通过关闭的主机、撤销的准入、替换的运行或替换的记录器进行刷新。

当运行时报告明确的超时时，网关会立即记录其终端状态和会话侧边栏的错误，而无需等待提供者重试宽限。像往常一样打开失败的会话会消除其侧边栏关注。后来的成功转弯会清除先前的错误，并且不会被较早的延迟故障所取代。

### <a id="stuck-session-diagnostics"></a> 卡住会话诊断

启用诊断后，内置的两分钟阈值会将长时间处于 `processing` 且未观察到回复、工具、状态、阻塞或 ACP 进度的会话分类为：

- 活动中的嵌入式运行、模型调用和工具调用会报告为 `session.long_running`。受控的静默模型调用会一直报告为 `session.long_running`，直到达到中止阈值，因此较慢或非流式提供方不会过早被标记为停滞。
- 正在工作，最近没有进度报告，如 `session.stalled`。在中止阈值或之后，拥有的模型调用切换到 `session.stalled`；无所有者的陈旧 model/tool 活动不会像长期运行那样隐藏。
- `session.stuck` 保留用于可恢复的过时会话簿记，包括具有过时无主 model/tool 活动的空闲排队会话。

中止阈值至少为 5 分钟，是警告阈值的 3 倍。过时的会话簿记在恢复门通过后立即释放受影响的会话通道；停滞的嵌入式运行仅在中止阈值之后才会中止排出，因此排队的工作会恢复而不会仅仅中断缓慢的运行。恢复会产生结构化的 requested/completed 结果；仅当相同的处理代仍然是当前时，诊断状态才会标记为空闲，并且重复的 `session.stuck` 诊断会在会话保持不变时退出。

待处理代码模式 `exec` 和 `wait` 调用在解决之前保持活动工具工作状态，包括等待嵌套工作的 `awaitResults: true` 调用。嵌套工具完成不会取消外部调用。正常的堵塞工具恢复津贴和强制执行的 run/tool 期限仍然适用；外部调用解决后，停止进展的嵌入式运行仍然可以恢复。

注意和恢复日志行仅在启用日志级别时才读取可选会话上下文。转录浓缩在后台读取工作器中运行，最多返回 140 个字符；它绝不会延迟分类或恢复。会话替换会丢弃待处理的充实，停止诊断会废弃待处理的日志发布。隐身回复仍然被排除在外。

悬而未决的人工输入问题可以保护其确切的活跃所有者免于过时的工作恢复。如果检查问题使其过期，或者诊断报告恢复或替换运行，则该观察结果不能授权中止恢复的工作。恢复重新验证通过观察捕获的会话生成。

当前等待本机工作的 Codex 尝试是这些空闲阈值的例外：它仍然是 `session.long_running`，原因是 `runtime_owned_wait`，并且不会仅仅因为它安静而中止或接管。恢复和指导重新验证了确切的活跃所有者及其执行预算。这不能保护过期的 OpenClaw- 拥有的请求或工具、取消、终端结算或无主状态。

## <a id="where-things-can-end-early"></a> 何时会更早结束

- Agent 超时（中止）
- AbortSignal（取消）
- 网关断开连接或 RPC 超时
- `agent.wait` 超时（仅等待，不会停止 agent）。
