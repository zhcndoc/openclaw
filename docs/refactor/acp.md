ACP 会话所有权现在已在会话行中明确记录，生成的 ACPX
包装器启动也由租约支持。剩余的进程清理启发式机制并非目标设计：
它们只是针对已发布的 `acpx` 运行时尚未向 OpenClaw 暴露的启动路径提供
临时覆盖。

本页面记录了当前的边界以及仍需完成的工作。它不是对第二个生命周期控制器的
提案。

## 不变量

- 基于租约的清理仅在当前存活证据与租约 ID、Gateway 实例 ID 以及预期的包装器路径相匹配后，才会向进程发送信号。
- `cancel` 会停止当前活动回合，但不会关闭可复用的 ACP 会话。
- `close` 负责终止会话清理。
- 会话可见性从会话记录中读取规范化的所有权信息。
- 核心部分仍独立于 ACPX 包及适配器细节。

## 当前所有权模型

ACPX 插件会在插件 SQLite 状态中持久化稳定的 Gateway 实例 ID 和版本 1 进程
租约。`v2026.7.2-beta.7` 中发布的租约形状保持不变且兼容：

```ts
type AcpxProcessLease = {
  leaseId: string;
  gatewayInstanceId: string;
  sessionKey: string;
  wrapperRoot: string;
  wrapperPath: string;
  rootPid: number;
  processGroupId?: number;
  commandHash: string;
  startedAt: number;
  state: "open" | "closing" | "closed" | "lost";
};
```

在进入使用 OpenClaw 生成的包装器的上游启动流程之前，插件会写入一条
`rootPid: 0` 的待处理租约。包装器命令会将租约 ID 和 Gateway 实例 ID 作为参数接收：

```sh
--openclaw-acpx-lease-id <lease-id> \
--openclaw-gateway-instance-id <gateway-instance-id>
```

ACPX 会话存储保存操作会使用包装器 PID 提升待处理租约。生成的包装器可用性检查和
doctor 探测也使用相同的租约优先顺序。委托完成并不能证明探测包装器已经退出：OpenClaw
会检查完全匹配的活动租约身份并回收仍存活的进程树，但即使包装器不存在，也会保留该租约。
包装器会在生成其分离的适配器之前移除租约参数，因此包装器缺失不能证明重新托管的后代进程
已经消失。探测租约会一直保持打开状态，直到稳定的后代身份能够证明整个进程树都已消失。
如果委托入口抛出异常，OpenClaw 同样无法区分生成进程前失败和生成进程后失败。

直接代理命令则不同。已发布的 `acpx` 会在内部解析并生成这些进程，既不提供生成进程前的
身份钩子，也不提供生成进程后的所有权回调。OpenClaw 不会重复该启动策略；因此，直接代理
会话和直接代理探测仍不在完整租约覆盖范围内。

## 启动恢复

启动时首先列出当前 Gateway 实例拥有的未关闭租约。

- 只有当活动的根命令与其租约 ID、Gateway 实例 ID 和包装器根目录均匹配时，才会回收带有已记录 PID 的租约。
- 通过枚举活动进程行来恢复待处理的 `rootPid: 0` 包装器租约，并要求恰好有一个进程的包装器路径、租约 ID 和 Gateway 实例 ID 均完全匹配。不会向外部进程或缺少匹配项的进程发送信号。
- 匹配不明确、进程证据不可用、包装器路径无效以及不受支持的平台，都会使租约保持打开状态，以便稍后重试。
- 缺少生成的探测包装器时，也会使其租约保持打开状态，因为脱离的后代进程不会携带租约标识。
- 聚合标记扫描与租约回收相互独立。其结果永远不会关闭或丢失某个特定租约。

旧版标记扫描仍会暂时用于未分配租约的直接代理进程和重新设置父级的后代进程。它保留现有的狭窄触发条件：启动时发现了一个来自不确定生成操作的待处理租约。具有租约感知能力的包装器根进程会从该扫描中排除，只通过精确的租约恢复机制进行处理。

## 会话可见性

会话行包含 `spawnedBy`、`parentSessionKey` 和
`ownerSessionKey` 等血缘信息。可见性检查会直接使用这些行字段来处理
`self`、`tree`、`agent` 和 `all`；不再针对每一行执行额外的
`sessions.list({ spawnedBy })` 查询。只要配置的可见性包含请求者的树，请求者拥有的跨代理 ACP
子会话仍然可见，并且 `all` 的能力不会弱于 `tree`。

## 剩余阻塞项

### 上游启动所有权

`acpx` 负责探测、初始会话、重连以及控制操作进程的创建。OpenClaw 需要上游提供预启动身份注入，以及一个在启动后报告根 PID 或等效启动原语的回调。如果没有这一契约，在本地包装直接启动将重复实现 `acpx` 的命令解析和平台行为。

### 稳定的后代进程身份

生成的包装器会在 Unix 上创建一个分离的适配器进程组，但进程组 ID 不会回传到租约中。当前的回收器通过 PPID 记录发现后代进程，因此重新托管的孙进程可能逃出已记录的进程树。移除其标记回退机制需要由上游或包装器负责报告稳定的进程组身份，并由回收器支持针对租约验证该身份。

### Windows 清理

ACPX 回收器目前尚未使用与 Unix 上相同的实时命令行证据来枚举并终止 Windows 进程树。因此，Windows 清理会安全失败并使租约保持打开状态。移除标记机制需要经过测试的 Windows 进程列表和进程树终止实现，而不是跳过该平台。

## 兼容性

租约架构与最新发布版本保持不变，因此无需为此项工作进行 doctor
迁移。没有 `leaseId` 的旧会话记录将继续使用传统的故障关闭清理路径：

- 要求存在一个存活的根进程
- 对生成的包装器，要求拥有包装器根进程的所有权
- 对非包装器根进程，要求存储的命令与当前运行的命令一致
- 绝不只根据过时的 PID 元数据发送信号

如果无法验证旧记录，清理操作会保留该记录不作处理。

## 证明要求

进程生命周期覆盖必须包括：

- 上游入口之前生成的探针租约持久化
- 已完成探针对精确包装器的检查，以及保守的租约保留
- 不相关进程或另一个 Gateway 实例进行的 PID 重用
- 精确的 `rootPid: 0` 自有与外部恢复
- 模糊、不可用以及 Windows 证据导致的安全失败
- 按子进程优先顺序回收适配器子进程
- 在声称已移除标记之前，先进行一个已重新托管后代进程的测试

会话可见性覆盖必须在同一代理、跨代理、禁用 a2a，以及请求方拥有的已生成行之间，保留 `self`、`tree`、`agent` 和 `all` 矩阵。

## 完成标准

只有在上游启动钩子覆盖每一个直接启动操作、租约在重新托管后仍携带稳定的进程树标识、Windows 具有经过验证的等效清理机制，并且删除标记扫描及其包/路径字面量不会降低孤儿进程清理覆盖范围时，重构才算完成。
