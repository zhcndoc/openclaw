`ask_user` 允许代理向人类提出一到三个结构化问题，并等待回答。它适用于真正属于用户的决策， 而不是例行确认，或代理可以从请求、 代码，或合理默认值中推导出的信息。

该工具仅在主会话中可用。子代理和其他非主运行不会获得它。

## <a id="answer-a-question"></a> 回答问题

您可以从任何受支持的对话界面进行回答：

- 网页 Control UI 在作曲家正上方停靠了一个问题面板。对于多问题提示，面板一次显示一个问题，并通过一个短步进器前进。解决后，面板关闭，聊天将完整的问题与您的答案一起保留在紧凑的摘要中。跳过或过期的问题的措辞与结果保持一致。即使键入的文本与选项标签匹配，在待决问题之间切换也会保留选定的选项和键入的答案。
- TUI 在网关和本地模式下都会显示问题提示。使用箭头键或数字键选择选项，使用 **Other…** 输入答案，或使用 **Skip**。多选提示可让您在确认之前切换选择；多问题提示一次提出一个问题。按 Esc 键返回到作曲家而不应答，然后按 `/question` 重新打开提示。
- Telegram 将每个选项呈现为一个单选问题的全角本机按钮。 **其他…**切换到Telegram的回复输入，但没有解决问题。
- Discord、Slack 和 Mattermost 呈现单选单问题提示的本机按钮。 Mattermost 在接受点击时取消提示；在其他地方结束的问题会将按钮保留在原位，直到有人点击其中一个按钮并被告知该问题已得到解答。
- 对于由活动的 OpenClaw 运行创建的问题，当您当前的权限与创建者的权限匹配时，纯文本回复适用于任何频道。使用数字、选项标签或您自己的答案进行回复。对于多选题，请用逗号分隔选项。

来自独立 [ 连接的 MCP 客户端 ](/cli/attach) 的问题不携带 OpenClaw 运行的创建者绑定。使用 Control UI、TUI 或本机应用程序中的问题控件回答那些问题，而不是普通的频道消息。

使用 `operator.sessions.write` 的来宾可以回答在他们创建的会话中运行的自己的授权代理的普通问题。 Control UI 在重新连接后恢复这些悬而未决的问题。访问他人的会话不会暴露他们的问题或让他们回答。秘密、管理和无会话问题保留其现有的特权访问要求。回答问题并不授予代理额外的权限。

接受的答案属于等待座席轮次，该轮次可以保存其工具结果并在答案进入对话历史记录后继续。不相关的新用户轮次、更改的转录分支或撤销的运行权限仍然会阻止旧轮次附加响应。

如果独立问题链接在重新连接后无法刷新，请使用 **Retry** 再次加载它，而不会丢失您在该页面中输入的答案。不再可用的问题仍然不可用。

OpenClaw 始终启用一个自由文本的 **其他** 答案。代理不得向已编写的选项列表中添加 `Other` 选项。

切勿使用凭据回答 `ask_user`。当代理需要 API 密钥时，它会使用 [`secrets` 工具 ](/tools/secrets)，其屏蔽提示会存储该值，而无需输入聊天、记录或模型的上下文。

## <a id="platform-behavior"></a> 平台行为

答案适用于每个受支持的对话界面。网页 Control UI 和 TUI 一次显示一个问题；折叠提示可以恢复作曲家并带有一个细长的待决问题指示器。 TUI 的 `/question` 命令重新打开它，简单的回复仍然可以回答符合条件的待决问题。 iOS、macOS和Android显示内联卡；多个问题堆叠起来，作为一种有意的触摸友好习惯用法。 TUI 在聊天中保留紧凑的分辨率通知；其他平台保留问答摘要，而不进行定时驱逐。 **Skip** 随处可用，并拒绝整个提示。

多问题和多选择提示在消息传递渠道上降级为可读文本。 Control UI 和 TUI 保留了完整的结构化步进器。 TUI 显示剩余时间，消除过期提示，并在重新连接或切换会话后恢复所选会话的待决问题。本地模式将问题保留在运行过程中；退出 TUI 后，它们将无法生存。

通过 `agent` 网关方法与消息传递通道目标启动的回合也会向该对话传递其问题。问题是一个明确的工具消息；自动最终回复传送是单独配置的。

## <a id="async-questions"></a> 异步问题

Codex 异步问题使用 Control UI 作曲家上方的相同面板。它们在不获取键盘焦点的情况下打开，并在代理继续工作时使消息框保持可用。折叠面板以保持紧凑的未回答问题计数并显示当前问题。新消息、问题本身已完成的回合以及折叠的工作历史记录不会忽略问题或重新打开最小化面板。当稍后的运行成功完成时，较旧的提醒会离开码头。重叠的运行、评论、中断和失败的运行不会退出问题。成功的重启恢复也会将旧的提醒变成历史；单独重新启动不会。文字记录将问题保留为 **不再待决** 和 **Answer** 按钮以重新打开它。重新打开会保留草稿，直到您提交、跳过或稍后运行完成。将提醒写入历史永远不会回答它、授予许可或标记其基本任务已完成。当插件替换作曲家时，问题码头也保持可用。

使用面板的请求箭头在待处理的请求之间切换，而不会丢失答案草稿。新的阻塞问题优先；通过相同的导航仍然可以使用异步问题。提交异步答案会使用现有的发件箱和重试控件发送普通聊天消息。跳过会从 Dock 中删除该请求而不发送答案。成绩单保留摘要。单独最小化既不能回答也不能跳过问题。

问题摘要显示您的答案是否已在保存的对话历史记录中排队、发送、失败或确认。如果重新连接后传送失败或变得不确定，**Retry answer** 会重试现有的发件箱消息，而不是提交第二个答案。 **Discard** 删除该排队的答案，并在该对话当前打开的窗格中重新打开其保留的草稿。重新加载后，保存的回复仍保持确认状态，包括在发件箱中编辑的答案或包含引用的问题标题。当这些标题使各个答案不明确时，摘要会显示已保存的回复文本而不将其拆分。

## <a id="timeout-and-no-answer"></a> 超时和无答案

默认超时为 900 秒。 `timeoutSeconds` 被限制在 30 到 3600 秒的范围内。这是最长的人工等待时间，受早期代理运行取消或当前模型尝试超时的影响。待决问题不会暂停或延长该尝试的执行预算。

如果问题在答案到达之前过期或被取消，工具会返回 `status: "no_answer"`。然后代理会基于自己的最佳判断继续执行。

Gateway 问题记录包含可选的来源 `runId`。客户端可以使用它将提示及其最终答案摘要与正确的代理轮次保持关联， 包括在重新连接并通过 `question.list` 或 `question.get` 恢复问题之后。

## <a id="tool-schema"></a> 工具 schema

```ts
{
  questions: Array<{
    id: string; // unique snake_case answer key
    header: string; // short label; truncated to 12 characters
    question: string; // one sentence
    options: Array<{
      label: string;
      description?: string;
    }>; // 2-4 options
    multiSelect?: boolean;
  }>; // 1-3 questions
  timeoutSeconds?: number; // integer; default 900, clamped to 30-3600
}
```

当 `multiSelect: true` 时，用户可以选择多个选项。每个问题的答案值都以数组形式返回。

示例已回答结果：

```json
{
  "status": "answered",
  "answers": {
    "answers": {
      "deploy_target": ["Staging (Recommended)"]
    }
  }
}
```

外层`answers`是协议的`QuestionAnswers`信封；其内部 `answers` 映射由 `questionId` 键入，每个问题都有一组选定的值。

## <a id="model-guidance"></a> 模型指导

面向模型的契约告诉代理要：

- 仅在真正由用户决定且因此被阻塞时才提问；
- ask 每次调用只询问一个问题，除非必须一起提交多个答案，因为单问题提示可以使用本机消息传递控件；
- 将每一个可选择的选择都放在`options`中，而不仅仅是在问题散文中；
- 仅当可以同时选择多个选项时才使用 `multiSelect`；
- 将推荐选项放在第一位，并在其标签后加上 `(Recommended)`；
- 省略手动编写的 `Other` 选项，因为自由文本会自动添加；
- 在 `no_answer` 后继续依据最佳判断执行。

代理不应使用 `ask_user` 来询问是否可以继续，或用于确认其自身的计划。
