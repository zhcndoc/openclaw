## <a id="personal-library-authoring"></a> 个人库创作

在共享网关上，通常询问代理：**为我创建一项技能，总结已审查的更改列表。** 经过身份验证的请求者拥有结果，即使其他人创建或拥有会话也是如此。不需要单独的创作模式或身份参数。默认情况下，单个管理员保留 Workshop 工作流程；当这是预定的目标时，明确要求个人图书馆技能。

个人创建和更新操作在验证和扫描后发布完整的托管修订。响应指出了技能和修订，并解释了它何时可用。发布不会替换当前会话的选择：要求在下一轮明确附加或刷新它。更新前阅读：响应包括面向人的`slug`、生成的命令`name`、修订和个人编辑权限。更新参数 `name` 表示 slug，而不是命令名称。更新时省略 `name` 或 `proposal_content` 以保留它们。

对于个人模型操作，`files` 包含命名的支持文件更新插入；省略它或传递 `[]` 将保留所有其他文件。省略的可执行标志也被保留。使用 `delete_files` 有意删除精确的支撑路径。重复或冲突的编辑以及 `SKILL.md` 的删除将被拒绝；将其全身更换为`proposal_content`。运营商 `skills.library.save` 继续替换整个捆绑包。

使用 `read` 和 `artifact_path` 来读取整个 UTF-8 支持文件，默认为 `SKILL.md`。二进制或超大工件会产生明显的遗漏，并引导您找到我的技能或 CLI；它们永远不会作为部分指令或 Base64 转储返回。个人创作没有待稿行动：主动提出的改进是建议，而不是出版物。

个人突变需要当前的、经过验证的人类转变。自主审查、cron 作业和子运行不会获得新的个人创作许可。如果其他人负责主动创作，请在发布前发送一条新的归因消息。共享使团队可以使用一项技能；只有管​​理员可以将其管理所有权转移给团队。
