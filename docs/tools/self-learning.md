自学习会将纠正和成功的工作转化为可复用技能。技能是持久化的单元：它们包含未来会话可以发现并遵循的流程。每项学习到的技能都会经过[技能工作坊](/tools/skill-workshop)，使用与显式创建技能相同的、受治理的提议、扫描、应用和生命周期流程。

默认模式为 `auto`。OpenClaw 会捕获强学习信号，并通过常规的、由扫描器控制的工作坊服务应用这些信号，而不会请求批准。选择 `propose` 可在每次捕获成为活动技能前进行审核，或选择 `off` 以仅保留建议提示。

## 捕获路径

OpenClaw 使用两条互补的捕获路径。

### 确定性纠正捕获

当交互轮次结束时，OpenClaw 会查找持久性指令，例如“从现在开始”、“下次”以及针对失败方法的直接纠正。这条路径具有确定性，不会启动另一次模型运行。它可以：

- 将相关指令归并到最多三个重点技能中；
- 将纠正路由到匹配的可写工作区技能；
- 修改其自身相关的待处理提案；以及
- 在轮次失败后进行捕获，因为即使工作未完成，用户指令仍然有用。

检测过程有意采用启发式方法。持久性短语偶尔可能产生范围过宽或价值较低的捕获。这是可接受的权衡，因为误捕获易于检查和删除，而 Workshop 治理机制会使写入范围受到限制且可恢复。

### 经验审查

在完成大量工作后，OpenClaw 可以运行一次隔离的后台审查，以寻找可复用的恢复技术或稳定流程，只要这些内容至少能消除未来两次模型或工具往返。用户中断的深度轮次也符合条件：错误路径及其纠正正是值得保留的证据。审查器会获知某个轮次被中断，并且只捕获在停止前明确奏效的流程。以提供商错误或提示错误结束的轮次不会安排审查；该失败属于暂时性的环境噪声，在同一模型上进行审查很可能会再次遇到该错误。

只有满足以下所有条件时，才会启动经验审查：

- 前台轮次已完成或被中断，但未以提供商错误或提示错误结束；
- 当前轮次至少使用了 10 次模型迭代；
- 此次运行是符合条件的前台对话，而不是 cron、heartbeat、memory、
  overflow、hook、subagent 或审查工作；
- 运行时报告了已解析的提供商、模型，以及 `skill_workshop` 的实际可用性；
- 系统已安静 30 秒；并且
- 没有代理或回复运行仍处于活动状态。

同一会话中稍后完成的前台运行会重新开始静默计时。一次只能运行一个经验审查。前台回答永远不会因此延迟。

审查器是隔离且保守的。它可以列出或检查提案，并且最多创建或修改一个待处理提案。其单次变更配额在重试之间共享。它不能应用、拒绝、隔离、发送消息、更新活动技能，也不能使用通用代理工具。被审查的轨迹是证据，而不是指令。

良好的候选内容包括：

- 在工具或模型反复失败后可靠恢复的方法；
- 能防止重复错误的非显而易见的顺序约束；
- 需要反复探索才能发现的稳定多步骤工作流；或
- 可以避免未来多次调用的可复用预检流程。

以下情况审查器应当放弃捕获：

- 常规的成功工作或一次性请求；
- 个人事实和简单偏好；
- 暂时性的环境或服务故障；
- 没有具体支持证据的泛泛建议；
- 无依据的负面断言；或
- 密钥和凭证材料。

## 模式策略

| 模式      | 捕获行为                                                                                              | 建议提示                                                    |
| --------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `off`     | 不创建确定性捕获或体验审查捕获。                                                                      | 已启用。OpenClaw 可以主动建议保存检测到的持久性指令。       |
| `propose` | 通过两种捕获路径创建或修订待处理提案。不会自动应用任何内容。                                           | 已抑制。                                                     |
| `auto`    | 创建或修订提案，然后立即调用常规 Workshop 应用路径。这是默认模式。                                    | 已抑制。                                                     |

使用 CLI 设置模式：

```bash
openclaw config set skills.workshop.autonomous.mode auto
openclaw config set skills.workshop.autonomous.mode propose
openclaw config set skills.workshop.autonomous.mode off
```

或者编辑 `~/.openclaw/openclaw.json`：

```json5
{
  skills: {
    workshop: {
      autonomous: {
        mode: "auto",
      },
    },
  },
}
```

更改模式不会影响现有提案或已应用的技能。手动历史记录审查、
`/learn` 和明确的 Workshop 请求在这三种模式下均可用。

## 为什么默认使用 auto 是安全的

自动学习使用与操作员批准的 Workshop 提案相同的应用路径。它不会为隔离的审查者提供新工具，也不会提供绕过生命周期检查的方式。

每个学习到的技能都会获得以下控制：

- **应用时进行安全扫描：**Workshop 会在实时写入之前立即重新运行扫描器。任何严重发现都会将提案隔离，而不是应用它。
- **仅写入工作区：**创建和更新只能针对所选工作区中可写入的技能。捆绑、插件、托管、个人代理、系统和额外根目录中的技能均处于写入边界之外。
- **哈希绑定：**更新提案会绑定到当前的实时技能；如果目标在应用前发生变化，提案就会过期。
- **回滚元数据：**应用会在实时写入前记录原有技能及支持文件的内容。
- **策展生命周期：**学习到的技能在闲置 30 天后会变为过期状态，90 天后会被归档。固定可保持技能处于活动状态；恢复可将已归档的技能返回到新会话快照中。
- **编写标准：**学习到的技能使用类别级名称、触发器优先的描述、有证据支持的步骤以及高效利用令牌的语言。
- **有界失败：**自动应用只会尝试一次。普通的应用失败会使提案保持待处理状态，而扫描器判定为严重问题的提案会被隔离。OpenClaw 不会循环重试。

使用一条命令拒绝待处理的误捕获：

```bash
openclaw skills workshop reject <proposal-id> --reason "Not reusable"
```

已应用的捕获内容仍会显示在 `openclaw skills workshop list` 中，保留其回滚元数据，并进入策展生命周期管理。这使得无需审批的学习过程具有可逆性且可观察，而不是悄无声息地进行。

剩余风险依然存在：学习到的内容来自对话和工具输出，扫描器会阻止已识别的危险模式，但无法阻止每一种可能的不良建议。如有疑问，请查看 `openclaw skills workshop list`。

## 运行时支持

延迟经验审查要求运行时报告其解析后的模型以及实际的
`skill_workshop` 可用性。嵌入式运行器和 Codex app-server
测试框架会报告这些信息；Codex 还会报告其准确的模型迭代次数。
在提供相同的运行时信息之前，其他由 CLI 支持的运行时将默认拒绝。

确定性更正捕获和 `/learn` 不依赖延迟审查，并会继续在这些运行时上运行。
在 `auto` 模式下，不报告实际 Workshop 可用性的运行时会使确定性捕获保持待处理状态，而不是应用这些捕获。

## 成本与隐私

确定性纠正捕获不会产生额外的模型调用。体验审查仅在一次重要轮次之后、而不是每条消息之后，在已配置的提供商上增加一次有界模型运行。审查器在检查或起草其单个提案时，可能会发起多次提供商请求。

审查器只会接收当前轮次的内容，从其中最近的用户消息开始。渲染后的轨迹限制为 60,000 个字符。当内容包过大时，OpenClaw 会保留第一条消息和最新证据，并标记省略的中间部分。

审查器会复用前台提供商、模型和可用的身份验证身份，同时禁用模型回退。提供商的定价和数据处理条款适用于此次额外运行。

手动历史扫描使用单独的有界路径。它最多审查 20 个重要会话，这些会话至少包含六个模型轮次；扫描会对已识别的机密信息进行删隐，限制会话记录内容包的大小，并且最多创建或修改三个待处理提案。它会将游标和覆盖范围元数据存储在共享状态数据库中，而不会将会话记录内容复制到扫描状态中。

<Warning>
  体验审查和手动历史扫描可能会将符合条件的对话内容（包括工具输入和结果）发送给已配置的模型提供商。请选择符合工作区隐私和数据处理要求的提供商与模式。
</Warning>

## 审查并还原学习内容

列出并检查每个待处理、已应用、已拒绝、已隔离或已过时的捕获内容：

```bash
openclaw skills workshop list
openclaw skills workshop inspect <proposal-id>
```

阻止待处理的捕获内容变为活跃状态，或将其隔离以进行安全审查：

```bash
openclaw skills workshop reject <proposal-id> --reason "Too specific"
openclaw skills workshop quarantine <proposal-id> --reason "Needs security review"
```

通过管理器检查和管理已应用的学习技能：

```bash
openclaw skills curator status
openclaw skills curator pin <skill>
openclaw skills curator unpin <skill>
openclaw skills curator restore <skill>
```

当你希望从当前对话或指定来源获取明确的提案时，请使用 `/learn`：

```text
/learn
/learn docs/runbook.md; focus on recovery
```

`/learn` 始终会创建一个待处理提案，并且永远不会自动应用。

若要手动检查较早的工作，请在控制界面中打开 **插件 -> Workshop**，然后选择 **查找技能创意**。每次点击都会检查一个有界窗口，并使任何结果保持待处理状态，无论是否启用了自主模式。

## 配置参考

| 设置                                       | 默认值 | 作用                                                                                                                     |
| ------------------------------------------ | ------ | ------------------------------------------------------------------------------------------------------------------------ |
| `skills.workshop.autonomous.mode`          | `"auto"` | 选择 `off`、`propose` 或 `auto` 捕获行为。                                                                                |
| `skills.workshop.approvalPolicy`           | `"auto"` | 控制普通代理发起的生命周期调用的提示行为。它不会扩展隔离审查器工具的可用范围。                                             |
| `skills.workshop.maxPending`               | `50`     | 限制每个工作区中待处理和隔离提案的数量。                                                                                  |
| `skills.workshop.maxSkillBytes`            | `40000`  | 限制提案正文的字节大小。                                                                                                  |
| `skills.workshop.allowSymlinkTargetWrites` | `false`  | 允许通过明确受信任的工作区技能符号链接执行应用操作。捕获本身不会扩大受信任目标列表。                                       |

请参阅[技能配置](/tools/skills-config#workshop-skills-workshop)，了解取值范围和完整的 `skills.*` 架构。

## 故障排查

### 未出现捕获内容

检查以下事项：

1. 活跃 Gateway 配置中的 `skills.workshop.autonomous.mode` 是 `propose` 或
   `auto`。
2. 修正内容使用了持久化语言，或者该轮对话至少经过了 10 次模型迭代，且未以提供商错误或提示词错误结束。
3. 对话符合前台工作条件。
4. 运行时报告了解析后的模型以及实际的 `skill_workshop`
   可用性。
5. 运行未处于沙箱中，且工具策略仍允许使用 `skill_workshop`。
6. 对于经验审查，Gateway 在 30 秒静默期间保持运行且处于空闲状态。

符合条件的经验审查仍可能选择不执行。证据不足以达到可复用流程的标准时，不生成提案才是预期结果。

### Doctor 报告 Workshop 被隐藏

在 `propose` 和 `auto` 模式下，`openclaw doctor` 会检查默认代理工具策略是否允许使用 `skill_workshop`。应用报告中的 `tools.allow` 或 `tools.alsoAllow` 更改，或者将自主模式设置为 `off`。

### auto 模式下提案仍处于待处理状态

自动应用只会运行一次。检查提案及其扫描器状态：

```bash
openclaw skills workshop inspect <proposal-id>
```

普通写入或目标失败会使提案保持待处理状态，以便手动审查。扫描器返回严重结果时，提案会被移至隔离区。修复原因后手动应用；不要围绕自动捕获构建重试循环。

### 出现过多低价值捕获内容

切换到 `propose` 以审查每次捕获，或切换到 `off` 以仅保留建议提示：

```bash
openclaw config set skills.workshop.autonomous.mode propose
openclaw config set skills.workshop.autonomous.mode off
```

模式更改后，现有提案和已应用的技能仍然可见。
