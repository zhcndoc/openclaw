`/btw`（别名 `/side`）用于就**当前会话**提出一个快速的旁路问题，而不会将其添加到对话历史中。它借鉴了 Claude Code 的 `/btw`，并适配了 OpenClaw 的 Gateway 和多通道架构。

两个附带问题的合同是故意分开的。 BTW 是关于会话实际模型的一次性问题，保留通道入口（WhatsApp、Telegram 和 Discord）、TUI 和嵌入式 `tui --local` 的harness行为和 Codex 线程叉连续性； TUI 的设计保留在 BTW 上。边聊对 Control UI- 类客户端使用持久、只读 RPC 线程。它的第一个问题是从所选会话中懒惰地准备有界可见上下文；临时历史记录故障仍可重试，并且不会作为空会话运行。频道无法使用侧聊，因为它们没有 RPC 连接。

```text
/btw what changed?
/side what does this error mean?
```

## <a id="what-it-does"></a> 它的作用

1. 将当前会话快照为后台上下文（包括任何正在进行中的主运行提示）。
2. 运行一个单独的一次性侧边查询，告诉模型只回答侧边问题，不要恢复或引导主任务。
3. 将答案作为实时侧边结果返回，而不是普通的助手消息。
4. 绝不会将问题或答案写入会话历史或 `chat.history`。

如果主运行当前处于活动状态，则不会受到影响。

附加到 `/btw` 消息的图像与直接提供商运行时和 Codex harness上的附带问题一起发送。这包括带有 `/btw` 标题的照片，或者当频道提供回复消息作为回复上下文时来自回复消息的媒体。其他harness将图像作为可选输入接收，并且可能会忽略它们。 CLI 运行时会收到一条文本注释，其中包含省略图像的数量。媒体理解已经描述的图像没有附加，因为它的描述存在于主要对话提示中，而不是在辅助问题中。

当其运行时提供使用情况时，已完成的直接提供者和harness端问题通过配置的 [ 诊断管道 ](/gateway/opentelemetry) 进行报告。这不会将交换添加到会话历史记录或会话派生的 `/usage cost` 总数中。

对于 Codex harness会话，BTW 将活动的 Codex 应用程序服务器线程分叉到临时子线程中，而不是运行单独的提供程序调用。这使 Codex、OAuth 和本机 tool/thread 行为保持完整，并且分叉线程保留父线程的当前批准策略、沙箱和本机工具界面。分叉线程收到一个边界提示，告诉模型它之前的所有内容都是继承的引用上下文，而不是活动指令，并且只有边界之后的消息才是活动的。 `/btw` 需要现有的 Codex 线程；先发送一条普通消息。

符合条件的Codex副题可以使用与主线程相同的OpenClaw Gateway shell工具。取消附带问题或达到超时会在释放附带线程之前停止其拥有的本机后台终端。主线程终端和 OpenClaw- 托管后台作业保持其现有生命周期。

对于 CLI 运行时别名，BTW 会以一次性的侧边问题模式调用所属的 CLI 后端：它会将已清理的对话上下文注入到新的 CLI 调用中，禁用工具捆绑和可重用会话状态，并添加后端支持的任何 no-resume/no-tools 标志。直接（非 CLI）运行时则改用直接的一次性提供方调用。

## <a id="what-it-does-not-do"></a> 它不做什么

`/btw` 不会创建持久会话、继续未完成的主任务或将 question/answer 数据持久保存到转录历史记录中。分离的 BTW 结果在重新加载后无法保存。 Control UI 侧聊天可以在重新加载后补充其内存中线程，但该线程会通过会话重置、网关重新启动、空闲到期或轨道的清除按钮来清除。

## <a id="delivery-model"></a> 发货模型

普通助理聊天使用网关 `chat` 事件。分离的 BTW 使用单独的 `chat.side_result` 事件，因此客户端不会将其误认为是常规对话历史记录。 Control UI 不消耗该事件；它调用 `sessions.companion.*` RPC 并在轨道中呈现它们的有界交换状态。

## <a id="surface-behavior"></a> 表现形式

| 表面           | 行为                                                                                                                                                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TUI               | 在聊天日志中内联渲染，与普通回复有明显区别，可使用 `Enter` 或 `Esc` 关闭                                                                                                                                    |
| 外部通道 | 作为带有清晰标签的一次性回复传递（Telegram、WhatsApp、Discord 没有本地临时覆盖层）                                                                                                                                  |
| Control UI / 网络  | 将 `/btw` 和 `/side` 路由至扩展侧聊天。只读线程由会话作为密钥，从网关内存中重新水化，并保留失败的问题以供重试。可以使用垃圾按钮将其清除。 `Esc` 使导轨塌陷。 |

## <a id="selection-popup-(control-ui)"></a><a id="selection-popup-control-ui"></a> 选择弹出窗口 （Control UI）

在 Control UI 中突出显示聊天消息内的文本，只需执行一个操作即可打开一个小的选择弹出窗口：

- **在侧边聊天中提问** 会打开侧边栏，并用带引号的草稿预填其编辑器，这样你就可以针对所选内容输入自己的问题。

该操作遵循正常的 `/btw` 语义：问题和答案不在会话历史记录中，并且主运行保持不变。

## <a id="when-to-use-it"></a> 何时使用它

在需要快速澄清、在长时间运行仍在进行时给出一个事实性的附带回答，或者提供一个不应进入未来会话上下文的临时回答时，使用 `/btw`。

```text
/btw what file are we editing?
/btw summarize the current task in one sentence
/btw what is 17 * 19?
```

对于任何你希望成为会话未来工作上下文一部分的内容，请改为在主会话中正常提问。
