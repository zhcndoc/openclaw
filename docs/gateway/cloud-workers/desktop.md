在 Crabbox 配置文件上启用交互式桌面并通过其经过身份验证的云节点进行连接。

## <a id="ask-the-agent-to-open-an-app"></a> 请求代理打开应用程序

使用已配置的 Crabbox 配置文件，询问 **“在 Crabbox 中打开此内容并向我展示。”** 代理可以将临时环境附加到当前对话，在那里运行应用程序，并在聊天侧面板中打开其视图。代理的主要工作空间和会话放置保持不变。

附加环境安装并验证远程应用程序命令的工作程序包，但跳过代理运行时预热，因为代理保留在当前执行主机上。 OpenClaw 工作人员仍然预热其代理运行时。

对于打开并显示请求，代理在创建附件时会传递 `presentation: "desktop"` 或 `presentation: "portal"`。侧面板在分配之前打开并显示机器启动进度。 Web 预览等待请求的应用程序，而不是显示另一个门户。如果请求的浏览器无法接收初始演示，则在配置之前取消新的预订；现有附件仍然可用。

对于本机应用程序，请使用 `settings.desktop: true` 的操作系统配置文件并启用 **Cloud Worker Desktop** 实验室。代理启动应用程序并打开桌面面板。当其模型支持视觉且工具策略允许`computer`时，可以使用附件的`environmentId`观察和控制同一桌面。采取手动控制暂停座席输入；观察结果仍然可用。当要求恢复时，代理可以在其现有计算机控制权限下使用 `computer` 和 `action: "take_control"`。您的查看器返回到仅供查看，并且代理会收到新的屏幕截图。不需要单独的观看者发出的切换令牌。您可以随时收回控制权或自行释放控制权；普通代理输入永远不会自动接管。

对于 Web 应用程序，代理启动服务器并在侧面板中打开 [portal](/gateway/portals)。连接桌面上的浏览器可以使用 CUA 测试该服务器，但它具有与门户视图分开的浏览器状态和 cookie。

Crabbox 插件的 `crabbox` 工具拥有创建、状态、远程命令、后台应用程序进程和停止。它仅适用于已配置的 Crabbox 配置文件和外部沙盒会话。现有的 `screen` 工具会在请求转弯的浏览器中打开桌面或门户面板。远程命令保留对话的 `exec` 和 `process` 工具策略，并在配置后使用正常的一次性执行批准。网关中的可执行白名单无法移植到临时计算机：禁用批准的白名单策略会拒绝远程命令，而不是绕过该策略。 macOS 和本机 Windows 配置文件需要进行如下所述的图像准备。

后续人员重复使用对话所连接的机器。关闭侧面板会隐藏其视图；后台应用程序在配置文件的生命周期内仍然可用。完成后要求停止特定应用程序或停止整个 Crabbox。该机器是一次性的：在停止之前保存所需的输出。连接机器不会自动同步主工作区；代理必须复制所需的文件或在计算机上准备项目。

该机器的有效总量 TTL 仍然限制桌面使用。 OpenClaw 在拥有工作线程时对有效空闲窗口进行心跳检测，但桌面输入、打开查看器和这些心跳不会延长总生命周期。 `keep` 不会使桌面持久化。到期前保存所需的输出；请参阅 [ 租赁生命周期 ](/gateway/cloud-workers#lease-lifetime)。

如果停止对话环境失败，则在下一次协调扫描时，将以 30 秒到 5 分钟的指数退避时间重试清理。十次尝试或一小时后（以先到者为准），清理工作将暂停到网关进程的其余部分。环境状态报告租约错误 ID、上次故障和恢复指令；在确认清理之前，租约仍保留并阻止更换。对于 Crabbox，使用 `crabbox inspect --id <lease> --json` 检查它并根据需要运行 `crabbox stop <lease>`，然后在对话中重试“停止”。显式停止或网关重新启动会启动新的重试预算。来自 Crabbox 的纯文本 404 是未知的清理结果，不能证明租约已释放。

在降级到没有对话附件的版本之前，请停止连接的计算机。较旧的版本可以读取数据库，但它们将这些计算机视为普通的未分配环境，并且不维护对话活动或清理。有关备份、保留和重新升级合同，请参阅 [ 会话环境存储](/reference/database-schemas/layout#conversation-environments)。

## <a id="desktop-(interactive)"></a><a id="desktop-interactive"></a> 桌面（交互式）

Cloud Worker Desktop 允许管理员从 Control UI 监视或控制有能力的工作人员，而无需将其云节点暴露为普通配对节点。启用 **Cloud Worker Desktop** 实验室，然后在 Linux、准备好的 macOS 或本机 Windows Crabbox 配置文件上设置 `settings.desktop: true`。 Windows选择`windows/normal`； WSL2 桌面不受支持。桌面功能在热时固定：更改设置会影响新配置的工作人员，而必须停止并重新配置现有的非桌面租赁。暖图像捕获仅保留 Linux。即使共享配置文件启用热图像，本机桌面也会进行冷配置。

实验室交换机无需重新启动网关即可应用。连接的 Control UI 页面自动更新桌面可用性。禁用它会关闭工作人员桌面观察；工作人员及其应用程序继续运行。重新启用它可以恢复对已经具有桌面功能的工作人员的访问权限。改变实验室并不会提供或更换工人。

捆绑的 Crabbox 插件支持直接 AWS 和 Azure 配置文件。当所选协调器支持该目标的桌面时，支持协调器支持的 AWS、Azure 和 Hetzner 配置文件。 OpenClaw 仅保持工作线程执行节点：`openclaw worker`、工作区传输、桌面观察和应用程序启动均使用经过身份验证的出站节点连接。它不会恢复 SSH 执行、反向隧道或 rsync。 Direct Hetzner 拒绝 OpenClaw 的固定租用 ID，因此除非 Hetzner 使用有能力的托管协调器，否则桌面配置文件在分配之前会失败。

每个节点通过 `127.0.0.1:5900` 连接到其桌面经过身份验证的 RFB 服务器。桌面还有一个在端口 `9222` 上带有环回 CDP 的浏览器以及提供商拥有的浏览器和终端启动器。 OpenClaw 安装了工人壁纸，因此一次性桌面很容易识别。设置可以安全地重复并在云桌面可用之前完成，包括在配置重播时。项目图像准备在项目设置和捕获之前保留桌面设置。

Linux 使用 Crabbox 的 XFCE 会话来显示 `:99`。本机 Windows 使用 Crabbox 的交互式会话启动器，因此注册节点和 CUA 作为桌面用户运行，并在重播时检查相同的帐户和会话。 macOS 使用专用签名的 **OpenClaw Cloud Worker** 应用程序来托管 CUA 和工作人员帐户的 GUI 会话中的注册节点；请参阅下面的图像先决条件。

具有视觉功能的代理，其工具策略允许 `computer` 通过会话的确切位置控制此桌面；它无法选择另一个节点。这适用于 OpenClaw 工作线程和 Codex 远程执行。请参阅 [ 桌面和计算机控制 ](/gateway/cloud-sessions#desktop-and-computer-control) 了解工具启用和手动控制指导。

桌面永远不会获得公共访问。该节点在本地读取租约的密码文件，检查环回 RFB 安全方案，并为查看器保留相同的连接。 Linux和Windows使用VNC密码验证。 macOS 使用 Apple 远程桌面帐户身份验证以及经过检查的工作人员用户名和 Crabbox 托管密码的私人副本。这些凭证短暂地通过经过身份验证的节点连接以进行预身份验证；查看者不输入工作人员密码。节点通过其已连接的源兑换一次性网关代理票证。因此，打开查看器不会创建额外的未经身份验证的检查连接。 TLS 部署固定节点连接使用的相同网关证书。网关在调度之前和连接之后重新验证持久环境、租约、节点、所有者纪元、桌面描述符、连接和配对；耗尽、替换或拆卸会中止流和任何挂起的应用程序启动。共享桌面会话所有者执行 RFB 预身份验证、仅查看输入过滤和单控制器仲裁。浏览器协议协商与工作人员身份验证重叠，但身份验证成功和桌面流量需要等待双方完成。

当提交的会话放置事件到达时（包括工作人员替换和拆卸），开放式聊天会更新其桌面目标，而无需等待侧边栏刷新。

关闭请求网关连接会取消挂起的查看器设置和无人认领的节点流，从而释放其观察者插槽，而无需等待票证到期。其他连接的观看者保留他们的流。

如果您在设置过程中关闭或更换桌面面板，它会在安装返回时释放未使用的观察结果。这会释放该尝试的节点流和查看器插槽，而无需等待票证到期或中断其他查看器。连接的查看器保留现有的简短隐藏行为。

网关在空闲时在桌面观察者和节点桌面或门户流上发送 WebSocket 保持活动，因此未更改的屏幕或安静预览不会在代理后面变得安静。背压可能会延迟 pong 回复而不撤销流；所属会话和控制连接仍然控制拆卸。

当另一位操作员接管控制权时，您的查看器会以仅查看模式重新连接。该通知通过其经过身份验证的配置文件名称来标识新控制器，或者在未设置配置文件名称时通过其经过身份验证的用户 ID 来标识新控制器。没有经过身份验证的用户身份的连接会显示通用接管通知。

在降级到无法读取正在使用的桌面元数据的网关之前，请停止并释放受影响的工作人员环境，包括主会话放置和对话附件。这包括旧网关缺少元数据时的本机桌面，以及在浏览器或终端描述符中使用固定启动器 `args` 的任何提供商。 Linux 提供商也可以使用启动器参数；仅支持本机桌面查看并不能使旧版网关与这些记录兼容。

等待确认的租约拆除；关闭查看器或暂停工作人员是不够的。较旧的网关可能会拒绝不受支持的密码路径或启动器参数，或者缺少身份验证所需的 macOS 帐户元数据。确认的拆卸会清除桌面描述符，以便旧版本可以读取这些记录。如果您已经降级，请返回到支持版本以首先停止这些工作人员。

## <a id="macos-image-prerequisites"></a> macOS 映像先决条件

使用 `/Applications/OpenClawCloudWorker.app` 准备 macOS 15 或更高版本的工作程序映像，使用开发人员 ID 应用程序身份进行签名并包含其捆绑的 CUA 驱动程序。从 macOS 上的源结帐构建专用应用程序：

```bash
OPENCLAW_MAC_CLOUD_WORKER_HOST=1 scripts/package-mac-app.sh
```

在映像中安装生成的 `dist/OpenClawCloudWorker.app`。为目标工作人员帐户授予 **OpenClaw Cloud Worker** 辅助功能和屏幕录制访问权限，安装 Google Chrome，然后登录到解锁的桌面。云应用程序有自己的捆绑标识和权限授予，与普通的 OpenClaw 应用程序分开。配置在启动之前验证签名的云主机功能；较旧的或普通的应用程序不满足此要求。

该应用程序使用现有的 [local CUA 信任边界](/nodes/computer-use#trust-model)：以工作人员帐户运行的进程可以发现和使用其桌面资源。桌面配置文件和工具策略设置管理托管的 OpenClaw 入口点；他们不会对授权的 shell 代码进行沙箱处理。当需要与该代码隔离时，请使用没有这些桌面授权的单独帐户或映像。

为工作人员帐户启用 Crabbox 的无密码 `sudo` 访问。桌面启动使用它进入 GUI 会话，然后以该工作人员帐户运行应用程序、浏览器和终端。

该应用程序同时拥有 CUA 和临时云节点。虽然其 GUI 会话保持解锁状态，但它会更新短暂的空闲断言以在轮次之间保持桌面活动。显式或托管锁仍然会终止云主机。如果其桌面会话或守护程序不可用，应用程序会在 CUA 退出之前释放断言并停止节点。恢复映像先决条件后重新配置不可用的桌面。现有的云部署、注册和拆卸所有者继续管理租赁。

AWS macOS 需要可用的 EC2 Mac 专用主机和按需分配。通过网关主机上的Crabbox配置准备好的镜像和主机选择。 Crabbox 不会隐式分配新的专用主机。请参阅 [Crabbox 提供商支持 ](/gateway/cloud-workers#coordinator-backed-crabbox)。

## <a id="native-windows-prerequisites"></a> Native Windows 先决条件

将托管 Windows 桌面映像与 Crabbox 的 **CrabboxDesktopLauncher** 服务以及已配置的工作人员帐户的活动桌面结合使用。桌面注册在该交互式会话内运行；普通的独立式 SSH 发射器仍然是无头 Windows 工人的路径。会话 0 进程或属于另一个帐户的进程无法满足桌面注册重播。请参阅 [Windows 运行时先决条件](/gateway/cloud-workers/setup-and-bundle-installation#native-windows-prerequisites)。

OpenClaw 将租赁的托管 TightVNC 服务器切换到具有 GDI 捕获的交互式帐户，保留 Crabbox 的 VNC 身份验证并将侦听器限制为环回。该映像必须允许 TightVNC 应用程序模式。配置重播会重复使用经过验证的服务器，以便连接的观看者保持连接；在交互会话结束后释放并重新配置工作线程。

该模式控制活动桌面；它不提供登录、Ctrl+Alt+Delete 或安全桌面控制。使用 OpenClaw 配置重播或重新配置进行恢复。 Crabbox 的通用 VNC 重置管理服务模式。

包含符号链接的工作空间需要映像中的 Windows 开发人员模式或 **交互式帐户的创建符号链接** 权限。

## <a id="desktop-size"></a> 桌面尺寸

在 Control UI 侧栏中打开 **Systems** 以选择工作人员并将其桌面用作主工作区。停靠和聊天端桌面面板仍然可用；所有演示都重用桌面连接实现和网关控制仲裁。

**桌面尺寸**菜单在面板和独立桌面视图中可用：

- **Fit** 是默认值。它将现有的帧缓冲区缩放到查看器，而不改变工作人员的显示分辨率。
- **Actual** 显示没有本地缩放或远程调整大小的帧缓冲区。
- **Match** 请求查看器的尺寸作为工作人员的显示分辨率。当请求待处理或不受支持时，它还可以在本地进行扩展。

仅当控制连接经过身份验证并且工作程序提供程序允许虚拟显示调整大小后，匹配才会出现。仅查看连接无法请求调整大小。直接主机桌面不会获得此权限。

Crabbox 插件允许调整其专用 Linux XFCE 桌面的大小请求。 Match 还需要 VNC 服务器来协商桌面大小调整，例如 Crabbox 的动态 TigerVNC 桌面。本机工作人员桌面和较旧的固定尺寸 Xvfb/x11vnc 工作人员使用 Fit 和 Actual。要调整旧 Linux 工作线程的大小，请将 Crabbox 更新为具有动态 XFCE 支持的版本，并重新配置桌面工作线程。仅更改菜单不会升级现有工作人员。

受控地重新连接到同一源可保留大小选择。更改来源会将其重置为适合。失去控制或调整大小权限也会重置“匹配到适合”。
