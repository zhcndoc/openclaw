从托管工作树的源远程选择默认配置文件，以及注册节点的状态和固定租约 ID 如何在调度中断时幸存下来。

## <a id="per-project-default-profiles"></a> 每项目默认配置文件

使用 `cloudWorkers.projectProfiles` 从受管会话工作树的 `origin` 远程选择默认配置文件。密钥使用规范化的小写存储库标识 `host/owner/repo`，没有尾随 `.git`：

```json5 validate=false
{
  cloudWorkers: {
    projectProfiles: {
      "github.com/acme/app": "aws",
    },
  },
}
```

在 **设置 → 连接 → 云环境** 中，选择存储库并使用 **机器 → 更改** 选择配置的配置文件。这将写入其默认值 `cloudWorkers.projectProfiles`。存储库身份已验证，并且拒绝映射到丢失的配置文件。通过配置为尚未列出的存储库添加默认值，或删除默认值。

`sessions.dispatch` 中的显式 `profileId` 或 `deviceId` 始终获胜。无目标项目配置文件查找需要 `operator.admin`。在云环境中从 **Advanced → Machines** 删除配置文件也会删除引用它的项目默认值。如果手动配置的映射命名了 `cloudWorkers.profiles` 中不存在的配置文件，则调度会停止，并出现命名存储库密钥和丢失的配置文件时出错。没有 `origin` 或没有匹配映射的工作树返回类型化的 `INVALID_REQUEST`，而无需配置或回退到另一个目标。

注册节点将其身份、持久设备令牌、端点、工作包和工作区存储在一次性盒子上的隔离的每租约状态目录下。配置重播首先采用固定的 Crabbox 租约，然后恢复该节点状态或在关闭注册后为相同的设置身份发出新的配对凭证。网关重新启动后，实时替换注册可能会采用幸存的待处理凭证；第一台设备兑换要求注册保持有效。 Replay 永远不会为同一操作创建第二个环境标识。

OpenClaw 从耐用准备业务中派生一份固定 `cbx_...` 租赁 ID 并将其传递给 `crabbox warmup --lease-id`；生成的 slug 仅显示元数据。如果预热提交但其响应丢失，网关协调会重复相同的固定 ID 操作，并且 Crabbox 返回或仅采用经过精确证明的租约。意图漂移、终端 ID 重用以及不明确的未经验证的资源将被拒绝，而不分配替代资源。

中断挂起配置的网关重新启动会将放置保留在 `provisioning` 中，并在启动后恢复相同的环境和提供程序操作。显式 **停止云工作人员…** 仍然请求销毁并阻止重播。

中断的遗留调度可能分配了随机租用，但没有记录其 ID。 OpenClaw 无法仅从旧操作安全地识别该分配。它拒绝重放和分段采用，在重新启动时保留未解决的分配和清理记录，而不是将资源视为已消失。在开始新的调度之前确定并清理任何先前的租约；不要通过蛞蝓来猜测。不支持旧记录的自动识别或结算。已标记为失败的旧记录不会自动重新打开。
