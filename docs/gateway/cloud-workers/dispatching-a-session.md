授权会话如何到达云目标、Control UI 在提供会话之前需要什么，以及哪些运行时可以使用它。

## <a id="dispatching-a-session"></a> 调度会话

管理员可以在配置的云配置文件上运行授权会话，包括没有存储库的全新工作区。在提交放置生命周期更改之前，会重新验证会话所有权和参与检查。

如果会话已经有活动轮次，`sessions.dispatch` 将返回繁忙错误，而不会中断轮次或启动工作人员配置。等待回合完成并重试调度。

在 Control UI 中，打开 **New Session** 并选择 **Cloud** 目标。当这些资格通过后，云目标就可用：

1. 已连接的操作员拥有 `operator.admin` 作用域。
2. `environments.list` 至少公布了一个已配置的配置。
3. 选定的代理运行时公布云放置支持。

如果没有明确选择的文件夹、项目或工作树，远程会话默认为 **New 工作区**：一个空的隔离工作目录。您还可以从项目选择器中选择 **New 工作区**。不需要存储库、初始提交或网关文件夹。 OpenClaw 对每个新会话使用私有后备存储库，以便工作区快照、恢复和清理保持正常行为；会话不共享 Git 远程或历史记录。现有本地文件不会复制到新工作区中。

选择存储库后，分支选择器会显示 **From main** （或选定的分支）；在选择引用之前，它显示 **起始分支**。选择 GitHub 存储库后，您可以选择源引用，而无需在网关上进行克隆。选择网关文件夹后，云选择将启用其托管工作树，并且仍然要求该文件夹是可用的 Git 签出。当 Git 发现待决​​时，选择目标不会丢弃显式源；选择 **New Workspace** 以空启动。网关创建会话，完成调度，然后才发送第一轮。会话侧栏中的服务器徽章显示持久放置状态。启动恢复保留工作区选择以及目标和第一条消息。

在节点上准备网关文件夹时，OpenClaw 会保留其无凭据 HTTP、HTTPS 或 Git 传输 `origin`（如果节点签出没有凭据）。现有节点原点保持不变。不会转发带有嵌入凭据、查询字符串、片段或其他方案的源。完整工作区替换保留现有的 [Git 元数据恢复限制 ](/gateway/cloud-workers/session-lifecycle#accept-a-completed-turn)。

如果网关在配置期间重新启动，则挂起的第一条消息将等待恢复，并在其工作线程准备就绪时自动继续。临时启动或暂停错误不会取消安装。第一条消息会在聊天中出现后续恢复通知之前保留，包括重新连接后。

如果启动恢复超时，该通知会将仍在进行中的设置与无法确认完成的网关区分开来，并确认第一条消息尚未发送。 **Retry** 首先检查现有的worker。它等待正在进行的设置，并在工作人员准备好后发送保留的第一条消息。仅当安置允许新的派遣时才要求更换；必须首先停止仍需要清理的失败工作进程。单独重新连接永远不会要求更换。

在新会话仍在配置时选择 **Stop 云工作线程...** 会在请求拆卸之前暂停其初始消息。延迟的调度响应无法发送该消息。草稿对于 **Retry** 保持可见，并且不会自动重新提交。常规会话草稿在重新连接和页面重新加载后仍然存在；隐身草稿仅保留在当前页面中。如果第一条消息已发送，则不确定的传递仍然存在 **检查传递** 而不是开始另一轮。

当放置处于活动状态时，OpenClaw 会自动对远程工作区卷上的可用空间进行采样。所选聊天和会话的云徽章上会出现空间不足警告。它们是建议性的，在空间恢复后自动清除，并且不会停止或回收工作人员。

### <a id="cloud-child-sessions"></a> Cloud 子会话

当 OpenClaw 工作程序使用 `sessions_spawn` 时，网关会在单独的托管工作树中创建可见的子会话，为工作程序提供父级配置文件，并在返回接受之前提交初始任务。该调用不会等待子任务完成。

当该调用等待时，父级在其现有的运行超时下仍保持活动状态。仅静默配置不会让排队消息接管父级消息或使恢复提前中止它。工人进度不会延长超时时间，聊天**Stop**控制或`/stop`仍然可以取消转弯。分别使用 **Stop 云工作者…** 来协调工作空间并释放机器。

### <a id="runtime-support"></a> 运行时支持

- **OpenClaw** 使用 `worker-turn` 放置。受限制的 `openclaw worker` 进程在租用节点上每轮运行，并默认通过网关代理推理。显式配置的配对设备配置文件可以选择 [worker-local inference](/gateway/cloud-workers/native-inference)。
- **Codex** 在同一捆绑 Crabbox 云配置文件、符合条件的配对设备或宣传 SSH- 支持的执行运营商的提供商上使用 `remote-exec` 放置。网关将 Codex 应用程序服务器和身份验证保留在本地；已注册的云节点仅运行显式授权的 Codex exec-server，并且不会启动 OpenClaw 工作子节点。

Control UI 在新会话和移动会话中检查每个云目标的公告执行模式。对于 OpenClaw 和 Codex，可以选择一个 Crabbox **Cloud · profile** 行，而真正的单模式提供程序对于其他运行时保持禁用状态。在活动源开始耗尽或更改其持久放置之前，不兼容的移动将被拒绝。

其他运行时保持不可用，除非它们的工具明确声明云放置模式。不为外部 CLI 会话目录提供云目标。如果选定的提供程序或放置沙箱不可用，Remote-exec 将拒绝执行；它永远不会回退到在网关主机上运行操作。
