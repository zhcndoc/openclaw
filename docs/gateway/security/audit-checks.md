`openclaw security audit` 发出由 `checkId` 键入的结构化结果。此页面是这些 ID 的参考目录。有关高级威胁模型和强化指南，请参阅 [Security](/gateway/security)。

某些检查仅使用 `openclaw security audit --deep` 运行：plugin/skill 代码扫描（`plugins.code_safety*`、`skills.code_safety*`）和实时网关检查（`gateway.probe_*`）。此表中的其他所有内容都在普通 `openclaw security audit` 上运行。

深度代码扫描每个插件或技能最多检查 500 个源文件，优先考虑声明的插件入口点，并跳过大于 1 MiB 的文件。遍历也会在 100,000 个目录条目（包括排除的条目）后停止。 `*.code_safety.scan_truncated` 警告表示某些文件未检查；它不识别危险代码。工作区技能路径扫描保留 2,000 个技能文件和 40,000 次目录访问的单独限制，以及相同的 100,000 项遍历限制。他们的 `skills.workspace.scan_truncated` 警告还涵盖了树的不可读部分。

像 `warn/critical` 这样的严重性表示同一个 `checkId` 可能根据配置以任一级别发出（例如，取决于 Gateway 是否对外远程暴露）。以下是实际部署中最可能看到的高信号值（并不完整）：

可变条目检查使用配置的 `allowFrom` 条目，不包括 `"*"` 和配对存储批准，并报告计数和没有原始值的配置路径。符号 `accessGroup:` 引用不计为可变标识符。可变别名是可更改或共享的标签；相反，准确、稳定的标识符可能拥有未经证实的所有权。入口诊断将 `mutable_identifier_disabled` 与 `identifier_authentication_too_weak` 区分开来。
