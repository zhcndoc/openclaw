# <a id="audit-history"></a> 审计历史

Gateway 会在共享的 OpenClaw 状态数据库中保留一个有界的、仅包含元数据的审计账本。它可以回答诸如“哪个代理运行了、何时运行、以及如何结束的”“某次运行执行了哪些工具操作”，以及在启用消息审计时，“一条已接受的入站消息是否到达了分发阶段”以及“ 一条出站消息是否到达了终态交付状态”等操作性问题。

分类账存储身份、排序、出处、操作、状态和标准化结果代码。它从不存储提示、消息正文、工具参数、工具结果、附件、文件名、URL、命令输出或原始错误文本。

Gateway 还会为新接纳的代理运行保留一个相邻的执行身份上下文。该上下文对于其中包含的身份事实具有权威性；但它不会使活动账本变得无损，也不会将审计记录转变为授权证据。

终端操作员审批是一个独立的权威来源。运行检查会直接将其现有的“首个回答获胜”行转换为决策回执；它不会将审批复制到审计账本或通用决策事实表中。

这包括操作员路由的本机 Codex 命令和文件提示。 Codex 桥将已承认的代理、会话密钥、运行、工具、上下文和执行绑定携带到同一批准所有者中，然后仅返回批准的本机范围。自动审查、完全访问策略、本机钩子决策以及在操作员路由之前拒绝的请求没有操作员拥有的行，并且仍然不支持作为操作员批准证据；后来的工具事件从未制造过。

共享外向交货是另一个所有者本地来源。队列准入和平台发送启动使用惰性进度同伴，而终端消息行保留在活动分类帐中。运行检查直接合并两个源；两者都不会复制到通用决策事实表中。

启用执行身份收集的计划运行将其承认的上下文和执行 ID 绑定到存储的 `cron_run_receipts` 行。检查加入了精确绑定并保留收据的记录状态，包括旧版本记录的运行。禁用集合不会创建绑定表或行。新任务和流程生命周期绑定写入和检查联接已停用，但它们的现有表和行不会删除或迁移。这些更改使数据库模式保持不变；请参阅 [ 版本控制合约 ](/reference/database-schemas/versioning)。独立审计事件和决策事实保留其现有的保留政策；它们不是从保留的任务或 TaskFlow 行重建的。单独的 `runId` 永远不会将所有者行连接到执行。丢失、删除、损坏或不匹配的绑定仍然未知或不存在；它们永远不会改变执行行为，也永远不会复制到 `execution_decision_facts` 中。

## <a id="run-identity-inspection"></a> 运行身份检查

默认情况下，执行身份记录处于关闭状态，包括全新安装和升级时。为新允许的运行显式启用它：

```bash
openclaw config set logging.audit.executionIdentity true
```

集合要求 `logging.audit.enabled` 和 `logging.audit.executionIdentity` 均为 true。设置为 `false` 会立即停止新上下文；没有环境变量别名或静默迁移启用该功能。保留的上下文在 30 天到期之前仍然可以检查。

审核设置无需重新启动网关即可应用。变更影响后续活动和入场；已接受的写入仍然通过同一队列排出，并且先前已接受的身份上下文仍然不可变。启用收集不会回填早期活动或将身份添加到已承认的运行中。

会话工作准入成功后，OpenClaw 验证并冻结一个有界身份信封，立即将其提供给现有审核写入器队列，并继续运行，而无需等待写入器准备就绪、SQLite 或持久性。队列耗尽初始化模式和 HMAC-key 状态，对原始引用进行假名化，构造不可变上下文，验证其规范字节，并通过现有共享状态工作线程将其持久化。流程拥有的 FIFO 保留每个已接受的项目，直到其工作人员尝试解决。因此，在排队工作完成时，已接受的信封可能暂时无法检查。

坚持仍然是尽最大努力。队列饱和、存储故障、关闭超时、进程崩溃都可能丢失证据；他们只记录有限的操作警告并且从不中止运行。当写入器生命周期允许时，正常网关和直接本地 CLI 关闭会刷新已接受的工作，但突然终止仍然可能会丢失排队的证据。

启用身份收集后，重新启动恢复仅存储其现有私有恢复所有者的安全 execution/context/run id 和时间戳。后来的模棱两可的重试引用该令牌，而不是从新进程重建身份。当收集或审计分类账被禁用时，恢复不会创建、存储和传播新的身份令牌。如果原始排队上下文丢失，则精确检查显然不可用；重试永远不会产生替代证据。原始身份引用不存储在恢复令牌中。

每个承认的外圈都会收到一个新的不透明 `executionId`； `contextId` 标识其不可变的证据记录，而现有的 `runId` 仍保留可能共享的路由、会话或恢复关联。使用 `audit.run.inspect` 或 [`openclaw audit --execution <id> --explain`](/cli/audit) 查询一个精确执行。使用 `--run <id> --explain` 发现运行关联的执行。一场保留的比赛直接解决。多个匹配返回`ambiguous`，最多有50个候选执行id，并且需要精确选择； OpenClaw 永远不会默默地选择第一个或最后一个执行。结果明确指出了这些字段的证据状态：

- 信任域、调用方和入口；
- 代理主体、代理定义和运行时实例；
- 所代表的主体和发起方；
- 适用的授权和保证证据；
- 可用时的父级或子级谱系。

对于从 `sessions_spawn` 开始的子进程，该子进程拥有一个新的上下文；它永远不会重用或改变父上下文。当确切的私有父令牌可用时，沿袭投影会链接父上下文、执行、运行和代理。其委托参考涵盖生成关系以及 requester/controller 和评估的 local/target 策略输入。适用的补助金和运行时间保证仍然是单独的证据类别。该报告报告了可能缩小儿童权威的输入；它并不声称身份改变了允许或拒绝的决定。

如果私有父令牌不可用，则子令牌仍可检查，但缺少的父上下文、执行和运行证据是明确的。 ACP 生成本身是可观察的。完全在外部 ACP 运行时内执行而没有回调的操作将被报告为不受支持的证据，永远不会从任务或脚本文本中推断出来。准入后，ACP 生命周期所有者在提交提示时使用确切的准入执行令牌记录该收据。它没有声称发生了天然副作用；适配器作者必须添加权威的本机操作回调以提供更有力的证据。

注册的插件运行时调用仅在精确运行许可后添加有界事实。 `before_tool_call` 钩子将其自己的允许或阻止记录为强制插件门；阻止执行的钩子错误是拒绝，而配置的失败打开错误仍然未知。当挂钩请求批准时，单独的所有者本机批准行仍然具有权限。

插件拥有的节点操作将网关与操作结果区分开来。强制执行配对、实时连接、命令功能、插件策略和主动权限检查。节点报告的成功仅归因于。如果插件策略返回时未调用提供的节点回调，则操作未知，缺少 `node.action_callback`； OpenClaw 不会从插件结果推断发送。

附加的工作人员将其当前凭证、bundle/version/features、所有者纪元和轮换声明许可记录为一个强制门。现有的安置和工人操作行保持权威；它们的哈希值、凭据、令牌、环境 ID 和会话 ID 不会复制到通用收据中。准入成功仅证明工作人员可以连接，而不证明稍后的工作人员操作成功。

该基金会记录直接本地 CLI 入口、网关引导系统入口，并在其权威生产者处接纳通道参与者。对于通道运行，受信任的活动注册本机插件会生成远程参与者事实。 Core 仅在精确记录、注册纪元、范围和一次性切换中接受它；房间、路线、帐户、线程、消息和交通仍然是非主要事实。 `boundary-verified` 描述的是进程内边界验证，而不是对 Telegram、Discord 或其他远程服务的独立核心查询。只有当每个贡献都证明是同一参与者时，收集的消息才能保留一个人。混合、缺失、无效、陈旧、重播或未铸造的证据未知，并且明确缺乏支持的适配器不受支持。 OpenClaw 永远不会根据 `SenderId`、`From`、会话密钥或路由元数据重建参与者。插件不能公开铸造或升级参与者证据；伪造、复制、更改、过时、重复使用或丢失的主机载体仍然未知。当其边界无法证明更具体的来源时，其他公共入口仍然明显未知。直接本地执行是 `unattributed`：存在网关单元、本地 CLI 入口、配置的代理和运行时绑定，但在此边界不提供持久调用者主体。仅当权威入口提供调用者事实时，运行才会变为 `attribution-only`。这两种状态都意味着身份会影响允许或拒绝的决定。

配置的 webhook 映射 ID 仅标识匹配的入口源。它们不对个人、服务或调用者进行身份验证。因此，除非存在另一个权威的主要生产者，否则共享挂钩身份验证和直接 `/hooks/agent` 请求将保持未归属状态。在准入之前抑制请求的映射转换返回其正常的 HTTP 响应，但不会创建运行、执行标识、任务或决策收据。仅在当前持久恢复所有者承认确切的尝试后，重新启动恢复才会记录系统归属。

经过身份验证的网关附加记录一次不可变的审核事实。会话创建单独读取当前主配置文件 ID，因此附加后执行的配置文件链接无法孤立会话所有权。普通会话来源仅保留该 id；它不保留配置文件显示标签。当显式启用执行身份记录时，其审计上下文还可以在秘密编辑和 128 个字符的限制后保留准备好的显示标签。解析的持久配置文件（包括由经过验证的可信代理或 Tailscale 身份创建的配置文件）提供假名的个人调用者。配对的设备增加了设备保证，但永远不会成为一个人。共享令牌、密码、无身份验证连接和其他无配置文件客户端保持未归属状态。如果经过身份验证的用户证据承诺提供持久的配置文件，但配置文件解析失败，则调用者为 `unknown`，而不是根据标头、设备 ID、连接 ID 或凭据猜测。

Control UI `chat.send`，包括排队回复和ACP轮流，将原始准备好的附加事实带入执行准入。稍后的配置文件更改或重新连接不会重写已承认的上下文。仅当每个来源都提供同等的附加事实时，收集的回复才会保留归属；相互矛盾或缺失的证据仍然未知。这些事实不会授予发送者或工具权限，也不会创建通道准入强制收据。

每个现有上下文都会生成一份运行准入回执。其结果为 `not-applicable`，策略和授权引用为空，原因说明未证明进行过任何身份感知的策略或授权评估。这是对准入证据的解释，而不是执行声明。

在其确切的 context/execution/run 元组排队后，承认的通道运行还会投射 `channel/admission` 决策收据。仅当每个贡献入口决策都具有参与者意识且影响结果时，覆盖范围才是 `enforced`。 Wildcard/open 策略和仅显式归因适配器保留为 `attribution-only`；混合或缺失的证据是 `unknown`。身份和相应的决策共享现有的审计编写者 FIFO。

已承认的会话工具访问拒绝通过同一 FIFO 对私有 `session` 决策进行排队。访问权限所有者提供原因、政策输入和缺失的证据；审计编写器在持久化之前将目标会话引用替换为安装本地 HMAC。不保留原始会话密钥。改变结果的政策否认是 `enforced`，而无法提供 `session.owner` 证据的所有权查找仍然是 `unknown`。公众检查故意将通用事实呈现为未经验证的`decision.record`；它不会暴露他们的私人原因或目标展示。没有确切承认的执行及其有效接收权限的调用不会创建选择器或事实。

运行绑定会话工具还在最终等待和权限重新检查之后将其所有者返回的结果排队。创建、分叉、发送、修补、重置、存档、恢复和删除事实将已提交或计划的工作与类型化的生命周期冲突和明确的无操作区分开来。这些机械师是 `attribution-only`；公开的通用展示仍未得到验证，而不是将其私人理由或目标作为可信证据呈现。

直接会话共享方法不允许模型运行，因此它们不会综合运行选择器。共享事件会在存在经过验证的个人资料参与者时保留该参与者；据报道，预期但未解决的情况未知，而遗漏的主要证据则无法确定来源。这两种状态都不是从操作员范围、共享令牌、会话路由或房间元数据重建的。成员列表使用相同的区别：`addedBy` 仅包含真实的主体 ID，`addedByState: "unknown"` 报告明确的无主体证据，省略意味着未提供参与者证据。网关永远不会返回内部存储标记。仅 Beta 版的 `local-operator` 和 `operator.admin` 成员属性值将作为不存在的证据而被丢弃；他们不会迁移或作为委托人出现。

对于启用了消息审核的已许可运行，运行检查还会调整出站消息生命周期。它使用固定规则将惰性进度所有者与终端分类帐行合并，并将 `queued`、`platform-started`、`delivered`、`failed`、`unknown` 和故意 `suppressed` 报告为不同的收据。队列和传输结果为 `attribution-only`：它们记录了交货所有者观察到的内容，但不证明授权。现有消息行保留其键控目标引用和 `runId`；惰性同伴保留主机验证的 context/execution/run 绑定。检查需要精确的元组，并且永远不会将仅运行交付证据分配给执行。结合仍然是诊断来源。只有改变结果的确切目标验证、消息策略或转向能力拒绝才是 `enforced`。没有持久所有者记录的可移植操作和早期抑制使用同一审计编写者 FIFO 上的通用事实所有者。

Cron 生命周期收据为 `attribution-only` 并具有 `not-applicable` 决策结果。他们报告权威生命周期所有者保留的内容；他们不要求授权决定。光标是不透明的并且特定于源。现有的数字游标和 `a:`、`m:` 和 `g:` 游标仍然被接受； cron 使用 `c:`。格式正确的历史 `t:` 和 `f:` 游标返回 `decision cursor is no longer retained; restart inspection without --cursor`。他们从不使用其他来源的别名或默默地重新启动分页。

当同一个 `runId` 在 `operator_approvals` 中具有保留的终端行时，检查器还会读取其所有者本地 `operator_approval_execution_identities` 绑定。只有精确的上下文、执行和运行元组才会强制执行批准。收据列出了持久所有者和记录引用、确切的稳定原因代码、第一答案和终端策略引用、允许决策创建的任何授权、使用的确切上下文字段以及有界的下一步。它从不包含命令、参数、路径、环境、审阅者设备 ID、解析器 ID 或批准演示文本。

审批结果映射到稳定的回执原因：

| 记录审批结果       | 收货原因代码                                                                       |
| ------------------------------ | ----------------------------------------------------------------------------------------- |
| 允许一次/始终允许      | `operator_approval_allowed_once` / `operator_approval_allowed_always`                     |
| 审稿人否认                | `operator_approval_denied_by_reviewer`                                                    |
| 截止日期到期                | `operator_approval_expired`                                                               |
| 运行中止/网关重新启动    | `operator_approval_cancelled_run_aborted` / `operator_approval_cancelled_gateway_restart` |
| 无审批交付途径     | `operator_approval_denied_no_route`                                                       |
| 批准判决格式错误     | `operator_approval_denied_malformed_verdict`                                              |
| 存储状态阻止批准  | `operator_approval_denied_storage_corrupt`                                                |
| 无法读取或不一致的行 | `operator_approval_record_corrupt`                                                        |
| 缺少执行绑定      | `operator_approval_execution_link_missing`                                                |
| 执行绑定格式错误    | `operator_approval_execution_link_malformed`                                              |
| 执行绑定不匹配   | `operator_approval_execution_link_mismatch`                                               |

允许、拒绝、过期和取消的行是 `enforced`，因为记录的人为决策或拒绝错误的所有者策略更改了操作是否可以继续。无路径拒绝是 `enforced`，只是因为批准所有者在返回不采取行动之前将 `no-route` 记录为获胜终端原因。无法读取的行是 `unknown`，从未重建。如果保留的批准命名了一次运行，但缺少其预期的执行上下文，则运行检查将返回 `decision_context_link_missing` 且覆盖范围为 `unknown`，并且不会创建接收上下文。

由于 `runId` 是关联标识而不是执行身份，因此它绝不会替代所有者本地绑定。缺失、格式错误或不匹配的绑定行会投影为没有授权引用且带有明确绑定修复措施的 `unknown`，即使该运行只保留了一个执行上下文也是如此。检查器绝不会根据会话元数据、时间戳或保留的上下文数量推断绑定。

运行检查会返回成功的类型化诊断，而不是编造事实：

- `unknown`：所选运行或执行未知，或者预期上下文损坏或不可读；这也涵盖保留的决策缺少其预期上下文链接的情况；
- `unsupported`：尽力而为的活动记录显示该运行存在，但没有可用上下文，例如功能启用前、功能禁用或上下文写入失败的情况。刚刚超出保留期的上下文也会在有界清理待处理期间使用此状态，并附带明确的过期修复措施；
- `ambiguous`：某个 `runId` 有多个保留的执行；请先选择候选 `executionId`，再检查身份或决策；
- `unattributed`：受支持的运行没有可用的调用方主体；
- `attribution-only`：调用方归属存在，但尚未针对授权进行评估。

该方法需要 `operator.read`。请求已关闭并仅选择一个 `executionId` 或 `runId`。公共结果始终包含所需的 `decisionDisplays` 数组，并且从不包含私有原始收据数组或 `decisions` 密钥。网关构建是由明确的安全域白名单产生的；客户不对收据散文进行分类。决策页面最多包含100个显示；不明确的运行发现页面最多包含 50 个候选执行。两者都使用有界游标。批准和消息传递选择器是从与其预计收据相同的所有者查询行元数据中创建的，使用 `approval-decision:` 和 `message-decision:` 命名空间，并且从不派生自收据、解决方案或事件标识符。

同一 Gateway 操作员域中拥有 `operator.read` 的每个客户端都可能接收此保留的身份类别。这是有意为之：该范围已经涵盖日志和会话读取，收集功能是显式选择加入的，保留的引用受到限制并经过伪名化，可选的显示标签会进行机密信息删减。`operator.read` 不是用于恶意多租户隔离的边界；当操作员不得共享此诊断数据时，请使用独立的 Gateway 信任域。

## <a id="record-families"></a> 记录类别

在启用审计时（默认），会记录运行和工具事件。 消息生命周期事件为可选启用，默认处于关闭状态。

| 家族       | 操作                                                                            | 默认值 |
| ------------ | ---------------------------------------------------------------------------------- | ------- |
| Agent 运行   | `agent.run.started`, `agent.run.finished`                                          | on      |
| 工具操作 | `tool.action.started`, `tool.action.finished`                                      | on      |
| 消息     | `message.inbound.processed`, `message.outbound.{queued,platform-started,finished}` | 关闭     |

每条记录都带有稳定的事件 ID、单调所有者序列、生命周期时间戳、参与者、操作、状态、`schemaVersion: 1` 和 `redaction: "metadata_only"`。活动分类账包含终端出库行；运行检查从其同伴获取非终端出站进度。有关完整字段引用和查询过滤器，请参阅 [ 审核记录](/cli/audit)。

## <a id="message-lifecycle-events"></a> 消息生命周期事件

在**设置→高级→日志记录**中选择消息审核元数据，或设置[`logging.audit.messages`](/gateway/config-observability#audit)。更改适用于后续消息生命周期事件：

- `off`（默认）：不记录消息。
- `direct`：仅记录直接对话中的消息。
- `all`：记录直接对话、群组和频道消息。

两种权威边界会产生消息记录：

- **入站**行会在已接受的消息到达核心分发时写入， 包括重复和终态处理结果。
- **Outbound** 进度记录是在共享持久交付接受队列托管并开始平台交付时写入的。终端活动行记录已发送、已抑制、已失败或针对崩溃模糊发送的显式 `unknown`。包括队列恢复和死信结果。稳定的队列派生源 ID 可以防止重复生命周期行的恢复。每个原始逻辑回复有效负载在每个到达阶段获取一行；分块和适配器扇出聚合到终端 `resultCount`。

### <a id="conversation-kind-classification"></a> 对话类型分类

`direct` 模式是一个隐私边界，因此只有当目的事实能够证明时，消息才会被归类为直接对话：发送路径声明了目标对话类型，或者投递会话路由名称与正在投递的通道和对等方完全一致。较弱的信号，例如策略状态或起始对话，可以将消息归类为 `group`（从而将其排除在 `direct` 收集之外），但永远不能声明为 `direct`。无法证明为直接对话的消息会被归类为 `unknown`，并且不会在 `direct` 模式下记录。因此，不声明聊天类型的通道在 `direct` 模式下记录的行数可能少于在 `all` 模式下记录的行数。

## <a id="privacy-model"></a> 隐私模型

消息活动和进度记录从不存储原始平台标识符。当关联可用时，帐户、对话、消息和目标标识符仅导出为安装本地键控假名 （`hmac-sha256:v1:<keyId>:<digest>`）：

- HMAC 密钥在首次使用时生成，按标识符类型进行域分离，并与账本保存在同一个状态数据库中。
- 伪名在单次安装内保持稳定，因此关于同一会话的行可以关联，而不会泄露平台标识符。
- 这属于**关联，不是匿名化**：任何能够读取状态数据库的人也拥有该密钥，并且可以将候选原始标识符与伪名进行比对。RPC 和 CLI 导出绝不会包含该密钥。
- 如果在保留消息行时密钥材料丢失或损坏，则网关会丢弃新消息记录，而不是默默地轮换到新密钥，这会分裂相关性。

运行和工具记录保留`sessionKey`和`sessionId`以进行关联；会话密钥本身可以包含平台帐户或对等 ID。消息记录有意省略两者。

执行身份上下文使用相同的安装本地密钥所有者和单独的 HMAC 域。原始运行时、调用者、入口源、保证、授予和子委托引用仅存在于有界私人准入载体中。深度冻结队列有效负载的上限为 16 KiB，每个有界证据数组中有 16 个条目。结构化克隆会在队列边界剥离原型。队列耗尽在持久化之前用键控假名替换原始引用；它们永远不会被存储、导出、检查或记录。配置的代理 ID 以及上下文、执行和运行 ID 仍然对操作员可见。上下文从不包含提示或消息文本、命令正文、参数、路径、凭据、环境值或任意插件有效负载。每个编码上下文的上限也为 16 KiB。

即使不包含内容，审计导出仍属于敏感的操作元数据： 时间、频道、结果和稳定的伪名都可能关联活动。 请对导出内容采取与其他操作员记录相同的访问控制和保留措施。

## <a id="coverage-and-proof-limits"></a> 覆盖范围和证明限制

该账本采用尽力而为的方式，并且有意设置了边界。请将其视为已记录内容的证据，而不是对实际发生情况的证明：

- **没有某一行并不能证明任何事情。** 预接纳的入站丢弃、绕过共享持久化传递的插件本地或直接发送路径、被丢弃的接纳信封，以及因崩溃而丢失的排队工作，都可能不会留下记录。
- Writes 通过有界异步进程拥有的队列；队列饱和、存储故障或有限的关闭超时可能会删除记录并记录一个操作警告。
- Shutdown 在现有截止日期删除等待的元数据，但在释放写入器之前加入已提交的工作操作。未知的工作结果不会重播；普通本机锁争用会保留现有的 FIFO 重试。
- 无法确定是否成功的崩溃期间出站发送会被记录为 `unknown`，而不是臆造结果。

该账本用于调试和运维审查。它不是无损的合规归档；如果你需要这样的归档，请使用由 [OpenTelemetry](/gateway/opentelemetry) 或通道级工具提供数据的外部系统。

## <a id="storage%2C-retention%2C-and-migration"></a><a id="storage-retention-and-migration"></a> 存储、保留与迁移

记录存在于共享状态数据库 （`state/openclaw.sqlite`） 中。现有的共享状态工作线程在网关线程之外执行审核写入和维护，包括 schema/key 首次使用和写入触发的修剪。查询永远不会返回超过 30 天的记录，并且分类帐的上限为 100,000 行；过期的行会在启动、每小时维护和以后的写入过程中被修剪。每个分类帐或进度清理事务最多删除 1,024 个过期行，并安排更多工作直到解决。即使禁用收集，保留维护也会继续运行。

出站 `queued` 和 `platform-started` 记录位于狭义拥有的 `outbound_message_progress` 表中。如果需要，该表会在第一次启用的进度写入时创建，在启动、只读检查、禁用收集和仅终端传递后保持不存在，并且不会推进状态模式版本。只读检查下缺失意味着没有保留进度。它的上限为 200,000 行，保留期同样为 30 天。终端 `message.outbound.finished` 行保留在 `audit_events` 中，因此兼容的旧版网关可以打开并使用数据库，同时忽略附加表。精确的终端连接位于惰性 `outbound_message_execution_bindings` 伴侣中，而不是改变已发布的 `audit_events` 形状。它仅为主机验证的精确绑定而创建；仅运行终端写入使其不存在。兼容的旧网关也会忽略此附加表。

从具有早期 run/tool-only 账本的网关升级会在启动时自动迁移模式（或通过 `openclaw doctor --fix`）；现有的行及其分类帐序列将被保留。

执行身份上下文也存在于共享状态数据库中。存储的行由唯一的执行和上下文 ID 来作为键控； `runId` 是非唯一的索引相关性。它们的附加表是在第一次使用时延迟创建的，没有模式版本冲突。在操作员启用收集之前，全新安装和升级安装不会填充身份上下文。首次使用模式创建、HMAC-key 访问、规范上下文构建和 SQLite 持久性发生在流程拥有的审计队列排出中，而不是在代理准入中。审核写入使用共享工作线程的 SQLite 繁忙超时。竞争的编写器可以延迟该工作程序直到超时，而网关线程保持非阻塞状态。失败的锁定尝试保留 FIFO 重试，并具有有限的异步退避。上下文保留 30 天，上限为 100,000 行。在上下文超过 30 天后，精确执行检查和运行发现永远不会返回上下文、候选者或准入决策，即使尚未运行物理清理也是如此。过期的行会在网关启动、每小时审计维护和稍后的上下文写入期间被修剪，每个写入或维护周期最多删除 1,024 个身份上​​下文行。禁用收集后，维护将继续。较旧的版本会忽略此表。

过期后，检查可以立即将运行报告为 `unsupported`，而过期的行仍然只能证明其身份上下文变得不可用；不会返回过期字段或决策。在有界清理之后，如果没有单独保留的尽力而为活动，则相同的查找可能会变成 `unknown`。这种转变并不能证明这次挤兑没有发生。这些限制使检查器成为操作诊断界面，而不是合规存档。

终端批准会在其所有者本地 `operator_approvals` 表中保留 30 天。即使物理修剪尚未运行，检查也会应用该截止值。附加 `execution_decision_facts` 表是为没有所有者本机持久记录的操作边界保留的，包括可移植消息操作、策略拒绝和早期有意抑制。它是在第一次通用事实写入时延迟创建的，保留事实 30 天，表的上限为 250,000 行，每次写入或维护周期最多修剪 1,024 行。批准路径从不写入此表。其事实和批准行对其记录的决策具有权威性。传递到通用表使用有界审计队列，并保持尽力而为直到持久化；批准所有者写入不依赖于该队列。活动分类帐在丢失后无法重新创建任一来源。

每次通用决策事实写入都会重新读取不可变的执行上下文，并要求完整的上下文、执行和运行元组。投影会再次验证同一个元组；不匹配时状态为 `unknown`，不会仅根据上下文或运行关联重新分配。

## <a id="querying"></a> 查询

网关在共享状态数据库工作线程上运行 `audit.list` 和 `audit.activity.list` 查询，因此 SQLite 工作不会阻止请求处理。每次读取开始时都会捕获过滤器和保留截止值；序列游标、结果限制和现有的 `operator.read` 权限保持不变。

`audit.run.inspect` 使用现有的只读工作线程进行身份发现和收据查询。缺失的数据库和可选的审计表仍然不存在；检查不会迁移状态或加入审计写入队列。每个请求在屈服之前都会捕获其选择器、游标、限制和保留时钟。

- CLI：[`openclaw audit`](/cli/audit)，支持按代理、会话、运行、类型、状态、方向、频道、时间范围和游标分页进行筛选。
- Gateway RPC：`audit.activity.list`（需要`operator.read`）返回版本化的V1活动事件联合；对于旧版 run/tool 客户端，已发货的 `audit.list` RPC 没有变化。请参见[网关协议](/gateway/protocol/ledgers#audit-ledger-rpc)。
- Identity RPC：`audit.run.inspect`（需要 `operator.read`）接受一个 `executionId` 进行精确检查，或接受一个 `runId` 进行有界发现。它返回不可变的 V1 上下文以及用于准入、批准、所有者本机出站消息的分页安全显示以及用于精确匹配的通用决策记录，或者当运行有多个执行时带有空显示数组的键入的不明确候选页面。原始所有者收据对于聚合和存储所有者来说仍然是私有的。

## <a id="maintainer-invariants"></a> 维护者不变量

对身份生成者、存储和检查的更改必须保留这些边界以及上述操作员行为：

- 仅存储记录的字节相同的重播被视为重复。重试、回退和恢复会重用原始准入身份。
- 上级审批行是唯一授权所有者。它的可选身份同伴仅在显式收集选择加入下为精确的主机验证源运行绑定保留身份；禁用和未绑定的路径使该表不存在。当出处丢失、删除或损坏时，它不得改变批准决定。不要添加急切创建、后期绑定、双重写入、后备读取器、sidecars 或架构版本解决方法。更改需要老年读者 open/use 和候选人重新开放证明。
- Invoker 证据是三态的：标记的本金承担输入是 `present`，标记的无本金输入是 `unknown`，仅遗漏是 `absent`。在投影或场丢弃之前验证封闭的原始变体；拒绝格式错误、混合、未标记或额外字段的输入，而不是将其标准化。
- 通用决策事实需要明确的产品边界生产者和运营商保留选择加入。 30 天绑定不授权默认收集。制作者使用admission的共享`AuditEventWriter` FIFO；切勿直接写入通用存储、创建另一个 writer/key 或在本地进行假名。作者独自 HMAC- 在持久化之前投射原始参考。
- `enforced` 收据覆盖范围是诊断性的，而不是权威性的：仅当所有者更改结果并且确切的 context/execution/run 元组验证时才发出它。等待工作完成后，立即在接收器之前同步重新验证确切的实时所有者，无需干预等待。过时、发布、替换或抛出权限不会发出任何收据，而不是 `unknown`。相同运行的包装器组成所有者谓词；不同的承认运行开始新的谓词根。 `unknown` 的决定证据仍然不足。
- Display 信任来自所有者持有的调用路径来源，而不是收据控制的 `source.owner` 或散文。将每个选定的所有者行或事件与其所需的来自同一 query/page 结果的不透明选择器配对。切勿从私人收据、解决方案或事件标识符中派生或重新查询选择器，或丢弃损坏的、过大的或未链接的结果。
- Admission 在模式检查或普通属性读取之前验证从描述符构造的递归拥有、可枚举、无访问器的数据快照。不存在继承属性；访问器永远不会运行。准入只能验证、绑定、冻结和入队：无同步 SQLite、模式、文件系统、HMAC-key 或准备工作。审核失败绝不会延迟或中止执行。
- 公共插件SDK入口剥离私有recovery/admission权限，包括JavaScript额外和继承的属性。
- Host 铸造的参与者证据根据最终确定的上下文和确切的插件 record/lifecycle 纪元进行一次兑换。混合参与者只能删除发送者衍生的权限；切勿扩大或消除独立工具、拨款、路由或批准权限。
- 在更改读取器范围、默认关闭集合、保留字段、30 天截止、maintenance/row 边界或 schema/protocol 合约之前询问。
