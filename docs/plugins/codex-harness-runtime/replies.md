## <a id="visible-replies-and-heartbeats"></a> 可见回复与心跳

Direct/source 聊天通过 Codex harness默认转为内部 WebChat 表面的自动最终助理交付，匹配 Pi harness合同：代理正常回复，OpenClaw 将最终文本发布到源对话。设置 `messages.visibleReplies: "message_tool"` 以将最终助理文本保密，除非客服人员呼叫 `message(action="send")`。

评论遵循对话的进度设置，可能是隐藏的或临时的。当工作继续时出现问题时，代理将被指示发送带有 `message(action="send", final=false)` 的答案并继续任务。最终答复涵盖尚未交付的答案和结果。这不会启用评论或更改流媒体设置。

显式标记为异步传递的本机 Codex 消息使用独立的传递意图。它们与可选进度和最终最终答案分开提供，包括禁用块流时。

默认情况下，Codex 心跳会在可搜索的 OpenClaw 工具目录中获取 `heartbeat_respond`，以便代理可以记录唤醒是否应该保持安静或通知。心跳轮次使用与普通聊天轮次相同的 Codex 默认协作模式。心跳监视器的 cron 暂存会附加到计划的心跳用户消息（如果存在）。

## <a id="attachments-in-a-remote-workspace"></a> 远程工作区中的附件

使用 `appServer.remoteWorkspaceRoot`，最终和异步回复可以使用 `MEDIA:./report.pdf` 或远程工作空间内的绝对路径。在释放应用程序-服务器连接之前，Codex 插件会读取带有有限 `command/exec` 请求的附件。主机的 [ 回复媒体功能 ](/plugins/sdk-agent-harness/attempt-runtime#reply-attachments-from-a-remote-workspace) 应用读取策略并暂存字节以进行传送。原始答复保留在笔录中；网关工作区副本不用作后备。远程工作区之外的文件会产生标记的附件失败。在发送之前将它们复制到工作区中。 HTTP 引用和托管 `media://` 附件继续有效。

## <a id="final-answers-after-settled-tool-work"></a> 解决工具工作后的最终答案

对于普通主机验证的 Codex 轮次（在没有可见答案的情况下完成工具工作），OpenClaw 可以在私人临时住宅中请求有限的最终答案轮次。它使用已完成线程的模型选择和原始主机身份验证路由或解析的配置文件，而不是从外部请求元数据中选择模型。现有环境、动态工具、MCP 和本机挂钩限制仍然存在。已完成的操作是记录证据，而不是重播指令。保留本机模型本身并不会禁用主机验证的终结。

当隐藏的后台任务完成消息属于模型上下文的一部分时，它们仍然符合此恢复的条件。主持人在允许的提示上记录他们的本地回合身份，同时将他们隐藏在聊天中。本地转录镜像重复使用该提示作为证据；它无法重新创建已消失的已承认提示。从模型上下文中明确排除的消息保留在本机提示注释之外。

恢复保留当前完整回合的现有限制，然后保留最近的整个早期交换。可以省略较旧的交换，包括太大的整个交换。在空间允许的情况下，发出通知来标识缺失的历史记录；终结器总是被指示说明缺失事实的不确定性。当前超过限制、无效工具对或不受支持的内容的证据仍然导致恢复不可用。现有的对话历史记录保持不变，并且已完成的操作永远不会重复。

通过 Codex 会话创建的聊天是不同的：其私有监督连接拥有本机身份验证。 Stock Codex 不会公开保留该连接帐户的通用免工具摘要操作。 OpenClaw 将此终结上下文标记为不可用，而不是选择主机凭据、复制本机凭据或启动另一个本机回合。如果需要最终答复，主机将提供其现有的后备：

> 工具运行已完成，但未生成最终摘要。我没有重复任何已完成的动作。

原始完成的结果、本机绑定和工具收据保持不变。如果本机转向失败并且最终化无法产生答案，则答复会解释失败和下一步。例如，模型容量错误建议等待并重试或选择其他模型。聊天和任务进度中回合仍然失败；已完成的动作不再重复。明确的停止仍然是取消的转弯。返回最终答案的本地轮次会正常传递。普通的 `homeScope: "user"` 选择保留其记录的私有主机身份验证最终确定；参见[Auth和环境隔离](/plugins/codex-harness-reference#auth-and-environment-isolation)。
