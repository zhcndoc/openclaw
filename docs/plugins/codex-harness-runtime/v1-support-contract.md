Codex 运行时 v1 支持和不支持的表面。 [Codex harness运行时 ](/plugins/codex-harness-runtime) 指南的一部分； [ 每个部分移动的位置](/plugins/codex-harness-runtime#where-each-section-moved) 列出每个部分。

## <a id="v1-support-contract"></a> V1 支持契约

Codex runtime v1 中支持：

| 表面                                       | 支持                                                                          | 原因                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenAI 模型环通 Codex               | 支持                                                                        | Codex 应用程序服务器拥有 OpenAI 回合、本机线程恢复和本机工具延续。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| OpenClaw 通道路由和交付         | 支持                                                                        | Telegram、Discord、Slack、WhatsApp、iMessage 以及其他通道都位于模型运行时之外。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| OpenClaw 动态工具                        | 支持                                                                        | Codex 请求 OpenClaw 执行这些工具，因此 OpenClaw 仍处于执行路径中。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 提示和上下文插件                    | 支持                                                                        | OpenClaw 将 OpenClaw- 特定的 prompt/context 投影到 Codex 转弯中，同时通常将 Codex- 拥有的基础、模型和配置的项目文档提示留在本机 Codex 通道中。对于没有本机文件系统环境的普通策略限制轮次，OpenClaw 携带有界工作区 `AGENTS.md` 快照作为线程级开发人员指令。零环和其他上下文限制的内部模式抑制这两条路径。 OpenClaw 禁用 Codex 本机线程的内置个性，以便代理工作区个性文件保持权威。本机 Codex 开发人员指令仅接受明确范围为 `codex_app_server` 的命令指导；对于非 Codex 提示界面，仍保留旧版全局命令提示。 |
| 上下文引擎生命周期                      | 支持                                                                        | Assemble、ingest 和回合后维护会围绕 Codex 轮次运行。上下文引擎不会替代原生 Codex 压缩。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 动态工具挂钩                            | 支持                                                                        | `before_tool_call`、`after_tool_call` 和工具结果中间件围绕 OpenClaw- 拥有的动态工具运行。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 生命周期挂钩                               | 支持作为适配器观察                                                | `llm_input`、`llm_output`、`agent_end`、`before_compaction` 和 `after_compaction` 使用诚实的 Codex- 模式有效负载进行触发。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 最终答案修订门                    | 通过原生钩子中继受到支持                                              | Codex 的 `Stop` 会中继到 `before_agent_finalize`；`revise` 会在最终确定之前请求 Codex 再进行一次模型处理。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 本机 shell、补丁和 MCP 阻止或观察 | 通过原生钩子中继受到支持                                              | Codex `PreToolUse` 和 `PostToolUse` 被中继用于承诺的本机工具表面，包括固定的 Codex 应用服务器上的 MCP 有效负载。支持阻塞；参数重写不是。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 原生权限策略                      | 通过 Codex 应用程序服务器批准和兼容性本机钩子中继提供支持 | Codex 应用程序服务器审批请求在 Codex 审核后通过 OpenClaw 路由。 `PermissionRequest` 本机挂钩中继选择加入本机批准模式，因为 Codex 在监护人审核之前发出它。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| App-server 轨迹捕获                 | 支持                                                                        | OpenClaw 会记录发送到 app-server 的请求以及收到的 app-server 通知。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

Codex runtime v1 中不支持：

| 表面                                             | V1边界                                                                                                                                   | 未来之路                                                                               |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 原生工具参数突变                       | Codex 本机预工具挂钩可以阻止，但 OpenClaw 不会重写 Codex-native 工具参数。                                             | 需要 Codex hook/schema 支持替换刀具输入。                            |
| 可编辑 Codex-native 成绩单历史记录            | Codex 拥有本机线程历史记录。 OpenClaw 拥有一个镜像，可以预测未来的上下文，但不应改变不受支持的内部结构。         | 如果需要本机线程手术，请添加显式 Codex 应用程序服务器 API。                    |
| `tool_result_persist` 用于 Codex-native 工具记录 | 该钩子转换 OpenClaw-owned 记录写入，而不是 Codex-native 工具记录。                                                         | 可以镜像转换后的记录，但重写本机记录需要 Codex 支持。   |
| 丰富的原生压缩元数据                     | OpenClaw 可以请求本机压缩，但不会收到稳定的 kept/dropped 列表、令牌增量、完成摘要或摘要有效负载。 | 需要更丰富的Codex压实事件。                                                     |
| 压实干预                             | OpenClaw 不允许插件或上下文引擎否决、重写或替换本机 Codex 压缩。                                           | 如果插件需要否决或重写本机压缩，请添加 Codex pre/post 压缩挂钩。 |
| 按字节精确的模型 API 请求捕获             | OpenClaw 可以捕获 app-server 请求和通知，但 Codex 核心会在内部构建最终的 OpenAI API 请求。                    | 需要一个 Codex 模型请求跟踪事件或调试 API。                                   |
