## <a id="compaction-and-transcript-mirror"></a> 压缩和转录镜像

当所选模型使用 Codex harness时，Codex 应用程序服务器拥有本机令牌压力和手动线程压缩。 OpenClaw 单独拥有其转录镜像。有效的超快将本机自动压缩限制为总上下文令牌 260,000 个，保留较低配置的 `model_auto_compact_token_limit` 值。 OpenClaw 在回合前通过本机线程配置应用此限制；更改回快速或标准会在下一回合恢复配置的本机限制。其他层保留其本机压缩设置。

隐身线程没有持久的恢复源，因此其创建时压缩设置无法就地更改。如果速度更改需要不同的限制，OpenClaw 会保留对话并要求您恢复之前的速度或开始新的隐身对话。如果设置不匹配，则不会发送轮次。

当 `agents.defaults.compaction.maxActiveTranscriptBytes` 设置为正值时，OpenClaw 在普通和心跳轮流之前检查该镜像。当字节保护触发时，OpenClaw 在允许轮流之前尝试通过其选定的主机上下文引擎进行语义压缩。此主机压缩本身不会替换或重写 Codex 的本机线程。

如果上下文引擎拒绝主机压缩或使历史记录过大，则 OpenClaw 继续对最近的整个回合进行有界投影。本机线程遵循该投影，因此省略的历史记录不能保留在其上下文中。明显的通知要求您重新发送任何重要的早期详细信息；保存的历史记录不变。失败原因以警告级别记录。失败的尝试不算作成功的压缩，并且抑制的重试仍然接收有界上下文。系统指令和当前请求保持不变。

主机镜像压缩提交后，OpenClaw 可以请求 `thread/compact/start` 同步符合条件的本机线程。此请求是次要的：OpenClaw 不会将其发送给主机隔离操作或具有受限本机权限的绑定，并且不可用或失败的本机同步不会回滚已提交的主机压缩。

显式压缩请求，例如 `/compact` 或插件请求的手动压缩操作，使用 `thread/compact/start` 启动本机 Codex 压缩。 OpenClaw 保持请求和共享客户端租约打开，直到 Codex 发出匹配的 `contextCompaction` 完成项，然后报告压缩轮次已完成。如果该终端轮次超过配置的压缩超时，OpenClaw 请求本机轮次中断。租约和每线程压缩栅栏保持保留，直到 Codex 报告终端状态或确认中断 RPC。如果 Codex 在中断宽限期内未确认，则 OpenClaw 在释放栅栏之前退出连接。远程连接还会分离匹配的线程绑定，因此以后的工作不能与未经确认的远程连接重叠。已停用连接的其他启动失败，可以在新客户端上重试。客户端关闭、请求取消或失败的压缩轮返回失败的操作。自动本机令牌压力压缩仍然是 Codex 的工作。在上述辅助同步之外，OpenClaw 仅针对显式手动请求启动本机压缩。

独立的冷压缩操作不会运行提示构建挂钩或建立普通转弯配置。操作完成后释放其订阅；下一个普通回合将验证配置并通过正常恢复路径刷新通用策略。热压缩仅返回其实际获取的配置所有权。

如果上下文引擎压缩轮换 OpenClaw 会话生成，则下一个 Codex 轮换、压缩或附带问题将继续相同的本机线程，即使网关在提交新一代后立即停止也是如此。只能采用该会话密钥下记录的前任。在恢复的线程执行之前，本机工具目录、连接所有权和监督检查仍然适用。

成功的本地倒带或分支切换是上下文更改。作为转录突变的一部分，它使旧的本机绑定失效，并在返​​回之前释放其订阅。下一个 Codex 回合将使用选定的 OpenClaw 历史记录启动一个新的本机线程；擦除的轮次无法通过本机简历返回。无效的剪切和回滚的转录突变保留了结合。

当 OpenClaw 将现有会话的连续性投影到新的 Codex 线程中时，它包括保存的压缩和分支摘要，即使没有保留早期的用户消息也是如此。上下文引擎投影也保留这些摘要条目。摘要仍作为先前上下文引用，与当前请求分开，并仍受投影大小限制的约束；过大的摘要或较旧的上下文可能会被截断。此切换不会更改本机 Codex 压缩所有权。

当上下文引擎请求 Codex 线程引导投影时，OpenClaw 将工具调用名称和 ID、输入形状和工具结果内容投影到新的 Codex 线程中，而无需秘密屏蔽。它不会将原始工具调用参数值复制到该投影中。

镜像包括用户提示、最终助理文本以及应用服务器发出时的轻量级 Codex 推理记录。推理保留键入的 `thinking` 内容，而不是普通的最终答案文本，因此 OpenClaw 的现有推理可见性和历史记录控件适用。 OpenClaw 记录本机压缩开始和终止状态，但它不会公开人类可读的压缩摘要或压缩后 Codex 保留的条目的可审核列表。

同一压缩项的重复完成通知计数一次，并且不重复完成挂钩或活动计划恢复。

由于 Codex 拥有本机线程，因此 `tool_result_persist` 不会重写 Codex-native 工具结果记录。它仅在 OpenClaw 写入 OpenClaw- 拥有的会话转录工具结果时适用。
