选择加入沙盒本机执行的流式传输，以及节点支持的远程执行与其有何不同。 [Codex harness运行时 ](/plugins/codex-harness-runtime) 指南的一部分； [ 每个部分移动的位置](/plugins/codex-harness-runtime#where-each-section-moved) 列出每个部分。

## <a id="experimental-sandbox-process-streaming"></a> 实验性沙盒进程流式传输

原生沙盒执行仍需通过 `appServer.experimental.sandboxExecServer` 选择性启用。启用后，对于处于活动状态的 OpenClaw 沙盒，沙盒进程会按顺序流式传输 stdout、stderr 或 PTY 输出通知。OpenClaw 仅保留有限的近期输出缓冲区，用于轮询和重放，因此长时间运行的进程不会无限制地增大应用服务器桥接的负载。进程退出和清理仍与沙盒所拥有的进程绑定。环境注册失败时，绝不会回退到主机执行。

交互式命令接收真实终端。 Ctrl-C 会中断交互式和非交互式本机命令。关闭 exec-server 连接会取消其未完成的 HTTP 请求，并在释放沙箱租约之前等待清理。

有关配置和仅限本地的传输限制，请参阅[沙盒化原生执行](/plugins/codex-harness-reference#sandboxed-native-execution)。

Node-支持的`remote-exec`，无论是在配对设备上还是在用于OpenClaw工作轮流的相同Crabbox云配置文件上，都与实验性本地沙箱标志分开。 Codex 应用程序服务器和模型身份验证保留在网关上，而注册节点上明确授权的托管执行服务器拥有进程、文件系统、功能和无凭据的 HTTP 操作。网关在身份验证、cookie、API-key 和其他敏感 HTTP 标头到达节点之前拒绝它们；经过身份验证的 HTTP 必须在网关上运行。现有双工节点通道承载 Codex JSON-RPC 流，而不启动 OpenClaw 工作子进程或消耗工作时隙。仍然需要显式网关命令白名单。启动需要每次尝试允许一次批准或确切承认的会话通过节点本地 full/off 策略进行完全访问。完全访问权限永远不会覆盖本地拒绝、询问或白名单限制、配对、托管同意、命令授权或工具策略。节点在生成固定二进制文件之前立即重新检查本地策略；过时的启动会被拒绝。每次尝试都拥有一个隔离的网关应用程序服务器客户端，因此其远程环境注册会随着该尝试而退出。 Disconnect 结束主动尝试及其远程进程；重新连接只允许重新尝试。正常的 Codex 可以正常工作，但 `/btw` 附带问题会被阻止，因为它们不受位置限制。放置工作空间不限制执行：进程和文件系统访问仅受节点操作系统帐户的限制。

分配给活动远程放置的轮次使用该执行所有者，包括可写沙箱检查。网关仍然根据其主机文件系统策略准备源文件并提示附件；远程执行根仍归该放置所有。本地沙箱分配保留用于没有远程放置的回合。
