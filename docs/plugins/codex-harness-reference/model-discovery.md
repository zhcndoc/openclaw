## <a id="model-discovery"></a> 模型发现

默认情况下，Codex 插件会向应用服务器询问可用模型。模型可用性由 Codex 应用程序服务器拥有，因此当 OpenClaw 升级捆绑的 `@openai/codex` 版本时、当 OpenClaw 选择 [ 较新安装的 Codex](/plugins/codex-harness-reference/app-server-transport#newer-installed-codex) 时、或者当部署将 `appServer.command` 指向不同的位置时，该列表可能会更改Codex 二进制。 ChatGPT-login 模型发现将所选二进制文件的版本报告为其 `client_version`，因此该列表与运行的二进制文件相匹配。可用性也可以是帐户范围内的。在正在运行的网关上使用 `/codex models` 查看该harness和帐户的实时目录。

自动发现和托管搜索模型选择使用可见的选择器条目。具有显式模型选择的有界转弯，包括图像理解、结构化提取、隔离完成和固定转弯终结，还会查找 `model/list` 返回的隐藏条目。该模型仍必须列出并支持所需的输入模式。列表并不证明帐户权利。

原生发现是需求驱动的。网关启动会发布配置的模型提示，而无需为每个代理启动应用程序服务器。打开代理的模型选取器或目录、创建 Codex 会话、运行轮次或请求本机 auth/status 信息会在需要时启动该代理的客户端。在发现之前，本机帐户准备情况未知；配置的提示不是登录证明。首次使用空闲代理可能需要几秒钟的时间来进行冷启动。

Discovery 从同一范围的应用程序服务器客户端读取 `model/list` 和 `account/read`。 API-key账户仍保持API-key认证；模型列表并不暗示 ChatGPT 传输或端点。仅当本地所有者及其 account/config 观察保持最新时，拾取器准备就绪才有效。帐户丢失、刷新失败、account/config 突变或停用的客户端会使本机模型不可用，直到发现再次成功。下一个 picker/catalog 请求或本机执行重新获取已停用的观测值。

没有自有工作的客户端将在 30 秒空闲后退出。该宽限期内的请求会重用它。活动请求、轮流、保留或释放线程、本机子线程、后台终端和临时历史记录保留其客户端，直到其所有者释放它。现有的热会话执行器和线程保留策略仍然有效。客户和账户通过代理主页保持隔离。

使用模型页面 **Refresh** 操作（`models.list` 以及 `view: "all"` 和 `refresh: true`）发布所选代理的完整目录。仅准备读取不会启动发现。 OpenClaw 之外的本机配置更改需要本机所有者支持的 reload/restart 和目录刷新； OpenClaw 不会轮询本机主文件的准备情况。创作的主机路由和显式配置文件选择保留其现有的身份验证和兼容性检查。

对于 Codex 运行时，仅当经过身份验证的帐户发现为所选模型、帐户、路由和运行时通告该服务层时，编写器才会显示 **Ultrafast**。 OpenAI 提供商现有的账户范围发现提供了这一观察结果；静态目录提示和本机应用程序服务器的后备列表不会建立访问权限。选择托管个人帐户会通过相同的提供商发现路径准备该帐户的目录，而无需更改共享身份验证顺序。仅准备读取不会启动发现。帐户更改、失败的发现和退役的世代无法重用其他帐户的层支持。

没有托管发现凭据的纯本机帐户、无法使用模型发现的令牌共享身份验证以及没有显式服务层元数据的目录使此功能未知。在这些情况下，作曲家会隐藏 Ultrafast，而不是提供禁用选项。发现支持描述可用性，而不保证上游请求将收到该层。

嵌入式 OpenClaw 运行时使用可用的 API-key OpenAI 响应路由来提供超快，无需目录元数据，无论密钥来自身份验证配置文件、环境还是提供程序配置（包括 SecretRefs）。这仍然取决于所选凭证和路线的观察到的提供商降级；请参见 [ 快速模式 ](/providers/openai/advanced#fast-mode)。使用 API-key 身份验证的 Codex-runtime Ultrafast 仍需要本机目录（包括固定的 `model_catalog_json`）来列出该模型的层。

本机目录标识符是运行时标识符，而不是隐私标签。使用代理拥有的别名的部署必须在启动应用程序服务器之前提供别名安全的本机目录：`model/list` 中的 `id` 和 `model` 都必须是别名，并具有所需的 `displayName`。不同的本机运行时标识符保留在 OpenClaw 模型参数中。重命名选取器标签不会隐藏请求或会话状态中的这些标识符。

Codex的启动`model_catalog_json`设置可以提供本机目录；每线程覆盖不会重新加载它。保留完整的模型功能、指令、压缩和审阅者元数据。目录成员资格不会拒绝任意模型覆盖，因此代理必须对每个请求强制执行允许的选择器。当不应导入本机历史记录时，使用 `sessionCatalog.enabled: false` 禁用本机会话发现。

自定义端点不会自动成为受支持的 Codex 路由。显式 `agentRuntime.id: "codex"` 不会绕过准备好的路线兼容性或模型支持的批准审查的可信端点要求。工作负载 API 密钥也不提供 ChatGPT 帐户身份或订阅刷新。在使用具有本机工具的代理之前验证这些合同；不要替换自定义提供程序、删除安全元数据或削弱审查以通过推理冒烟测试。

如果发现暂时不可用或超时，订阅路由将使用从捆绑的 OpenAI 模型清单中派生的离线提示，以及 `gpt-5.5` 和 `gpt-5.5-pro` 推理工作的 Codex 插件回退：

| 模型 id      | 显示名称 | 推理努力             |
| ------------- | ------------ | ----------------------------- |
| `gpt-5.6-sol` | GPT-5.6 索尔  | 低、中、高、xhigh、最大 |
| `gpt-5.5`     | GPT-5.5      | 低、中、高、x高      |
| `gpt-5.5-pro` | gpt-5.5-pro  | 中、高、x高           |

离线提示永远不能证明账户拥有相应权限。即使经过身份验证的发现响应中没有可见模型，它仍然具有权威性；HTTP `401` 和 `403` 会返回空目录，而不会暴露备用模型。

OpenClaw 推理控件保留支持的本机级别，包括 `ultra`。 Codex 拥有 Ultra 的主动委托和特定于模型的推理工作；平台 API 工作量元数据不会降级所选运行时模式。隐藏模型也可以出现在内部或专用流程的应用程序服务器目录中，而不是正常的模型选择器选择。
</Note>

通过 `plugins.entries.codex.config.discovery` 调整发现行为：

默认预算为 10 秒。它允许 Codex 的五秒远程目录刷新完成或返回其本机 cached/bundled 目录，并留有传输和帐户读取的时间。设置较短的预算可以取消本机后备，并使本机模型不可用，直到发现成功。

```json5
{
  plugins: {
    entries: {
      codex: {
        enabled: true,
        config: {
          discovery: {
            enabled: true,
            timeoutMs: 10000,
          },
        },
      },
    },
  },
}
```

禁用发现以避免本机 model/account 目录检查（即使是按需）：

```json5
{
  plugins: {
    entries: {
      codex: {
        enabled: true,
        config: {
          discovery: {
            enabled: false,
          },
        },
      },
    },
  },
}
```
