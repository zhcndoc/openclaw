# <a id="writer-admission-authority"></a> 作家录取权限

该程序将捆绑的作者许可移交给一名专门的工作人员，同时保留当前权限、FIFO 订购、最终主机 COMMIT 授权和收据结算。不建议架构、持久性、配置或更新迁移。重新启动通过现有所有者重建进程本地权限。

瓶颈在于主机调度，而不是布尔检查的成本。被跟踪的 `chat.send` ACK 花费了 765 毫秒中的 673 毫秒等待准入；上述更改在 20 个发送器的情况下测量 ACK p50/p99 为 1,209/1,693 毫秒（[ 先前测量 ](https://github.com/openclaw/openclaw/pull/170376)）。可行性探测在 0.064 毫秒内从共享状态得到答复，但在策略撤销后错误地授予。转发实时回调会等待 200 毫秒的主机停顿。这些诊断性观察证明了转让权力所有权合同的合理性；他们不预测生产延迟。

第一个切片传输配置文件 revision/status 通过共享单元进行检查，并在 `src/infra/sqlite-writer-admission-service.test-support.ts` 中添加只读准入服务测试工厂。绑定和当前稳定的操作使用与主机断言相同的规范状态。工厂通过真人工人测试进行锻炼；生产调度保留在主机上，直到剩余的依赖项可以转移。测量的中间主机到服务准备绕道增加了延迟，因此被删除。原生发行商在物理 COMMIT 之前立即围栏；已知的回滚保留先前的修订，而不确定的本机结果则保持隔离。退休的一代永远不会因为延迟的描述符传递而复活。即使数据库准入本身在路径到文件身份提升过程中仍然有效，首次创建也会取消未解析的配置文件权限。生命周期在更改身份之前通过其现有的共享完整性修订版发布该升级，包括仅工作人员创建和别名协调。现有的工作任务所有者处理服务失败、终止和重新启动。

该切片不传输策略负载或本机写入授权。描述符直接保留其确切的共享缓冲区，因此任何服务注册映射都无法回收或替换一代。混合physical/request/run权限，最终主机COMMIT和结算仍保持现有路径。描述符还保留现有的共享准入-撤销单元，因此仅工作线程关闭会在异步引流之前拒绝读取。服务读取并不证明主机仍检查剩余的物理保管。后来的所有者必须提供这些合约和本机到服务的传输，然后交易准入才能绕过主机。

代理切片使槽和请求托管规范的共享状态。在替换当前工作或通知观察者之前，调度、排队取消、完成、失败和本机退休会发布到相同的保留单元。接受的取消保留发送历史记录和收货结算。本地阶段在请求宿主准入之前和消耗其授权之后检查这些确切的单元格；迟到的描述符无法通过重用的数字请求 ID 重新获得权限。

服务测试助手还公开了带有有限等待的直接本机端口托管检查。到期会自动关闭待处理的决策，因此延迟的服务回复无法授予该决策。服务关闭会在等待清理之前撤销其纪元；更换使用新鲜电池。这种传输仍然是工人测试执行的先决条件：混合生产准入仍然使用主机，并且在剩余所有者可以转移之前不会添加第二次服务往返。它仅授予经纪人托管权，不授予保单授权、本机 COMMIT 或收据结算。

执行切片为每个逻辑所有者、本地生成和借用者提供了自己的共享生命周期。逻辑关闭在清理之前发布 `closing`，并且可以在清理失败后重新打开；撤销和本地退休仍然是永久性的。借款人释放结束新的呼叫和索赔，而已接受的操作通过结算保留 logical/native 托管权。热操作将这些确切的细胞及其公认的物理身份带到本地阶段和服务。冷创建、准备、删除和策略仍然需要其主机所有者；服务运输不受混合生产准入的约束。

## <a id="shared-publication-and-retention"></a> 共享发布和保留

每个所有者导出一个不可变的描述符，其中包含其种类、进程纪元、确切的 identity/generation 和保留的依赖项引用。每个可变主题都有所有者编写的原子单元：修订、状态（`ready`、`pending`、`uncertain`、`revoked`）和现有的 lifetime/reference 状态。可变大小的策略事实作为不可变的修订标记消息传播。该服务将这些有效负载存储为投影；共享单元保持规范。缺失、部分或不匹配的修订将拒绝或返回所有者现有的可重试待定结果。使用非重用代；在柜台包装之前退休。

出版顺序是强制性的：

1. 准备替换事实而不暴露它们。在 **更改权威状态或授予更改它的本机效果之前，同步使旧的 revision/status** 无效。保留所有者特定的回滚语义：永久退休保持永久；中止的临时配置激活不得撤销仍保持最新状态的已接受源。
2. 在当前所有者下执行突变。保留 pending/uncertain 区别，直到本地解决确定结果。
3. 在服务中安装新的不可变事实，然后让其原始所有者在安装确认后发布匹配的就绪修订版。延迟的有效负载无法覆盖后续版本。不相关的密钥保持有效；没有每次写入注册表重建或文件系统轮询。

读取器加载所有依赖项 revisions/statuses，评估类型化操作，然后在发布其决定之前一次尝试重新检查所有这些操作。作者在本机阶段之前对这些引用的最后检查是该阶段的权威线性化点。在任一边界观察到的撤销均被否认；稍后的撤销保留了今天的 next-boundary/rollback 语义。最终主机 COMMIT 重新验证仍然是强制性的。这不是持久功能或在等待后使用先前答案的权限。

**each** 所有者的证明义务是完整的写入器清单：所有更改消费事实的路径必须首先失效，包括工作器 COMMIT、配置激活、删除、修复和关闭。更改后的侦听器无法满足它。在结果尚未可用的效果之前发布待定修订；停滞的出版可能会延迟工作，但不能授予陈旧的工作。测试实际的发布者，而不是单独的合成撤销助手。

使用[保留修复](https://github.com/openclaw/openclaw/pull/170423)中的开放时间协调保留物理代：保留原始物理身份，acquire/reconcile暴露句柄之前的引用，平衡废弃的引用，仅重试元数据关闭，并拒绝显式报废或替换。在服务切换之前整合修复；不要重复其协议。权限描述符同样仍然由操作保管保留，直到结算和本机清理，而不仅仅是直到 grant/reply. 撤销和内存回收不同的转换。

## <a id="service-and-typed-operations"></a> 服务和类型化操作

代理为每个网关进程拥有一名准入工作人员。它保留现有的每个数据库 FIFO，并通过专用端口仅发送当前作业、确切的依赖关系、阶段和事务事实。该服务拥有决策执行，而不是 SQLite 连接、策略突变、调度顺序或收据。

初始操作是 `assertBoundRevision` 和 `readCurrentSettledFacts` 用于配置文件权限。后来的所有者模块提供了 `assertRunBinding`、`authorizeOperatorPolicy`、`authorizeSessionTarget`、`validatePreparedSources`、`acceptConversationAlternatives` 和 `authorizePendingInputCustody`。每个都有一个封闭的 input/result 类型和一个定义的效果所有者。保留参与者序列：accepted/current 检查→本机观察→策略操作→current/accepted 检查→授予。保持有序的准备工作，包括在前台等待的规划人员 FIFO；仅在具有等价性证明的情况下才将其提前移动。依赖于事务的决策会消耗本机事务的原像。在赠款移交给其指定所有者之前或在分配之前完成的记账工作；它不能成为异步通知。

最终主机COMMIT授权，原生COMMIT，收据公布及结算不变。因此，主机停顿仍然会延迟 COMMIT、调度和 ACK 发布。分别测量；该程序首先删除重复的准入传递等待及其 FIFO 占用，而不是所有主线程延迟。冷 creation/schema 准备在其所有者迁移之前一直是主机所需的。

不透明发布的 SDK 防护是另一种显式主机要求的情况：`config/sessions/session-source-authority.ts:47–67,127–156` 允许任意同步 SQLite 读取。保留该适配器和公共行为；将每个类型化操作的所有捆绑调用者迁移到一起并删除其旧的回调路径。不受支持的回调绝不能落入共享允许快照。通用 SDK 线程外准入需要单独审核的公共合约。

服务失败必须拒绝未授权的请求，并通过现有的本机 retirement/settlement. 路由分派的工作。终止的工作线程无法发布其自身的死亡，并且同步等待不能依赖于端口关闭回调。在切换之前，实现有界服务响应等待：本机等待者自动终止其挂起的请求，无需主机调度；过期永远不会授予权限。经纪商主管在更换之前关闭失败的服务纪元。根据慢主机测量调整内部等待预算；不添加用户配置。保存完整的收据；报告未知写入未知并通过现有所有者进行协调，从不自动重播。在旧的本地监护权解决后，替换使用新的服务纪元和新的注册。网关 crash/restart 丢弃共享内存并补充规范的持久状态；没有任何权限可以仅靠令牌或路径名来生存。

## <a id="incremental-delivery-and-proof"></a> 增量交付及证明

每 PR 土地一位所有者。首先传输配置文件 revisions/status 及其现有的 pre-COMMIT 栅栏，并使用服务骨架执行这两个类型的读取。保持混合操作明确主机所需，直到每个依赖项都可转移；不要声称第一片的聊天延迟有所改善。然后按该依赖关系顺序迁移 broker/execution/maintenance 托管、request/run/operator 所有者、config/tool 策略和 session/sharing/source 操作。将每个组拆分为各自的所有者。每个 PR 列出了调用者、突变覆盖范围、删除的回调代码、保留的公共合约和测量的成本；如果没有后来的 PR，早期的 PR 仍然是安全的。

所需的对抗性证明通过真实所有者路径使用障碍：在有效负载交付和评估期间撤销；当主机被阻止时，变异 config/membership；在两个消息顺序中保留然后退出；替换物理文件；重用一次运行 ID；断开接受与不接受的来源； pending/unknown型材COMMIT；回调引起的撤销； duplicate/delayed 赠款和收据； service/native 在授予之前、授予之后和 COMMIT 之后崩溃。断言拒绝、永久状态与可重试状态、未更改的 FIFO 排序、保留已提交的事实和平衡保留。包括进程重新启动和过时时期拒绝。针对相同的合同固定装置运行保留的主机路径和迁移的路径。

对于每个可执行切片，使用合成的隔离团队沙箱和四个预选的 A-B-B-A 块、相同的 instrumentation/builds、每次运行的新鲜状态并且没有丢弃的故障。重用 [ 写入器计数测量 ](https://github.com/openclaw/openclaw/pull/169800) 中的写入器工作负载：20 个会话 × 5 个回合，每个回合排除一次预热，20 个历史记录 messages/session，400 个历史读取，100 个元数据 updates/probe 轮次，四个订阅者、可见观察者、工具事件和控制平面。还重复先前 ACK 测量中的 20 发送器 `chat.send` 协议，保留其夹具和节奏。
