# <a id="security-audits"></a> 安全审核

ClawHub 安全审核可帮助您确定技能或插件是否足够安全，可以安装。它们显示了版本的作用、它要求什么权限，以及在访问文件、帐户、凭据、代码或外部服务之前是否有任何内容值得额外关注。

审核是强有力的安全信号，但并不能保证发布没有风险。在授予敏感访问权限之前始终进行判断。

另请参见 [Security](/clawhub/security)、[ 可接受的用法](/clawhub/acceptable-usage) 和 [ 审核和帐户 Safety](/clawhub/moderation)。

## <a id="what-to-check-before-installing"></a> 安装前要检查什么

安装之前，请检查：

- 总体审核状态
- 风险等级
- any 列出的调查结果
- 所需的凭据、权限或环境变量
- owner、来源、版本、变更日志、下载、星级和其他信任信号

仅安装您理解和信任的内容。

## <a id="audit-status"></a> 审核状态

审核状态告诉您如何对审核结果做出反应：

| 状态      | 含义                                                                   |
| ----------- | ------------------------------------------------------------------------- |
| `Pass`      | 未发现低风险以上的明显问题。                                |
| `Review`    | 安装前请阅读调查结果。该发布可能仍然是合法的。 |
| `Warn`      | 请格外小心。 ClawHub 发现高影响力的关注或警告信号。 |
| `Malicious` | 不要安装。                                                           |
| `Pending`   | 审核尚未完成。                                             |
| `Error`     | 审核无法完成。                                         |

`Pass`让人放心，但它不能取代你自己的判断。这对于可以发布内容、编辑数据、运行命令、读取文件或访问生产系统的工具来说最为重要。

## <a id="risk-level"></a> 风险级别

风险级别描述了爆炸半径：如果您按预期使用释放器，则释放器的威力有多大。

| 风险等级 | 含义                                                                       |
| ---------- | ----------------------------------------------------------------------------- |
| `Low`      | 几乎没有发现敏感权限或用户影响。                          |
| `Medium`   | 该发布具有有意义的权限，例如帐户访问或数据更改。 |
| `High`     | 该发布具有高影响力、严重发现或恶意信号。 |

风险级别和审计状态回答不同的问题：

- 风险等级询问：“这里有多少力量？”
- 审核状态询问：“我应该如何处理这个结果？”

例如，发布技能可能显示 `Review` 和 `Medium` 风险。这并不意味着它是恶意的。这意味着该技能看起来与目的一致，但可以以有意义的帐户权限进行操作。

## <a id="findings"></a> 发现项

调查结果解释了为何显示审计结果。每项发现通常包括：

- 是什么意思
- 为什么被标记
- 相关技能或插件内容
- a推荐

结果可能标记为 `Info`、`Low`、`Medium`、`High` 或 `Critical`。严重性越高的结果对风险级别和审计状态的影响越大。

低可信度调查结果隐藏在公共审计汇总中，因此该页面始终专注于有用的证据。

## <a id="what-clawhub-checks"></a> ClawHub 检查什么

ClawHub 审核提交的发布工件，包括：

- 技能说明或插件元数据
- 声明的环境变量和权限
- 安装说明和包元数据
- 包含的文件和文件清单
- 兼容性和功能元数据

主要问题是连贯性：名称、摘要、元数据、请求的权限和实际内容是否符合用户的合理期望？

强大的行为并不一定是坏的。许多有用的工具需要凭据、本地命令、提供程序 API 或软件包安装。审计会检查该权力是否符合预期、是否已披露且是否相称。

工件页面链接到完整审核：

```text
/<owner>/skills/<slug>/security-audit
```

审核页面结合了：

1. SkillSpector
2. A.I.G
3. 风险分析

## A.I.G

技能审核包括腾讯朱雀实验室 A.I.G 扫描仪的结果。 A.I.G 检查代理指令中的漏洞模式，并为 ClawScan 的工件范围审查提供支持证据。它不发布ClawHub的最终裁决或独立阻止安装。

A.I.G 0.2.1 无法检查打包的 Python 字节码。在腾讯发布 [CVE-2026-84809](https://nvd.nist.gov/vuln/detail/CVE-2026-84809) 修复之前，ClawHub 会在 A.I.G 运行之前拒绝包含 `.pyc`、`.pyo` 或 `.pyd` 文件的技能。 ClawScan 还可以独立检测打包的 Python 字节码。

## <a id="risk-analysis"></a> 风险分析

风险分析由 ClawScan（ClawHub 自己的安全审核系统）内部提供支持。它将每个版本作为面向代理的工件进行审查：指令、元数据、声明的权限、文件、功能信号、静态扫描信号、SkillSpector 结果、A.I.G 技能结果以及发布者提供的上下文。静态扫描信号是本次审查的内部背景；它们不是独立的公共审计部分或阻止安装的裁决。

风险分析使用 [OWASP 代理技能排名前 10](https://owasp.org/www-project-agentic-skills-top-10/) 作为风险的镜头，例如提示注入、工具误用、凭证暴露、不安全执行、内存或上下文中毒以及过度代理等。

ClawScan 不会将看起来可怕的功能视为自动恶意。它询问该功能是否已公开、是否与目的一致以及是否受到版本声明的用例的支持。
