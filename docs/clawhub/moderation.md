# <a id="moderation-and-account-safety"></a> 审核和帐户安全

ClawHub 已开放发布，但公共发现和安装表面仍需要护栏。当发布或帐户出现不安全、误导性或不符合政策时，报告、审核保留、隐藏列表和帐户操作有助于保护用户。

此页面涵盖审核和帐户信誉。有关 `Pass`、`Review`、`Warn`、`Malicious` 等审核标签和风险级别，请参阅 [Security Audits](/clawhub/security-audits)。

另请参见 [Security](/clawhub/security) 和 [可接受的用法](/clawhub/acceptable-usage)。对于版权或其他内容权利问题，请使用 [ 内容权利 Requests](/clawhub/content-rights)。

## <a id="reports"></a> 报告

登录用户可以报告技能、插件和软件包。

仅针对不安全的市场内容使用 ClawHub 报告，例如：

- 恶意列表
- 误导性元数据
- 未声明的凭据或权限要求
- 可疑的安装说明
- 冒充
- 恶意注册或商标滥用
- 违反 [ 可接受的用法的内容](/clawhub/acceptable-usage)

使用技能页面上的 **报告技能** 按钮，或使用包报告 command/API 包。

请勿使用 ClawHub 报告第三方技能或插件自身源代码中的漏洞。直接向列表中链接的发布者或源存储库报告这些内容。 ClawHub 不维护或修补第三方技能或插件代码。

GitHub `openclaw/clawhub` 的安全公告针对 ClawHub 本身的漏洞。示例包括网站、API、CLI、注册表、身份验证、扫描、审核或 download/install 信任边界中的错误。请勿使用 ClawHub 针对第三方技能或插件中的漏洞的建议。

好的报告是具体的、可操作的。滥用报告本身可能会导致帐户采取行动。

## <a id="org-and-namespace-claims"></a> Org 和命名空间声明

组织、品牌、包范围、所有者句柄或命名空间所有权争议应使用 [Org 和命名空间 Claims](/clawhub/namespace-claims) 流程，而不是产品内报告流程或帐户申诉表单。

当您需要 ClawHub 员工审查命名空间应保留、转移、重命名、隐藏、隔离、别名或以其他方式审查的非敏感证据时，请使用该流程。请勿在公开发行中包含秘密、私人文档、私人法律文件、个人身份证件、API 代币或 DNS 质询代币。

## <a id="moderation-holds"></a> 适度持有

一些严重的调查结果或政策问题可能会使发布商或列表处于审核状态。发生这种情况时，受影响的内容可能会隐藏起来，不让公众发现，或者未来的发布可能会开始隐藏，直到问题得到审核。

审核保留旨在保护用户，而 ClawHub 则解决高风险案例。当确认误报时，它们也可以被解除。

## <a id="hidden-or-blocked-listings"></a> H隐藏或阻止的列表

列表可能会被保留、隐藏、隔离、撤销或以其他方式在公共安装表面上不可用。

如果您看到这些状态之一，请不要安装该版本，除非所有者解决了问题或审核将其恢复。

业主仍然可以看到自己持有或隐藏的列表的诊断信息。这些诊断有助于解释发生了什么以及在列表重新公开之前需要进行哪些更改。

## <a id="bans-and-account-standing"></a> 禁令和帐户信誉

违反 ClawHub 政策的帐户可能会失去发布访问权限。严重滥用可能会导致帐户禁止、令牌撤销、隐藏内容或删除列表。每天都会检查出版商滥用压力信号。达到 ClawHub 潜在禁止阈值的信号可以触发自动警告。如果警告截止日期后的下一次符合条件的扫描仍将发布商置于潜在禁止阈值中，则 ClawHub 可能会自动应用帐户操作。较低置信度和有限时间审查信号不会自动执行。

已删除、禁止或禁用的账户无法使用 ClawHub API 代币。如果 CLI 身份验证在帐户操作后开始失败，请登录到 Web UI 以查看帐户状态。如果登录或正常的 CLI 访问被禁止或禁用帐户阻止，请使用 [ClawHub 申诉表 ](https://appeals.openclaw.ai/) 进行恢复审核。

如果扫描仪触发的电子邮件将技能或插件版本命名为恶意版本，请下载已阻止的提交版本的存储扫描结果：`clawhub scan download <slug> --version <version>`。对于插件，添加 `--kind plugin`。查看扫描输出，修复列表，增加版本号，然后上传修复的版本。

## <a id="publisher-guidance"></a> 发布者指导

为了减少误报并提高用户信任度：

- 保持名称、摘要、标签和变更日志准确
- 声明所需的环境变量和权限
- 避免混淆安装命令
- 尽可能链接到源
- 在发布插件之前使用试运行
- 如果用户或版主询问发布行为，请明确答复
