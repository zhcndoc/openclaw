# <a id="org-and-namespace-claims"></a> Org 和命名空间声明

ClawHub 使用所有者句柄、组织句柄、技能别名、插件包名称和包范围作为公共命名空间。如果命名空间看似属于现实世界的项目、品牌、包生态系统或组织，但已在 ClawHub 上声明、保留、误导或有争议，请要求工作人员使用 [Org/命名空间声明问题表 ](https://github.com/openclaw/clawhub/issues/new?template=org-namespace-claim.yml) 对其进行审核。

使用此路径进行公开的、非敏感的所有权审查。请勿使用产品内报告或帐户申诉表来声明命名空间。

## <a id="when-to-open-a-claim"></a> 何时提出索赔

当您认为 ClawHub 工作人员应检查命名空间是否应因实际所有权而保留、转移、重命名、隐藏、隔离、别名或以其他方式更改时，请打开命名空间声明。

示例包括：

- an 与您的 GitHub 组织、项目、公司或社区匹配的组织句柄
- a 包范围，例如 `@example-org/*`，应仅在匹配的 ClawHub 所有者下发布
- a 冒充项目的技能 slug 或插件包名称
- a 品牌、商标、项目更名或包装历史争议
- a 已删除、不活动或无法访问的所有者，阻止了合法的命名空间所有者

如果列表存在除所有权争议之外的不安全、恶意或误导性内容，也请遵循相关的审核或安全指南。命名空间索赔表用于所有权审查，而不是紧急漏洞披露。

## <a id="before-you-file"></a> 提交之前

首先确认您正在与与命名空间匹配的所有者进行发布。对于插件包，必须将 `@example-org/example-plugin` 等范围名称发布为匹配的 `example-org` 所有者。

如果您可以管理当前所有者，请通过发布、重命名、转移、隐藏或删除受影响的资源来直接修复命名空间。当您无法管理当前所有者或员工需要解决争议时，请使用索赔。

## <a id="evidence-to-include"></a> 要包含的证据

使用公开的、非敏感的证据。有用的证据包括：

- GitHub 组织、存储库、发布或维护者历史记录
- 命名命名空间的官方项目文档
- 域名或官方电子邮件域名证明
- npm、PyPI、crates.io 或其他包注册表范围控制
- 可安全公开讨论的商标、品牌或项目所有权证据
- 源存储库历史记录、包历史记录或公共重命名通知
- 链接到有争议的 ClawHub 所有者、技能、插件、包或问题

解释每个链接证明了什么。员工应该能够了解这种关系，而无需私人凭证或秘密。

## <a id="what-not-to-include"></a> 不包括的内容

不要将秘密或私人证据放在公开的 GitHub 问题中。不包括：

- API 令牌、签名密钥或凭证
- DNS 挑战令牌
- 私人法律文件或合同
- 个人身份证件
- 私人电子邮件、私人安全报告或机密客户数据

索赔表询问敏感证据是否需要私人员工渠道。使用该选项而不是公开发布敏感材料。

## <a id="possible-outcomes"></a> 可能的结果

根据证据和风险，ClawHub 员工可以保留命名空间、转移所有权、重命名资源、隐藏或隔离现有列表、添加别名或重定向、要求更多证据或拒绝请求。

命名空间审查并不能保证每个匹配的名称都会被转移。工作人员权衡公开证据、现有使用情况、安全风险和用户影响。
