## macOS UI

- 菜单栏：**语音和通话设置…**打开本机**语音和通话**设置页面。
- 本机设置：**使用实时网关中继** 是此 Mac 的本地默认关闭选择加入。
- **在仪表板中打开**将提供商、模型、语音和传输设置交给Control UI **Settings →**Connections**下的Talk**。
- 菜单栏：**Talk模式**启动或停止当前Talk会话。
- Overlay：球体呈现通用通话波形（与 iOS、watchOS 和 Android 共享）。聆听遵循现场麦克风电平，说话遵循实际的 TTS 播放包络，思考轻柔地呼吸。单击球体 pause/resume，双击停止讲话，单击 X 退出讲话模式。

## <a id="apple-watch-ui"></a> Apple 手表 UI

在 iPhone **设置中点击** 连接 Apple Watch**→ Apple Watch**，然后在 Watch**上打开**Talk 并点击**开始**。包含语音，无需单独的启用设置；单独设置不会激活麦克风。当有多个客服人员可用时，手表会要求您选择一名客服人员，为呼叫创建单独的聊天，并使用 **Mute** 和 **End** 控件显示最新的语音记录。它不在本地运行代理或库存 Codex 运行时。

将应用程序保持在前台直至连接。建立的呼叫使用背景音频；如果处于后台，未完成的启动将停止。物理手腕向下、扬声器路由、蜂窝切换和长时间通话耐力仍未得到验证。模拟器结果和 macOS 提供商音频检查并不能证明手表后台行为。请参阅 [ 手表设置和限制 ](/platforms/ios#standalone-voice)。

## Android UI

- Android 的主导航是 **Home**、**Chat** 和 **Settings**。语音输入位于 Chat 编辑器中，而不是单独的 Voice 选项卡。
- 点击编辑器麦克风可进行设备端听写。长按它可录制语音笔记附件。从 Talk 波形开始连续 Talk。
- 当 Talk 处于活动状态时，Chat 显示其当前状态。 Native Talk 识别设备语音识别和配置的 Talk 语音，并解释网关何时不通告 GPT-Live 中继支持或明确拒绝配置的中继支持。显式 `stt-tts` 模式显示为本机 Talk，而不是实时故障。
- 听写、语音笔记录制和 Talk 是互斥的麦克风路径；启动其中一个会停止或阻止其他路径。
- 实时 Talk 优先使用已连接的 Bluetooth Classic 或 BLE 耳机麦克风；如果断开连接，应用会请求另一个耳机输入，或回退到默认麦克风，并在捕获停止后恢复默认偏好。
- Realtime Talk 使用连接的外部输出或内置扬声器请求 Android 通信模式和音频焦点。仅当启用回声消除且通信模式和焦点保持活动状态时，才会在播放期间发送麦克风音频。如果没有回声消除，则播放期间不会发送麦克风音频。 Android 演示时间戳在可用时估计播放完成情况。没有可用时间戳的路由使用近似播放位置加上标称 PCM 持续时间；这不能保证每台设备上的所有声音输出都已耗尽。
- 失去音频焦点或遇到播放设备故障会结束实时通话并出现错误。在捕获恢复之前中断会清除排队的输出；停止的会话无法通过替换网关确认播放。
- 实时 **Thinking** 遵循提供者响应生成或接受的 OpenClaw 咨询，而不是输入转录，这可能会在答案后完成。没有提供者或网关响应开始信号的直接回复将保持 **Listening** 直到输出到达。空的已完成响应返回到 **Listening**；缓冲的音频保持 **Speaking** 直到播放耗尽。
- 当应用离开前台或用户离开 Chat 时，听写和语音笔记录制会停止。
- Talk Mode 会一直运行，直到被切换关闭或节点断开连接，激活时使用 Android 的 microphone 前台服务类型。
- Android 支持 `pcm_16000`、`pcm_22050`、`pcm_24000` 和 `pcm_44100` 输出格式，用于低延迟的 `AudioTrack` 流式传输。
