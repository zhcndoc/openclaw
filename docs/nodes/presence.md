活动计算机的存在告诉网关哪个连接的 macOS 节点收到了最近的活动。当您与 OpenClaw 应用程序交互时，可以使用基本状态，无需额外权限。可选的 **系统范围内的存在检测** 还包括其他应用程序中的物理鼠标和键盘活动。 OpenClaw 使用该信号将一台 Mac 标记为 `active`，为代理提供稳定的活动节点提示，并将节点连接警报路由到您最有可能出现的计算机。

这是最近活动的提示，而不是哪台计算机发送特定聊天消息的证明。活动 Mac 可能与运行网关或代理的计算机不同。设备状态和连接警报路由选择网关上最新的合格 Mac。代理的提示提示会在与经过身份验证的请求者关联的节点中进行选择。它永远不会落回到另一个人的机器上。共享所有者和身份不明的回合可以收到未分配的节点提示，明确标记未知人员身份。

核心 [ 在线状态工具 ](/concepts/presence#ask-the-agent-about-presence) 将这些观察结果与人员和客户的实时名册相结合。它保留活动源并分别识别共享或未分配的计算机。持久 `node.presence.alive` 信标记录移动节点上次唤醒的时间，而不将其视为已连接或建立用户活动。

## <a id="requirements"></a> 要求

- OpenClaw macOS 应用已配对并以 node 模式连接。
- 与 OpenClaw 应用程序交互以提供基本状态。仅运行或前台应用程序不算为活动。
- 要包含其他应用程序中的活动，请启用 **设置 -> 权限 -> 系统范围存在检测** 并向签名的 OpenClaw 应用程序授予 **Accessibility**。默认情况下，系统范围的检测处于关闭状态。
- 对于连接提醒，还需要授予 **Notifications** 权限，并且 Mac node 暴露 `system.notify`。

活动报告仅由本机 macOS 节点实现。 iOS、Android、watchOS 和无头节点主机可以报告连接或后台上次看到的状态，但它们不会竞争活动计算机指定。

## <a id="check-the-active-computer"></a> 检查当前活动的电脑

1. 与 OpenClaw macOS 应用程序交互。此基本存在信号不需要辅助功能许可。要也检测其他应用程序中的活动，请启用 **设置 -> 权限 -> 系统范围存在检测** 并在 macOS 系统设置中授予 **Accessibility** 。
2. 确认 Mac 节点已连接：

   ```bash
   openclaw nodes status --connected
   ```

3. 在该 Mac 上单击或输入 OpenClaw，然后运行：

   ```bash
   openclaw nodes status
   openclaw nodes describe --node <node-id-or-name>
   ```

最近且符合条件的 Mac 会被标记为 `active`。状态输出会显示其最后输入的时间间隔；`describe` 会暴露 `active`、`lastActiveAtMs` 和 `presenceUpdatedAtMs`。 活动会被刻意合并，因此在最近一次报告之后，显示内容最多可能需要大约 15 秒才能反映另一次输入。

## <a id="how-activity-becomes-presence"></a> 活动如何变为在线状态

macOS 应用程序记录 OpenClaw 接收到的本地输入事件。当启用系统范围检测并授予可访问性时，它还会每两秒对 HID 系统空闲时钟进行采样。报告被合并：新活动每 15 秒发送不超过一次，空闲时每三分钟发送一次保持活动。空闲时间的上限为 30 天，因此非常旧的样本不会向前漂移并错误地成为最新的计算机。

禁用 **系统范围的存在检测** 或失去可访问性，会清除之前的系统范围样本，并回退到应用程序本地活动（如果观察到任何活动）。它不会关闭基本存在或断开其他节点功能。如果没有应用程序本地示例，则该 Mac 将保持未选中状态，直到您与 OpenClaw 交互。

Gateway 仅在以下条件全部满足时才接受活动：

- 该事件属于该 node id 当前已认证的连接；
- 有效负载包含有界整数`idleSeconds`值；
- 源是应用程序本地或具有有效 `accessibility: true` 权限的系统范围。没有来源的旧报告被视为系统范围的报告。

Gateway 会用自身的观测时间减去 `idleSeconds`，从而推导出 `lastActiveAtMs`。它绝不会信任节点提供的墙上时钟时间戳。在已连接且符合条件的 Mac 之间，`lastActiveAtMs` 更新最新者获胜；若相同，则以最近的 presence 更新为准。

存在是进程本地的和连接绑定的。断开当前会话或使用相同节点 ID 将其替换为另一个会话会清除该节点的活动状态并重新计算活动 Mac。撤销辅助功能会使系统范围的活动无效，但应用程序本地活动仍然符合资格。

## <a id="privacy-and-model-context"></a> 隐私和模型上下文

无需辅助功能授权即可使用基本的应用程序本地存在。仅选择加入系统范围的检测，与用于 UI 自动化的辅助功能授权分开。 OpenClaw 发送空闲时长和活动源，而不是输入内容。它不发送键值、鼠标坐标、应用程序名称、窗口标题或原始输入事件。

系统范围的检测读取硬件 HID 状态，因此综合计算机控制事件不计为物理系统范围的活动。应用程序本地检测记录传送到 OpenClaw 的输入，并不能证明事件来自物理设备。

连续活动不会创建面向模型的系统事件。在轮流准备时，动态上下文包含一个紧凑的提示，其中仅包含经过身份验证的节点 ID：

```text
active_node=<node-id> active_node_identity=requester
```

当当前不存在符合条件的已连接 Mac 时，提示为 `active_node=unknown`。这会清除之前的选择，而不是让代理重新使用断开连接的 Mac。它不会识别消息的源设备或暗示没有人正在使用计算机。

对于共享所有者或未识别的回合，身份标记为 `active_node_identity=unknown`；该机器上的活动无法确定谁使用了它。指定人员的提示需要匹配的经过身份验证的节点配置文件。设备名称、IP 地址和单个可见人员无法建立该关联。

准确的时间戳和节点控制的显示名称不会出现在提示中，以避免提示注入和缓存搅动。提示保持逐字节相同，而所选节点 ID 不变。当代理需要当前详细信息时，`presence` 工具可以检查请求者及其设备。 `nodes` 工具继续通过 `node.list` 或 `node.describe` 读取设备状态和控制功能。

## <a id="how-connection-alerts-are-routed"></a> 连接提醒的路由方式

在节点完成批准后的第一次成功 Gateway 握手后， OpenClaw 会等待 750 毫秒，以便连接中的 Mac 能提交其首个活动样本。随后，它会使用最新的活动信息尝试向已连接且具备通知能力的 Mac 发送提醒。

- 如果主投递成功，则不会有其他 Mac 收到该提醒。
- 如果没有可用的活跃 Mac，或者主投递失败，OpenClaw 会等待五秒，然后尝试向所有其余已连接且暴露 `system.notify` 的 Mac 发送提醒。
- 后续重新连接不会触发提醒。Gateway 会在配对元数据中记录成功连接， 因此 Gateway 重启不会为每个先前连接过的节点重新播放提醒。

提醒与经过身份验证的节点身份绑定。对于同一节点的替代会话会接管其待处理的首次连接提醒；如果在投递执行时该节点已不再连接，则该提醒会被取消。

## <a id="troubleshooting"></a> 故障排查

| 症状                                   | 检查                                                                                                                                                                                                                       |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 未标记任何 `active` 行                 | 确认本机 macOS 节点已连接，然后单击或输入 OpenClaw。对于 OpenClaw 之外的活动，启用系统范围的检测并检查 `openclaw nodes describe --node <id>` 中的 `permissions.accessibility: true`。 |
| 错误的 Mac 仍然处于活动状态              | 在要使用的 Mac 上与 OpenClaw 交互，等待合并窗口，然后重新运行 `openclaw nodes status`。启用系统范围的检测后，其他应用程序中的物理输入也很重要。                        |
| 最后输入数据消失                | 检查Mac是否断开连接或者其节点会话被替换。禁用系统范围的检测或撤销可访问性会清除系统范围的样本；应用程序本地活动仍然可以选择 Mac。                  |
| 警报出现在多台 Mac 上         | 主投递不可用或失败，因此延迟回退机制被执行。请确认活动中的 Mac 已连接、允许通知，并暴露了 `system.notify`。                                                        |
| 代理没有提到活动中的 Mac | 在活动状态变更后开始一个新的轮次。运行时提示是稳定且简洁的；请使用 `nodes` 工具获取当前准确元数据。                                                                                           |

有关 TCC 恢复，请参阅 [macOS 权限](/platforms/mac/permissions)。有关节点连接和命令失败，请参阅 [节点故障排除](/nodes/troubleshooting)。
