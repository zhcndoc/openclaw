## <a id="agent-json-predicate-columns"></a> Agent JSON 谓词列

[代理架构 26](/reference/database-schemas/agent-schema-history#json-predicate-columns)实现代理存储部分[接受的栏目推广设计](https://github.com/openclaw/openclaw/issues/169254)。这JSON仍然是规范的。每个编写器派生其查询列TypeScript并承诺他们JSON在一份声明中；会话参与者重用该派生。运行时谓词使用列。没有引入触发器、第二个持久性所有者或读取时回填。

版本化迁移仅使用 SQLite JSON 函数对现有行进行分类，并在完成回填后发布两个架构标记。它保留第一个成员查找、旧的最后一个成员转录导航、SQLite 整数转换语义、格式错误的行处理、有效负载字节和现有保留规则。 Schema 准入和 Doctor 仍然是唯一的迁移所有者。可选的发件箱存储保持懒惰。添加的文本和整数字段转换为具有 C 排序规则和 bigint 的 PostgreSQL 文本；支持引擎共享架构版本，并且必须提供等效的向前迁移。

在传输之前绑定大有效负载的 SQL 投影保留在 SQL 中。当前作者与权威的比较也保留了现有的实施方式，而不是削弱实际效果边界。迁移增加的存储量与保留的行成比例，并且首次升级证明测量每个数据库和跨多个代理主机的时间。 Older binaries refuse the new schema；恢复恢复经过验证的迁移前备份及其匹配的二进制文件。

## <a id="session-writer-validation"></a> 会话写入器验证

每个代理会话编写器在单个网关编写器合约下拥有行有效性。模式 25 从已验证的写入中删除触发器驱动的挂起簿记，并在持久化之前验证确切的序列化行。离线迁移和修复保留明确的待处理工作并使会话验证收据无效；他们从不重复准备承认未经验证的进口。

挂起的表仍然是派生的，并且不存储权限或复制的有效负载。迁移会验证先前的模式，停用其验证触发器，对所有现有节点进行排队，并通过版本发布自动清除旧的会话验证收据。这将执行与会话库存成比例的一次启动传递，而无需重写会话或脚本有效负载。普通写入避免了挂起的查找、写入后验证读取、标记删除和有效性更新。 FIFO 准入、效果边界权限、保留和持久性保留在现有所有者手中。其他进程必须通过网关路由写入或在网关停止时保持离线维护保管。

Older binaries refuse the new schema.恢复使用其匹配的二进制文件恢复经过验证的升级前备份；仅包回滚无法逆转迁移。有关迁移、准入和回滚的详细信息，请参阅 [schema 25 历史记录](/reference/database-schemas/agent-schema-history#canonical-writer-validation)。

## <a id="preparing-for-another-database-backend"></a> 准备另一个数据库后端

提交收据是进程本地发布证据，而不是持久格式。共享的 receipt/completeness 合约既不会更改架构版本，也不会更改存储的字节、保留、备份或回滚策略。现有的已发布更新程序不需要收据迁移。如果通知或结果传送失败，已确认的写入仍保持已提交状态；恢复通过其原始所有者进行协调，而不是重复写入。请参阅 [ 承诺的事实和完整性 ](/reference/database-schemas/worker-access#committed-facts-and-completeness)。

SQLite remains the supported default.实验性PostgreSQL适配器支持一个网关的远程持久化；多个活动网关需要单独的所有权和协调设计。单独的共享数据库并不能使进程本地写入器队列、会话生命周期或主机拥有的租约在网关实例之间安全。

### <a id="shared-state-postgresql-schema-generation"></a> 共享状态 PostgreSQL 架构生成

`pnpm db:postgres:gen` 重新生成 `src/state/postgres-schema.generated/` 中提交的急切模式、命名的惰性片段、依赖项清单和可移植性报告。 `pnpm db:postgres:check` 验证其新鲜度和发电机组合同。 `IS JSON` 需要 PostgreSQL **16 或更新版本**；一致性作业当前使用 PostgreSQL 17。默认情况下，详细的 JSON 诊断报告保留在内存中。显式 `pnpm db:postgres:gen --out <diagnostic-directory>` 将其与生成的文件一起导出； `portability-report.json` is not a tracked artifact。

规范的 SQLite 模式和功能本地 DDL 仍然具有权威性。 `src/state/openclaw-state-feature-schema.ts` 中的功能声明同时提供 SQLite 确保和生成器。他们的 DDL 提供程序保留现有的 SQLite 语句字节和首次使用计时，包括配置文件所有者的两个安装阶段。清单列出了每个片段的表、索引和片段依赖项。 `activation` 将首次使用片段与版本附加片段区分开来：新的引导程序或版本迁移会安装后者，而现有的相同版本存储将它们留给其功能所有者。 PostgreSQL 所有者在同一事务中首先安装依赖项，然后是片段的表和索引，最后是其外键。特别是，`user_background_images` 依赖于 `user_profiles`；仅当两个表都存在后，才会保留并安装其级联外键。生成片段不会激活 PostgreSQL 共享状态运行时支持。

`state.postgres.sql` 和每个清单 `file` 包含其状态 DDL 的单一运行时形式。生成的 `runtime.ts` 模块将相同的 SQL 与片段 activation/dependencies 以及状态所有者的预期目录打包在一起；它不维护单独的模式定义。他们省略了事务包装器和固定模式限定；所属连接提供命名空间和事务。 `agent.postgres.sql` 工件遵循相同的仅运行时约定。

对于手动状态模式检查，请运行`psql`从生成的目录中并显式提供事务和选择的模式：

```sql
\set ON_ERROR_STOP on
BEGIN;
CREATE SCHEMA review_state;
SET LOCAL search_path = review_state;
SET LOCAL standard_conforming_strings = on;
\i state.postgres.sql
-- Include each desired fragment's manifest file, dependencies first.
\i fragment-user_profiles.postgres.sql
\i fragment-user_background_images.postgres.sql
COMMIT;
```

使用一次性模式进行此准备情况检查；它不启用共享状态PostgreSQL支持或迁移现有商店。

两个引擎使用相同的共享状态模式版本（当前24）。未来的每次版本更改都必须同时提供两个引擎的前向迁移和目录等效性证明。JSON保持规范：query/index投影导出一次TypeScript并在同一份声明中承诺JSON。请参阅[接受的设计](https://github.com/openclaw/openclaw/issues/169254)。

模式 24 包括 `state-v23-v24.postgres.sql`，它是根据迁移所有者的废弃索引名称和规范的替换索引定义生成的。 It contains forward DDL only；调用者提供事务、命名空间和版本发布。 PostgreSQL 一致性根据新架构验证升级后的索引定义，并保留保留的行和本地索引。此准备工件不启用共享状态 PostgreSQL 运行时支持。

Generation 拒绝不支持的共享状态表、列、默认值、CHECK、索引和外键及其确切来源和原因。文本使用 C 排序规则。文本长度映射到 `char_length`，字节长度映射到 `octet_length`，空安全 SQLite `IS` 与 `IS [NOT] DISTINCT FROM` 进行比较。支持的 GLOB 模式使用区分大小写的正则表达式和 C 排序规则；不支持的模式或 LIKE 表达式会导致生成失败，而不是更改大小写规则。 SQLite rowid 别名成为标识列：PostgreSQL 添加 SQLite 不报告的主键索引，并且序列分配不是 rowid 兼容性承诺。数据可移植性，包括PostgreSQL对NUL文本的拒绝，属于单独的端口预检。

这SQLite-仅允许列表仅包含这些纯`instr(column, char(0)) = 0`子谓词：`node_worker_launches.{launch_id,environment_id,session_id,run_id, result_json,error_text}`和`node_worker_turns.{turn_id,run_id,result_json,error_text}`. **PostgreSQL文字无法容纳NUL；守卫是由类型强制执行的。**所有周围的长度，JSON，并且换行符约束仍然是 CHECK，保留NULL语义。这是十个子谓词；报告了六次检查`instr`作为他们的第一个不受支持的构造，而另外四个守卫则隐藏在字节转换后面。

模式 22 将两个 ACP 恢复索引表达式提升到列。单个元数据编写器使用现有的空白规则修剪字符串标识值；缺失值和非字符串值变为 NULL。迁移保留了 SQLite 的第一个重复密钥行为。恢复查找直接比较列。 JSON 保持规范；收据发布和群组缓存生命周期保持不变。

批准、cron 收据、执行决策事实和技能研讨会更改使用显式唯一的 `cursor_id` 列。迁移保留原始 rowid 值，包括间隙；现有的光标连线格式和插入顺序关系仍然有效。序列化写入者在其现有事务中分配 `max(cursor_id) + 1`。生成器的 `pendingPromotion` 列表为空。

CI **PostgreSQL conformance** 作业将生成的 eager 模式和所有片段引导到真实服务器上的隔离模式中，然后比较每个表的列、类型、可空性、默认值、primary/unique 键、CHECK 计数、索引计数和外部针对 SQLite 目录的密钥（包括操作和可延迟性）。所有共享状态索引都会被翻译。本地运行`pnpm db:postgres:gen --check-connection '<disposable PostgreSQL DSN>'`；检查之后会删除其隔离模式。这证明了 DDL 等效性，而不是运行时 SQL/concurrency 一致性或每个代理 PostgreSQL 拓扑的选择。

`pnpm check:database-dialect-ratchet` 通过仅扫描 `src/`、`extensions/` 和 `packages/` 下的不同生产 `.ts`/`.mts`/`.sql` 文件（不包括测试和夹具），保持机械、设计和引擎维护计数仅收缩到 Git 库； `--staged` 读取索引，`--full-tree` 报告总计，`sqliteStringSet` 所有者子集在机械债务中报告。 SQLite 中列出的 `SQLITE_PRIMITIVE_OWNERS` 原始所有者可能会增加发动机维护结构，消费者称其为发动机维护结构。词法门检查减去注释的 `.sql` 文件、标签最终标识符以 `sql` 结尾（不区分大小写）的模板的所有静态部分、以空格和 `(` 开头的字符串和带有大写 SQL 语句关键字的无标签模板，以及 `orReplace`/`orIgnore`/`orAbort`/`orFail`/`orRollback` 方法调用；构造正则表达式保持不区分大小写，排除 SQL 双引号文本，需要 `name(` 函数，并需要 `PRAGMA <name>` 或 `pragma_<name>(` 用于 `data_version`/`schema_version`/`user_version`. Prose，没有语句前缀的片段，并且替换被忽略，接受组装 SQL 的计数不足；两个修订版都使用相同的规则，没有类型、符号、导入或 SQL 令牌角色分析，并且运行时行为和架构保持不变。

### <a id="experimental-postgresql-engine-(workboard-pilot)"></a><a id="experimental-postgresql-engine-workboard-pilot"></a> 实验型PostgreSQL发动机（工作台飞行员）

`database.engine: "postgres"` 为每个注册了 PostgreSQL 模式的商店选择 PostgreSQL； Workboard 是目前唯一受支持的商店。 Doctor 报告每个商店的引擎并对 SQLite 上保留的商店发出警告。请参阅 [ 数据库引擎（实验）](/reference/database-engines)，了解 SecretRef 配置、隔离和持久性、匹配的 anchor/schema 备份、限制和引擎边界观察。丢失机密、连接失败和准入错误永远不会回退到 SQLite。现有的 SQLite 工作板数据在切换引擎之前需要支持的离线 `openclaw database port` 流程。

`pnpm db:postgres:gen --target workboard` 从其 SQLite 模式生成工作板 DDL； `pnpm db:postgres:check` 验证新鲜度。准入会在一笔事务中安装表并记录当前商店版本。所有者提供连续的正向迁移，每个迁移都有其生成的源和目标 DDL。引擎保留写入者的保管权，并在失败时回滚所有待处理的步骤，包括与生成的目标不同的结果；较新的版本和缺失的迁移拒绝恢复指导。目录指纹检测精确的架构漂移，而生成的 DDL 哈希栅栏构建不匹配。服务器重大更改在替换指纹之前使用 PostgreSQL 自己的解析器执行一次临时比较。使用 SQLite 引擎打开 PostgreSQL 锚也被拒绝；它永远不会在锚点中创建 SQLite 工作板表。

### <a id="keep-operations-at-the-owning-store"></a> 在所属商店继续运营

会话清理在向现有历史工作者发出的一个请求中读取条目元数据和丢失的转录本分类。读取事务保留每个肯定分类及其删除快照；包含消息的记录不需要删除快照。预览和应用保留选定的物理数据库，生命周期编写器在删除任何内容之前重新读取条目和快照。如果商店在阅读期间首次出现，则其本机阅读收据会将后续阶段绑定到该物理身份。并发追加或重写会使过时的删除计划无效。网关保留调用者权限，并且释放的同步提交回调保留其本机事务边界。显式隐身选择器使用提交的内存参与者事实，而无需打开数据库。架构、存档字节、保留和更新行为保持不变。

延迟转录投影协调通过共享代理数据库工作线程发布有界活动事件和 FTS 块。主机在调度之前捕获现有的执行所有者，并在每个本机事务和提交授权时重新验证它。准备好的生成声明、存储的转录字节、有界的仅追加追赶和原子最终准备情况保持不变。提交的终结将其会话更改返回给主机以进行通知；拒绝或回滚的最终确定不会发布准备就绪通知。未知的写入结果永远不会重播。

在确认本机提交后，重新启动恢复会将克隆副本的投影修复交给已承认的主机，包括提交后结果传送失败的情况。如果该所有者退休，则修复仍等待下一个承认的读者，而不替换已提交的恢复结果。过时的活动摘要提交谓词拒绝补丁并让其主机读取器重试和修复； SQLite 工人从不安排该维护。转录字节、会话恢复行、架构和更新行为保持不变。

全局投影预检和搜索准备使用投影维护所有者的连接本地事实。事务性 TEMP 触发队列受影响的会话，用于追加、重写、投影发布、删除、冷存储移动和原始本地 SQL。兄弟作者收据或模式更改重新启动有界准入；本地更改仅消耗排队的会话。有界递归键查询会跳过整个会话范围，而不是扫描记录行，然后复合读取使用投影所有者的就绪谓词对批次进行分类。队列消耗和脏会话发布在同一事务中批量进行。每个维护事务最多检查 128 个会话，并删除每个投影表最多 512 个孤立行。状态请求在 32 个批次后停止；不完整的准入仍待处理，现有的协调节奏将恢复它。在有界批次之间进行协调，直到有序遍历完成，然后将观察到的待处理积压交给调度程序并等待其重建。即使并发写入妨碍了干净的认证，它也可以重建该工作；所有者保留遍历完成，因此另一个状态调用者无法隐藏该进度。随后发现的更改将继续按现有节奏进行，包括对已重建的会话进行更新的修订。写入者收据会使准备状态无效，而不重置正在进行的游标。维护在开始另一遍之前到达较晚的密钥，并且只有稳定所有者修订版的完整通行证才能证明干净的存储。规划器使用该所有者的待处理列表。搜索将其命中读取、主机就绪交换和原始连接修订检查保留在一项工作任务中，同时独立搜索保持并行。一个单独的、有界的搜索通道可以防止可写准备检查占用服务于承诺历史、反应和进度卡读取的工作人员。更改的命中快照会保留索引提示。当可写维护不可用时，只读搜索也会保留其结果并带有保守的提示。干净状态读取重用这些事实，无需输入写入事务或请求写入授权，直到突变使它们无效；连接关闭会丢弃它们。不添加持久表或迁移。已发布的同步持久 SDK 回调和操作员维护保留其本机协调适配器；将这些回调移动到另一个线程需要单独的 SDK 切换。他们的一次性孤儿清理保留了有序的、索引的所有者集差异，而不是每行成员资格探测。 Incognito 没有需要协调的 SQLite 预测。

每会话准备情况轮询使用现有的只读转录工作器。就绪等待在惰性读取器加载和转发取消到排队读取时保留其原始执行所有者。退出后重新准入会等待底层数据库关闭（包括本机清理）完成。如果退出阻止任何后续的孤儿扫描批次开始，则承诺的最终确定将保持成功；下一次预检将检测并删除任何剩余的派生行。 Incognito 使用记忆演员；本机维护和删除范围保留其现有所有者。商店关闭与已接受的出版物和策划者租赁清理一起进行；较新的预定所有者不能被较旧的退休通行证使用。架构、保留、权限和更新行为保持不变。

网关用户首选项 RPC 和对话外观读取解析共享状态工作线程中的合并配置文件 ID 和访问首选项。偏好写入将配置文件解析、配额验证和变更保留在一个同步写入事务中；完成后网关回复并更改事件。配置文件合并和同意更新保留其连接绑定内核。 Web 推送浏览器设置使用相同的首选项工作人员，同时通过首选项完成保留订阅快照保管权。在等待之后以及在事务和提交准入时重新检查请求和配置文件权限；回复和偏好更改事件遵循受保护的完成。设备订阅突变在快照准备后保持延迟启动。

共享只读工作线程所有者保留继承的快照和一次性源范围，直到任务确认本机读取器清理。固定读取共享两个执行工作线程，并具有现有的挂起任务和捕获的输入字节限制。成功的读取在 Node 和 Bun 上重用其工作线程和本机读取器，在每次读取时检查物理文件身份和模式准入。结果永远不会被缓存。在释放文件保管之前，特定于路径的退休会加入每个工作人员中公认的读取器清理工作。私有快照读取器在任务完成之前仍然关闭。完成的回复将保留其工作槽位，直到被接受。 Node和Bun具有本机关闭功能，在30分钟不使用后关闭单个读卡器，并可以在有针对性的清理后保留工作人员。没有该功能的 Bun 将相同的空闲间隔委托给工作程序退休，并在读取器关闭或更换时加入工作程序退出，包括私有快照和主机请求的清理。健康的阅读本身并不会让其工人退休。长期存在的池主机选择 SQLite 并在创建池之前等待现有库所有者的本机关闭决定。 Workers 继承创建时的当前决定；早期的工人在其一生中保持保守，而替代工人则继承已完成的决定。失败的回复和取消的任务会淘汰其确切的工作人员，而不会停止不相关的读取。在退出共享池之前，整个缓存关闭会耗尽已接受的资源，包括任何剩余的头像结算读取。失败的资源耗尽会保留该池以供存储所有者清理重试。本机句柄保持打开状态，因此关闭会释放其读取密封；每次重试密封件在排水前都会再次读取。失败的本机退出会保留密封，并且在重试之前在该路径上发布的替换文件也会保留密封。路径特定的关闭仅消耗该数据库允许的操作。尽力而为的隔离读取会保留域结果，但未经确认的隔离读取器清理还需要工作人员在源发布之前退休。如果退出失败，其原始故障仍然可用。一旦验证，隔离决定仍然是拒绝，即使其阅读器无法关闭；完整性错误保留清理失败作为其原因。普通固定读取会观察独立提交的数据库状态，即使不相关的缓存本机游标仍然看到较旧的快照。缓存的写入器保持打开状态，并通过读取结算保留；在阅读器打开之前和之后以及在结果接受时检查其捕获的物理身份。它的读取引脚不公开任何数据库：普通固定读取不会查询、备份、加入或结束该连接的事务。快照借用保留了其本机事务拒绝。明确选择的快照保留其原始私有源。修复了保存来自封闭源的工件的工作人员读取，将其私有所有权令牌保留在一个共享的暂存子项中，与复制和查询工作人员分开。每个私有查询读取器还通过其本机关闭持有令牌读取租约，因此分段子故障无法删除活动查询下的字节。清理在删除复制的字节之前等待令牌失效；关闭失败和未确认的清理保留保管权。分配使用现有的回收规则。在确认的暂存进程退出后，相同的检查器和独占令牌锁会在替换会话释放保留的字节之前协调退出。对缓存的本机源的保留工件的固定读取也使用该令牌所有者。他们保留原始源连接和备份所有者，重新检查等待准备的权限，并在释放源借用之前加入令牌清理。此移动令牌 SQLite 起作用，而不是本机备份或读者的回调 SQL。通用复合回调和已经打开的本机源备份保留其现有的快照所有者。这些准备路径仍然可以执行主线程SQLite。已发布的 SDK 准备助手也保留其同步 `cleanup()` 合约。复制状态错误将返回给该读取器，而不会成为实时缓存的确认故障；本机访问和事务所有者保留自己的版本检查、故障锁定和损坏驱逐。失败的读取清理仍会注册以供店主重试；源快照和 pin 保持所有权，直到任务清理（包括所需的工作进程终止）得到确认。维护范围在其资源、引用和句柄清理阶段之前加入已承认的读取。缓存的读取器仅在工作人员输入其模式验证的查询回调后（包括该查询稍后失败时）记录共享维护所有权。启动和模式拒绝不会转移所有权。

用于连接、运行器启动和仅节点状态的 Node-host 配置加载使用相同的独立只读工作线程。两个读取器都保留缺失存储非创建和现有 JSON、元数据和配置验证。他们在等待之前捕获选定的状态环境，并在接受工作人员回复之前重新检查原始根上的退休文件拒绝。受管节点保留共享的现有架构范围，而不接管架构修复。配置替换保留其同步事务所有者。

首次使用会话组注册在共享状态工作线程中运行。现有类别返回，无需作者许可；丢失的名称会在同步事务中重新检查，分配它们的位置并插入它们。会话创建和补丁调用者在发布组失效之前等待注册。两者都保留持久的会话结果，并在目录簿记失败时发出警告。补丁也只会刷新不确定结果的目录；重试相同的类别分配可以修复丢失的注册。目录读取和其他突变、默认值和侧边栏排序保留其所有者。

主机在等待工作之前捕获数据库路径、状态环境和当前准入。共享工作者拥有其底层连接和模式开放，其网关模式权限由其实时主机操作授予。分类数据库错误可以在传输中幸存下来，并且存储紧密连接工作人员操作和本机清理。冷子代理注册表恢复会在安装其驻留快照之前读取共享状态只读工作线程。异步运行时配置准备还会读取共享状态工作线程中的 Claw 同意来源；同步配置加载器保留其现有的兼容性路径。

动态模型解析等待持续的身份验证配置文件读取。代理本地和旧共享凭据使用隔离的只读子级，因此读取可以与代理数据库的内存发布工作线程共存。选定的快照保留其拥有的私有源。重新定位的共享凭据和选定的个人帐户使用共享状态工作线程。失踪的商店仍然下落不明。有界传输帧保留完整的凭证行，没有聚合大小限制。在结果到达模型准备之前完成读取器清理；主机拥有的覆盖和迁移检查保留捕获的持久事实并在清理后重新验证。不可读的继承代理存储上记录的拒绝不会隐藏健康的本地凭据；选定的存储故障仍然会传播。凭证突变和同步 SDK 读取器保留其现有所有者。

有界 CLI 和提供程序设置身份验证范围在调用回调之前通过同一共享状态工作线程准备共享所有权和可移植凭证。每个范围都会读取新的凭据并在准备过程中保留其原始状态根。数据库关闭或共享所有权更改可防止延迟范围输入。嵌套和并发范围保留单独的通读视图； OAuth 更新材料仍归其现有所有者所有。

嵌入式运行的延迟条目加载通过共享只读工作线程所有者准备固定的库描述。每个未缓存的加载都会在工作区准备之前捕获其库引脚值和状态上下文，并仅在准备和当前所有者检查完成后才发布组合条目。即使库条目已缓存，数据库关闭也会使挂起的准备工作无效。准备期间工作区源发生变化，重试进行中的加载；已完成的缓存条目保持稳定，并发加载保留第一个完整的发布。工作区过滤仍然先于附加的库引脚；仅工作区加载忽略它们。工作区插件发现保留其现有的同步元数据路径。架构、保留和更新行为保持不变。

MCP OAuth 存储读取、挂起回调查找和请求者计数在工作线程中运行。只读操作通过共享状态读取所有者保留捕获的存储以及调用者的快照和工件保留范围。其现有的工作池拥有队列准入、存储关闭连接接受的读取和工作清理。提供程序创建准备 SDK 的同步元数据获取器所需的重定向事实；凭证和发现回调等待新的存储读取。较早的读取无法替换稍后写入确认的元数据。如果写入在可能的提交后报告错误，则提供程序需要在再次提供元数据之前进行确认的读取。登录回调在等待读取后重新检查其当前生命周期。状态和库存读取不会创建状态。运行时租约获取、验证、更新、释放和有界突变在原始捕获上下文下的工作线程中运行。事务在写入和提交之前重新读取确切的租约并获得实时调用者权限。令牌回调在提交准入时锁定取消，并仅在确认后报告保存的凭据。在释放其确切所有者之前，存储已接受的租赁工作的封闭排水沟；不确定的写入保留了租约障碍。本地维护和医生保留其现有所有者。租约验证在等待主机准入之前释放每个读取快照，然后从当前提交的状态重新读取确切的未过期所有者。主机调度不pin WAL；写入和续订保留其交易持有的支票。架构、保留、持久性和更新行为保持不变。

MCP 事件保留来自同一 OAuth 凭证所有者的非秘密授权化身。当事件使用者首次观察到时，现有的 OAuth JSON 行通过租用写入器获得 `authorizationId`；没有引入新的表或模式版本。成功的令牌刷新会保留 ID。注销、当前令牌终端拒绝和授权代码替换将其淘汰。作者在授予提交之前保留了观察结果，并通过本机提交收据仅发布非秘密的生命周期事实。已知的回滚恢复之前的观察结果；在数据库生命周期结束之前，未知的结算仍然不可用。新的读取工作者观察会检测到在此流程之外进行的凭证更改。没有租约跨越订阅请求或其同步 Webhook 验证。这些事实既不授权工具执行，也不授权替换帐户：事件准入仍然需要原始自动化和调用者权限。在降级到没有此生命周期合同的运行时之前删除事件作业，并验证目标版本数据库兼容性。删除作业无法逆转架构升级；不兼容的目标需要恢复兼容的升级前备份。

Auth-profile 支持的事件源在其现有凭证 JSON 行中使用私有 `authorizationLifetimes` 元数据。通过凭证保存工作人员事务，仅注册显式观察到的配置文件 ID。丢失的配置文件化身保留为非秘密选择逻辑删除，因此本地覆盖或删除后进行相同字节重新连接无法恢复继承的订阅。显式的更新插入取代了化身；刷新所有者通过其现有的声明、结算、回滚和对等继承操作保持连续性。传入的序列化元数据无法保证连续性。规范读取绕过运行时行缓存；最终同步防护消耗​​凭证编写者的无令牌发布。这不会添加凭证存储、表、调度程序或承载凭证的运行历史记录。

Doctor通过同一个共享状态worker导入退休的MCP OAuth JSON。主机保留独占维护所有权、已停用的运行时的文件锁和原始源声明，而工作线程读取收据、自动导入凭据及其收据并记录源删除。现有 SQLite 凭证和显式注销保留优先权。明确的预提交失败会恢复源；不确定的导入会保留 Doctor 声明以在下次运行时进行收据验证，而无需重播写入。即使交付失败，已确认的提交也会保留其结果，并报告该失败。已发布的更新程序仍然调用相同的 Doctor 修复路径；没有架构或存储格式更改。

请求者 MCP 设置在一个当前的读取工作器操作中读取其排序的授权集。工作器按调用者顺序解码选定的行，并仅返回状态事实；每条消息在运行时重用之前仍然观察当前存储。架构、存储格式、迁移或更新程序行为不会发生变化。

模型上下文读取和会话记录准备使用具有单独有界队列的会话记录工作线程。后台准备不能占用前台上下文队列。前台历史记录池和模型上下文池各自使用最多八个只读工作线程，每个线程的上限为主机计算预算的一半（向上舍入）。单个 CPU 主机在每个池中保留一个工作线程。每个worker保留自己的SQLite连接和快照；写入器准入和最终快照验证保留有序读取。数据库关闭将每个读取器加入池中，空闲退出会释放其保留状态。后台维护、导出和 SQLite 写入器保持现有容量。不需要架构、存储格式或更新迁移更改。会话从一个只读 SQLite 快照导出读取事件、统计数据和会话分类，然后从网关线程准备文本和出处。对话和工具文本保留其存储的内容，无需秘密屏蔽。重置-召回元数据跨越工作人员边界与准备好的内容。失败的索引重建会保留已发布的索引并保留重试状态。从捕获的会话文本中进行块准备使用现有的本地工作区队列，无需持久写入租用。文件和多模式准备保留该租约，所有缓存、索引和发布突变也是如此。这些突变在等待准备后重新检查当前所有权和会话墓碑。隐身转录读取使用记忆演员。存档物化和调用者拥有的记录观察者保留其现有的本地执行。索引发布和恢复仍由其现有数据库和生命周期所有者保留。仅在读取报告冷存储后，冷内存导出才会通过主机现有的副本所有者进行恢复；热导出添加无主机 SQLite 读取。无法读取的存储副本、工作人员准入和传输故障会保留已发布的索引和重试状态。启动检查批量转录统计数据并使用转录突变水印，因此独立于会话活动检测相同大小的重写。内存源哈希连同其内容哈希一起携带此修订；源修改时间保留时间排名的活动。旧版源哈希刷新一次，无需重建未更改的块。转录本导出哈希值和出处保持不变。现有的分块修订会触发一次性重建以修复先前索引的重置边界。重建重用缓存的嵌入（如果可用）并保留现有的原子发布路径。

分支列表使用相同的工作入口点及其自己的有界后台队列，与历史记录和模型上下文读取分开。工作线程读取一个只读 SQLite 快照并计算分支摘要；只有紧凑的结果返回到网关。仅当物理数据库身份和转录水印匹配时，两者才隔离重用有界紧凑缓存。网关在恢复之前检查缓存的摘要，并仅共享相同数据库声明、会话生命周期和转录水印的正在进行的读取。缓存未命中首先读取转录工作者；只有冷存储响应才会进入现有的存档工作人员恢复所有者。每个调用者都会在数据库或会话所有权更改后拒绝结果并接收自己的摘要对象。隐身分支使用内存参与者。存储的行、架构和更新行为保持不变。

[ 接受的任务和 TaskFlow 删除 ](https://github.com/openclaw/openclaw/pull/156532#issuecomment-5798987497) 删除运行时 API，而不更改共享状态或代理数据库架构。现有的 `task_runs`、`task_delivery_state` 和 `flow_runs` 定义、列和索引保持不变。非 Cron 任务和 TaskFlow 行在运行时保持不变和不使用；没有替代账本收到他们的数据。 Cron 仅拥有 `task_runs` 中的 `runtime = 'cron'` 行，并保留其历史记录和安静结果范围。本机 Codex 挂起分配使用现有父绑定中的元数据。插件拥有的 [Doctor 迁移 ](/gateway/doctor/config-migrations#native-codex-recovery-after-tasks-removal) 读取共享的 SQLite 快照，并将合格的所有者标记的本机恢复事实和最终结果导入到该元数据中。它的每个源任务 ID 标记提交分配并在确认、本机轮换、清除和重置后继续存在；源任务行保持字节相同。未标记或不明确的记录仍然可供操作员恢复，并带有可恢复的警告。 Cron 收据仍然具有执行和恢复权限；历史从未授权推出或采用。独立的审计事件和决策事实保留其所有者。 Task/flow 生命周期联接和写入仍然停用。此迁移不添加运行时任务读取器、替换分类帐或 SQL 架构更改。

GitHub OAuth 协调通过异步配置所有者加载持久配置。读取期间的运行时配置替换或更改的 OAuth 记录会留下待处理的结果以供以后协调。运行状况比较对每个原始原始字段（包括空字段）使用条件写入；审核附加在现有写入事务中一起读取其序列和保留计数。每个新操作都使用由所有者写入者收据无效的当前行或事实。这些更改保留了架构、保留、同步冷加载兼容性和更新行为。

本机网关主机通过其注册的配置所有者提供快照准备。这些读取使用现有的共享状态参与者准备延迟迁移和插件元数据。每次读取在等待准备之前都会捕获一个确切的所有者，并在该所有者关闭时拒绝其结果；故障永远不会选择更换或切换读卡器。直接服务器和独立配置读取器保留其现有的执行路径，除非其主机明确提供此操作。丢失文件默认值仍然仅在默认值需要时加载插件元数据。该操作不会更改架构、持久表示或发布权限。

会议记录身份、描述符、注释、摘要、话语和导出所有权读取使用共享状态工作线程。键入命令调用现有的同步查询内核，保留完整的存储结果和库错误字段，并保留首次使用模式创建。复合枚举、匹配和库读取使用一个延迟读取快照，使其查询与并发捕获写入保持一致。架构创建在读取事务之前完成，域错误在解决后进行转换。在关闭工作连接之前，存储关闭这些读取的内容。导出所有权查询返回现有的有序行事实；文件系统案例、工件身份和哈希检查由导出所有者保留。待处理和清单写入保留其现有事务。捕获话语附加还在该工作线程上运行现有的重复数据删除、序列分配和插入事务。捕获在准备其不可变输入之前记录接受的语音，保留其顺序，并通过本地定居保留权威。终端注释和启动失败恢复等待接受的附加；终端回调不能接受新语音。摘要发布会检查与摘要写入相同的工作事务中捕获的输入修订、之前的注释和语音序列。主机在事务和提交准入时保留实时摘要生成、调用者和中止检查；过时的结果保留了之前的注释。有界转录工具列表和显示查询在同一个工作线程上执行。标准UTC日期字符串在那里解析；其他日期格式通过保留的准备请求调用者的本机解析器，保留临时技能时区。此类读取期间的时区更改会拒绝结果，而不是混合解释。查询保留其排序、有效负载限制和同步语句快照。会话元数据、待导出标记和清单更新也在现有工作线程中运行。准备工作在屈服之前捕获物理数据库和序列化元数据；写事务重新检查规范化选择器和预期输入修订，同时保留承认的ID起源。出口簿记通过本机结算保留实际的出口租赁，包括未知结果，并在其写入事务中验证该租赁。待定标记在文件系统更改之前提交，清单更新在成功返回之前解决。会议导出快照现在在现有的共享状态读取器中运行，通过有限的块消耗和清理保留一个私有快照。工件发布使用私有暂存和受保护的文件系统副本所有者；它保留了先前的尽力而为文件和父目录同步策略。这暂时需要一份额外的工件大小的副本。主机租约原语仍然是文件突变之前的最终实时权限保护。

转录工件所有权恢复通过共享状态工作线程按顺序流式传输原始话语，并返回其标准化 JSONL 的 SHA-256 摘要。元数据和摘要读取保持其现有的单独计时；这不会在它们之间创建原子快照。人工制品更换、清单维修和出口租赁保留其现有所有者。

SQLite 工作人员传输保留完整的结果值。 64 MiB 内联回复预算内的结果保持其现有回复路径；较大的结果会被序列化一次并以 8 MiB 帧的形式传输。原始操作保留其工作线程，直到确认完整的结果和清理，包括在关闭期间。框架不会分页或重复数据库查询、截断结果或更改请求和队列预算。调用者仍然在内存中具体化了他们的完整结果。

必要时，工作线程执行输入也会使用有界框架。最多 64 个 MiB 的命令可以在共享的 256 个 MiB 聚合预算内排队并保留其完整的序列化字节费用。较大的命令需要立即接纳闲置工人，并通过结算预留 32 MiB 运输窗口。否则，准入将返回现有的过载错误，而不对该值进行排队或执行其任何部分。只有经过验证的完整输入才会到达后端。传输队列保持有界；活动的完整输入或结果仍然需要其物化记忆。

为某个操作获取一次连接，并通过其事务助手传递该确切连接。 SQLite 写回调保持同步：先完成异步规划，然后在写准入后重新读取权威行。仅在持久写入成功后才发布实时会话更改和其他相关效果。未来网络支持的所有者必须在等待驱动程序时保留该顺序。

现有的每线程数据库所有者在上次使用后将可重用的实时连接保留 30 分钟。留存的消费者、活跃的借款和交易推迟了闲置退休。 Incognito 没有 SQLite 连接：内存参与者保留其状态，直到会话或所有者关闭、到期或进程退出。代理句柄不再仅仅因为另一个代理打开数据库而退出。空闲退休保留 WAL 检查点和租约清理；显式关闭、删除、隔离和替换保留其现有的关闭和撤销路径。重用可以保留读取许可和拥有写入者失效，而无需更改架构、存储保留或更新行为。空闲窗口是一个内部常量，而不是一个配置选项。

显式的工件保留检查、私有快照以及启用扩展或嵌套的事务读取保留其隔离的连接和清理契约。

缓存代理编写器持有事务时进行的只读回调使用单独的只读配套连接。每次调用都会重新读取已提交的行并检查当前架构、代理所有者和物理文件标识。同伴保留准备好的语句，而不是授权结果或开放读取事务。在其所有者启用语句缓存的连接上，架构版本检查重用准备好的 `PRAGMA user_version` 语句，但在每次调用时读取其当前值。授权者更改、数据库替换和关闭保留现有的语句缓存失效规则。会话验证属于已承认的物理数据库：首先承认需要完整的证明，然后 schema-21 挂起键投影记录独立于连接生命周期的更改。未经许可的读者的启动和初始网关授权使用现有的突变工作人员进行待定验证，并在等待后重新检查实时权限。同一本机数据库所有者上的并发运行时读取器共享其主动验证消耗。每个服务员保留自己的生命周期声明，并在之后重新检查物理所有权和会话验证证明；完成或失败会删除共享排水管。 Startup 的作用域工作人员保留自己的批处理生命周期。架构、存储的数据和更新行为保持不变。本机读取器保留其现有的主键准入和原始行解析器行为；每个新读者都会检查待处理的密钥，而无需重新扫描不相关的经过认证的条目。同步提交防护仍然读取已提交的行。有关迁移和回滚行为，请参阅 [ 增量会话验证](/reference/database-schemas/agent-schema-history#incremental-canonical-session-validation)。同伴会以其作者的本机关闭、处置或替换而退休，包括逐出和更新清理。冷会话搜索保留一个只读连接，同时同步列出条目并检查其当前可见性。无范围角色过滤搜索对每个物理存储的精确元数据读取进行分组，并按原始密钥顺序保留失败。每个组都使用准确的读者冷准入快照；温暖组保留普通的提交读取。隐身检查使用提交的内存参与者事实。条目访问器在转录搜索之前关闭连接，包括出现错误时；继承的异步回调回落到普通的新鲜读取。准备好的元数据保留在同步请求中，并且从不缓存可见性决策。历史工作者之外的其他冷读者，包括具有扩展能力的读者，仍然是一次性的；隐身读取使用内存演员。

Doctor维护期间，会话突变和worker-close作业通过异步工作和清理保留了原始操作的维护准入。工作人员验证其参与者、操作和共享数据库；主机重新检查事务和提交授权的当前权限。撤销会阻止以后的写入。已接受的作品仍然拥有所有权，直到其结果确定或加入本机退出；如果仅后续清理失败，已确认的突变就会保持成功。

删除、隔离、维护范围、根退休和关闭在释放数据库所有者之前撤销重用并加入本机工作程序退出。在同步关闭可以等待写入器锁定之前，挂起的提交请求将被拒绝。仍在共享存档队列中等待的请求会在释放其保留声明之前删除其回调，因此退休不会等待不相关的排队工作。幸存的请求保持 FIFO 顺序。一旦获得批准，即使其请求被撤销，业务也可以通过实物结算保留托管权。架构、保留和更新行为保持不变。本机退出后，崩溃清理只能释放确切承认的租约收据；不确定的清理仍然是一个错误，并且永远不会导致突变重播。父级仅在操作清理后才采用新建立的完整性验证，并且其数据库声明保持最新状态。这些连接寿命记录在 [ 接受的回收设计](https://github.com/openclaw/openclaw/pull/140897#issuecomment-5647899202) 中。

压力扫描和显式删除在其操作范围内重复使用一名档案工作者。共享归档队列分别接纳每个具体化或发布；每个请求都会打开一个新的只读数据库，并在确认完成之前关闭其数据库和文件句柄。请求之间没有存档数据库连接或租约存在。在删除下一个受害者之前，每个受害者仍然会提交和发布。准备或发布失败会使工作线程退出并在返回现有错误之前加入其本机退出。范围完成和数据库退休撤销排队的请求、排出分派的工作并加入本机退出。该进程最多保留一名可重用的归档工作者；竞争范围会淘汰以前闲置的工人。冷准备和突变保留了各自独立的一次性工作者；冷突变加入了现有的页面维护和本机退出。

历史驱逐在该存档工作人员的现有实现请求中准备其删除快照。最终的回收事务重新读取持久引用、新近度和完整快照；主机授予重新检查实时会话准入和捕获的物理数据库的权限。档案出版物保留相同的来源围栏。实现后的并发更新由最终事务解决，并且拒绝仍然会加入工作人员清理。保留策略、存档选择、架构和更新行为保持不变。

删除快照在一个语句中选择窗口、重写生成、转录本和轨迹尾部以及父流计数。失踪的窗户仍然保留着孤儿与孩子的比较。原子重置还重用已在其写入事务中读取的进度卡元数据，保留修订逻辑删除和数字验证。这两种更改都不会保留跨操作的事实，也不会削弱当前行谓词。

单候选引用检查缩小哪些节点元数据达到 JavaScript。具有可选历史引用的行仍然使用共享条目解析器，并且不明确的 SQLite 文本或 JSON 保留完整的读取路径。每个检查都会读取其现有计划阶段或删除事务中的当前行；没有引入引用缓存。

磁盘预算清理会在归档实现后重新检查保护。已被该新保护集排除的候选者将在工人加入之前被取消，并且不被视为回收。释放其生命周期保留后，清理会在考虑另一个候选者之前重新测量物理使用情况，因此对等方释放的空间不会导致不必要的驱逐。每个被接纳的工人仍然执行当前所有者和模式检查；完整性重用遵循 [ 完整性检查](/reference/database-schemas/integrity-and-recovery#integrity-checks) 中描述的网关生命周期策略。

档案发布和级联删除仍然是原子的。在COMMIT之前，worker在共享内存中发布其授权请求并等待父进程的当前所有者检查。同步写入器服务，在回收所有者捕获的异步上下文中，在短锁定准入尝试之间的共享 SQLite 事务边界处发出请求。这包括会话条目、交付记录以及首次使用板和目标模式事务。注册使用打开连接的本机数据库位置，因此其他连接和重新打开的连接可以处理共享准入。仅重试入场；交易回调和突变永远不会重播。保留原定的锁定入学截止日期。批准后，母公司同步加入交易结算，方可允许业主退休；该强制加入不能在附加截止日期前放弃。

定期增量清理使用相同的写入准入边界，因此它可以在获取写入器锁定之前为回收批准提供服务。每个连接从 8 个页面单元开始，并朝着 25 毫秒的保持目标进行调整，每个单元最多增长两倍，直至 512 个页面。调度估计随着连接而过期。定期维护保留每个周期 512 页的总预算，重新获得单元之间的许可；被动检查点保留在写事务之外。

WAL 所有者提供一个清理前检查点操作，用于定期、回收和归档维护。不完整的检查点会跳过真空。每个单元最多释放512页，在线锁准入采用零忙超时；检查点帧复制本身不受该页面限制的限制。存档修剪会耗尽这些单元中最初观察到的空闲页面，并在检查点不完整时在删除存档之前停止。其结果记录完成情况、检查点事实以及前后的物理字节。预算清理仍然推迟到检查点所有者报告完成为止，保留保留的数据，而不是在固定的 WAL 后面添加写入。

检查点排序使用主机及其工作人员共享的私有单调观察；健康时间戳仍然是挂钟诊断。提交后页面维护还会等待父级的提交结算检查以释放其写入器锁。子交易结算和父支票释放是现有提交门中不同的事实；失败的发布不能确认成功。

归档修剪保留其维护读取器和执行生命周期，而每个页面回收单元分别获取和释放物理写入器。每次归档删除都会在其物理写入器之前获取归档许可，并在项目解决后释放两者。无关存储中的前台会话写入和冷历史记录恢复可以在回收单元之间运行。持久归档元数据读取使用现有的历史工作者；有条件删除、遗留文件删除和页面回收使用代理数据库执行代理。主机在等待之前捕获物理文件，并在生效之前和工作人员准入时重新检查原始路径别名和实时权限。每次写入都会加入本地结算，而无需重播已调度的突变。主机连接驱逐不会重定向工作或需要同步数据库重新打开。 Incognito 使用内存参与者，并且没有要回收的存档文件或 SQLite 页面。显式 Doctor/cleanup 范围保留其本机所有者。

删除存储的档案可通过选择、派生文件删除和有条件行删除来保留档案准入和一个写入器部分。在删除存储的恢复副本之前，它会重新检查压力、权限和选定的已发布行。失败的准入或更改的行将保留该副本并停止当前的清理尝试。旧文件删除会检查精确的规范化文件名所有权、统计文件并在一个同步工作写入事务中取消链接。它保留已发布或未发布行所拥有的文件，并通过取消链接持有 SQLite 写入器锁。由于文件删除无法回滚，因此主机在取消链接之前立即授予提交；无效果的结果也需要当前的提交权限。本地结算在物品作者被释放之前完成。文件系统清单和连续页面消耗在存档准入和项目写入器之外运行。聚合修剪诊断独立于实际写入等待来报告整个操作。存档顺序、保留策略、架构和更新行为保持不变。

仅历史记录的磁盘预算逐出不会触发批量会话条目规划器统计信息刷新。它在不改变会话条目基数的情况下删除老一代；转录阅读器保留其会话范围的索引路径。实际的归档条目删除保留现有的批量刷新阈值。这避免了在大量仅历史记录之后进行整个数据库分析。

Worker 退休会保留原始操作失败，而不会再次将其报告为清理失败。成功退休的执行所有者将被释放以供以后的请求使用；真正的本机关闭和租约清理失败保留其现有的重试保管权。下一个承认的代理操作会在打开替换生成之前重试该清理，因此短暂的生命周期争用不会永久禁用历史记录逐出。 Cleanup重新检查原始数据库身份和请求权限；它永远不会重播失败的操作。显式资源撤销仍然是终端。架构、保留和更新行为保持不变。在本机和租约清理解决后，成功的池代理关闭会中继其记录的 WAL 检查点。原始生成和物理数据库身份会隔离该观察，并且预算所有者仅针对较新完成的检查点释放延迟。

使用缓存汇总写入、修剪和刷新锁定更改使用相同的异步代理数据库准入。冷突变等待着现有的诚信工作者；它的比较和设置事务在已承认的连接上保持同步。刷新完成和清理等待持久化。操作在准入之前捕获其已解析的数据库路径，并且当调用者的目录或环境发生更改时，刷新锁定释放会保留该路径及其原始环境。医生报告拒绝了修剪操作，然后继续下一个代理。

使用缓存解码、报告折叠、记录清单和刷新扫描在现有会话记录工作线程中运行。前台报告使用单独的有界工作通道；后台刷新使用共享计算准入。报告返回紧凑的结果，刷新将准备好的 UTF-8 比较和设置值发送到现有主机编写器。选定的报告仅读取其请求的缓存键，并刷新仅解码选定的记录。只读操作不会创建或注册丢失的数据库，并保留临时 SQLite 故障的空缓存回退。刷新锁定状态读取不会等待写入队列。

主机保留刷新锁、当前写入权限和定价上下文。隐身使用读取提交的内存参与者事实并且不分配数据库工作线程；它的命名空间永远不会作为数据库重新打开。取消和数据库关闭加入了本地工作人员的工作、接受的主机效果以及释放托管之前的刷新锁清理。原子修剪保留主机上所有过时的行比较字节，直到其事务解决；有界 SQL 批次不会施加聚合内存限制。缓存格式、架构、保留和更新行为保持不变。

共享状态数据库引流还会加入在较早的资源关闭时注册的资源。本地退休人员正在等待这些资源；失败的清理仍保留，以便稍后显式重试。维护清理会在关闭其使用的资源之前加入早期清理阶段开始的工作。演员退休采用的客户分享其清理结果。

内存管理器承认在其确切借用的代理连接上进行写入。入院前进行提供商通话和资源准备； generated-cache 和源写入在等待后重新检查其生成、修订和源谓词。完整的重新索引发布在一个同步承认的操作中附加、替换和分离已完成的影子。管理器在释放借用之前通过提供者准备和最终写入关闭已接受的同步。

工作空间租赁声明保留与原始物理状态数据库的比较绑定和唯一的所有者身份。工作人员结算后，失败的获取回复和失败的清理会保留有限的内存中收据，以便在另一个编写者进入之前有条件释放。恢复不会重播任务、删除替换租约或将清理重定向到另一个数据库。活着的和未知的所有者保留现有的陈旧锁检查。收据过期仅丢弃本地恢复元数据；存储的锁字段、保留和架构版本保持不变。

本机钩子中继桥持久性在共享状态工作线程中运行。发布和续订请求实时主机在其写入事务中进行当前注册检查。这座桥保留了当地定居点所接受的运营；取消注册会在令牌拥有的删除和侦听器关闭之前加入它们。修剪会在主机上保留 PID 活动检查，然后在删除之前将每个完整候选者与工作事务中的权威行进行比较。读取保留仅现有准入，并且修剪的所有阶段都使用捕获的数据库上下文。冷钩 CLI 保留其单独的只读定位器工作线程。

浏览器选项卡读取和更改使用共享状态工作线程，包括别名引导、仪表板停止意图和板事件协调。读取现有 `browser.session-tabs` 命名空间不会创建丢失状态。突变使用工作器比较并仅在接受后发布进程本地别名；仅重新计算显式比较冲突。私有每个选项卡准入保持最终所有权读取和同步关闭调度与本地突变排序，并在网络响应之前释放。身份不明的 Playwright 关闭会短暂加入仪表板突变，同时保留其空存储后备；普通选项卡活动保持独立。服务关闭会加入接受的选项卡操作和协调，并且替换的运行时无法发布后期别名。存储的记录、边界和更新行为不变；无需迁移或操作员操作。

选定的图书馆资源通过共享只读工作器读取冷引脚描述和合格清单。资源准备通过读取和文件准备保留其捕获的状态根和准入，保留快照范围、选定的修订字节、隐藏引脚省略和第一次资源故障。同步发现和借用数据库的读者保留现有的合同。这不会更改架构、迁移或持久数据。

### <a id="memory-chunk-path-index-retirement"></a> 内存块路径索引退休

维护者于 2026 年 10 月 4 日接受了这种仅索引的设计。每个代理内存存储停用 `idx_memory_index_chunks_path(path)` 并保留 `idx_memory_index_chunks_path_source(path, source)`，其最左边的前缀也用于仅路径查找。块行对于该派生索引仍然具有权威性；逻辑身份、FTS 和修订触发器、召回元数据、出处和向量发布保持其现有所有者和原子性。

新的代理模式和 SDK 内存引导程序省略了仅路径索引。更新时，SDK 现有的可写内存初始化在验证和转换任何旧存储后会将其删除。冻结的前任验证仍然接受历史索引。当前版本所需索引修复不会重新创建它；只读承认接受其存在或不存在。从不初始化内存的现有代理数据库可以保留它。没有每个查​​询的清理、新的准入所有者、架构版本碰撞或已安装的更新程序更改。

每个替换的 chunk 避免了一次冗余的索引删除和插入； SQL 源替换中的语句计数保持不变。在具有块 FTS 和修订的完整 delete/reinsert 期间，使用 15,183 个块保存了 183 个 4-KiB 页（749,568 字节）和 753,960 WAL 字节（0.32%）的 Synthetic 组件测量触发器。矢量、出处和召回写入被排除在外，因此这不是端到端估计或实际加速声明。删除索引使其页面可重用；它不承诺立即物理文件收缩或运行 `VACUUM`。降级或二进制回滚可以安全地重新创建旧运行时的索引，而无需进行行转换；重新升级会在内存初始化时再次停用它。回滚的封闭模式事务会使用该事务的其余部分来恢复索引。

### <a id="preserve-the-data-and-concurrency-contracts"></a> 保留数据和并发合约

转录回合谓词仅在需要时才获取最新的助手。助理重播和谓词查找在加载匹配的消息正文之前检查导航元数据，因此不相关的压缩工具结果在写入事务内保持压缩状态。会话行更新和副本追加保留其原子提交和当前权限检查。代理存储写入诊断为域操作命名。存储的字节、模式、持久性和更新行为不变；现有商店无需迁移。

异步设备身份加载使用共享状态工作线程。第一个创建者在数据库引导之前运行现有的身份所有者，因此挂起的遗留身份文件仍然会阻止创建。只读加载不会创建丢失的数据库或更改其工件。现有的Ed25519密钥、首写者收敛、权限以及Doctor的迁移和修复权限保持不变。进程身份缓存保留其现有的数据库路径和身份密钥范围；热缓存值不需要数据库操作。架构和更新行为不变；无需迁移或操作员操作。

技能研讨会更改源读取和写入以及技能使用读取和写入在现有共享状态工作线程中执行。退役的提案表没有运行时工作者操作； Doctor 在一次性导出时读取它们一次，然后将其丢弃。参见 [ 提案报废 ](/reference/database-schemas/state-schema-history#skill-workshop-proposal-retirement-state-schema-20-same-version)。

Cron 接收执行身份绑定在共享状态工作线程中运行。它的事务在突变和提交之前重新读取确切的实时收据所有者并重新检查调用者的当前执行权限。调用者捕获一个数据库上下文并在释放该权限之前等待解决。新运行绑定收据，而不是任务记录或流程。任务和流生命周期绑定和联接已停用。独立审计事件和决策事实仍属于其现有所有者和保留政策。收据元数据仅保留出处；收集设置、不匹配报告和接收权限保持不变。

Doctor 的本地设备令牌清单在共享状态工作线程中执行。检测器等待其结果并保留角色排序、格式错误的行遗漏和尽力而为的诊断行为。 Lint 将此读取保留在其私有活动状态视图中，并在淘汰该快照之前加入工作线程清理；源路径遗留文件检查保留其单独的环境。设备身份创建保留其现有所有者。

设备配对列表和查找在共享状态只读工作线程中执行。拥有者-写入者收据使工作人员之间的配对快照缓存无效。 CLI 配对突变通过网关路由或拥有排他性离线所有权。 Workers项目列表和节点身份绑定；网关会安装针对配对修订版的绑定，而无需重新打开 SQLite。对较新版本的查找或接收标记已发布的集不完整，但保留其他设备的绑定；只有完整的列表才能替代该集合。历史巡检快照从不发布活节点权限。

配对所有者将其单调递增的发布修订存储在 `config_machine_state` 下的 `devicePairing.revision` 下。每个配对设备写入都会递增同一事务中的该行，并在其提交收据中携带返回的修订版本。仅待处理和引导写入使其保持不变。缺少修订版行意味着修订版为零，直到第一次配对设备写入为止；现有数据库不需要架构迁移。精确查找仅在一个语句中读取键控设备和此修订版，而不加载挂起的请求或散列所有配对记录。完整列表保留其完整快照，连接授权在等待配对工作后仍会查找设备。

配对、批准、角色令牌、引导和节点表面突变在共享状态编写器中执行。每个同步事务都会在突变之前和提交之前读取权威行并获取当前主机策略或连接准入。在调用者继续之前，提交收据会发布修订和更改的节点绑定；不确定的结果不会重播。待定的突变使已发布的绑定可用，因为存储的行在提交之前保持权威，并且下一个绑定读取会安装已提交的收据。 Node 即时准备刷新已发布的信息，Web Push 通过网络启动保留配对和订阅许可，并在提供完成之前释放两者。 APNs 注册检查其工作事务中的配对，并通过相同的代理准入重新验证确切的活动节点连接。

转换不会更改架构、持久记录表示、配置、保留或更新行为。 Doctor/import 交易保持其同步维护所有者；常规 CLI 配对使用与网关相同的工作操作。

Kysely 的 TypeScript 类型不会转换驱动程序结果；驱动程序确定运行时值。请参见 [Kysely 数据类型](https://kysely.dev/docs/recipes/data-types)。 PostgreSQL 事务必须使用一个获取的客户端，其默认的已提交读隔离可以为连续语句提供不同的快照。因此，适配器需要特定于操作的隔离和重试决策，而不是 `BEGIN IMMEDIATE` 的机械替代。请参阅 [node-postgres transactions](https://node-postgres.com/features/transactions) 和 [PostgreSQL 隔离 ](https://www.postgresql.org/docs/current/transaction-iso.html)。

跨存储会话切换保留每个保留的世代、其沿袭、转录字节、物理序列号和记录的事件身份，包括防重复记录的有效所有权。接受的输入和完成收据使用其现有的修复所有者：排队的输入被中断，取消和消费事件引用仍然存在，并且最终目标收据保留优先于可重试尝试的优先级。板、进度卡、心跳结果、建议、参与者历史记录和保留的 ACP 出处使用逻辑节点修复所有者及其现有修订和身份优先级。这些副本不转让实时执行或会员权限。在删除每个复制的代之前，源清理会验证复制事务中捕获的物理源和完整的目标收据。未更改的进程内编写器修订会重用已验证的收据；更改或未解决的作者修订需要精确的重新验证，包括输入和重写水印事实。精确的节点工件指纹通过条目删除来保护源和目标状态。源删除仅在入口边界检查这些节点有效负载；历史生成清理保留其仅生成的检查。当数据库和归档目录保持不变时，就地密钥迁移会保留冷归档；存档清单仍然是其受保护的源快照的一部分。较旧的精确导入可能会保留没有标识行的记录。历史读取器识别未索引的前缀并从存储的事件中恢复显示导航，包括在以后的附加之后；他们从不从 JSON 重建防重复记录的写入权限或所有权。第一个新追加使用现有写入权限下经过验证的投影光标，因此继续保留导入的会话。完整的转录本替换通过创建新的存储代来淘汰该读取路径。

### <a id="keep-engine-specific-capabilities-owned"></a> 保留特定于发动机的功能

Native-close生命周期设计于2026年9月29日被维护者接受。现有的 SQLite runtime/library-selection 所有者发布了一项内部事实：`explicitSqliteCloseReleasesNativeResources`。 Node 供应 `true`，无需支票。选择库后，在 macOS 和 Linux 上拥有 SQLite 池的长期网关、节点和工作主机在创建池之前显式等待一个进程范围内的仅内置检查工作线程的承诺。短 CLI 路径不运行检查。保留的实时语句对私有 WAL 数据库执行普通的、不可重入的关闭和处置，检查本机资源释放，同时不相关的连接仍然可用。结果及其诊断原因通过现有的工作环境数据切换传播。在初始化解决之前，每个操作的消费者都会收到一个保守的未定结果，而不密封全局决策。稍后的读取和关闭路径可以使用完整的事实。网关启动诊断将 `decided: true` 和检查原因与此未确定的后备区分开来。错误、超时和不受支持的 WAL 会保守解决。保守的决定不会等待支票清理；后台清理使工作人员及其五秒截止日期未被引用。在接受成功之前，通过检查会等待相同的有界工作人员加入。只有确认退出才允许删除支票的私人目录。未经确认的退出将保留该目录，取消引用工作线程，并发出一个命名保留路径的 `SQLITE_CLOSE_PROBE_CLEANUP` 警告。 Windows Bun 不会运行检查并保持保守，直到 Windows 一致性运行使其合格为止。工人在创建时继承决策并终生保留，包括在决策之前创建的保守工人；后来的工人继承完成的结果。

每个写入代理在构建时都会根据此事实来快照放置、本地停止确认和退出策略。早期的保守代理即使稍后初始化成功，也会保留其原始拓扑和生命周期；一次性 `SQLITE_EARLY_TOPOLOGY` 警告记录了该情况。使用该功能创建的代理使用现有的 2 到 8 个工作人员池，在不停止不相关的行动人员的情况下释放已确认的已关闭行动人员，并在成功进行目标读取器或转录本发现清理后重用工作人员。保守的运行时保留专用的编写器和本机退出清理。这两种策略都保留队列和客户端限制、别名保管、生成防护、失败或活动操作轮换以及未知结果写入的解决。能力结果不能将真正的清理失败转化为成功。库选择、TypeScript 加载程序、本机工作程序退出连接和不相关的 Bun 兼容性规则保留其自己的所有者。

这不会更改架构、磁盘格式、保留或持久配置。没有保存的功能标志或要反转的迁移。安装的更新程序运行不变；每个新的长期池主机在升级、降级或回滚后都会再次选择其库和功能。短 CLI 路径保持保守，无需检查。非决定性的优化检查保留了受支持的运行时的保守行为，而不会阻止启动或放松运行时和 SQLite 安全底线。实现 PR 记录运行时一致性、生命周期策略和同头性能比较；仅此决定并不构成任何性能要求。

WAL 检查点所有者执行运行时维护、空闲读取器检查、医生压缩和重复代理恢复的检查点。运行时维护保留其健康观察和部分检查点报告；离线维护仍然拒绝在压缩或恢复进行之前进行繁忙的截断。 WAL 框架观测结果归 WAL 所有者所有；行缓存失效使用进程内写入收据，并且不会发出外部提交探测。此所有权削减不会更改架构、存储字节、准入或更新行为。

每个 WAL 连接都拥有一个用于检查点标记和有界回收的调度程序范围。有序的数据库退役会停止计时器准入，并在最终检查点和本机关闭之前加入接受的维护。共享连接仅在其最终本机引用发布后才停止维护；关闭一个工人演员并不会停止兄弟姐妹的维护。同步退出和失败打开清理仍然是尽力取消路径。已弃用的同步调试捕获存储保留了相同的紧密契约。检查点模式、写入准入、存储字节和回收限制保持不变。更新不需要架构或配置迁移；新进程根据现有数据库所有者重建其连接拥有的调度。

SQLite FTS5/BM25、向量表、JSON 表值查询、附加影子数据库、WAL 维护、完整性检查和备份操作仍保留 SQLite 功能。将其实现保留在内存或数据库生命周期所有者之后。未来的后端必须提供等效的产品行为或明确的功能边界；第二种 SQL 方言本身无法取代这些功能。架构、保留、迁移和多主机更改仍然使用下面的审核检查点。

准备好的节点工作空间注册、绑定、突变完成和退役在与节点启动日志相同的共享状态工作线程中运行。仅现有读取不会创建数据库或运行架构打开。文件系统准备和工作空间序列化保留在主机上；在事务准入时写入重新检查取消和主机所有权。退休行仅在丢失突变许可后保持清理状态，并且成功的覆盖仅在持久完成后返回。保留围栏在等待退役逻辑删除时保留旧的同步采集，然后在删除之前保留现有的路径检查。已弃用的公共同步工作区功能保留其读取路径；内部调用者和捆绑插件使用其异步伴侣。表形状、标识符、事务边界和保留的恢复状态保持不变。

会话成员资格、参与者显示事实和类别成员资格在现有会话读取工作线程中准备并由会话行投影保留。存储准入获取紧凑快照；提交的会话出版物刷新确切的密钥并隔离延迟的结果。列表和广播阅读器重复使用这些事实，无需查询成员资格表或为每个观看者传输完整的会话行。提交的缓存和成员身份事实在常驻行投影刷新之前确定；普通观察者随后运行，因此即使是较早注册的广播公司也会看到当前的共享策略和撤销，而显示行仍然是脏的。回滚的保存点更改永远不会到达任一阶段。组目录同样从共享状态工作线程发布其有序快照。这些预测不授权写入：实时呼叫者准入和交易举行的会话以及跨商店目录检查仍由突变所有者保留。隐身成员资格和类别事实属于记忆演员。架构、存储字节、保留和更新行为保持不变。

上游会话监控使用其调度程序范围来取消未来的检查并加入已接受的工作。会话读取使用现有的读取工作线程；事件记录和标记结算在事务和提交准入时重新验证空闲会话。共享状态工作人员在推进其标记或删除丢失的源之前比较完整扫描的上游链接。持久事件插入或重复数据删除仍然先于标记解决。失败的事件记录留下可用于下一次检查的标记。模式、存储字节、保留、提供者合同和更新行为不变；不需要迁移。

## <a id="trajectory-retention-covering-index"></a> 轨迹保持覆盖指数

公认的轨迹保留设计将存储的运行时事件保留在每个代理存储中，并用 `(session_id, run_id, created_at, octet_length(event_json))` 替换其派生的 `idx_agent_trajectory_runtime_run` 索引。保留读取工作线程直接从追加事务外部的覆盖索引进行聚合。没有引入物化事件大小分段、汇总表、触发器、计数器、第二索引或新的持久性所有者。

可写数据库准入通过所需索引所有者及其现有的完整性检查以原子方式修复同名索引。这是代理模式 24 处的仅索引更改；不需要架构版本碰撞或事件转换。一次性重建读取保留的轨迹行并在保存点内构建替换；回滚在失败时恢复旧索引。侦听器绑定后，网关启动会将修复推迟到其代理准备工作线程。稍后的事件写入维护字节长度表达式，包括空运行 ID。较旧的相同版本可写所有者可以在降级或二进制回滚时重建其先前的部分索引，而无需更改事件行。严格的只读验证可能需要在重新打开之前进行可写修复。

保留保留 14 天年龄规则、整体驱逐、当前会话豁免、512 MiB 默认全局预算、JSONL 分隔符记帐和现有数据库编码语义。每会话修剪仍然测量 UTF-8 字节。在写入器准入之前附加序列化事件，并独立于全局清理进行提交。首次使用和每小时清理使用一个生命周期拥有的读取器和删除事务，限制为 16 次运行和 10 MiB，从而允许一次超大的完整运行。删除仅重新验证写入者准许下的选定批次：运行标识、最新时间戳、字节、事件计数和受保护的会话。读取工作线程每次扫描都会聚合一次运行摘要。本机所有者游标会在有限的批次中耗尽该快照；选择和排序在删除事务之前运行。

保留所有者仅持有主动扫描的突变收据。提交的追加会发布其保留会话的运行摘要，包括每个会话的修剪。在所有补丁拥有的写入之后，会话元数据补丁仅推进收据的已提交突变计数器。它们保留轨迹行并重复使用扫描准备好的运行摘要，而无需其他聚合。在接受仅元数据收据之前，所有者修订和租赁检查仍然适用。所有者用这些收据替换受影响的快照会话，因此与快照创建重叠的写入既不会丢失，也不会被计数两次。它的字节和到期事实会确定每个批次，而无需等待免写读取。回滚后不会发布任何收据。拥有写入者的收据和连接本地突变计数使受其他写入影响的事实无效。不完整的覆盖需要新的读取工作快照，而不是写入器保持的扫描或外部提交探测。每次扫描允许一次刷新；另一个则在下一个追加时进行清理。提交的删除在刷新后仍然有效。共享租赁围栏会使取消或业主释放的收据失效；本机连接替换无法重用它们。嵌套同步追加将清理推迟到独立追加为止。

这种内存收据和保守刷新设计于2026年10月5日被维护者接受。权限、持久性、模式、保留行策略和更新行为保持不变。 WAL 检查点安排仍由现有维护所有者负责。

综合 241,697 个事件固定装置测量的总时间为 31-40 毫秒，而分阶段查询的总时间为 407-453 毫秒，所有 3,836 个组都是相等的。替换索引占用了 7,712,768 字节，而旧部分索引占用了 6,598,656 字节，大约多了 1.06 MiB。对于两种形状，不包括提交、缓存逐出和检查点放大，热 320 行 insert/rollback 探测大约需要 0.7 毫秒。这些是组件测量，而不是生产吞吐量或端到端保持保证。回归证明捕获保留读取的聚合计划，要求覆盖访问而无需临时分组或表体读取，断言空运行和命名运行的保留事件，并通过数据库准入打开填充的旧索引装置，而不更改其版本或行。

## <a id="talk-voice-session-lookup-indexes"></a> Talk 语音会话查找索引

语音会话查找更改保留了现有的 `cache_entries` JSON 主体和表格形状。两个部分表达式索引仅包含状态为 `open` 的有效 JSON 记录：一个索引代理、会话密钥和旧客户端推理的来源；其他索引更新过时恢复时间。格式错误的 JSON 和关闭的记录不会进入任一索引。 JSON 表达式是单独保护的，因此不相关的缓存值不需要包含 JSON。

这是存储审查检查点下的仅索引更改。可写准入通过 required-index 所有者安装或修复索引；现有记录不需要 Doctor 转换或架构版本冲突。初始安装扫描一次缓存表。仅当语音记录打开时，后续写入才会维护索引条目。较旧的同版本读者会忽略附加索引；升级、降级和回滚保留记录字节和保留。

遗留推理和陈旧候选解码在现有代理历史记录读取器中运行。恢复会重新检查关闭事务内的截止，因此并发恢复不会从较早的快照关闭。同步工具策略在每个本机连接中最多保留 128 个紧凑的语音事实，这些事实会因承认的模式、所有者作者收据或本地突变修订而失效。事务和固定或授权者控制的读取不会重用这些事实。关闭本机连接会废弃其缓存。呼叫关闭后，确认功能仍可供绑定咨询使用，与开放状态检查无关。

## <a id="session-usage-overview-projection"></a> Session 使用情况概述预测

会话使用将其派生缓存保留在现有 `cache_entries` 所有者中。 `session-cost-usage-rollup-v3` 范围包含版本化的转录检查点和未加时间戳的贡献。相邻的 `session-cost-usage-projection-v1` 范围存储包含四分之一小时会话和模型聚合的 UTC-month 分区。检查点和受影响的分区以原子方式提交。这取代了之前的每个事件的整个历史缓存主体；没有表、索引或数据库架构版本更改。隐身会话保留其现有的进程本地、非持久性缓存，并且不创建月份分区。 Projection 版本 2 将稀疏的季度打包成按月压缩的主体；版本 1 每日行将被忽略并由正常的可恢复刷新替换，无需架构迁移。检查点和分区替换仍然是原子的。

使用承载的转录出版物通过现有的使用工作队列安排进展。每个脏会话都会等待 30 秒，没有其他使用情况发布或活动代理轮流。其最旧的待处理更改在连续轮流中幸存下来：五分钟后，它可以在下一个空闲间隙中刷新。刷新期间开始的回合可能与其已承认的有界批次重叠。用户和元数据行加入下一次使用情况扫描。成本和概览读取刷新并等待挂起的发布批次，绕过空闲延迟，因此已完成的回合的使用情况立即可见。目标预算和提供商计费限制使用自己的当前会计，与此显示投影无关。关闭取消挂起的延迟而不刷新；提交的记录仍然是事实的来源。启动和拓扑更改在有界批次中回填，在批次之间产生。缓存写入在代理写入器 FIFO 外部等待，直到前台工作耗尽，然后一次提交一个会话。报告读取使用其单独的工作通道并在回填期间返回部分或过时的总计。重新启动会从已提交的检查点重新发现未完成的会话。调试级别的关闭日志期间预期刷新取消；刷新或清理失败仍会发出警告。在进程内 DDL 之后，即使保留的读者在挂起时采用了先前共享收据的另一个包装器，工作人员准入也会发布其经过验证的模式。收到的模式和物理数据库证明必须保持有效； JavaScript 包装器标识不会建立较新的架构修订版。仅附加刷新在检查点序列之后恢复，并对每个新页面解码一次。抄本所有者现有的重写水印在重写后使检查点失效；分支更改从可见的祖先中重建。网关使用进程本地保留而不是持久缓存锁定写入来序列化刷新。仅使用写入不会使会话事实无效。刷新工作人员还保留有界的、包含收据的转录统计数据和汇总输入的工作集。未更改的收据重用统计信息（包括生成和冷状态）并跳过未更改的计算。成功的写入会将其检查点和分区输入向前传送；转录写入使统计数据无效，而汇总写入或修剪使汇总输入无效。工人退休会丢弃工作集。报告保留其独立的读取快照。刷新期间的并发修复可以将修正推迟到下一次刷新；它不需要在普通后台路径上进行另一个元数据比较。仅当元数据扫描发现陈旧行时，完全刷新才会提交修剪；删除仍然匹配每个观察到的行的检查点和更新时间戳。 Doctor 负责清理已退休的缓存范围，因此普通刷新不会重复旧删除。停用的行可能会保留到 `openclaw doctor --fix` 运行为止。删除、记录倒带或分支更改以及定价修订通过同一所有者重建。 SQL 和单代理聚合在工作线程中运行。跨代理报告在网关上按全局会话顺序折叠工作人员摘要，以保留浮点加法。仅当报告的记录、使用情况、会话元数据、可见性、配置文件和配置修订保持最新时，报告才会重复使用已完成的结果。

成绩单仍然具有权威性；该预测既不会改变保留数据，也不会改变计费数据。精确的部分季度范围和算术无法通过聚合使用规范转录本读数来表示。部分回填在现有缓存​​状态字段中仍然可见。较旧的实现会忽略新表示的版本并从记录中重建其先前的缓存，因此回滚不需要反向数据迁移。

## <a id="background-exec-notification-obligations"></a> 后台执行通知义务

当符合条件的进程进入后台时，执行完成所有者将 `pendingExecNotifications` 存储在现有专用会话行 JSON 中。每个唯一的注册表进程实例 ID 都保留公共进程 ID、拥有会话 ID 和生命周期修订、网关化身、启动时间、通用命令标签以及现有的完成策略和路由。参数、环境、输出、操作系统句柄、批准和执行权限不会保留。

此附加字段不需要架构迁移或索引。现有的会话编写者提交它；启动过滤 SQL 中的私有事实，并在商店准入后通过现有工作人员仅读取 64 页中匹配的会话列表投影。不相关的条目有效负载和保存的提示保留在 SQLite 中。存储空间随着待处理的后台完成而增长。通知使用当前会话准入和稳定的源轮标识；它无法重新运行该命令。在抄本采用、明确的 cancellation/removal、重置、存档或当前通知策略拒绝之前，事实仍然存在。隐身会话不保留义务。正常会话删除会删除该字段及其行。

较旧的二进制文件会忽略此字段并且不会恢复其通知；稍后的升级可以报告未决的未知结果。回滚不会更改历史记录、执行命令或要求数据库还原。维护者授权的重启连续性修复接受这种范围狭窄的耐久性更改；所有者和单独网关进程测试涵盖生命周期清理和重新启动切换。

## <a id="review-checkpoint-for-material-changes"></a> 审核材料变更检查点

明确的维护人员修复和着陆请求涵盖内部调度、数据库准入和生命周期实施决策。实施者负责设计选择、风险评估和验证。在PR中描述设计及其证据；不需要对该范围内的每个实施决策进行单独批准。

在更改公共合同、模式、持久性、保留或权限之前，打开或链接维护者讨论并记录设计的接受情况。架构版本升级始终需要接受，但保持数字版本不变并不能免除对这些合约的更改：

- a 表、专用数据库、持久投影、持久缓存、索引或其他模式表示
- 哪些数据是真实来源、派生、可重构、保留、删除、导出或重启后可见
- 用户可见的持久性语义，包括现有持久数据的第二种解释
- 升级、降级、回滚、保留、压缩或损坏恢复合约
- 持久性、读取器一致性或权限边界

内部事务边界、写入者准入、锁定和生命周期机制是授权修复中保留这些合约时的工程决策。证明 FIFO 排序、等待工作后的当前权限、完整性检查、发布防护以及可写工作的结算。作为验证的一部分，评估性能和存储成本。

仅删除无效或无法访问的行（例如缺少引用的父行的行）的医生或恢复修复也是授权修复中的工程决策。它必须首先进行经过验证的备份，报告删除的内容，并保持有效数据不变。将修复、备份及其升级兼容性证明记录在PR中；不需要单独的设计验收。更改保留或删除哪些有效数据仍需接受。

当需要单独接受时，讨论应确定所属存储和生命周期、要解决的问题、避免新持久性的替代方案、源数据与派生数据、模式和 upgrade/downgrade 行为、保留和删除行为、并发和恢复不变量、performance/storage 影响、回滚计划和验证限制。实施 PR 必须链接已接受的决定。

检查点通常不适用于保留现有语义的只读查询、没有重大 write/disk 权衡的有界查询计划改进、现有批准模式的例行维护，或仅遵循已接受设计的测试、生成的基线和文档。机械迁移或维修仍然与批准其持久合同的决定相关。

对于紧急的数据丢失、安全或恢复修复，维护者可以在实施之前授权一个范围狭窄的例外。适当的公共或私人审查记录必须记录原因、临时范围、回滚和验证计划以及完整设计决策所需的任何后续行动。例外加速设计记录；它不会放弃合并前的审查。

## <a id="preflight-a-target-release"></a> 预检目标版本

在激活或回滚版本之前，针对一个明确复制的状态数据库，运行目标版本的 CLI：

```bash
openclaw database preflight <copied-state.sqlite> --json
```

该命令不会读取默认状态目录或更改提供的文件。它将提供的合并文件打开为 immutable/read-only，比较目标版本自己的架构契约，并报告一种状态：

- `exact`：复制的数据库与目标版本的运行时架构匹配。那些在首次使用前有意缺失的功能本地表不需要修复。
- `startup-repairable`：数值版本匹配，但仍存在由运行时负责的增量差异；启动时需要写入以使结构趋于一致。
- `migration-required`：数据库版本低于目标版本。
- `incompatible`：数据库版本较新，或同版本结构存在阻塞性偏差，例如出现意外列。
- `indeterminate`：无法验证文件、完整性元数据或所有权元数据。

JSON 输出通过 `schema: "openclaw.state-schema-preflight.v1"` 进行标识。

使用 SQLite 在线备份或安全协调源时生成的另一个 WAL-aware 快照。生成的预检输入必须是一个合并文件，没有同级文件 `-wal`、`-shm` 或 `-journal`； sidecar 的结果为 `indeterminate`。不要仅从活动的 WAL 数据库复制主 `.sqlite` 文件。预检将被激活的确切运行时间；单独的包版本或数字模式版本并不能证明相同版本形状的兼容性。

准备自己的私有只读快照的诊断路径使用[完整性检查](/reference/database-schemas#integrity-checks)中描述的大小派生的子进程预算。

### <a id="preflight-an-explicit-agent-copy"></a> 预检显式代理副本

提供代理读取器的运行时还支持：

```bash
openclaw database preflight-agent <copied-agent.sqlite> --agent-id main --json
```

使用精确的规范化代理 ID 和已解析的非符号链接常规文件路径。此命令通过该版本的维护读取器验证完整性、架构版本标记、架构形状和代理所有权，而无需创建、注册、迁移或修复任何存储。提供的文件必须与 WAL、SHM 或同级期刊进行合并。 JSON 使用`openclaw.agent-schema-preflight.v1`；只有 `exact` 具有兼容性证明。其他结果退出非零并且不需要写入。

共享状态预检无法验证代理数据库。不带 `preflight-agent` 的旧保留有效负载仍然不受支持；在其他地方安装较新的 CLI 不会使这些有效负载兼容。 Runtime/package 身份和服务运行状况是与数据库兼容性分开的检查。成功的只读预检不会授权检查点重放或替换实时数据库。
