## <a id="full-docker-suite-(pnpm-test%3Adocker%3Aall)"></a><a id="full-docker-suite-pnpm-testdockerall"></a> 完整 Docker 套件（`pnpm test:docker:all`）

构建共享的实时测试映像，将 OpenClaw 打包为 npm tarball，将 builds/reuses 打包为裸 Node/Git 运行程序映像，加上将该 tarball 安装到 `/app` 的功能映像，然后通过加权调度程序运行 Docker 烟雾通道。 `scripts/package-openclaw-for-docker.mjs` 是稳定的 local/CI 包打包程序入口点，并在 Docker 使用 tarball 和 `dist/postinstall-inventory.json` 之前验证它。

- 裸图（`OPENCLAW_DOCKER_E2E_BARE_IMAGE`）：installer/update/plugin-dependency泳道；安装预构建的 tarball 而不是复制的存储库源。
- 功能镜像（`OPENCLAW_DOCKER_E2E_FUNCTIONAL_IMAGE`）：普通的已构建应用功能通道。
- 通道定义：`scripts/lib/docker-e2e-scenarios.mts`。规划器：`scripts/lib/docker-e2e-plan.mts`。执行器：`scripts/test-docker-all.mjs`。
- `node scripts/test-docker-all.mjs --plan-json` 发出调度程序拥有的 CI 计划（通道、图像类型、package/live-image 需求、状态场景、凭证检查），而无需构建或运行 Docker。

资源上限的环境变量模式为 `OPENCLAW_DOCKER_ALL_<RESOURCE>_LIMIT`（资源名转为大写，非字母数字字符折叠为 `_`）。

每个lane执行一次；测试、提供程序和超时失败在运行摘要中仍然失败。

其他行为：运行程序默认预检 Docker，清除过时的 OpenClaw E2E 容器，在兼容通道之间共享提供程序 CLI 工具缓存，并在第一次失败后停止调度新的池通道，除非设置了 `OPENCLAW_DOCKER_ALL_FAIL_FAST=0`。如果一个通道超过低并行度主机上的有效 weight/resource 上限，它仍然可以从空池启动并单独运行，直到释放容量。每通道日志、`summary.json`、`failures.json` 和相位时序写入 `.artifacts/docker-tests/<run-id>/` 下；使用 `pnpm test:docker:timings <summary.json>` 检查慢速通道，使用 `pnpm test:docker:rerun <run-id|summary.json|failures.json>` 打印廉价的目标重新运行命令。

### <a id="anthropic-runtime-context-cache-regression"></a> Anthropic 运行时上下文缓存回归

使用 `ANTHROPIC_API_KEY` 运行 `pnpm test:docker:live-anthropic-cache`，以根据 `claude-sonnet-4-6` 验证软件包安装的 Anthropic 提供程序和托管传输。功能图像使用准备好的候选包； `OPENCLAW_SKIP_DOCKER_BUILD=1` 重复使用现有图像。首先通过相同安装的构建器运行 `pnpm test:docker:live-anthropic-cache --mock` 以进行秘密 HTTP/SSE 证明。模拟输出标记其合成用途；只有默认的实时模式才能证明提供程序缓存的读取和写入。

每个构建器都会提出四个请求：初始对话、两个实际的工具结果延续以及下一个用户回合。该工具将合成的临时运行时上下文载体移动到请求尾部，并检查它是否永远不会成为缓存断点或缓存前缀的一部分。初始会话必须写入至少 4,096 个缓存令牌；后续读取必须达到写入的 90%，并且在每次继续后都会增长，而新写入则保持在初始写入的 25% 以下。简短的系统提示可防止仅系统缓存命中满足对话楼层。每个请求都有 90 秒的截止日期，并且不得重试。

此阻塞通道在 stable/full 完整版本验证 Docker `core` 块中运行。日志包含令牌使用情况和断点位置，合成提示内容不输出。网关会话生命周期和保留的运行时上下文仍然由其所有者测试覆盖。

## <a id="onboarding-e2e-(docker)"></a><a id="onboarding-e2e-docker"></a> 入门 E2E（Docker）

可选；仅在容器化入门冒烟测试时需要。在干净的 Linux 容器中执行完整的冷启动流程：

```bash
scripts/e2e/onboard-docker.sh
```

通过伪终端驱动交互式向导，验证 config/workspace/session 状态，然后启动网关并运行 `openclaw health`。

检查维护的 QR 运行时帮助程序是否在默认 Docker Node 24 运行时下加载：

pnpm test:docker:qr
