# <a id="voice-wake-%26-push-to-talk"></a><a id="voice-wake-&amp;-push-to-talk"></a> 语音唤醒与按住说话

## <a id="requirements"></a> 要求

语音唤醒和一键通需要 macOS、26.2 或更新版本。他们的设备控件出现在 **Dashboard → 设置 → 通话 → 这台 Mac** 中，当语音功能在此 Mac 上不可用时报告。

语音唤醒要求 Apple Speech 为所选语言支持设备端识别。当该仅本地模式的约束不可用时，应用会拒绝启动被动唤醒词监听；它绝不会回退到网络识别。按键通话、对话模式和快速聊天听写都是用户的显式操作，并且可以使用 Apple Speech 网络服务以支持更广泛的语言覆盖。

## <a id="modes"></a> 模式

- **唤醒词模式**（默认）：始终开启、在设备端运行的语音识别器会等待触发词（`swabbleTriggerWords`）。匹配后，它会开始捕获，显示带有部分文本的浮层，并在静音后自动发送。
- **按键通话（按住右侧 Option 键）**：按住右侧 Option 键即可立即开始捕获，无需触发词。按住时会显示浮层；松开后会完成识别，并在短暂延迟后转发，这样你可以编辑文本。

## <a id="runtime-behavior-(wake-word)"></a><a id="runtime-behavior-wake-word"></a> 运行时行为（唤醒词）

- 识别器位于 `VoiceWakeRuntime` 中。
- 触发器仅在唤醒字和下一个字之间存在有意义的暂停时触发（`triggerPauseWindow` = 0.55s）。即使在命令开始之前，overlay/chime 也可以在暂停时启动。
- 静音窗口：当语音持续流动时为 2.0s（`silenceWindow`），如果只听到了触发词则为 5.0s（`triggerOnlySilenceWindow`）。
- 硬性停止：120s（`captureHardStop`），用于防止会话失控持续。
- 会话之间的防抖：发送后等待 350ms（`debounceAfterSend`）。
- 叠加层通过`VoiceWakeOverlayController`驱动，并带有committed/volatile文本着​​色。
- 发送后，新的识别任务监听下一个触发。通话、语音唤醒、一键通和快速聊天听写会重复使用其识别器，而所选语言不变；停止捕获仍会释放麦克风并取消任务。

## <a id="lifecycle-invariants"></a> 生命周期不变量

- 如果启用语音唤醒并授予权限，唤醒词识别器将保持监听状态，除非一键通或通话模式拥有麦克风。
- Overlay 关闭（包括通过 X 按钮手动关闭）请求识别器刷新。只有在所有活动语音所有者都释放暂停后，才能恢复收听；在捕获或 Talk 关闭期间，关闭叠加层无法重新启动它。请参阅 [ 语音叠加 ](/platforms/mac/voice-overlay) 了解 session/token 模型。

## <a id="push-to-talk-specifics"></a> 按住说话细节

- 热键检测观察 `.flagsChanged` 和物理右选项标志。即使左侧选项保持按下状态，释放右侧选项也会结束保持。事件永远不会被吞噬。
- Capture 位于 `VoicePushToTalk` 中：权限解析后，仅当相同的保留保持活动状态时才开始语音。在转发之前，发布最多允许 1.5 秒的最终语音结果；空捕获会立即解除。
- 禁用一键通或进入通话模式会取消待处理或活动捕获而不转发。在 Talk 关闭完成之前，一键通将保持不可用，即使其首选项同时发生变化。
- 启动一键通会暂停唤醒词运行时间以避免竞争音频点击。暂停在最后的语音耗尽期间保持不变，并在音频拆卸后释放。
- A 新鲜保留采用可见的覆盖文本，包括仍在等待最终语音结果的先前捕获，而不会转发替换的捕获两次。
- 权限：需要麦克风+语音；接收关键事件需要Accessibility/Input 监控批准。
- 外接键盘：某些键盘不会如预期暴露右 Option。若用户反馈漏检，请提供备用快捷键。

## <a id="user-facing-settings"></a> 面向用户的设置

在 macOS 应用程序中打开 **Dashboard → 设置 → 通话 → 此 Mac** 进行设备语音设置。麦克风和语音权限位于 **仪表板 → 设置 → 本机 → 权限** 下。

- **Voice Wake** 开关：启用唤醒词运行时。
- **按住右侧 Option 键说话**：启用按键说话监视器。
- 如果所选语言在此 Mac 上缺乏设备识别，该页面会解释无法启用语音唤醒的原因。已启用的语音唤醒设置仍可以关闭；一键通和通话模式仍然可用。
- 语言和麦克风选择器选择此 Mac 的输入。 **系统默认**使用系统麦克风。
- 主要语言包括标记为 **（系统）** 的当前系统区域设置。选择它会保存其具体的区域设置标识符（例如，`en_US`），就像本机选择器所做的那样；它不保存空字符串或 `system` 标记。现有系统标记解析为显示此选项，而无需重写已保存的首选项。显示的选择中省略了不可用的其他语言。
- 麦克风测试打开带有实时电平表的本机面板，并使用唤醒词捕获管道而不转发语音。诊断让位于通话模式和一键通。选择 **Done** 关闭面板并释放其麦克风捕获。
- 触发字是 **Talk** 页面上的网关设置，并且在常规浏览器中保持可编辑。 Mac 的唤醒运行时使用主网关的触发字；打开另一个网关窗口不会重新定位该运行时。
- 如果选定的麦克风断开连接，语音运行时会暂时使用系统默认值并在返回时保留选择。
- 触发和发送提示音切换可打开或关闭每个声音。该页面还控制唤醒是否启动通话模式、一键通话、通话阶段声音、切换停止和实时中继。

## <a id="forwarding-behavior"></a> 转发行为

- 在转发时，`VoiceWakeForwarder.selectedSessionOptions` 会优先选择当前活跃的 WebChat 会话键（如果已设置），否则使用网关的主会话键。
- 它通过 `sessions.list` 查找该会话，并从会话的传递上下文中派生传递通道和目标（回退到最后一个 channel/target，然后返回到解析的会话密钥），如果没有解决，则默认为 WebChat。
- 如果交付失败，则会记录错误（`voicewake.forward` 类别），并且通过 WebChat/session 日志仍然可以看到运行情况。

## <a id="forwarding-payload"></a> 转发载荷

- `VoiceWakeForwarder.prefixedTranscript(_:)` 会在转录内容前添加一行机器提示（解析到的主机名，若失败则回退为“这台 Mac”），该行为在唤醒词和按键通话路径之间共享。

## <a id="quick-verification"></a> 快速验证

- 打开按住说话，按住右 Option 键，说话后松开：覆盖层应先显示部分识别结果，然后发送。
- 当语音覆盖可见时，菜单栏耳朵保持放大状态，当其消失时恢复正常。
