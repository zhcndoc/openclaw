OpenClaw 可以在你已经在使用的任何聊天应用上与你交流。每个频道都通过 Gateway 连接。 所有平台都支持文本；媒体和表情反应因频道而异。

标记为“捆绑插件”或“包含在核心中”的条目随核心安装一起提供。标记为“官方插件”的频道可通过一个命令 （`openclaw plugins install @openclaw/<id>`） 安装或在 `openclaw onboard` / `openclaw channels add` 期间按需安装。插件管理将更改应用于正在运行的网关；请参阅 [ 应用更改并检查 ](/plugins/manage-plugins#apply-changes-and-inspect)。 “外部插件”通道在 OpenClaw 存储库外部维护。

## <a id="which-channel-should-i-connect-first%3F"></a><a id="which-channel-should-i-connect-first"></a> 我应该先连接哪个通道？

从 **Telegram** 开始。它需要机器人令牌并且无需安装插件，因此它是最快的工作渠道。 WhatsApp 需要 QR 配对并在磁盘上存储更多状态。

```bash
openclaw channels add --channel telegram --token <bot-token>
```

运行不带标志的 `openclaw channels add` 来从列表中选择一个通道。使用默认的 [hot reload](/gateway/configuration/hot-reload)，正在运行的网关将应用新的帐户配置。检查`openclaw channels status --probe`；如果网关离线，则启动网关。完整演练：[Telegram](/channels/telegram)。命令参考：[`openclaw channels`](/cli/channels)。

## <a id="group-join-introductions"></a> 集团加盟介绍

当机器人加入允许的组时，Discord、LINE、Matrix、Slack 和 Telegram 会发布一个特定于房间的介绍，而不是静默加入。简介中介绍了这个房间的用途，并根据该平台实际可以展示的内容，列出了机器人可以在那里承担的一些具体工作。

**Disabling.** 简介默认处于打开状态。使用 `channels.<channel>.joinIntro: false` 将每个通道关闭，或使用 `channels.<channel>.accounts.<accountId>.joinIntro` 覆盖单个帐户。解析顺序是账户值，然后是通道值，然后是默认的`true`。没有每个房间的开关，因为只有在机器人加入房间后才可以配置房间。仅 Discord、LINE、Matrix、Slack 和 Telegram 接受此选项；其他频道会拒绝它，而不是接受他们从未阅读过的设置。

**它读取的内容。** Core 请求最多 100 条最近消息以及房间元数据，然后将整个快照截断为 12,000 个字符，首先删除最旧的消息。每个平台可以提供的内容有所不同：

| 渠道  | 房间元数据                            | 之前的消息                                  |
| -------- | ---------------------------------------- | ----------------------------------------------- |
| Discord  | 频道名称、主题                      | 最多 100 个，仅限 `Read Message History`     |
| LINE     | 团体名称；多人房间没有  | 无 - Messaging API 没有历史记录阅读器  |
| Matrix   | 房间名称、主题                         | 多达 100 条可读的房间消息                |
| Slack    | 频道名称、目的、主题             | 通过对话历史记录最多 100 个              |
| Telegram | 群组标题、描述、固定消息 | 无 - 机器人 API 无法读取预加入历史记录 |

当历史记录不可用或不可读时，介绍仍然仅从房间元数据发布，并说明它可以看到的内容，而不是发明活动。

**发布的地方。** LINE、Matrix、Slack和Telegram在加入的房间中介绍。 Discord 加入服务器而不是通道，因此当它既可以在系统通道上查看又可以发送时，它使用系统通道，否则使用第一个符合条件的文本通道；如果没有频道符合条件，则会记录跳过而不是发布。

**多久一次。** 每个房间一次。每个频道、帐户和房间都会记录一个具有 90 天生命周期的持久声明，因此重新连接和网关重新启动不会重复介绍。 Discord 另外会忽略超过五分钟的服务器可用事件，因此重新启动绝不会大量引入机器人已经所属的服务器。 Matrix 忽略启动房间快照和使机器人保持连接状态的成员资格更新，例如显示名称更改。未接受的 Matrix 邀请不会触发介绍。索赔过期后重新邀请会再次引入。

**Safety.** 房间标题、主题、固定文本和消息历史记录都是第三方内容，因此它们被包装为不受信任的外部内容，并且介绍轮运行时根本没有可用的工具。嵌入房间的指令无法到达工具。回合时间限制为 60 秒，绝不会在直接消息中运行，也绝不会绕过频道访问策略 - 不允许机器人进入的房间不会得到任何介绍。提及要求不适用，因为加入事件不包含提及机器人的消息。

## <a id="delivery-notes"></a> 交付说明

- 如果可能，包含 Markdown 图像语法的 Telegram 回复（例如 `![alt](url)`）将转换为最终出站路径上的媒体回复。
- Slack 多人私信会按群聊路由，因此群组策略、提及行为和群组会话规则都适用于 MPIM 对话。
- WhatsApp 的设置采用按需安装：引导流程可以在插件包尚未安装时显示，而 Gateway 只有在频道实际处于活动状态时才会加载外部 ClawHub/npm 插件。
- 接受由机器人编写的入站消息的频道可以使用共享的 [机器人循环保护](/channels/bot-loop-protection)，以防止机器人配对彼此无休止地回复。
- 支持常驻房间的频道可以使用 [环境房间事件](/channels/ambient-room-events)， 这样未被提及的房间聊天就会成为安静的上下文，除非代理使用 `message` 工具发送。

## <a id="notes"></a> 说明

- 各个渠道可以同时运行；配置多个后，OpenClaw 会按聊天自动路由。
- 群组行为因渠道而异；参见 [群组](/channels/groups)。
- 为了安全起见，DM 配对和允许列表会强制执行；参见 [安全](/gateway/security)。
- 故障排除：[渠道故障排除](/channels/troubleshooting)。
- 模型提供者单独记录；参见 [ 模型 Providers](/providers/models)。
