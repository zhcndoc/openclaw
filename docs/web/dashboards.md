Control UI 中的每个线程都可以拥有一个 **dashboard** — 您的代理为您构建的实时小部件网格。在侧面板中选择 **Dashboard** 以打开当前任务的面板，甚至在它具有小部件之前也是如此。这会使您的聊天草稿保持不变。当第一个小部件被固定时，仪表板将在可调整大小的侧面板中的对话旁边打开，除非您已经为该任务选择了布局。使用任务工具栏的 **Swap** 按钮交换仪表板和聊天，或其 **Layout** 菜单将侧面板向左、向右或主区域下方移动。稍后的小部件更新会使您当前的面板布局保持不变。关闭并重新打开面板不会重新启动加载的小部件或丢弃其未保存的输入。重新加载页面会启动新的小部件视图。

无需进行任何设置，也没有单独的应用需要配置：仪表板是一个核心功能，归属于线程，随代理一起存储，并且会在 `/new` 和 `/reset` 之后继续保留（对话上下文会清除；看板会保留）。

## <a id="find-your-dashboards"></a> 找到你的仪表盘

打开 `/dashboards` 以卡片库形式浏览支持仪表板的线程。按主题或作者搜索、按作者过滤以及按最近活动或标题排序。没有匹配任务 URL 的存储会话在没有打开链接的情况下仍可作为预览可见。选择链接的卡片以使用您的个人演示覆盖或仪表板的共享默认值打开其所属任务。普通卡片点击会保留在应用程序中并保留保留的小部件交互。在全屏模式下，选择 **Restore split** 以使侧面板与其并排。当线程被重命名、存档或删除时（包括在网关重新连接之后），打开的仪表板页面会更新。如果刷新失败，页面会保持上次加载的仪表板可见，并显示陈旧数据警告。选择 **Retry** 再次加载列表。

当您从其他设备连接到同一网关时，仪表板及其共享演示默认会跟随您。个人演示覆盖、活动仪表板选项卡和其他任务布局选择保持每个设备的 UI 状态。浏览器最多可保留 500 个会话的布局和选项卡首选项，并在达到该限制时保留最近更改的条目。普通任务重新访问会恢复浏览器为该任务保存的安排；画廊卡遵循相同的呈现偏好。增加限制不会恢复已被旧版本驱逐的首选项。

当您切换任务或访问“设置”时，浏览器会在每个加载的窗格中保留最近访问的三个任务，包括其仪表板小部件。返回到保留的任务可以保留小部件交互和阅读位置；更改的内容刷新到位。重新打开时，较旧的任务可能会重新加载。浏览器重新加载或网关或登录用户的更改会清除这些保留的视图。

## <a id="arrange-your-task"></a> 安排你的任务

主区域和侧面板可以显示仪表板或聊天。浏览器、终端、文件和审阅使用相同的布局控件：

- 任务工具栏中的 **Swap** 交换主视图和活动侧面板选项卡。其工具提示为这两个视图命名，例如 **Swap Chat 和 Dashboard**。先前的主视图成为活动的侧面板选项卡；其他选项卡仍然可用。
- 任务工具栏中的 **Layout** 将侧面板向左、向右或主区域下方移动。拖动分隔线以调整其大小。窄窗格使用底部面板，直到再次有空间进行并排布局。
- 单击 **Dashboard** 侧面板选项卡可一步将仪表板扩展到整个任务区域，即使选择了另一个选项卡也是如此。再次单击可恢复分割。箭头键选项卡导航仅选择选项卡； Enter 或 Space 展开或恢复仪表板。其他选项卡保持其正常的选择行为。
- 侧面板关闭的 **×** 旁边的 **Expand** 展开其活动选项卡。相同的控件变为 **Restore split** 并在展开时保留在 **×** 旁边。恢复将返回原始主视图、面板位置和大小，而无需交换聊天和仪表板。关闭展开的面板会返回到主视图。
- 任务工具栏中的 **Focus** 提供了完整任务区域的主视图。 **恢复拆分**恢复侧面板的位置和尺寸。

交换、移动和聚焦可保留实时视图，包括聊天草稿和小部件交互。关闭整个侧面板会隐藏其选项卡并保留主视图。关闭仪表板选项卡会从布局中删除该视图；它不会删除该板。从面板的 **+** 菜单中重新打开它。空仪表板保持打开状态，因此您可以添加其第一个小部件，而无需更改所选布局。任务工具栏位于主窗格上方，当窗格并排时，任务工具栏与侧面板选项卡对齐。在堆叠布局中，每个标题都位于其自己的窗格上方。仅当存在要切换的视图时才会显示侧面板选项卡。

当选项卡具有一个全角小部件时，无论是在分屏视图还是全屏视图中，其标题和控件都位于任务菜单中，而不是小部件上方的药丸。较小的小部件和多小部件选项卡保留其单独的控件。

## <a id="the-board"></a> 面板

- **流体网格。** 通过手柄拖动小部件；一切都会自动回流和压缩。通过手柄调整大小或从小部件菜单中选择预设尺寸（小、中、大、超大）。没有人放置像素——不是你，也不是代理。在窄板上，小部件按照其保存的顺序以全宽堆叠；加宽板会恢复其保存的列宽。
- **自动高度。** HTML 小部件调整其高度以适应其内容。通过手柄调整大小或选择尺寸预设可固定高度。从小部件菜单中选择 **自动高度** 以再次适合内容。
- **Tabs.** 一个看板可以有多个页面 - 例如，一个概述选项卡和一个带有一个大部件的聚焦选项卡。每个选项卡都会记住其小部件布局。访问的选项卡保持加载状态，同时保留仪表板，从而在您切换回来时保留本地过滤器和小部件交互。未访问的选项卡按需加载；更改的内容仍然会刷新，并且删除的选项卡会释放其小部件。将加载的小部件移动到另一个选项卡还会保留其未保存的输入和交互。
- **仪表板视图。** 该板可以占据主要区域或可调整大小的侧面板。当仪表板在侧面板中处于活动状态时，在任务工具栏中选择 **Swap**，然后选择 **Focus** 以获取仅仪表板视图。 **恢复拆分**使侧面板恢复。带有一个全角小部件的选项卡填充焦点仪表板，使用所有可用的宽度和高度，而无需卡片边框。标准 HTML 小部件在最大化时保持其内容填充；明确设置为全出血或无框的小部件保持边缘到边缘。当您调整窗口大小或恢复分割时，嵌入式 MCP 应用程序将遵循可用空间。其小部件控件移至任务工具栏的 **…** 菜单中，不会在页面上留下悬停药丸或拖动和调整手柄大小。授予的权限在该菜单中仍然可用；批准请求和错误在小部件中保持可见。恢复分割或添加另一个小部件会恢复正常间距。
- **默认共享。** 在任务菜单的**Layout**子菜单中，选择**使用当前视图作为默认**使普通会话打开，包括侧边栏链接，在当前视图中显示Dashboard全屏或分割视图。显示仪表板时，**This is the default view** 确认当前全屏或分割视图以及会话的打开视图均与共享默认视图匹配，包括只读查看器。当视图不同时，如果您可以编辑会话，则 **使用当前视图作为默认值** 可用。两者都解释说，个人布局选择仍然适用。仅打开、交换或聚焦面板不会更改共享默认值。如果较旧的仪表板保存了全屏或拆分演示文稿，但仍以聊天方式打开，请选择 **使用当前视图作为默认值** 一次，以将两个选择一起保存。保存不会重新排列已经查看仪表板的任何人；默认值适用于后续打开和重新访问，包括从仪表板库打开。您的浏览器故意的 **Focus** / **Restore split** 选择优先于共享默认值。再次选择共享视图会清除个人覆盖。应用共享默认值不会创建个人覆盖。停靠位置、尺寸和其他面板保持本地不变。重新打开或重新加载未更改的仪表板视图将保留选定的侧面板选项卡，包括侧聊天或聊天保持主要状态时的文件。它还保留了封闭的侧面板或集中的聊天视图。没有演示文稿来源的现有浏览器布局将保留其完整保存的布局，直到您故意选择演示文稿为止； OpenClaw 不会猜测较旧的扩展是否是自动的。本地布局保留仍为 500 个会话。显式 `?dashboard=expanded` 链接仅请求该访问的全屏显示。
- **代理奇偶校验。** 代理的 `dashboard` 工具创建或更新受信任的插件小部件、移动、调整大小和删除小部件、管理选项卡、切换可见选项卡，并请求使用 `set_presentation` 和 `presentation: "split"` 拆分或扩展仪表板或`"expanded"`。 `show_widget` 工具创建或刷新本机报告、自定义 HTML 和注册源小部件。更新使用 `pin: true`、相同的 `name` 和用于 HTML 或注册源的新 `widget_code`，或用于本机报告的新 `report` 对象。板快照标识每个小部件的 `contentOwner` 以及（如果适用）`registeredContentKind`；在替换其内容所有者或注册源类型之前删除小部件。询问“显示财务选项卡并展开仪表板”并观察它的发生。

  要发布初始视图，请将 `dashboard` 与 `action: "set_default_presentation"` 和 `presentation: "split"` 或 `"expanded"` 结合使用。这种持久的操作无需连接浏览器即可工作。 `action: "read"` 返回有效的 `defaultPresentation`，未设置时为 `"split"`。菜单和代理都使用相同的授权`sessions.patch`突变将`boardFace: "dashboard"`和`boardPresentation`保存在一起。可选的 `boardPresentation` 元数据与会话一起存储，在该会话重新启动和 `/new` 或 `/reset` 后仍然存在，并随着会话删除而删除。修补 `boardPresentation: null` 可恢复内置拆分默认值。不需要数据库架构迁移或回填。较旧的版本会忽略此呈现行为；恢复不会删除板或成绩单。

  切换可见选项卡或仪表板演示需要连接 Control UI。如果没有连接，则命令返回`UNAVAILABLE`；打开 Control UI 并重试。 `focus_tab` 在当前位置显示仪表板。聚焦选项卡后调用 `set_presentation`：`presentation: "expanded"` 使仪表板成为主仪表板并聚焦它； `"split"` 使用当前的布局显示它，在仪表板处于主要状态时将聊天功能带到一起。

如果小部件更改失败，则当仪表板刷新而没有任何保存的更改时，其错误仍然可见。您可以从小部件菜单重试。新操作或更新的仪表板状态会清除之前的错误。

## <a id="show-a-website-fullscreen"></a> 全屏显示网站

询问您的智能体：

> 将 <https://status.example.com> 放在此仪表板上，将其展开以填充任务，
> 并将此会话固定在侧边栏中作为“状态”。

内置的 **Website** 小部件直接在浏览器中加载实时站点。它不需要插件、中继服务器或复制的网站代码。一个全宽网站填充了扩展的仪表板；添加其他小部件会恢复正常网格。该网站控制自己的刷新和导航。

代理使用现有的 `dashboard` 工具创建它：

```json
{
  "action": "widget_put",
  "name": "status",
  "title": "Status",
  "pluginKind": "session:website",
  "props": { "url": "https://status.example.com" },
  "size": "full"
}
```

然后它用 `action: "set_presentation"` 和 `presentation: "expanded"` 调用 `dashboard`。会话命名和固定使用现有的 `sessions` 工具。重新使用小部件名称来更改其 URL。 URL 和布局与电路板保持一致；扩展的呈现遵循现有的每设备任务布局首选项。网站小部件不会加载到图库缩略图中。

URL 必须使用 HTTPS，不包含用户名或密码，且长度不超过 2048 个字符。渲染器拒绝 Control UI 和连接的网关主机名，包括使用这些主机上的另一个端口的 URL。该框架支持网站的脚本、表单、存储和链接，但不接收注入的网关令牌、小部件工具桥或导航父应用程序的权限。它遵循网站自身的身份验证和您浏览器的 cookie 策略。

有些网站拒绝嵌入，有些登录流程需要单独的选项卡。如果框架保持空白或无法登录，请使用 **打开网站**。OpenClaw 不会代理该网站或删除其嵌入限制。此小部件与自定义 HTML 小部件分开，不会放松其沙箱或网络授权。

## <a id="share-a-browser-dashboard-with-your-agent"></a> 与您的客服人员共享浏览器仪表板

当您想要一个已保存的仪表板（您的代理可以在其中读取您所看到的同一页面并与之交互）时，请请求 **浏览器仪表板**：

> 打开此 HTTP 状态应用程序作为全屏仪表板。将此会话固定为
> Service Status，并在我要求您更改其过滤器时使用同一页面。

要在聊天旁边显示浏览器，请要求打开 [ 浏览器侧面板 ](/web/control-ui/panels#browser-panel)。这将打开现有面板，而无需创建仪表板小部件或扩展面板。

浏览器插件的 `browser:dashboard` 小部件在本地 OpenClaw- 托管浏览器中显示一个选项卡。 Control UI 流式传输该选项卡，因此当 Control UI 本身使用 HTTPS 时，HTTP 应用程序也可以工作。浏览器现有的导航策略仍然适用。它不会继承您手机或笔记本电脑上的浏览器 cookie。管理员使用托管配置文件的登录会话。其他会话编写器使用带有自己的 cookie 和存储的隔离上下文。

代理通过 `dashboard` 创建小部件：

```json
{
  "action": "widget_put",
  "name": "service-status",
  "title": "Service Status",
  "pluginKind": "browser:dashboard",
  "props": { "url": "http://status.example.com" },
  "size": "full"
}
```

然后，它使用现有的 `browser` 工具和小部件名称：

```json
{ "action": "snapshot", "dashboard": "service-status", "refs": "aria" }
```

`act` 和 `navigate` 接受相同的 `dashboard` 选择器。选择器解析当前选项卡，因此代理不需要重新打开 URL 或猜测目标 ID。使用`dashboard`排列棋盘，使用`set_presentation`扩展它，并删除小部件；会话命名和固定使用 `sessions`。不需要单独的特定于站点的工具。

对于管理员来说，隐藏仪表板或重置其对话会保留其浏览器选项卡。普通选项卡关闭和空闲清理不会关闭仪表板拥有的选项卡。使用 **停止浏览器** 释放正在运行的选项卡，使用 **恢复浏览器** 再次打开它。代理等效项是 `browser` 与 `action: "close"` 或 `"open"` 以及 `dashboard` 选择器。首次打开之前停止也会持续存在，无需启动浏览器；重新打开仪表板或重新启动网关会使其暂停，直到恢复。恢复加载已保存的URL；关闭浏览器后，未保存的文档状态将无法保存。如果关闭暂时不可用，仪表板会显示停止正在等待，并提供 **Retry stop**，直到确认关闭。当浏览器收到面板更改时，删除或替换小部件会释放其旧选项卡；现有的清理周期还可以协调遗漏的更改。图库预览永远不会启动浏览器。

管理员浏览器仪表板需要浏览器访问权限并默认使用 `openclaw` 托管配置文件。可选 `props.profile` 选择另一个本地托管配置文件；此小部件不支持附加的个人浏览器、节点路由和远程浏览器配置文件。当您只需要在自己的浏览器中显示可嵌入的 HTTPS 网站时，轻量级 **Website** 小部件仍然很有用。

### <a id="session-writer-access"></a> 会话写入者访问

启用浏览器插件后，非管理员会话编写者可以在没有 `operator.admin` 的情况下打开浏览器仪表板。 `operator.write` 保留会话的现有协作者规则。较窄的 `operator.sessions.write` 仅授予对调用者自己的会话的访问权限。有效的浏览器工具政策仍然适用；此功能不会更改角色或工具默认值。

**Session browser** 模式使用配置的默认本地托管配置文件为该会话和小部件启动空的、隔离的浏览器上下文。不支持自定义、附加、个人、扩展、节点和远程配置文件。 Cookie 和存储与管理员浏览器和其他会话是分开的。代理的 `dashboard` 选择器在代表非管理员操作员时使用相同的上下文。管理员视图和选择器继续使用其单独的托管配置文件选项卡；它们的页面状态不与会话浏览器共享。

会话浏览器支持页面导航、检查、截图和交互。它不公开配置文件管理、任意选项卡选择、文件传输或 cookie/storage 管理。通用浏览器工具保留其现有配置的 host/profile 访问权限：此隔离适用于仪表板路由和选择器，而不适用于整个代理。

上下文在正常回合结束或观看者断开连接后仍然存在。撤销某人的访问权限会停止其查看者和操作，而不会破坏其他授权协作者的上下文。重置或删除会话、删除小部件、停用浏览器配置文件或重新启动网关都会关闭上下文。会话浏览器的Stop状态在内存中；恢复从保存的小部件 URL 开始。网关最多保留64条独立的仪表板记录；如果达到该限制，请删除未使用的浏览器小部件。

需要沙箱或锁定模型选择的会话无法使用此模式。隔离的网关浏览器上下文不是沙箱后端。现有管理员浏览器路径在其现有规则下仍然可用。

## <a id="what-widgets-are-allowed-to-do"></a> 小部件允许执行的操作

撤销会话访问权限会拒绝新的仪表板写入。当访问被撤销时已经在进行的写入可能仍然完成保存其小部件或布局。阅读私人内容和使用小部件的工具仍然需要当前访问权限。

自定义 HTML 和仅渲染的注册源小部件不需要批准 - 它们会立即出现，就像内联聊天小部件一样，并且它们的网络访问完全禁用。

想要 **reach** 的小部件必须声明它。显式的 [ 会话权限模式 ](/gateway/permission-modes) 决定发生什么： **完全访问** 立即授予； **Workspace** 使用 AI 审阅者并拒绝任何其不允许的内容； **Guarded** 显示 **Allow** / **Reject** 卡； **只读** 拒绝请求。如果没有显式会话模式，则应用等效配置的执行批准策略。

- **网络**（`net`）：从沙箱中直接获取已声明的 HTTPS 源——例如，一个会从 API 自行刷新的天气卡片。
- **网关数据**（`data`）：只读信息流，如会话、用量或 cron 状态，由网关解析——小部件绝不会持有你的令牌。
- **自动化**（`actions`）：触发特定的 cron 作业，因此按钮可以运行一个真正的任务（可能会使用更小的模型），而不会唤醒你的主对话。
- **提示**（`prompt`）：将消息发送到你的线程中，而无需未批准小部件所要求的逐次点击确认。

已启用的插件可以向这些能力列表中添加它们自己命名的只读信息流和操作；禁用插件会移除这些集成。

拨款与您的会话策略批准的确切小部件字节绑定。即使权限保持不变或缩小，更改的 HTML 或注册源字节也需要新的决定。仅当批准的字节仍然匹配并且请求的权限不扩大时，才会保留授予。创作结果区分待定、拒绝和已授予的访问权限；保存小部件并不意味着其功能已获得批准。当同一代理在另一个会话中重新创建具有相同名称、源和声明的 HTML 或注册源小部件时，自动审核可以重复使用低风险批准。当运行时配置或执行批准策略更改时，这种有界内存中重用会重置。每个会话的当前权限模式和每个小部件的授予权限仍然适用。 MCP 应用程序和隐身会话不会重复使用这些评估。新内容仍在等待审核。代理应该了解的小部件交互（您单击的过滤器、您切换的视图）会在会话通知时悄悄地到达它 — 它会保持通知状态而不会被中断。

## <a id="mcp-apps-on-the-board"></a> 面板上的 MCP 应用

如果您的网关配置了 MCP 服务器，则可以像任何小部件一样固定聊天中显示的交互式 MCP 应用程序。固定的应用程序通过新的会话在板上重新焕发活力。默认情况下，它们无需服务器工具或同一服务器资源访问即可进行渲染。授予小部件其声明的服务器工具可以启用两个桥，同时修订版绑定的授予保持活动状态。

## <a id="a2ui-widgets"></a> A2UI 小部件

启用 Canvas 插件后，代理可以将 A2UI JSONL 呈现为仪表板小部件。 A2UI 小部件使用与 HTML 小部件相同的稳定名称、选项卡、大小、固定、沙箱和就地更新行为。渲染器是从网关的 `/__openclaw__/a2ui/` 资源路径加载的，因此渲染器包不会复制到每个小部件中。必须启用 Canvas 插件及其托管路由；两者均默认启用。

A2UI 操作使用普通的小部件桥。默认情况下，点击会变成安静会话通知，代理会在下一回合看到。如果小部件声明并接收 `prompt` 授权，则其操作可以改为向线程发送可见提示。禁用 Canvas 插件会删除 A2UI 类型，并使存储的小部件明显不可用，直到再次启用该插件为止。

## <a id="retired-workspaces"></a> 退休工作空间

实验性 Workspaces 插件、其 Control UI 选项卡、`openclaw workspaces` CLI 和 `workspace_*` 工具已被删除。会话仪表板使用不同的存储模型：每个板都属于一个会话，并且存在于所属代理的数据库中。旧版工作区文档和数据库不会自动转换。

在运行 `openclaw doctor --fix` 之前保留任何旧文档、数据和小部件资产：其工作区修复会删除 `<stateDir>/workspaces` 下识别的旧状态，而不将该内容导入仪表板。

## <a id="good-to-know"></a> 了解须知

- 重置带有看板的线程时会要求确认，并会保留该看板。
- 删除线程会删除其看板。
- 看板存储在你的网关上（位于所属代理的数据库中），并会在你连接的每台设备上显示。
- 支持仪表板的线程出现在 `/dashboards` 中。关闭仪表板选项卡或侧面板不会删除仪表板或将其从库中删除。
- [仪表板 Architecture](/web/dashboard-architecture) 中包含安全模型、存储详细信息和设计原理，包括记录的沙箱权衡。
