Control UI 中的每个线程都有两面：你熟悉的对话，以及一个由代理为你构建的实时小部件网格，即
**仪表板**——。没有小部件的线程就只是聊天。小部件一旦被固定，标题栏中就会出现
**聊天 | 分屏 | 仪表板**切换开关：聊天仅显示对话，分屏显示仪表板并将聊天停靠在其旁边，而仪表板则让看板占据整个界面。

无需进行任何设置，也没有单独的应用需要配置：仪表板是一个核心功能，归属于线程，随代理一起存储，并且会在
`/new` 和 `/reset` 之后继续保留（对话上下文会清除；看板会保留）。

## 找到你的仪表盘

打开 `/dashboards`，即可查看所有首选界面为“仪表盘”的线程，最近更新的线程排在最前面。打开任意一行，即可直接进入该线程的
`/dashboard/<agent>/<sessionRef>` URL。打开的“仪表盘”页面会随着线程被重命名、归档、删除，或在“聊天”和“仪表盘”之间切换而更新，包括网关重新连接之后。

聊天或仪表盘界面偏好会按线程保存在服务器端。因此，当你从另一台设备连接到同一个网关时，它也会随你而来。从侧边栏、Sessions、Tasks、Workboard 或 Worktrees 打开线程时，即使该线程不在浏览器已加载的会话页面范围内，也会应用已存储的界面偏好。
活动的仪表盘标签页和记住的聊天停靠位置属于按设备保存的界面状态，因此每个浏览器都可以保留自己的工作布局。

## 通过询问来构建仪表板

告诉你的代理你想看到什么：

> 创建一个名为 revenue-graph 的小组件：一个按月收入的交互式柱状图。添加 “Bars” 和 “Trend” 按钮，用于切换视图。将它固定到我的仪表板上。

代理会先在聊天中内联渲染这个小组件，这样你可以先查看它，再决定是否放到别处。从这里开始：

- **你来固定它**：将鼠标悬停在内联小组件上，然后选择 **Pin to dashboard**。
- **或者代理直接固定它**：当你提出请求时，代理会直接将其固定，并在之后按名称更新它——小组件具有稳定的名称，因此“用 6 月的数据更新 revenue-graph”会在原位替换内容，同时面板保持不变。

小组件是自包含的小型应用（在严格沙盒中的 HTML/JS/SVG）。小组件内部的按钮和视图切换会立即生效——切换图表视图完全不需要代理。

## 面板

- **流式网格。** 通过控件的拖动手柄拖动控件；所有内容都会自动重新排列并紧凑布局。通过手柄调整大小，或从控件菜单中选择尺寸预设（小、中、大、超大）。无需手动放置像素——无论是你还是代理都不需要。
- **标签页。** 一个面板可以包含多个页面——例如，一个概览标签页和一个带有大型控件的专注标签页。每个标签页都会记住自己的聊天停靠位置。
- **停靠式聊天。** 在分栏模式下，你的对话可以停靠在左侧、右侧或底部——通过标题栏切换按钮上的小箭头选择位置——并且可以像侧边栏一样调整大小。选择“仪表盘”即可完全隐藏聊天；当你重新打开聊天时，代理仍能听到你的消息。
- **代理功能对等。** 你能执行的所有操作，代理都可以通过其 `dashboard` 工具完成：添加、更新、移动、调整大小和移除控件，管理标签页，切换可见标签页，以及移动或隐藏聊天停靠栏。你可以说“把聊天放在左侧并显示财务标签页”，然后看着它完成。

## 小部件允许执行的操作

仅负责渲染的小部件无需批准——它会立即显示，就像内联聊天小部件一样，而且其网络访问会被完全禁用。

想要获得**访问权限**的小部件必须声明它，并且你只需一键即可为每个小部件授予一次：

- **网络**（`net`）：从沙箱中直接获取已声明的 HTTPS 源——例如，一个会从 API 自行刷新的天气卡片。
- **网关数据**（`data`）：只读信息流，如会话、用量或 cron 状态，由网关解析——小部件绝不会持有你的令牌。
- **自动化**（`actions`）：触发特定的 cron 作业，因此按钮可以运行一个真正的任务（可能会使用更小的模型），而不会唤醒你的主对话。
- **提示**（`prompt`）：将消息发送到你的线程中，而无需未批准小部件所要求的逐次点击确认。

已启用的插件可以向这些能力列表中添加它们自己命名的只读信息流和操作；禁用插件会移除这些集成。

授予权限会绑定到你审查过的确切小部件字节和版本。如果代理更改了小部件并请求比你批准的**更多**权限，它会回到待处理状态；在相同权限下刷新内容会保留该授权。代理应当知道的小部件交互（例如你点击的筛选器、切换的视图）会作为会话通知悄悄传递给它——它可以在不中断的情况下保持知情。

## 面板上的 MCP 应用

如果你的网关已配置 MCP 服务器，那么聊天中出现的交互式 MCP 应用可以像任何小部件一样被固定到面板上。固定的应用会在面板上以新的会话重新激活；默认情况下它们仅用于显示，授予该小部件其声明的服务器工具后，它就会变得完全可交互——并且与其他内容一样，享有同样的一键式、按修订版本绑定的审批。

## 了解须知

- 重置带有看板的线程时会要求确认，并会保留该看板。
- 删除线程会删除其看板。
- 看板存储在你的网关上（位于所属代理的数据库中），并会在你连接的每台设备上显示。
- 将线程切换到看板界面会把它添加到 `/dashboards`。再切回聊天界面会将其移除。
- 安全模型、存储细节和设计原因都记录在 [看板架构](/web/dashboard-architecture) 中，其中也包含已说明的沙箱权衡。
