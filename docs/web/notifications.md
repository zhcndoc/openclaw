当有事情需要您注意时，包括执行或插件批准请求，OpenClaw 可以 ping 您。 ping 到达运行 Control UI 的浏览器。当您使用 OpenClaw macOS 应用程序时，它还可以通过本机 macOS 通知到达。您的第一次聊天发送可能会自动请求权限。 **设置→通知**仍然是启用或修复当前设备的位置。使用同一页面检查其状态并向自己发送测试。

本页涵盖了这两个表面。它不控制通道反应通知、Android通知转发或iOS后台推送。移动应用程序通过自己的节点路径注册推送。请参阅 [iOS](/platforms/ios) 和 [Nodes](/nodes)。

## <a id="which-surface-you-get"></a> 你获得的界面类型

“通知”页面的控制项取决于你从哪里打开它：

| 设置打开的位置                            | 传输方式                                          | 你可以执行的操作                                                                                         |
| ------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 支持的网络浏览器或已安装的 Control UI PWA | 浏览器通过 Control UI 服务工作者推送 API | 接收批准和启用的关注类别、管理此浏览器的订阅并发送测试 |
| OpenClaw macOS 应用                                | 原生 macOS 通知                         | 授予应用权限、被阻止时跳转到系统设置、发送本地测试通知                           |
| 不支持推送 API 的浏览器                  | 无                                               | 仅状态。启用和测试保持不可用                                                           |

macOS 应用程序故意使用本机权限流而不是浏览器推送。这是您的 Mac 已经遵循的通知系统。

## <a id="enable-browser-notifications"></a> 启用浏览器通知

当您第一次发送聊天消息时，Control UI 会自动请求通知权限。其中包括从 **新会话** 或 **在后台启动** 发送。每个浏览器和来源都会出现一次提示。 **设置→通知**仍然是启用或修复通知的手动路径，包括在您拒绝自动提示之后。

1. 在支持 service worker、`PushManager` 和通知的浏览器中打开 Control UI。
2. 确保 Control UI 已连接到网关。
3. 打开 **设置 → 通知**，然后选择 **启用通知**。
4. 在浏览器询问时允许通知。
5. 选择 **发送测试** —— 几秒钟内应该会收到测试通知。

在幕后，启用会在此浏览器中创建推送订阅，并向网关注册其端点和密钥。网关将订阅绑定到浏览器的配对设备，并且在启用操作员角色时，将其经过身份验证的用户配置文件绑定。网关将浏览器订阅及其 VAPID 签名密钥保留在 `state/openclaw.sqlite` 中 — 没有要编辑的 `openclaw.json` 密钥。当 Control UI 重新连接时，现有订阅将自动与网关进行协调。

浏览器注册和通知设置读取不会等待后台通知来加载对话访问数据。网关在发送每个通知之前仍会重新检查当前访问。

批准通知使用通用锁屏文本。命令、工作目录、提示和插件详细信息不包含在推送有效负载中。选择通知将打开经过身份验证的 `/approve/<approvalId>` 页面。每次发送之前，网关都会重新检查配对设备的当前批准范围、操作员角色、用户配置文件和批准可见性。被撤销或降级的浏览器将停止接收批准推送，无需先取消订阅。

### <a id="choose-what-reaches-each-device"></a> 选择到达每个设备的内容

订阅后，**Settings→Notifications** 公开两个首选项层：

- **帐户默认值** 遵循跨设备的持久的经过身份验证的用户配置文件。他们控制批准请求和更新、代理完成、代理问题和人工提及。它们还控制计划任务失败、后台任务失败、锁屏详细信息、安静时间、时区和可选的代理白名单。
- **此浏览器或应用程序** 可以将一个浏览器配置文件或已安装的主屏幕应用程序静音。它还可以添加源标签或覆盖单个类别。帐户默认值保持不变。本机 OpenClaw 应用程序通知是单独配置的。

单用户网关使用其持久的所有者配置文件作为帐户默认值，因此这些首选项可以跨设备跟随所有者。没有配置文件的连接保留控件，但仅存储当前浏览器订阅的首选项。首选项从不授予访问权限：每次交付仍会重新检查配对设备、当前角色和范围、经过身份验证的配置文件以及会话可见性。没有权威会话所有者的多用户事件将被抑制，而不是广播给每个操作员。

默认情况下，批准请求和解决通知处于启用状态，并且所有其他关注类别都是选择加入的。安静的时间会抑制匹配的发送，而不是将过时的警报排队以供以后发送。

选择注意通知会在生成它的网关上打开其问题、对话或自动化运行。 **代理完成**等待完成。等待子代理的父代理不算作完成。自动化故障使用 **计划任务故障**，而不会为同一运行生成 **后台任务故障** 警报。

详细级别为：

- **Private** — 仅通用注意文本。
- **仅名称** — 可能包括已清理的人员、会话、设备、代理、任务或自动化标签。
- **Detailed** — 目前使用相同的有界、经过净化的生产者拥有的标签。消息摘录、原始提示、命令参数、输出、环境值和错误永远不会进入推送负载。

在 iPhone 和 iPad 上，只需完成两步即可使用 Web Push。首先，安装 Control UI 和 **Share → 添加到主屏幕**。然后打开已安装的应用程序。普通的 Safari 选项卡仍然可用于 Control UI。在该选项卡中，“通知”页面报告安装要求。它不会尝试取消引用不可用的 `PushManager`。

**发送测试**要求网关将测试消息推送到每个注册的浏览器订阅。测试仅有意检查传输。批准请求针对授权设备绑定。仅当其配对设备和用户配置文件仍拥有订阅时，**Unsubscribe** 才会从网关中删除当前浏览器的端点。然后它在本地取消订阅。在另一个配置文件下重新连接只能使用其现有订阅密钥转移浏览器订阅。仅了解端点无法更改其所有者或将其删除。

网关将 Web Push 直接发送到浏览器供应商的推送服务。这与自托管网关配合使用，不使用 OpenClaw- 托管的 iOS 中继。

### <a id="receive-human-mention-alerts"></a> 接收人工提及警报

在支持的浏览器中订阅或安装Control UI PWA后，打开****设置→通知**下有人提到我**。默认情况下，类别为**off**，并且需要登录的网关配置文件。帐户默认设置可以在您的设备上启用它。当前浏览器可以覆盖或静音它。这些类别控件针对订阅的 Web 客户端显示，而不针对本机 macOS 通知设置。

只有绑定到上述配置文件的浏览器才会收到警报。每次交付都会重新检查设备、当前配置文件和角色、读取范围和会话可见性。然后，它会应用类别设置、安静时间和代理过滤器。不需要在线。通过 **Private** 详细信息，警报仅表示有人在对话中提到了您。 **仅名称** 和 **Detailed** 可能包括已清理的发件人和会话标签，而不是消息摘录。选择它会通过正常的经过身份验证的 Control UI 路由打开会话。

您的 [ 提及 Inbox](/concepts/multi-user#temporary-mentions-inbox) 不依赖于 Web 推送权限或此设置。在 Gateway 重新启动后，其条目和删除将在 7 天的保留期内继续存在。打开收件箱、重新连接或重新启动网关不会将旧条目作为浏览器通知重新发送。 Service Worker 显示浏览器警报。实时收件箱更新不会创建第二个 OS 通知。人工提及警报不是通过本机 macOS 或 iOS/Android 推送路径实现的。

要检查定位，请让其他符合条件的登录人员从聊天 `@` 选择器中选择您并发送普通消息。检查 **Inbox → Mentions**，然后检查已启用的浏览器警报。 **发送测试**仅检查浏览器推送传输，并且可以到达每个注册的订阅。它并不能证明人工提及是被选择、提交或针对您的个人资料的。交付是尽最大努力，而不是一次性保证。

### <a id="use-more-than-one-gateway-on-one-phone"></a> 在一部手机上使用多个网关

建议的自托管设置是每个网关一个 Control UI 服务工作线程范围。从其自己的 HTTPS 源或基本路径打开或安装每个网关的 PWA。在那里启用通知。升级后重新连接一次。然后，每个范围都拥有一个独立的浏览器订阅，并且批准链接返回到创建它们的网关。

单个安装的 PWA 也可以在远程网关之间切换。该 PWA 后面的每个网关都必须使用相同的 VAPID 密钥对。每个还必须将 `gateway.publicOrigin` 设置为其浏览器可访问的 HTTPS 原点。将 PWA 重新连接到每个网关一次，以便每个网关注册共享浏览器订阅和当前的 device/profile 绑定。批准通知链接保留在已安装的 PWA 范围内，并在其片段中携带所属网关 URL。 Control UI 在身份验证之前删除片段并使用正常的远程网关切换。

浏览器 Push API 只允许每个服务工作人员注册一个应用程序服务器密钥。如果 PWA 订阅属于不同的 VAPID 密钥，则 OpenClaw 将从当前网关中删除不可用的行。 OpenClaw 还显示 **Unavailable** 和 **Not subscribed**，并显示错误解释不匹配。要将 PWA 范围切换到当前网关，请选择 **Unsubscribe**，然后选择 **启用通知** 和 **发送测试**。取消订阅会停用通过该范围注册的每个网关的共享浏览器订阅。重新启用后，重新连接每个网关一次。

共享私有 VAPID 密钥和浏览器端点使这些网关成为一个推送签名信任域。仅对您同样信任的网关使用该布局。通过每个网关进程的安全环境或秘密管理器配置 VAPID 值。不要将私钥放在 URL 或命令参数中。

## <a id="enable-notifications-in-the-macos-app"></a> 在 macOS 应用中启用通知

macOS 应用程序还会在您第一次聊天发送时自动询问，但前提是权限为 **未请求**。拒绝后它永远不会自动打开系统设置。使用**设置→通知**手动管理权限。

1. 在 OpenClaw macOS 应用中打开 **设置 → 通知**。
2. 当权限显示为 **未请求** 时，选择 **启用通知**。
3. 批准 macOS 权限提示。
4. 选择 **发送测试** 以发布本地 OpenClaw 通知。

如果权限显示**Denied**，则macOS不会重新提示。选择**打开系统设置**。在那里允许 OpenClaw 的通知。然后切换回来。当应用程序重新获得焦点时，页面会重新检查权限。该权限属于macOS，不属于网关配置。

### <a id="background-session-completion"></a> 后台会话完成

您可以从 **New Session** 在后台启动会话。然后，macOS 应用程序会在运行完成后发布本机通知。这需要已授予通知权限。在运行时保持原始仪表板加载。您可以最小化其窗口或在其他应用程序中工作。还会显示应用程序内完成消息。在会话完成之前选择该会话会抑制其完成通知。

本机通知使用通用文本，没有会话标题、提示或响应。选择它可在其原始网关上打开会话，包括该窗口关闭后的时间。如果该网关连接发生更改，请从正确的网关会话列表中打开会话。如果通知在应用程序重新启动后过期，请执行相同的操作。

这是 **New Session** 后台启动流程，而不是每个聊天响应的本机通知。浏览器**代理完成**首选项保持独立。完成后台运行永远不会打开新的权限提示。首先在“设置”中启用通知。

## <a id="troubleshooting"></a> 故障排查

### <a id="enable-is-unavailable"></a> 启用不可用

浏览器缺少所需的 Web Push API，或者 Control UI 未连接到网关。尝试使用当前浏览器，检查网关连接，然后重新加载页面。

### <a id="browser-permission-is-blocked"></a> 浏览器权限被阻止

无法从页面重新打开被拒绝的浏览器权限。在浏览器的站点设置中允许 Control UI 源的通知，然后重新加载设置。

### <a id="permission-is-granted-but-the-browser-is-not-subscribed"></a> 已授予权限但浏览器未订阅

浏览器权限和网关订阅是分开的。选择**启用通知**来注册此浏览器，然后启用您想要的类别，例如**有人提到我**。重新加载或发送另一条消息不会自动订阅已授予权限的浏览器。这保留了有意取消订阅。

### <a id="service-worker-is-not-ready"></a> Service Worker 尚未准备就绪

Control UI 等待其服务工作线程长达 10 秒。如果更新后立即超时，请硬刷新页面。如果旧工作人员留下来，请清除仪表板源的站点数据并重新连接。

### <a id="web-push-asks-for-a-doctor-migration"></a> Web Push 要求执行 Doctor 迁移

在网关停止的情况下运行 `openclaw doctor --fix`。在 Doctor 将已弃用的 JSON 存储导入 SQLite 之前，Web Push 会拒绝使用这些存储。

### <a id="an-enabled-notification-does-not-arrive"></a> 启用的通知未到达

检查网关的`gateway/web-push`日志。准备失败包括类别、阶段（`subscriptions`、`sender` 或 `authority`）、错误类别、原因和堆栈。推送服务失败包括订阅 ID、端点主机、HTTP 状态、响应正文以及订阅是否将被修剪或保留。这些诊断信息将原始写入本地日志；在分享之前先查看它们。

HTTP 404 和 410 响应会删除无效订阅，除非有较新的注册已替换它。在该浏览器中重新启用通知以再次订阅。其他失败保留订阅。失败的事件不会自动重试； `retry=false` 记录该决定。清理警告意味着删除失败，因此可以在下一个事件中尝试过时的订阅。在再次测试之前更正报告的存储问题。

### <a id="tests-arrive-but-approval-requests-do-not"></a> 测试已到达，但批准请求未到达

重新连接或重新加载 Control UI 一次，以便将旧订阅绑定到当前配对的设备。该设备仍必须具有 `operator.approvals` 和 `operator.read`。启用网关角色后，当前用户配置文件的角色也必须允许这些范围。批准可见性和会话共享规则可以有意排除同一网关发送给另一个操作员的请求。

对于在网关之间切换的单个 PWA，还要检查两件事。每个网关必须使用相同的 VAPID 密钥对。每个网关必须有一个可通过浏览器访问的 `gateway.publicOrigin`。单独的 PWA 源或基本路径范围不需要共享 VAPID 密钥。

### <a id="a-mention-is-missing-or-produces-no-browser-alert"></a> A 提及缺失或不产生浏览器警报

检查发件人是否从选择器中选择了您的个人资料，而不是仅输入您的姓名。检查原始消息是否已到达转录本。使用相同的配置文件登录并检查您是否仍然有权访问该会话。隐身、目标、目录、仅建议和命令发送模式不支持人工提及。

如果该条目位于 **Inbox → Mentions** 中，请检查此浏览器的订阅，并且 **有人提到了我**。还要检查安静时间、静音覆盖和代理过滤器。收件箱条目并不意味着有权显示浏览器通知。如果该条目消失，则可能已使用您的个人资料从另一个浏览器中将其关闭。它也可能已过期、被驱逐或在会话访问更改后变得无法访问。网关重新启动会保留保留的条目和解除。保留的聊天消息独立于收件箱条目。在引入持久存储之前已经丢失的条目不会从旧消息中恢复。
