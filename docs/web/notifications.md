当有事情需要你注意时，OpenClaw 可以提醒你——在运行控制界面的浏览器中，或在使用 OpenClaw macOS 应用时通过原生 macOS 通知提醒。所有设置都位于 **设置 → 通知**：启用当前设备、查看其状态，并向自己发送测试通知。

本页面介绍这两种通知方式。它不控制频道回应通知、Android 通知转发或 iOS 后台推送——移动应用通过各自的节点路径注册推送；请参阅 [iOS](/platforms/ios) 和 [节点](/nodes)。

## 你获得的界面类型

“通知”页面的控制项取决于你从哪里打开它：

| 设置打开的位置                              | 传输方式                                     | 你可以执行的操作                                             |
| ------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| 受支持的网页浏览器或已安装的 Control UI PWA | 通过 Control UI service worker 使用浏览器推送 API | 授予权限、订阅或取消订阅此浏览器、发送测试通知                 |
| OpenClaw macOS 应用                           | 原生 macOS 通知                              | 授予应用权限、被阻止时跳转到系统设置、发送本地测试通知         |
| 不支持推送 API 的浏览器                       | 无                                           | 仅显示状态；启用和测试功能将不可用                             |

macOS 应用特意使用原生权限流程，而不是浏览器推送——这是你的 Mac 已经遵循的通知系统。

## 启用浏览器通知

1. 在支持 service workers、`PushManager` 和通知的浏览器中打开控制 UI。
2. 确保控制 UI 已连接到网关。
3. 打开 **设置 → 通知**，然后选择 **启用通知**。
4. 浏览器询问时允许通知。
5. 选择 **发送测试** — 几秒钟内应该会收到测试通知。

在后台，启用通知会在此浏览器中创建推送订阅，并将其端点和密钥注册到网关。网关会将浏览器订阅和其 VAPID 签名密钥保存在 `state/openclaw.sqlite` 中——无需编辑 `openclaw.json` 中的任何键。控制 UI 重新连接时，现有订阅会自动与网关进行协调。

**发送测试** 会要求网关向每个已注册的浏览器订阅推送测试消息。**取消订阅** 会从网关中移除当前浏览器的端点，然后在本地取消订阅。

## 在 macOS 应用中启用通知

1. 在 OpenClaw macOS 应用中打开 **设置 → 通知**。
2. 当权限显示为 **未请求** 时，选择 **启用通知**。
3. 批准 macOS 权限提示。
4. 选择 **发送测试**，发布一条本地 OpenClaw 通知。

如果权限显示为 **已拒绝**，macOS 将不会再次提示：选择 **打开系统设置**，在那里允许 OpenClaw 的通知，然后切回应用——应用重新获得焦点时，页面会重新检查权限。此权限属于 macOS，而不是网关配置。

## 故障排除

### 启用不可用

浏览器缺少所需的 Web Push API，或控制界面未连接到网关。请尝试使用最新版本的浏览器，确认网关连接正常，然后重新加载页面。

### 浏览器权限被阻止

被拒绝的浏览器权限无法从页面中重新开启。请在浏览器的站点设置中允许控制界面来源发送通知，然后重新加载设置页面。

### Service Worker 尚未准备就绪

控制界面最多会等待 10 秒以获取其 Service Worker。如果更新后立即超时，请强制刷新页面。如果旧的 Worker 仍然存在，请清除控制面板来源的站点数据，然后重新连接。

### Web Push 要求执行 Doctor 迁移

在网关停止的情况下运行 `openclaw doctor --fix`。在 Doctor 将已弃用的 JSON 存储导入 SQLite 之前，Web Push 会拒绝使用这些存储。
