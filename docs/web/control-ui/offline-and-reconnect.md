连接断开后什么会继续存在，以及 Control UI 在恢复时如何恢复。

返回暂停的选项卡或重新获得网络连接可以恢复失效的连接。这些信号不会重试需要重新加载页面、更正凭据或新的配对请求的连接。按照显示的恢复说明进行操作；更新后自动文档刷新仍然可用。

当身份刷新失败时，代理名称和头像将保留其上次加载的值。对同一代理的读取在侧边栏和聊天中共享一个请求，包括失败：后续读取从 500 毫秒回退到 5 秒，并接受更长的网关重试提示。重新连接会清除重试等待，以便身份读取可以在新连接上恢复。

## <a id="busy-initial-connection"></a> 初始连接忙

如果 WebSocket 升级失败，但同源网关仍回答其 `/healthz` 活动检查，则登录屏幕会显示 **Gateway busy， retrying…** 并显示下一次自动尝试的倒计时。当容量可用时，无需单击或更改凭据。当许多访问者共享一个场地 IP 并耗尽 [preauth 连接预算 ](/gateway/security/rate-limiting#unauthenticated-websocket-connections) 时，就会发生这种情况。

该检查不发送网关令牌，也不遵循重定向。无法访问或未经验证的端点使 **Gateway 无法访问** 指导；不检查跨源网关连接。身份验证和配对拒绝保留其特定的恢复指令。

## <a id="warm-reload"></a> 热重载

成功登录后，当网关无法访问时，浏览器可以重新打开其缓存的 shell、侧边栏、对话和草稿。令牌和设备令牌登录保留其凭据检查。当网关提供稳定的恢复身份时，可信代理、Tailscale 和密码登录也支持热重新加载。一次性引导凭证绝不会保留用于离线入场；成功的配对可以使用浏览器客户端已发出并存储的可重用设备授权。

保留的身份用于本地显示和存储，而不是调用网关的权限。阅读、起草和排队输入仍然可以离线使用；发送和同步等待网关重新验证帐户。不会为此功能保存密码或新的持有者凭据。任何有权访问浏览器配置文件的人都可以访问其本地保留的数据。

普通网络故障会在继续重试时使已承认的本地 shell 保持可见。身份验证或配对拒绝会废弃缓存的准入，而不是在稍后出现网络错误后静默恢复它。 **忘记这个浏览器** 和显式凭证替换也退出准入。断开连接时无法观察到在 OpenClaw 之外执行的代理注销；当联系恢复时，网关的下一个身份验证结果适用。

成绩单、花名册数据、文本草稿和排队输入由网关和帐户分隔。切换帐户无法发送或覆盖先前帐户的输入。取消离线访问不会丢弃未发送的草稿或排队的工作；该作品仍属于其原始存储所有者。实时状态会替换连接时缓存的名册数据，并且聊天会从保存的脚本光标中恢复。缓存的文字记录在其最新消息中打开，没有初始滚动动画。它保留参与者和已完成工作的计时信息以及最后的任务进度卡，以便在连接时显示；实时网关结果会替换那些缓存的事实。缓存的进度不授权离线操作。第一个聊天请求最多等待 300 毫秒以获取存储的历史记录，然后再返回实时读取。代理切换和过时的异步读取保留其自己的身份检查。代理选择器和代理目录等待实时名册；存储的代理列表无法建立当前角色的发现权限。短对话链接在代理发现之前使用缓存的路由默认值和会话行；连接后网关重新验证已建立的会话。唯一的显示名称链接使用相同的缓存路由解析，包括 `/dashboard` 命名空间。缺失或不明确的名称仍在等待网关。

确切的对话链接也会在显示其标头之前等待作用域缓存名册。仪表板布局会在窗格呈现之前恢复，嵌入式 HTML 小部件在板元数据和文档到达时保留一个加载表面。小部件请求仍然需要当前的网关连接。

加载更多会话可以使侧边栏的热重载快照保持可用。路由名册保留其第一页；侧边栏单独保留其可见行、固定目标以及连接时显示的选定视图。页面视图可以保存和恢复其仪表板目录，而无需等待非活动会话名册。

启动和名册记录保留现有的 30 天有效期，而记录则保留其有限的缓存限制。清除站点数据会删除本地恢复数据。如果浏览器存储不可用或不存在可用记录，连接屏幕将照常显示。

批准、问题和焦点文档不会读取或发布工作区的温暖状态。独立登录尝试不能仅仅因为其凭据不同或其配对链接被拒绝而删除另一个选项卡的有效许可。退休的范围仍然限于被承认的所有者；实际帐户更换，**忘记此浏览器**，或者清除站点数据仍然会取消受影响的许可。

### <a id="upgrading-existing-browser-data"></a> 升级现有浏览器数据

帐户范围的副本缓存取代了旧的无范围派生快照；这些旧的记录将被丢弃，而不是归因于下一个帐户。连接的访问​​会填充新的缓存。现有的无主草稿和排队输入将被保留以供显式恢复和审查，而不是自动分配或发送。现有附件存储和存储限制保持不变。较旧的 UI 无法读取新的帐户合格发件箱密钥；回滚不会将保留的输入转换回无主队列。

## <a id="offline-page-reload"></a> 离线页面重新加载

生产版本通过服务工作线程准备通用的离线 shell 和关键的聊天和新会话接口文件，以及已注销的回退。静态资产准备可以使用浏览器已有的同源代理登录；仅允许具有可缓存响应的完整性匹配的构建字节。准备完成后，明确报告自身离线的浏览器可以从当前构建缓存重新加载这些路由。当浏览器返回在线状态时，中断的准备工作会在现有的 startup/resume 检查上恢复，重新使用经过验证的下载而不是重新开始。准备工作是有限的，因此停滞的下载无法无限期地保留 UI 更新。现有的热重载凭据和帐户检查仍然决定缓存的对话是否可能出现。没有网关呈现的私有 HTML、API 响应或授权票证添加到此 shell 缓存中。

重新加载重用缓存的构建版本字体、主题和 Web 清单，而无需联系网关。 Service Worker 仅保留当前构建的资产。更新后，打开的选项卡会自动重新加载，除非未保存的工作保护阻止恢复；然后保存或放弃受保护的工作并使用 **Reload** 横幅。仅当 URL 与图像的内容修订版匹配时，上传的个人资料头像才使用私有浏览器缓存；未版本化的 URL 和外部头像后备仍会重新验证。内容寻址插件接口资产在授权更新期间保留在私有浏览器 HTTP 缓存中；到达网关的请求仍然需要当前的插件授权，并且插件数据仍然受到每次调用 RPC 授权的约束。

在线导航仍然直接进入网络，因此反向代理 HTTP 身份验证对话框可以正常工作。如果浏览器在连接断开的情况下仍报告自己处于在线状态，则导航会保留该网络行为。打开选项卡仍然是在间歇性服务中继续工作的最可靠方法。未访问的视图和未缓存的外部资源可能仍需要连接。

## <a id="gateway-updates-and-suspended-tabs"></a> Gateway 更新和暂停的选项卡

打开的选项卡会检查活动的UI当它返回前台、重新上线或从浏览器历史记录中恢复时构建。如果更新在选项卡暂停时完成，它可以在不接收原始更新通知或打开新选项卡的情况下恢复。

自动构建恢复重新加载将其第一页检查时间延长到最多两秒，并且每个目标构建每 30 秒最多重新加载一次。重新加载等待页面可访问并尊重未保存的工作保护。当前路线和存储的草稿在重新加载后仍然存在。如果浏览器存储不可用或重新加载保护阻止恢复，请在保存工作后重新加载选项卡；当草稿或排队消息仍需要恢复时，请勿清除站点数据。

如果在网络中断期间视图或样式表下载失败，则打开的页面会继续检查可达性，退避时间上限为 15 秒。返回在线或返回选项卡会唤醒提前检查的内容。一旦文档可访问，UI 就会重新加载以恢复失败的浏览器模块下载；它不会在同一文档中重试这些导入。未保存工作保护仍然适用，并且手动 **Reload** 操作仍然可用。

在启动过程中，缓慢的应用程序下载会导致 **Control UI 仍在加载** 通知，而不会中断下载。文档加载完成后，应用程序在恢复开始之前还有 12 秒的时间进行渲染。如果网关无法访问，启动恢复会继续探测，并有 15 秒的退避时间。它允许最多三个自动恢复导航；如果新页面仍然无法启动，请使用 **重试** 或故障排除指南。

未保存的文件编辑会阻止自动和应用内重新加载，即使您关闭预览或切换对话也是如此。重新打开每个已编辑的文件并保存或放弃其更改，然后重试重新加载。如果服务器更新导致编辑器不可用，请在重新加载通知中选择 **查看文件草稿**。您可以在不连接到网关的情况下复制或下载每个保留的草稿，明确放弃已解析的草稿，然后再次尝试 **Refresh**。 **保留草稿** 在此选项卡中使它们受到保护。每个草稿都会显示打开文件时捕获的会话标题、会话密钥和窗格位置，因此匹配的文件名仍然可区分。如果在您审阅较旧的草稿时较新的编辑内容发生更改，则新的编辑内容仍将受到保护。文件编辑保留在当前页面的内存中；显式浏览器重新加载或关闭浏览器选项卡会丢弃它们。

## <a id="visualizations-during-a-connection-loss"></a> 连接丢失期间的可视化

当与同一网关和帐户的连接暂时断开时，已渲染的内联可视化将保持其 iframe 和本地交互状态，包括唤醒恢复和 **立即重试**。他们不需要再次下载其内容即可保持可见。重新连接时，客户端重新验证文档；更改的内容或更改的帐户、网关或授权范围将替换旧视图。依赖于服务器的小部件操作在其当前权限建立之前保持不可用。

小部件加载缓慢会在 10 秒后显示等待通知，但不会立即取消工作。它们的 30 秒硬性截止时间和有节奏的瞬态重试允许在不重复出现终端错误的情况下进行恢复。最终的访问失败和脚本错误仍然显示可操作的反馈。外部小部件资源无法通过保留 iframe 来离线使用，并且整页重新加载不会保留小部件未保存的本地交互状态。

## <a id="connection-loss-and-reconnect"></a> 连接丢失和重新连接

一旦建立会话，断开的网关连接不会使您注销。仪表板保持可见，其侧边栏页脚中的一种连接状态解释了网关是否正在挂起、挂起、重新启动、重新连接或完成恢复。有计划的转换和自动重新连接使用平静的演示；需要您注意的身份验证和其他失败保留其解释和恢复操作。 macOS 应用程序的嵌入式仪表板中也会显示相同的状态。连接状态不会替换帐户菜单中的网关名称。

客户端通过随机退避自动重试普通连接丢失：第一次重试等待 800–960 毫秒，持续的失败会在 12.5–15 秒内进行重试。服务器重试提示仍然是最短等待时间，并且可以超出正常上限，最多有 20% 的额外差价。网关的 WebSocket ping/pong 保持活动检测死传输。繁忙网关上的延迟应用程序检测信号本身不会重新连接打开的选项卡。返回暂停的选项卡仍会在两个通告的心跳静默间隔后恢复连接。单个请求超时不会重置套接字。重新连接不会重放任意请求；读取所有者重试读取，写入所有者协调不确定的结果。网关启动提示保持其单独的有限时间（100-2000 毫秒），在重新连接选项卡之间最多有 20% 的额外扩展。如果断开的连接中断了“使用情况”导出，则导出会显示错误。连接恢复后，再次选择 **Export**；导出不会自动重播。如果浏览器未提供断开连接的原因，连接工具提示会说明连接已中断以及是否正在进行自动重新连接。保留WebSocket关闭代码，用于故障排除；具体网关错误保留其解释。打开帐户菜单并使用 **立即重试** 请求在提供时立即尝试。登录失败使用登录流程，所需的仪表板刷新使用其重新加载流程；重试连接不会替代任何操作。实时更新和 realtime/session 操作会暂停，直到连接恢复。聊天在没有队列前助手的情况下仍然可以编辑。仅当邮件排队后，特定于对话的发件箱摘要才会与实际排队的邮件一起显示。

普通文本和附件发送需要成功进入当前选项卡的 Gateway/session-scoped 浏览器发件箱。连接和帐户恢复后，符合条件的消息会自动恢复，但活动运行、打开的排队消息编辑或不确定的先前传送可能会让它们等待。 **Inbox → System** 显示失败或需要交付审核的本地提交，并使用 **Review** 打开其对话及其现有恢复控件。普通排队消息停留在聊天队列中；它们不会引起收件箱的关注。帐户和连接指示符描述身份和连接，而不是消息传递。作曲家计数仅涵盖其对话，不保证自动发送。等待目标恢复的草稿文本和保存的消息是分开的。

当连接的聊天完成帐户恢复时，“发送”保持不可用，并说明恢复正在等待。您的草稿保留在作曲家中。恢复完成后，即使聊天历史记录仍在加载，普通消息也可以进入队列。停止和批准控制保持其现有可用性。

这些收件箱条目是当前帐户浏览器 tab/Gateway 发件箱的只读视图，而不是新的服务器端或跨设备收件箱。它们显示可用的对话标签，而不是消息文本、附件名称或私人错误详细信息。审核不会重试或丢弃任何内容，并且条目不能独立于其待处理副本而被驳回。断开连接时，本地审核仍然可用；依赖于服务器的收件箱操作仍然不可用。从“设置”返回到工作区以打开“收件箱”。如果存储失败，Composer 会保留未发送的输入并显示恢复指南。

需要实时连接的控件在离线时保持不可用。 **Stop** 可以对精确的本地运行 ID 进行排队以进行重播。仅会话停止不会重播，因为在连接返回之前，较新的工作可能会在该会话中开始。

排队的消息遵循队列中显示的顺序，包括重新连接后加载附件字节时进行的移动。已发送的消息保留其位置。如果另一个窗格正在编辑消息，请先完成或取消该编辑，然后再在其中移动消息。成功重试会清除该编辑冲突通知。在其他窗格释放其编辑后打开排队消息编辑器会清除先前的编辑冲突通知。

如果连接在编辑过程中中断，编辑未发送的排队消息仍然是安全的。使用输入法确认文本可以使排队消息编辑器保持打开状态；合成完成后再次按 Enter 键以保存编辑。当您切换对话时，打开的排队消息编辑仍然可用，即使在访问足够多的聊天以替换旧的缓存视图之后也是如此。完成或取消编辑以释放保留的对话。开放的排队消息编辑还会阻止网关更新后自动重新加载 UI。即使在切换到另一个页面后，在重新加载通知中使用 **Review edit** 也可以返回其对话并拆分。保存或取消编辑，然后使用 **Refresh 获取完整功能** 继续。显式浏览器重新加载不会保留未保存的排队消息更正。如果另一个窗格更改或删除该消息，编辑将保持打开状态：复制您的更正，取消编辑，并在重试之前查看队列。已满的队列要求您等待或删除消息。如果浏览器存储阻止保存编辑，请保持选项卡打开并在释放存储之前复制更正内容。成功保存会清除之前的错误。

由于网关挂起、重新启动、启动或无法访问而失败的页面和侧边栏刷新不会显示内联错误：页脚连接指示器拥有该状态。每个面板都会保留其最后的数据，并在网关再次接受工作后自动刷新。代理选择器和代理目录在重新连接时会清除其名册，并等待新的授权列表，包括同一用户的角色发生更改时。重新连接到同一网关和帐户时，已建立的对话名称在浏览器选项卡和聊天标题（包括拆分视图）中仍然可见。其他刷新失败与其消息一起保持可见，并在网关再次可用时自动重试。这些刷新标注没有手动 **Retry** 按钮。

当代理身份保存中断时，其编辑器会在重新连接时保留保存状态。如果仍然选择同一代理，则草稿仍可供再次审阅和保存；中断请求产生的延迟结果无法清除较新的编辑。

重新连接后，将根据网关检查打开的对话链接。如果网关确认对话不再存在，例如网关重新启动后的隐身对话，页面将显示 **Session not found** 以及打开主会话或浏览会话的操作。连接失败或当前侧边栏页面中丢失的对话不算作删除。

如果无法下载视图的接口文件，则首次打开视图可能会失败。 UI 等待可达性并自动重新加载，受重新加载保护和 30 秒环路保护的影响。您还可以使用 **Reload**。更新后可能会出现同样的错误；它本身并不意味着安装了新版本。如果未保存的工作阻止重新加载，请按照显示的保存或取消指导进行操作，然后重试。

延迟的历史记录刷新会保留任何较新的运行及其实时输出。运行完成后，新的空闲响应可以清除陈旧的忙碌指示器。

瞬时历史记录和实时订阅读取会在对话和连接保持当前状态的情况下重试并进行回退。当打开的对话恢复时，左下角的连接指示器显示 **Restoring…**。聊天上方不会出现额外的恢复通知；缓存的文字记录和草稿仍然可用。在现有的 60 秒消费者恢复窗口内，每个历史记录尝试都有 30 秒的截止时间。仅在其先前的观察者安全协调后，订阅获取才会重试。如果恢复仍然不成功，一条历史记录通知会提供 **Retry**，它会重新加载对话并恢复其实时订阅，包括批准更新。权限和其他终端故障仍然可见，而不是默默地重试。

当网关确认其持有相同的待处理输入时，Control UI 会清除不确定传送警告，而不会再次发送消息。浏览器保留其重试有效负载，直到确认消耗或取消为止。如果交货仍然未知，则审核警告仍然存在。如果网关保留该输入以供稍后使用，它将出现在编辑器上方的队列中。删除该行会撤回确切的排队消息，而不会停止活动轮次。一旦确认取消，删除的提示及其附件就会从队列和对话中消失，包括在重新连接或重新加载之后。服务器保存的消息无法编辑或重新排序。如果消息已经开始，则“删除”将单独保留活动的运行；使用 Stop 来中断它。停止转弯或发送不成功仍会留下带有恢复指导的已取消提示；这些操作不会删除提示。隐身聊天保留其现有的取消行为：删除会取消排队的工作，但取消消息通知将保留到私人会话结束为止。

如果在代理恢复之前自动重新启动恢复被中断或取消，**System·重新启动恢复** 通知将显示该结果并要求您发送消息以继续。这并不意味着代理已恢复。从其他会话转发的消息在每条消息旁边保留自己的传送状态。

一旦网关确认消息位于记录中，即使原始消息位于最新历史记录页面之外，重新连接也会停用其临时浏览器副本。当先前未确认的消息仍然阻塞队列时，传递检查还会清除稍后确认的消息，因此这些已传递的副本不再引起侧边栏或收件箱的关注。这不会重试不确定的消息或乱序发送稍后排队的消息。加载较旧的历史记录会在其原始位置显示已保存的消息，而无需添加第二个副本。

停用已交付的附件不会放弃运行的完成情况。如果浏览器错过了该完成，则确认同一会话和运行已完成的队列恢复读取会清除陈旧的运行指示器并恢复排队输入。

排队附件使用浏览器的 IndexedDB 中的二进制 Blob；发件箱仅在会话存储中保留传送元数据和有效负载引用。附件字节保留在排队的输入中；即使配置的主会话默认值发生更改，捕获的队列元数据也拥有其目标。所有附件必须在消息被接受之前存储，并且所有附件在发送之前必须可读。失败的录取导致草稿未发送。丢失或无法读取的排队有效负载会留下可见的行并提供恢复指导；浏览器绝不会只发送剩余的附件。二进制发件箱存储需要浏览器存储访问。在普通 HTTP 上，每个页面加载都使用新的有效负载所有者，因为 Web Locks 不可用；重新加载和重复选项卡在发送之前复制有效负载，并保留旧的有界有效负载以进行浏览器存储清理。网关连接限制仍然适用。

发件箱为每封邮件保留最多 25 MiB 附件，并在该浏览器源中保留 250 MiB，具体取决于浏览器自身的配额。排队的有效负载没有基于年龄的到期时间。交付或丢弃释放它们；关闭选项卡或中断选项卡复制或清理可能会在该范围内留下孤立的有效负载。如果在发送或丢弃队列后容量仍然已满，请在清除此站点的浏览器存储之前保存所有需要的草稿。这还会清除浏览器本地草稿和登录状态。发件箱队列属于浏览器选项卡；它们与可重新启动恢复的作曲家草稿不同。隐身会话保留其现有的仅选项卡内联发件箱及其较小的浏览器存储限制；它们从不在 IndexedDB 中存储排队的附件 Blob。

复制选项卡会复制相同的提交 ID。一旦打开，副本就会声明自己的有效负载副本，并将这些提交标记为 **Delivery unconfirmed**。重试之前请检查对话。在源丢弃或传递消息后首次打开的副本可能会报告丢失的附件。独立选项卡不共享新创作的发件箱消息。

连接后，聊天会等待帐户范围内的恢复，然后再接受或发送普通消息。在此简短检查期间，提交的文本和附件保留在作曲家中。一旦恢复准备就绪，离线队列就会恢复，除非会话仍然拥有未解决的初始轮次；首先使用 **Retry** 或 **Check Delivery** 操作解决该回合。断开连接时，作曲家上方会出现一条通知，显示初始消息未解决；作曲家仍然接受排队的消息。如果初始消息正在等待恢复，则其聊天会显示加载占位符，直到消息可以恢复为止，而不是空的新聊天欢迎屏幕。恢复通知出现在作曲家下方，并在阻塞情况解决后清除。

如果发送的消息在确认之前超时，浏览器会将其保留为 **Delivery unconfirmed**，而不是 **Not sent**。当连接可用时，它会自动检查送达收据，而无需再次发送消息。超时收据读取重试并退避；它们不会在不确定的输入之前释放稍后排队的消息或覆盖较新的草稿。

如果在确认发送之前连接断开，则重新连接会检查脚本和会话的活动状态或上次运行的 ID 以作为发送证明。匹配的运行甚至在其转录行出现之前就确认了接收。如果没有证据，尝试的消息将保留在带有琥珀色 **Delivery unconfirmed** 页脚、**Retry** 和 **Discard** 的对话中。检查对话并仅在消息未到达时重试。放弃将从该浏览器的发件箱中删除待处理的副本；它不会撤消或取消网关已接受的工作。稍后排队的消息将保持暂停状态，直到先前未确认的消息得到解决或丢弃，并且队列会解释该阻塞。丢弃较早的消息可以让下一个排队的消息在会话准备就绪时继续处理。未确认的本地命令保留其 retry/discard 队列控制。

被网关拒绝的普通消息将保留在带有 **Not sent** 页脚的会话中。使用 **Retry** 重试或使用 **Discard** 删除其挂起的浏览器副本。重新加载选项卡后丢弃仍然有效；它不会取消网关工作或删除对话历史记录中已有的消息。

如果网关报告`/steer`或`/redirect`消息启动失败，Control UI会在composer仍为空时恢复提交的草稿。它保留较新的文本、回复和附件。如果您切换了对话，恢复仍保留原来的对话。如果在命令挂起时在页面及其停靠栏之间移动主页，则恢复将遵循当前的主页编辑器并保留在其中输入的任何较新的草稿。

排队的消息和草稿使对话和代理在创建时保持选中状态。切换代理、打开分割窗格或重新加载不会将它们移动到另一个目标。当拆分窗格显示相同的对话时，访问其他对话后返回到较旧的窗格不会替换较新的保存的草稿。文本、选定的收件人、引用的回复、目标模式和附件遵循相同的草稿修订版。即使在您输入文本之前，选定的回复也可以通过预览和原始消息目标重新加载。取消回复会清除该选择，而不丢弃文本。发送传输对已提交消息的回复；仅当您尚未开始更新的草稿时，失败的接纳才会恢复它。在分割窗格之间快速切换可以使最后选择的对话保持活动状态，包括在缩小窗口时。字面上的 `global` 对话会保留其捕获的代理；除非网关配置了全局会话范围，否则代理的主要对话保持独立。

较旧的浏览器状态可能已将多个目标组合到一个存储桶中。 Control UI 使用元数据版本 4 （`openclaw.control.chatComposer.v4:`），在目标仍可识别时直接迁移版本 1、2 和 3 记录。它会在删除旧源之前验证新元数据，并在存储或恢复容量阻止迁移时保留完整源。此元数据更改不会更改 IndexedDB 架构或持久草稿密钥。保存的等待审核的输入在编辑器正上方显示为紧凑的 **Unsent** 或 **Draft** 行。使用空的编辑器和队列打开预期的非隐身对话，选择 **Restore**，然后确认显示的对话。 **Delete** 在删除已保存的副本之前询问。恢复的排队消息保持暂停状态：在使用 **Retry** 之前检查以前的传送。恢复的附件草稿返回给作曲者而不发送。重新连接、更换会话或在确认打开时启用隐身模式会取消传输；在预期的对话中再次确认。当目标有较新的清除时，其目标已知的旧附件草稿将保持清除状态。不明确的保存数据仍可供审查。排队的 Blob 引用和原始提交 ID 在自动迁移和显式目标恢复中仍然存在。凭证绑定消息仅在其原始网关凭证范围内显示，包括当较旧的存储桶包含来自多个范围的消息时。将消息移入或移出恢复不会删除其字节；清理是在经过验证的传递或丢弃之后进行的，并且也会考虑保留的恢复消息。当原始对话的加载历史记录证明保存的排队提交已交付时，其恢复副本将自动删除。证明需要在同一对话中以及记录时的同一物理会话中准确提交持久用户消息 ID。匹配的文本或本地显示副本并不能作为证据。该行中的任何草稿或其他未经确认的输入仍然可用；恢复永远不会自动发送消息。如果目标发生更改、出现更新的草稿或存储失败，恢复将保持源可用，而不是覆盖更新的输入。当您仍有保存的邮件或附件草稿需要恢复时，请勿清除浏览器站点数据。

如果浏览器关闭其草稿数据库连接，下一个存储操作会自动打开一个新连接。恢复存储错误出现在composer上方；它们并不意味着消息已丢失目标或浏览器存储空间已满。如果错误仍然存​​在，请重新加载以重试，从而保持站点数据完整。

在网关解析初始连接时，在没有可用热状态的情况下首次打开和重新加载会显示一个小的动画 OpenClaw 标记，包括当身份验证来自可信代理或 Tailscale 而不是浏览器存储的凭据时。仅在初始连接失败或网关主动拒绝身份验证（错误的 token/password、缺少可信身份、撤销配对）后才会出现登录门。瞬时连接失败自动重试；身份验证失败说明了需要您输入的内容。

## <a id="reloading-a-session-link"></a> 重新加载会话链接

经过身份验证的应用程序文档具有与 `control-ui-config.json` 相同的表示和功能配置，因此第一个渲染可以使用配置的助理身份，而无需等待 WebSocket。这些文档使用私有的、无存储的缓存。公开和未经身份验证的文档不携带受保护的引导程序数据；应用程序在连接启动的同时启动其配置请求。重新连接和配置更改事件会刷新服务网关的配置。
