# v2026.10.3

AI 代理和工具可以将这些发行说明读取为 [plain Markdown](https://raw.githubusercontent.com/openclaw/openclaw/main/CHANGELOG/2026.10.3.md)。

OpenClaw 2026.10.3 修复了多个更新阻止程序，在受影响的 Doctor 修复期间保留保存的登录和内存文件，并帮助 Mac 应用程序在本地设置期间进行连接，并修复了在压缩或中断的提供商回复后允许对话继续的问题。

**发布规模：** 79 个拉取请求、8 个直接提交和 97 个贡献者。

## <a id="updates-and-maintenance"></a> 更新和维护

- **阻止的更新。** 更新可以清除符合条件的剩余恢复工作，并存档先前阻止下一次升级的已完成更新记录。已被阻止的旧更新程序需要 [ 手动安装或恢复第一步 ](https://docs.openclaw.ai/install/updating#package-publication-recovery)； [独立的恢复助手](https://docs.openclaw.ai/install/updating#recover-a-completed-receipt-with-an-older-updater)可以保留完整的记录并解锁原始更新程序。 [#168388](https://github.com/openclaw/openclaw/pull/168388)，[#169038](https://github.com/openclaw/openclaw/pull/169038)，感谢[@steipete](https://github.com/steipete)，[@k94118](https://github.com/k94118)， [@kimjinsuhh](https://github.com/kimjinsuhh)、[@GoldenrodScript](https://github.com/GoldenrodScript)、[@neilofneils404](https://github.com/neilofneils404)、[@mkdelta221](https://github.com/mkdelta221)、[@waynegault](https://github.com/waynegault)、 [@clawdgawd](https://github.com/clawdgawd)、[@yoyo837](https://github.com/yoyo837)、[@lishewen](https://github.com/lishewen)、[@nukk-pain](https://github.com/nukk-pain)、[@jullianatolentino](https://github.com/jullianatolentino)、 [@joshpetras](https://github.com/joshpetras) 和 [@creanet-64](https://github.com/creanet-64).
- **中断的 2026.9.8 更新。** 更新的 CLI 可以解决受支持的阻止另一次更新的中止记录。当无法重新检查包内容时，此旧恢复路径会发出警告，因此请保留恢复证据并遵循 [ 修复指南 ](https://docs.openclaw.ai/cli/update/repair-and-recovery)。 [#169027](https://github.com/openclaw/openclaw/pull/169027)，感谢 [@steipete](https://github.com/steipete) 和 [@chedong](https://github.com/chedong).
- **FreeBSD 软件包恢复。** 由固定更新程序生成的恢复助手可以修复或停用 FreeBSD 上中断的 npm 软件包更新。较旧的帮助程序仍然仅支持状态，并且包恢复仍然与重新启动或验证网关分开。请参阅 [ 更新指南 ](https://docs.openclaw.ai/install/updating)。 [#168775](https://github.com/openclaw/openclaw/pull/168775)，感谢[@steipete](https://github.com/steipete).
- **剩余更新程序副本。** 医生可以删除符合条件的废弃 npm 更新程序副本，该副本会阻止下次更新。等待更新程序工作完成，从受影响的安装运行 `openclaw doctor --fix`，然后重试。保持恢复日志及其权限完好无损；请参阅 [ 更新故障排除](https://docs.openclaw.ai/install/update-troubleshooting)。 [#170170](https://github.com/openclaw/openclaw/pull/170170)，感谢 [@steipete](https://github.com/steipete)、[@sunnyshu0925](https://github.com/sunnyshu0925) 和 [@warhangel](https://github.com/warhangel).
- **候选者与较旧的更新者进行检查。** 新的候选者不再仅仅因为Doctor会更新版本、设置或迁移簿记而被拒绝。真实设置修复和实质性迁移仍遵循现有处理方式。请参阅 [ 更新指南](https://docs.openclaw.ai/cli/update)。 [#170195](https://github.com/openclaw/openclaw/pull/170195)，感谢 [@steipete](https://github.com/steipete)、[@maestrokling](https://github.com/maestrokling) 和 [@frxiaobei](https://github.com/frxiaobei).
- **Older Node updaters.** 当旧的和新的更新进程测量时间不同并将有效更新误认为丢失时，更新可以避免不必要的回滚。 [#169915](https://github.com/openclaw/openclaw/pull/169915)，感谢[@vincentkoc](https://github.com/vincentkoc).
- **聊天中请求的更新。** 修复了 Doctor 清理检查，该检查错误地拒绝许可并回滚聊天请求的更新，有时导致插件升级未完成。 [#170218](https://github.com/openclaw/openclaw/pull/170218)，感谢[@RomneyDa](https://github.com/RomneyDa)，[@hannesrudolph](https://github.com/hannesrudolph)，[@ezimerman](https://github.com/ezimerman)， [@yoyo837](https://github.com/yoyo837)、[@aia007731-lab](https://github.com/aia007731-lab)、[@justinforsound](https://github.com/justinforsound) 和 [@steipete](https://github.com/steipete).
- **Doctor 正在更新。** Doctor 在后续进程检查失败后（如果已验证更新程序）可以继续。如果记录新启动的命令失败，Doctor可以在确认其停止后进行清理，避免遗留工作阻碍以后的修复。 [#169563](https://github.com/openclaw/openclaw/pull/169563)、[#169665](https://github.com/openclaw/openclaw/pull/169665)，感谢 [@RomneyDa](https://github.com/RomneyDa) 和 [@steipete](https://github.com/steipete).
- **Windows 服务帐户。** 更新可识别同一服务帐户的不同任务计划程序名称，并且可以重新启动网关，而无需重写其他人拥有的服务。请参阅 [ 更新指南](https://docs.openclaw.ai/cli/update)。 [#169481](https://github.com/openclaw/openclaw/pull/169481)，感谢[@steipete](https://github.com/steipete).
- **Windows 更新和恢复路径。** 更新程序工作人员可识别同一安装文件夹的短名称和不同的大小写。恢复快照也停止拒绝自己的 Windows 临时目录。路径更正要求在开始升级之前安装固定更新程序。 [#169292](https://github.com/openclaw/openclaw/pull/169292)、[#169397](https://github.com/openclaw/openclaw/pull/169397)，感谢 [@RomneyDa](https://github.com/RomneyDa) 和 [@steipete](https://github.com/steipete).
- **pnpm 服务命令。** 新的或修复的网关服务命令使用 pnpm 的持久安装链接，因此替换版本化包文件夹不会破坏它们。更新规划还可以识别通过嵌套 pnpm 路径到达的安装。固定到旧文件夹的现有命令需要修复或重新规划；参见[更新方法](https://docs.openclaw.ai/install/updating/update-methods)。 [#170003](https://github.com/openclaw/openclaw/pull/170003)，感谢 [@steipete](https://github.com/steipete)、[@xilopaint](https://github.com/xilopaint) 和 [@k-sekula](https://github.com/k-sekula).
- **pnpm 12发射器。**固定本机pnpm更新保留`openclaw`命令在暂存清理后可用，包括符号链接的全局 bin 文件夹。更新程序必须已包含此修复程序。已经损坏的命令需要手动修复或[相同版本pnpm重新安装](https://docs.openclaw.ai/install/updating/update-methods#alternative-manual-npm-pnpm-or-bun)备份后，使用相同的帐户和全局目录。[#170131](https://github.com/openclaw/openclaw/pull/170131)，感谢[@steipete](https://github.com/steipete)， [@goutamadwant](https://github.com/goutamadwant)和[@k-sekula](https://github.com/k-sekula).
- **服务刷新拒绝。** 更新可以在安全地拒绝重写其定义后重新启动保留的网关服务。重新启动仍然需要现有的定义和服务所有权来通过重新验证，保留自定义。请参阅 [ 如何更新运行 ](https://docs.openclaw.ai/cli/update/how-updates-run)。 [#169658](https://github.com/openclaw/openclaw/pull/169658)，感谢[@steipete](https://github.com/steipete).
- **繁忙状态数据库。** 可选进度日志记录不再仅仅因为数据库短暂繁忙而中止更新，并且更新历史记录写入阻塞网关工作的时间更少。所需的恢复写入仍然是强制性的。这些驱动程序端改进需要固定更新程序才能开始升级；请参阅 [ 更新指南](https://docs.openclaw.ai/cli/update)。 [#168210](https://github.com/openclaw/openclaw/pull/168210)、[#169283](https://github.com/openclaw/openclaw/pull/169283)，感谢 [@steipete](https://github.com/steipete)、[@jlapenna](https://github.com/jlapenna) 和[@DonnieFi](https://github.com/DonnieFi).
- **不相关的依赖项复制。** 更新避免从不相关的封闭安装复制依赖项并扫描不相关的 npm- 全局工具。开始升级的更新程序必须已经包含这些修复程序；请参阅 [ 更新指南 ](https://docs.openclaw.ai/install/updating)。 [#168927](https://github.com/openclaw/openclaw/pull/168927)，[#169551](https://github.com/openclaw/openclaw/pull/169551)，感谢[@steipete](https://github.com/steipete)，[@RomneyDa](https://github.com/RomneyDa)， [@goutamadwant](https://github.com/goutamadwant) 和 [@holgergruenhagen](https://github.com/holgergruenhagen).
- **配置的更新内存限制。** 使用捕获的服务设置的更新命令保留配置的 Node 内存限制，包括来自 shell 的仅内存覆盖。这需要在升级开始之前安装固定更新程序；请参阅 [ 更新指南](https://docs.openclaw.ai/cli/update)。 [#168889](https://github.com/openclaw/openclaw/pull/168889)，感谢 [@steipete](https://github.com/steipete) 和 [@bluet](https://github.com/bluet).
- **修复结果和后续步骤。** 未完成的医生维护报告为待处理，并有有用的下一步操作。数据迁移后出现的故障也指向支持的修复命令。保留新的安装和恢复快照，并按照警告保持网关停止，而维修人员仍心神不宁。请参阅 [ 更新修复 ](https://docs.openclaw.ai/cli/update/repair-and-recovery#update-repair)。 [#167714](https://github.com/openclaw/openclaw/pull/167714)、[#168905](https://github.com/openclaw/openclaw/pull/168905)，感谢 [@steipete](https://github.com/steipete)、[@ruicozibon](https://github.com/ruicozibon) 和[@ezimerman](https://github.com/ezimerman).
- **更新切换报告。** 已报告的更新结果不再产生第二次误导性失败，并且后台帮助程序接受的更新保持挂起状态。使用打印的状态和健康命令来检查其最终结果；参见 [ 重新启动切换 ](https://docs.openclaw.ai/cli/update/how-updates-run#restart-handoff)。 [#168587](https://github.com/openclaw/openclaw/pull/168587)、[#168993](https://github.com/openclaw/openclaw/pull/168993)，感谢 [@steipete](https://github.com/steipete) 和 [@sayitfast](https://github.com/sayitfast).
- **更新警告详细信息。** 恢复复制警告标识受影响的数据库，而失败的候选配置读取会解释错误并使服务定义保持不变。请参阅 [ 恢复捕获 ](https://docs.openclaw.ai/cli/update/repair-and-recovery#original-state-captures) 和 [ 更新指南 ](https://docs.openclaw.ai/install/updating)。 [#169282](https://github.com/openclaw/openclaw/pull/169282)、[#169284](https://github.com/openclaw/openclaw/pull/169284)，感谢 [@DonnieFi](https://github.com/DonnieFi) 和 [@RomneyDa](https://github.com/RomneyDa).
- **Git 更新清理。** 当进度报告失败时，临时工作树清理将继续，并且原始更新错误与辅助诊断一起仍然可见。如果 OpenClaw 无法确认更新进程已停止，它将保留恢复文件并拒绝继续。这需要固定安装的更新程序；请参阅 [ 维修指南 ](https://docs.openclaw.ai/cli/update/repair-and-recovery)。 [#169454](https://github.com/openclaw/openclaw/pull/169454)，感谢[@hannesrudolph](https://github.com/hannesrudolph).
- **迁移警告和验证计时器。** 已完成的插件迁移停止显示过时的未完成警告。当系统时钟发生变化时，包验证也会保持其截止日期。真正的待定迁移仍需关注；请参阅 [ 维修指南 ](https://docs.openclaw.ai/cli/update/repair-and-recovery)。 [#169004](https://github.com/openclaw/openclaw/pull/169004)，感谢 [@steipete](https://github.com/steipete)、[@adenzhou1350](https://github.com/adenzhou1350) 和 [@wg-mojo](https://github.com/wg-mojo).
- **修复前的恢复副本。** 新的恢复副本包括迁移前较旧的 Canvas 文档和 Memory Core 文件。医生和更新恢复不再拒绝副本，因为计划的后台数据库维护会在创建文件时更改文件。当配置的代理列表为空时，更新检查也会起作用。现有副本不会追溯丢失的文件。 [#169436](https://github.com/openclaw/openclaw/pull/169436)、[#170022](https://github.com/openclaw/openclaw/pull/170022)、[c01331a](https://github.com/openclaw/openclaw/commit/c01331a76beb292d1c05f22409c71a20c5cc9085)，感谢[@RomneyDa](https://github.com/RomneyDa) 和 [@steipete](https://github.com/steipete).

## <a id="messaging"></a> 消息传递

- **重新启动后的频道工具。** 由聊天或操作员任务启动或重新启动的消息帐户在该任务完成后继续使用频道工具，并且仍强制执行每个后续回合的权限。 [#159396](https://github.com/openclaw/openclaw/pull/159396)，感谢[@ceckert](https://github.com/ceckert)，[@RomneyDa](https://github.com/RomneyDa)，[@slinkoff](https://github.com/slinkoff)， [@fuller-stack-dev](https://github.com/fuller-stack-dev) 和 [@sjf-oa](https://github.com/sjf-oa).
- **消息已被发送。** 恢复扫描会在其活动发送者处留下消息，从而防止报告的竞争导致排队消息未发送。 [#169010](https://github.com/openclaw/openclaw/pull/169010)，感谢[@RomneyDa](https://github.com/RomneyDa).
- **重新启动后引导对话。** 人类对话可以在更正后恢复，并且当原始授权源仍然存在时网关重新启动。已经失败的会话不会重新打开，并且丢失的发件人权限也不会重建。请参阅 [ 重新启动恢复 ](https://docs.openclaw.ai/gateway/restart-recovery)。 [#170252](https://github.com/openclaw/openclaw/pull/170252)，感谢[@steipete](https://github.com/steipete).

## <a id="memory"></a> 内存

- **内存文件修复。** Doctor 在格式错误的 UTF-8 阻止合并 `MEMORY.md` 和旧版 `memory.md` 时保留原始字节。保留原始文件或保留的存档，并在重试之前修复或将副本转换为 UTF-8。请参阅 [ 工作区修复指南 ](https://docs.openclaw.ai/gateway/doctor/workspace-and-dreams)。 [#169029](https://github.com/openclaw/openclaw/pull/169029)，感谢 [@steipete](https://github.com/steipete) 和 [@wangmiao0668000666](https://github.com/wangmiao0668000666).

## <a id="native-apps"></a> 本机应用程序

- **在此 Mac 设置上。** Mac 应用程序可以连接之前因“网关拒绝身份验证”而失败的符合条件的“在此 Mac 上”设置，从而减少不必要的准备和等待。如果无法保存所需的新令牌，安装程序将停止并出现可重试错误。请参阅 [ 捆绑网关指南](https://docs.openclaw.ai/platforms/mac/bundled-gateway)。 [#169403](https://github.com/openclaw/openclaw/pull/169403)，感谢[@steipete](https://github.com/steipete).
- **Mac 续订后重新连接。** Mac 应用程序在可信网关证书续订后自动重新连接。习得的指纹可以在正常的信任检查后更新；显式配置的指纹保持固定。请参见[远程连接指南](https://docs.openclaw.ai/platforms/mac/remote)。 [#168151](https://github.com/openclaw/openclaw/pull/168151)，感谢 [@steipete](https://github.com/steipete) 和 [@fuller-stack-dev](https://github.com/fuller-stack-dev).
- **Mac 更新和恢复检查。** 该应用程序识别其受保护的 Bun 网关命令，解决了尽管网关正常但恢复屏幕卡住的原因。保护性启动选项和所有权检查仍然存在。 [#170006](https://github.com/openclaw/openclaw/pull/170006)，感谢 [@steipete](https://github.com/steipete)、[@jokerman1302-eng](https://github.com/jokerman1302-eng)、[@davidmackrory-byte](https://github.com/davidmackrory-byte) 和[@josephsilvagnoli](https://github.com/josephsilvagnoli).

## <a id="models-and-providers"></a> 模型和提供商

- **Muse Wonder.** Meta 用户可以选择具有文字和图像输入、最大思维的Muse Wonder。 Spark 1.3 Standard 还支持最大思维并保持设置默认值。 API支持Wonder标准；最大努力不选择Wonder Full。请参阅 [ 元指南 ](https://docs.openclaw.ai/providers/meta)。 [#170232](https://github.com/openclaw/openclaw/pull/170232)，感谢[@RomneyDa](https://github.com/RomneyDa).
- **MiniMax M3.1 Flash 预览。** 合格代币计划或 MiniMax 代码用户可以选择预览模型并选择低、中、高、xhigh 或最大思考努力。预览默认为最大，包括保存的或自适应的选择。 M3 仍为默认模型。缺少公布的目录费率并不意味着免费使用；请参阅 [MiniMax 指南](https://docs.openclaw.ai/providers/minimax)。 [#160089](https://github.com/openclaw/openclaw/pull/160089)，感谢[@NianJiuZst](https://github.com/NianJiuZst)，[@RomneyDa](https://github.com/RomneyDa)，[@steipete](https://github.com/steipete)， [@Takhoffman](https://github.com/Takhoffman)、[@php737](https://github.com/php737)、[@ns-spec](https://github.com/ns-spec)、[@Hansen1018](https://github.com/Hansen1018) 和 [@olveww-dot](https://github.com/olveww-dot).
- **MiniMax 登录续订。** Global 和 CN OAuth 登录在其发行区域账户端点续订过期令牌。较早保存的登录信息和区域更改需要使用 `openclaw models auth login --provider minimax-portal` 重新登录。请参阅 [MiniMax 指南](https://docs.openclaw.ai/providers/minimax)。 [#160459](https://github.com/openclaw/openclaw/pull/160459)，感谢 [@masatohoshino](https://github.com/masatohoshino)、[@RomneyDa](https://github.com/RomneyDa)、[@rongtianhua](https://github.com/rongtianhua) 和[@mychataa](https://github.com/mychataa).
- **在本机压缩后回复。** 下一条消息等待保存的对话历史记录变得可读，而不是在重建历史记录时失败。请参阅 [OpenAI 指南](https://docs.openclaw.ai/providers/openai/advanced)。 [#169583](https://github.com/openclaw/openclaw/pull/169583)，感谢[@obviyus](https://github.com/obviyus).
- **Interrupted ChatGPT 回复。** 当正常连接关闭中断未完成的 ChatGPT 回复时，在现有重试限制内，该回复可以从保存的对话中继续。请参阅 [ 模型故障转移指南](https://docs.openclaw.ai/concepts/model-failover)。 [#167512](https://github.com/openclaw/openclaw/pull/167512)，感谢 [@ericcurtin](https://github.com/ericcurtin)、[@obviyus](https://github.com/obviyus)、[@mightyx](https://github.com/mightyx) 和[@aleps001](https://github.com/aleps001).
- **Codex 后续消息。** 对话准备失败后，兼容的后续操作可以继续，同时现有后台命令继续运行。当受保护的工作运行时，不兼容的权限或策略更改仍然被拒绝。 [#169431](https://github.com/openclaw/openclaw/pull/169431)，感谢 [@jjjhenriksen](https://github.com/jjjhenriksen) 和 [@RomneyDa](https://github.com/RomneyDa).
- **切换回 OpenAI.** 当 Codex 禁用且该运行时可以运行它们时，OpenAI 模型可以使用现有的内置运行时。显式配置的 Codex 运行时仍需要启用 Codex 插件。 [#169412](https://github.com/openclaw/openclaw/pull/169412)，感谢[@obviyus](https://github.com/obviyus).
- **Claude CLI 工具发现。** Claude CLI 接收已注册的 OpenClaw 工具名称以及必须通过工具发送的回复指南，从而减少失败的查找。本指南适用于对话实际可用的工具。请参阅 [CLI 后端指南](https://docs.openclaw.ai/gateway/cli-backends)。 [#153032](https://github.com/openclaw/openclaw/pull/153032)，感谢[@kiranvk-2011](https://github.com/kiranvk-2011)，[@RomneyDa](https://github.com/RomneyDa)，[@lakemike](https://github.com/lakemike)， [@philknows](https://github.com/philknows)、[@destinedenergy](https://github.com/destinedenergy) 和 [@wbumgardner-max](https://github.com/wbumgardner-max).
- **Claude CLI 会话工具。** 在启动共享连接的回合结束后，稍后的回合将保留其授权的会话、历史记录和管理工具。每个调用者都保留自己的权限和撤销检查。请参阅 [CLI 后端指南](https://docs.openclaw.ai/gateway/cli-backends)。 [#165432](https://github.com/openclaw/openclaw/pull/165432)，感谢[@Oldrich333](https://github.com/Oldrich333)，[@Leit-motif](https://github.com/Leit-motif)，[@steipete](https://github.com/steipete)， [@XX441](https://github.com/XX441)、[@aaajiao](https://github.com/aaajiao)、[@alexph-dev](https://github.com/alexph-dev)、[@Claynetic](https://github.com/Claynetic)、[@N4DH](https://github.com/N4DH)、 [@Jeehut](https://github.com/Jeehut)、[@S1gv4rd](https://github.com/S1gv4rd)、[@arifarai](https://github.com/arifarai)、[@davidevelyn](https://github.com/davidevelyn)、[@marl0n](https://github.com/marl0n) 和[@Mydudeclaps](https://github.com/Mydudeclaps).
- **Copilot 提示容量。** 缺少本机限制的模型可以使用帐户报告的提示容量而不是 128K 估计值，而实际限制和配置的上限仍然有效。刷新发现以替换以前缓存的估计。 [#156636](https://github.com/openclaw/openclaw/pull/156636)，感谢[@saju01](https://github.com/saju01)，[@RomneyDa](https://github.com/RomneyDa)，[@snotty](https://github.com/snotty)， [@vinaycodeaxe](https://github.com/vinaycodeaxe)、[@zhangguiping-xydt](https://github.com/zhangguiping-xydt) 和 [@Yigtwxx](https://github.com/Yigtwxx).
- **DeepSeek 回复和工具操作。** 已识别的内部工具标记不会出现在回复中，托管轮次可以恢复有效的标记工具操作，包括 `calls` 包装器。直接提供商调用和最终回复会过滤标记，无需恢复工具；格式错误或未完成的识别块将保持隐藏状态而不执行。请参阅 [DeepSeek 指南](https://docs.openclaw.ai/providers/deepseek)。 [#169728](https://github.com/openclaw/openclaw/pull/169728)，感谢 [@steipete](https://github.com/steipete) 和 [@TOMUIV](https://github.com/TOMUIV).
- **IPv6 提供程序后备。当 IPv4 无法访问且启用了 Node 地址系列自动选择时，** 受保护模型请求可以尝试工作 IPv6 地址。配置的网络安全检查仍然适用。请参阅 [ 连接故障排除](https://docs.openclaw.ai/gateway/local-models#troubleshooting)。 [#168973](https://github.com/openclaw/openclaw/pull/168973)，感谢[@steipete](https://github.com/steipete)，[@an2in](https://github.com/an2in)，[@georgenaz](https://github.com/georgenaz)， [@motookoyama](https://github.com/motookoyama) 和 [@orthogonalistic](https://github.com/orthogonalistic).

## <a id="plugins-and-integrations"></a> 插件和集成

- **阻止本地插​​件设置。** Doctor 和更新保留由路径安全检查阻止的已安装或链接插件的启用、设置和策略。该插件将保持阻塞状态，直到其路径被修复；请参阅 [ 阻止插件指南 ](https://docs.openclaw.ai/gateway/doctor/config-migrations#blocked-local-plugins)。 [#168111](https://github.com/openclaw/openclaw/pull/168111)，感谢[@obviyus](https://github.com/obviyus).
- **oc-path 文件编辑。**选择加入 oc-path 插件拒绝`openclaw path set`修改无效UTF-8在重写文件之前，保留原始字节。在重试之前，请备份并修复或转换文件。[#168491](https://github.com/openclaw/openclaw/pull/168491)，感谢[@wangmiao0668000666](https://github.com/wangmiao0668000666)， [@yetval](https://github.com/yetval)和[@Takhoffman](https://github.com/Takhoffman).
- 升级期间的 **Webhook 回调。** 在激活延迟插件替换之前，可以保留现有的官方 webhook 通道回调，包括受影响的 Microsoft Teams 路径。撰写的回调和选择退出仍然受到尊重；请参阅 [webhook 迁移指南](https://docs.openclaw.ai/gateway/doctor/config-migrations#channel-webhook-listeners)。 [#169035](https://github.com/openclaw/openclaw/pull/169035)，感谢 [@steipete](https://github.com/steipete) 和 [@sirius1024](https://github.com/sirius1024).
- **本机插件目录。** 目录更改可避免重复加载未更改的已安装本机插件，从而消除了内存使用不断增长的根源。刷新失败后，下一个请求可以使用其请求的配置。 [#169272](https://github.com/openclaw/openclaw/pull/169272)，[#169321](https://github.com/openclaw/openclaw/pull/169321)，感谢[@obviyus](https://github.com/obviyus)，[@mcooks-cmd](https://github.com/mcooks-cmd)， [@svdinu-jpg](https://github.com/svdinu-jpg)、[@eduherranz](https://github.com/eduherranz) 和 [@RomneyDa](https://github.com/RomneyDa).
- **配对节点上的命令。** 未更改的连接节点在更新不相关的配对信息或正在写入另一个设备的配对时继续处理命令、请求和事件。实际撤销和令牌轮换仍然拒绝旧连接。 [#169486](https://github.com/openclaw/openclaw/pull/169486)、[#169575](https://github.com/openclaw/openclaw/pull/169575)，感谢 [@steipete](https://github.com/steipete) 和 [@gisk0](https://github.com/gisk0).
- **Codex 插件兼容性。** 早于 2026.9.7 的官方外部 Codex 软件包在破坏回复之前报告不可用。合格的官方更新遵循核心版本，失败会显示有用的原因。使用`openclaw update repair`或`openclaw plugins update codex`；链接副本需要更新其源或删除加载路径覆盖。当迁移挂起时，请在重新启动之前完成 Doctor。请参阅[插件更新指南](https://docs.openclaw.ai/cli/plugins/uninstall-and-update)。 [#170306](https://github.com/openclaw/openclaw/pull/170306)，感谢 [@RomneyDa](https://github.com/RomneyDa)、[@steipete](https://github.com/steipete) 和 [@ezimerman](https://github.com/ezimerman).
- **插件包修复。** 在数据迁移未完成时可以保存替换包，以便Doctor继续。 **在重新启动或重新加载替换之前完成 `openclaw doctor --fix`。** 不可用自动选择的官方 ClawHub 版本可以使用受信任的相同版本 npm 软件包，或保持兼容的已安装代码并重试警告。删除插件的条目会保留其备份和待处理的迁移义务。请参阅 [ 更新指南 ](https://docs.openclaw.ai/install/updating)。 [#170339](https://github.com/openclaw/openclaw/pull/170339)，感谢[@RomneyDa](https://github.com/RomneyDa)，[@steipete](https://github.com/steipete)，[@h6y3](https://github.com/h6y3)， [@CodeForcer](https://github.com/CodeForcer)、[@waynegault](https://github.com/waynegault) 和 [@rauf543](https://github.com/rauf543).

## <a id="security-and-privacy"></a> 安全与隐私

- **Doctor 修复期间保存的登录。** 不可读的旧版身份验证文件不再导致受影响的清理操作丢弃已保存的 OAuth 配置文件。 Doctor 在重试之前识别要检查或恢复的文件，而不相关的修复可以继续。以前删除的配置文件和已停用的凭据导入不会恢复。参见[医生状态恢复指南](https://docs.openclaw.ai/gateway/doctor/state-and-sessions)。 [#170256](https://github.com/openclaw/openclaw/pull/170256)，感谢 [@steipete](https://github.com/steipete) 和 [@nosmile99](https://github.com/nosmile99).
