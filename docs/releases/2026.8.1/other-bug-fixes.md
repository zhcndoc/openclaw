OpenClaw 现在通过覆盖的切换保留完整的 Codex 委托结果，防止接受的用户轮次存储两次，在开始之前停止取消的命令，并在重新加载后保留 Canvas 小部件身份和引脚状态。本节的其余部分涵盖浏览器 Talk、Copilot 和 xAI 重播、[Doctor](/cli/doctor) 恢复、插件升级、会议音频和 [ 终端应用程序 ](/web/tui) 的范围修复。

<AccordionGroup>

<Accordion id="agent-work-and-handoffs" title="代理工作和交接">

在修复的 [Codex 委托 ](/tools/subagents) 和 `sessions_yield` 路径中，已完成的子代理结果现在可以在清理和移交中幸存下来，产生作业启动一次，并且父代理在扇出完成后恢复。

<Accordion id="agent-tools-and-code-execution" title="代理工具和代码执行">

[Code Mode](/tools/code-mode) 可以让符合条件的任务在采取行动之前或发现工具和技能时失败时保持移动，并且嵌套工具调用现在可以干净地完成或取消，而不是挂起。一旦发生写入，恢复仅限于检查发生了什么变化，而不是重播不确定的操作，而取消、策略拒绝和其他最终结果仍然会停止任务。

<Accordion id="processes-and-background-commands" title="进程和后台命令">

现在，取消排队的命令会使其无法启动，启动期间的取消会到达进程（一旦存在），并且显式替换会停用它所替换的命令，而不会终止恰好同时运行的普通工作。已经在后台运行的命令保持其现有的生命周期。

[进程输出](/tools/exec)也保持在OpenClaw观察它的顺序，完成仍然附加到完成的确切进程，并且轮询表明何时省略了早期输出。完整的历史记录仍然可以通过分页的进程日志获得，而不是可以无限增长的一个响应。
