重建的 [Control UI](/web/control-ui) 将对话置于 OpenClaw 的中心，文件、批准、设置和现场工作都靠近对话，因此您可以设置 Claw，跟随它正在做什么，并继续工作，而无需在不同的工具之间切换。

<AccordionGroup>

<Accordion id="navigation-and-sidebar" title="导航和侧边栏">

对于使用 ChatGPT、Claude、Gemini 或 Perplexity 等应用程序的任何人来说，OpenClaw 中的 [ 基于 Web 的体验 ](/web/control-ui) 现在感觉更加熟悉，对话位于侧边栏中，而您正在使用的对话则位于中心在单独的概述页面上打开。设置和收件箱会保留设置详细信息和警报，直到您需要为止，而对话和新会话草稿可以在真实的浏览器选项卡或窗口中打开。

侧边栏可以保持完全平坦，或者按项目、人员或您自己的自定义组进行分组对话，将工作树折叠回原始项目，并记住其宽度，这使得当您在大量工作之间移动时，它感觉不像开发人员工具。

<Accordion id="starting-and-managing-conversations" title="启动和管理对话">

启动 [ 新对话](/concepts/session) 现在是一个正确的设置屏幕，而不是继承任何默认活动的空白聊天。在开始任何操作之前，您可以选择代理、模型、推理级别、打开消息或图像、工作区以及应运行它的计算机，然后使用组、脚本搜索、状态和批处理操作来管理稍后的工作。

工作树对话立即打开并显示原始消息，同时命名、结帐和设置继续进行。如果远程启动失败，提交的提示和附件通过同一会话重试或只读检查传递操作保持可见，并且稍后的消息会等待，直到 OpenClaw 知道发生了什么，而不是冒重复或乱序发送的风险。

支持的 Codex 对话可以从较早的消息分支，而无需更改原始消息，并且当所选子模型可以安全地接受该上下文时，显式分叉可以使用超过 100,000 个令牌。自动线程和子代理分叉保持 100,000 个令牌的限制。

<Accordion id="chat-and-history" title="聊天和历史记录">

[Chat](/web/webchat) 现在在爪子工作时感觉更加活跃。回复在流式传输时呈现为 Markdown，加载较旧的消息不会让您陷入困境，并且最近的对话可以在网关完成刷新之前显示。

作曲家在长时间运行的工作中更容易使用。您可以在发送之前更改模型、推理或速度，编辑和重新排序排队的后续内容，并使用听写而不会意外发送结果。

其中一个更有用的新增功能是 `/btw`，它会打开一个单独的多轮对话，这样您就可以提出附带问题，而不会破坏工作或填充主要历史记录。更快的初始历史记录使用未加密存储在浏览器配置文件中的有界副本快照。

<Accordion id="follow-the-work-and-approve-actions" title="跟踪工作并批准行动">

当爪子工作时跟随它要容易得多。现在，工具调用与其结果清晰地配对，命令活动更易于阅读，文件更改显示重点差异，并且更大的屏幕可以在对话旁边继续运行后台任务以及已用时间和最近的活动。有权更改对话的人可以在那里停止工作，而完整的 [ 任务页面 ](/automation/tasks) 涵盖跨对话的工作。

目标现在从正常的编辑模式开始，并通过编辑、暂停、恢复和清除保持可管理性，而不是用斜杠命令填充对话。草稿可以在重新加载和会话切换后保存下来，并且即使目标很长，该卡仍然可以在手机上使用。旧的网关保留文本/目标工作流程而不是这些结构化控件。如果您在 ChatGPT 或 Claude Desktop 中使用过 [ 批准门 ](/tools/exec-approvals)，批准流程也应该感觉很熟悉，对话中的请求会触发它们，而当需要注意某些事情时，其他地方会有一个安静的指示器。

一旦回合结束，中间评论和工具就会折叠成 **Worked for** 摘要，您可以重新打开。实时活动、搜索结果、仅附件回复、未解决的错误和待批准的审批在实际完成之前保持可见，而不是被清理掉，关闭审批队列会留下待处理的请求，而不是为您决定。

<Accordion id="files-git-browser-and-terminal" title="文件、Git、浏览器和终端">

OpenClaw 现在可以将工作与对话分开，而不是让您在工具之间来回切换。在支持的管理员连接上，您可以从聊天中打开和编辑符合条件的现有文本或 Markdown 文件，如果 Claw 在您工作时更改同一文件，编辑器会因冲突而停止，而不是覆盖较新的版本。 “更改”面板显示分支提交和工作树编辑，而符合条件的 GitHub 签出会添加拉取请求状态、CI 摘要以及在 GitHub 上启动拉取请求的链接。

[ 停靠的浏览器面板](/tools/browser) 可以在将屏幕截图和页面上下文附加到对话之前导航、单击、键入、滚动、检查元素和标记屏幕截图，但它需要广告浏览器支持和管理员连接，并且页面或捕获中出现的任何内容都可能是敏感的。

聊天、详细信息和讨论可以位于可调整大小的列中或合并到选项卡中，而当您需要更多空间时，仪表板、[终端](/tools/exec)和桌面可以在集中视图中打开。文件编辑器仍然无法创建或删除文件，“更改”保持只读状态，“创建 PR”将移交给 GitHub，而不是在 OpenClaw 内提交。

<Accordion id="settings-and-connected-services" title="设置和连接的服务">

[Settings](/gateway/configuration) 现在更易于导航。它有自己的全页工作区，搜索目标和单独的控件，将常用选项与高级选项分开，并使面板 URL 保持可书签状态。如果值不完整或无效，草稿将保留在屏幕上，以便您可以修复它，并且正常形式的设置无法在原始模式下安全打开，而不是默默地丢失。

主要控件也有更清晰的归属。连接详细信息、代理身份和内存、插件、MCP 服务器、设备、通道和配对围绕您实际管理它们的位置进行组织，而模型提供商则汇集了每个提供商报告的凭证运行状况、可用模型、配额、余额、预算和支出数据。该提供程序视图是只读的，引导式 MCP 管理仍然存在于插件中，而设置则保留诊断和原始编辑。

访问权限有限的浏览器可以请求管理员范围，但另一位管理员仍必须批准来自该设备的签名请求。受信任的仪表板链接和本机配对流程可以帮助符合条件的管理员恢复访问权限，而无需将共享令牌转变为旁路。

<Accordion id="sharing-and-incognito" title="共享和隐身">

在 [ 多用户 Gateway](/concepts/multi-user) 上，对话现在使其创建者和每个已识别人员的提示保持可见，而所有者或管理员可以选择其他人是否可以阅读、建议更改、处理草稿或直接参与。草稿可以在没有竞赛的情况下创建和发布，建议可以保留作者，轻量级的存在和打字提示可以让您更容易地知道谁在场，而不会弄乱单独的设置。

人们可以管理自己的显示名称和头像，并且允许的在线卡可以显示某人正在做什么，而不会暴露 IP 地址或查看者无法打开的对话。这些控制使协作变得易于理解，但它们不是租户隔离或安全边界，并且撤销的访问权限可能会短暂地看起来可用，直到 UI 刷新或网关拒绝该操作。

隐身模式默认处于关闭状态，并且故意缩小范围。它的对话保留在进程内存中，不会将正常的记录或自动 OpenClaw 内存写入磁盘，并在网关重新启动时消失，但模型提供者仍然会收到消息，工具仍然可以写入文件或影响外部服务，无内容的审计元数据仍然存在，并且任何操作网关的人都可以看到实时工作。

<Accordion id="control-ui-latency-and-responsiveness" title="Control UI 延迟和响应能力">

[Control UI](/web/control-ui) 现在可以更快地实现聊天。在使用模拟网关和 50 毫秒 HTTP/1.1 延迟的模拟默认聊天测试中，JavaScript 请求从 140 下降到 45，启动时间从大约 1.6 秒下降到 575 毫秒。

打开的时间越长，它的重量也会越轻。隐藏面板停止获取它们不显示的数据，保留状态受到限制，并且返回对话重复更少的渲染。

重新连接会拒绝过时的响应，并在连接发生变化时保持选择正确的对话。如果页面包加载但从未呈现，OpenClaw 现在会显示恢复指南和重试操作，而中断的更新会与替换网关协调，并仅在报告预期版本后确认成功。
