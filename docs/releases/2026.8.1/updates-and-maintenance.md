title: "v2026.8.1：更新和维护"
description: "支持的更新路径在替换之前检查安装，维护工具提供更清晰的恢复路径。"
---

用户在更新 OpenClaw 后有时会遇到不稳定的情况。 [支持的更新路径](/install/updating)现在在替换之前检查安装并停止不安全的候选者，同时保持以前的CLI可运行。在 Control UI 中，更新会识别目标、要求确认并保持进度和最终结果可见。

维护工具现在提供更清晰的恢复路径。配置错误指出需要注意的设置，医生专注于问题和下一步操作，根据受保护的恢复路径检查新备份，当所有权不清楚时停止破坏性清理，支持的重新启动为跟踪工作提供了在移交之前完成的时间。

<AccordionGroup>

<Accordion id="installing-openclaw-updates" title="安装 OpenClaw 更新">

在 [Control UI](/install/updating) 中启动的网关更新现在可以识别目标、需要确认、显示更新和重新启动的进度，并报告最终结果。在符合条件的签名 Mac 应用程序上，该流程首先更新应用程序，然后仅更新应用程序管理的本地网关；浏览器和用户管理的安装保留其仅网关路径。

[支持的CLI更新](/cli/update)在替换之前检查Node兼容性、包管理器生命周期规则以及npm、pnpm或Bun是否拥有安装。不安全的候选者会停止，同时使先前的 CLI 保持可运行状态，而精确的 `openclaw update --dry-run` 会预览路径，而不更改配置、切换、清理或重新启动状态。

在 Linux 上，代码更新可以保留管理员拥有的服务定义，而不是尝试重写它，而不安全或不可检查的服务切换仍然会明显失败。如果插件替换需要新功能，OpenClaw 会在替换等待审核时保持已知良好的插件可用； `openclaw update --accept-capabilities` 或 `openclaw update repair --accept-capabilities` 仅批准该调用的暂存工件，而 `--yes` 则不批准。

其中一条升级路径仍需要手动修复。如果您在 OpenClaw 2026.7.1 上使用 pnpm 11，请运行 `pnpm add -g openclaw@latest` 一次。 OpenClaw 不会为您升级 Node。

<Accordion id="configuration-errors-and-service-repairs" title="配置错误和服务修复">

错误的 [configuration](/gateway/configuration) 现在会以有用的答案停止，而不是悄悄地用其他东西启动 OpenClaw。打包构建、CLI 检查、服务预检和网关启动显示文件、行、完整设置路径、允许的值（如果可用）以及所接收内容的安全版本；格式错误的顶级标量文件无法关闭，而不是加载默认值。

如果您要升级仍包含已停用密钥的配置，请在 2026 年 9 月 18 日之前运行 `openclaw doctor --fix`。[Doctor](/cli/doctor) 在新旧密钥冲突时保留规范值，并删除不再执行任何操作的设置，尽管显式停用的调整值会返回到内置默认值。

支持的网关服务修复会保留已安装的状态目录、配置路径、端口、托管环境和合格的文件支持凭据，而不是默默地重新定位服务。有意更改这些目标需要 `openclaw gateway install --force`；在 Linux 上，服务命令还拒绝冲突的用户和系统单元，并显示哪个单元拥有网关。

<Accordion id="openclaw-restarts-and-running-work" title="OpenClaw 重启并运行工作">

在支持的快照或 [ 有针对性的重新启动 ](/gateway/restart-recovery) 之前，网关挂起和恢复可以暂停新的普通工作、报告阻止程序并耗尽 OpenClaw 已跟踪的代理运行、交付、计划作业、队列、会话和后台命令。失败的配置重新加载会保持先前的一致状态，并且快速配置写入会保留挂起的重新启动意图而不是丢弃它。

重新启动后，运行状况检查、代理列表和核心控件将在可选目录、插件和迁移工作完成之前变得可用。该工作被推迟而不是删除，因此第一个显式目录请求仍然可能需要更长的时间。

等待涵盖了 OpenClaw 曲目。新通道或外部入口、现有插件连接、未注册的后台工作以及传入消息的持久接收仍保留在其外部，并且外部监督的安装必须消耗切换并完成自己的重新启动。

<Accordion id="troubleshooting-system-health-and-logs" title="故障排除、系统运行状况和日志">

[Doctor](/cli/doctor) 现在花更少的时间来背诵健康的库存，而用更多的时间来展示什么坏了以及下一步该做什么。可恢复的交互式启动故障可以提供一次确认的 `doctor --fix` 尝试，而不可恢复的配置保持不变，并提供检查、编辑或将其移到一边的确切说明。裸 `openclaw doctor --json` 是只读咨询检查；当您需要从默认运行中省略咨询检查时，请使用 `openclaw doctor --lint --all`。

[Logs](/cli/logs) 现在在短读取中填充其有界尾窗口，在文件边界保留 Unicode，区分行和字节截断与翻转，并报告不可用存储而不是空成功。当可选的运行状况详细信息失败时，状态会保留其基本报告，因此丢失的信息仍然未知，而不是显示为运行状况良好。

在管理 Control UI 中，询问 OpenClaw 可以将相应的健康状态转变为诊断问题，并在您四处走动时保持系统维护对话对接，而系统覆盖图则显示调度程序压力、CPU、内存、事件循环延迟和可选磁盘活动的简短历史记录。这些控件需要管理员或操作员访问权限，并且不会在入门引导期间或读取范围内的客户端中出现。

<Accordion id="command-line-output-and-shell-completion" title="命令行输出和 Shell 完成">

脚本使用的命令现在具有更可预测的机器界面。命名的 JSON 和 JSONL 命令将终端重置字节保留在标准输出之外，并在调用失败时返回一致的结构化错误，因此自动化不再需要对它们进行特殊处理。

[Shell 完成](/cli) 安装和刷新保留不相关的配置文件内容和权限，同时跨 Bash、Zsh、Fish 和 PowerShell 自动发布配置文件和缓存。远程网关转动和常见的只读命令也会跳过它们不需要的启动工作，而本地探测和人工输出则保持更全面的验证；错误输入的命令现在指向拒绝它们的命令树、附近的命令以及正确的帮助。

可预测的机器输出合同涵盖了指定的命令路径。人工诊断仍然可以出现在 stderr 上，成功的降级结果仍然是特定于命令的，并且原始生命周期错误编辑尚未普及。

<Accordion id="backup-restore-reset-and-uninstall" title="备份、恢复、重置和卸载">

[重置并卸载](/cli/reset)现在拒绝删除数据，直到网关服务被拆除并且OpenClaw可以确定没有其他进程拥有该状态。如果拆卸或所有权检查失败，状态将保持不变，并且仅状态卸载将保留已配置的工作区。

新的 [ 完整备份](/cli/backup) 保留配置的代理状态根和安全相关链接，避免将活动存档工作误认为是停顿，并通过相同的受保护流程恢复默认或自定义布局。托管 `dev/` 签出和本地源编辑仍然需要单独的备份，而包含绝对生成的 `plugin-skills/` 链接的旧存档仍然被拒绝。

已知存在漏洞的 Node 和 SQLite 组合现在会在状态打开之前停止，并指导嵌入式 Node 运行时或共享系统 SQLite 库是否需要升级。
