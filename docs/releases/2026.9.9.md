# v2026.9.9

AI 代理和工具可以将这些发行说明读取为 [plain Markdown](https://raw.githubusercontent.com/openclaw/openclaw/main/CHANGELOG/2026.9.9.md)。

OpenClaw 2026.9.9 将 GPT-6.1 Sol 添加到 Codex 模型列表中，并支持 Claude Haiku 5.5 至 Anthropic 和 Claude CLI，改进更新失败后的恢复，修复丢失的 iMessage 回复，并防止旧的计划作业中断新的对话。

**发布规模：** 112 个拉取请求、69 个直接提交和 91 个贡献者。

## <a id="installation-and-onboarding"></a> 安装和入门

- **通道设置。** 在引导设置中逐个添加通道不再使 OpenClaw 等待设置窗口本身时保存卡在工作状态。 [#161116](https://github.com/openclaw/openclaw/pull/161116) by [@steipete](https://github.com/steipete).

## Web UI

- **Windows 工作区。** 在 Windows 上创建空工作区不再因 OpenClaw 调用 Git 的方式而失败。您可以选择 **New 工作区** 并开始对话，而无需更改全局 Git 设置。首先使用 [native Windows 设置指南 ](/platforms/windows#native-windows-cli-and-gateway) 安装 Windows 的 Git。嵌套太深的文件夹仍然可能达到单独的 Git 限制。 [#164202](https://github.com/openclaw/openclaw/pull/164202) by [@steipete](https://github.com/steipete).
- **对话标题。** 当您的模型服务器一次处理一个请求时，OpenClaw 可以在第一个回复完成后尝试再次命名新对话，而不是保留随机名称。您自己选择的名称将被保留。 [#163817](https://github.com/openclaw/openclaw/pull/163817) by [@MertBasar0](https://github.com/MertBasar0) 和 [@obviyus](https://github.com/obviyus).
- **聊天阅读位置。** 跳转到最新消息并向后滚动后，调整聊天大小不再将您拉到最新消息。 [#162411](https://github.com/openclaw/openclaw/pull/162411)，合著者 [@steipete](https://github.com/steipete).
- **频道对话历史记录。** 从仪表板发送到频道的消息会保留其原始对话关联。来自链接请求者的新消息也不再在 Claude CLI 聊天历史记录中出现两次，并且内部请求者指令不显示在显示的文本中。现有记录不会被重写。 [#151786](https://github.com/openclaw/openclaw/pull/151786)，作者：[@Alix-007](https://github.com/Alix-007)，报告者：[@Rotocruz](https://github.com/Rotocruz)； [#161012](https://github.com/openclaw/openclaw/pull/161012)，作者：[@Marvinthebored](https://github.com/Marvinthebored) 和 [@Peetiegonzalez](https://github.com/Peetiegonzalez)，来自 [@Oldrich333](https://github.com/Oldrich333) 的报告， [@holgergruenhagen](https://github.com/holgergruenhagen) 和 [@obnoxious2011-cmd](https://github.com/obnoxious2011-cmd).
- **打开和更新聊天。** 聊天可以在其标签或活动详细信息更改时打开，并且当较旧的历史记录请求较晚完成时，保存的后台回复仍然可见。 [#162681](https://github.com/openclaw/openclaw/pull/162681)、[#162763](https://github.com/openclaw/openclaw/pull/162763)，[@VACInc](https://github.com/VACInc) 的贡献和后续调查[@steipete](https://github.com/steipete).
- **聊天滚动。** 当您观看最新消息时，聊天会继续跟踪传入的轮次和大型更新，而向后滚动可保留您的阅读位置。扩展细节和延迟布局更改保留了这种选择。在不改变高度的情况下刷新历史也避免了不必要的跳跃。 [be6713b](https://github.com/openclaw/openclaw/commit/be6713bf97f9a8044982a6fb0a2bbc3fdc3afec0)、[0c01cc6](https://github.com/openclaw/openclaw/commit/0c01cc6e0aaa757700476db707785998391ff9b9)、[#166239](https://github.com/openclaw/openclaw/pull/166239)、 [#166258](https://github.com/openclaw/openclaw/pull/166258)、[#166301](https://github.com/openclaw/openclaw/pull/166301)、[#166341](https://github.com/openclaw/openclaw/pull/166341)，贡献来自[@steipete](https://github.com/steipete) 和 [@RomneyDa](https://github.com/RomneyDa).
- **展开的聊天详细信息。** 打开消息的可展开详细信息会将单击的内容保留在适当的位置，而不是将其拉向聊天底部。 [#166200](https://github.com/openclaw/openclaw/pull/166200)，作者：[@RomneyDa](https://github.com/RomneyDa)，包含 [@steipete](https://github.com/steipete). 的源代码
- **流式回复和作曲家间距。** 跳转到不需要移动的底部后，随着文本到达，回复不断滚动。空通知也不会在消息框上方留下空白。 [#166348](https://github.com/openclaw/openclaw/pull/166348) by [@RomneyDa](https://github.com/RomneyDa)，间距由 [@vincentkoc](https://github.com/vincentkoc). 修复

## <a id="updates-and-maintenance"></a> 更新和维护

- **更新完成。** 更新OpenClaw不再仅仅因为同时保存数据而失败。受影响旧版本的更新会保留插件完成升级所需的文件，全局 npm 安装可避免错误的恢复文件检查失败。一旦所需的数据库工作完成，停滞的关闭也可以停止阻止更新结果；该保护措施适用于固定安装运行的后续更新。 [30c180a](https://github.com/openclaw/openclaw/commit/30c180a4ece3ae149286b80174b0edb526aa88ae)、[ecac0d3（原始迁移修复）](https://github.com/openclaw/openclaw/commit/ecac0d3f0bdca5d127df1b4f269d007714697ce4)、[55360c6](https://github.com/openclaw/openclaw/commit/55360c6bdbd479d4e784aed79c6350b61f6febb0) [@RomneyDa](https://github.com/RomneyDa)； [#161258](https://github.com/openclaw/openclaw/pull/161258) by [@steipete](https://github.com/steipete).
- **维护错误。** 修复了错误的维护警告，该警告可能会中断更新并不必要地将 OpenClaw 返回到先前版本。 [#164554](https://github.com/openclaw/openclaw/pull/164554)，作者：[@RomneyDa](https://github.com/RomneyDa)，源代码作者：[@steipete](https://github.com/steipete)，报告和调查作者：[@DasX](https://github.com/DasX).
- **更新失败恢复。** 支持的更新程序可以在更新失败后恢复兼容的 OpenClaw 安装，同时保留尝试期间写入的数据。返回 2026.9.8 也使以后的更新成为可能。已经运行的旧更新程序无法获得这些保护措施。在 macOS 和 Linux 上，重新启动将保持阻止状态，直到确认 Doctor 进程已停止。按照 [ 修复步骤 ](/cli/update/repair-and-recovery) 和 [ 回滚指南 ](/install/updating/rollback-and-recovery) 进行操作。 [#164497](https://github.com/openclaw/openclaw/pull/164497)、[#164724](https://github.com/openclaw/openclaw/pull/164724) by [@RomneyDa](https://github.com/RomneyDa)，原始恢复工作由[@steipete](https://github.com/steipete) 以及来自 [@DasX](https://github.com/DasX) 和 [@jarvisnextgeneration20-lang](https://github.com/jarvisnextgeneration20-lang). 的报告
- **FUSE 存储上的备份。** 如果您使用通过 FUSE 安装的存储，备份和恢复将不再仅仅因为文件的记录时间更改而失败。 OpenClaw 在继续之前检查内容是否仍然匹配。这包括更新、Doctor 修复和回滚；请参阅 [ 容器升级指南](/install/docker#upgrading-container-images)。 [3ecb62a（原始 FUSE 修复）](https://github.com/openclaw/openclaw/commit/3ecb62aad260e3f871e7ae83d446404abfc83bed) by [@steipete](https://github.com/steipete).
- **较旧的内存数据库。** 即使某些保存的条目太大或损坏，Doctor也可以完成旧内存缓存的升级。它会警告您有关跳过的条目，这些条目会根据需要重建，同时原始数据保持不变。在数据库升级之前，请停止使用该数据库的进程并按照 [ 迁移指南](/reference/database-schemas/agent-schema-history#compact-agent-payload-storage) 中的说明进行经过验证的备份。 [#164303](https://github.com/openclaw/openclaw/pull/164303) by [@steipete](https://github.com/steipete).
- **Package-manager更新。** pnpm更新避免“不是终端”故障，并且可选的插件语法错误可以产生警告而不是阻止更新快照。大型 npm 安装可以继续超过扫描限制，并发出完整包内容未经验证的警告。较旧的更新程序可能需要 [ 手动首次更新 ](/install/updating/update-methods#alternative-manual-npm-pnpm-or-bun) 或 [ 插件恢复步骤 ](/install/update-troubleshooting)。 [df11aae](https://github.com/openclaw/openclaw/commit/df11aae60f49047bf56903b5fd0b79be4760a5b1)，作者：[@alkor2000](https://github.com/alkor2000)； [#161001](https://github.com/openclaw/openclaw/pull/161001)、[#162298](https://github.com/openclaw/openclaw/pull/162298)，作者：[@steipete](https://github.com/steipete)，报告作者：[@jamiezigelbaum](https://github.com/jamiezigelbaum).
- **Windows 更新检查。** 修复了较旧的更新程序兼容性问题，该问题可能导致第一个 Doctor 检查失败并回滚 Windows 更新。 [#162245](https://github.com/openclaw/openclaw/pull/162245)，作者：[@steipete](https://github.com/steipete)，报告和诊断者：[@WG-Mojo](https://github.com/WG-Mojo).
- **Docker 启动。** 修复了受影响的较旧 Linux 主机上的升级循环，该循环反复拒绝未更改的数据库。重试重复使用经过验证的回滚备份，而不是每次都制作另一套完整的备份；历史备份仍然可用。请参阅 [Docker 恢复指南](/install/docker)。 [#162305](https://github.com/openclaw/openclaw/pull/162305)，作者：[@steipete](https://github.com/steipete)，报告和调查：[@Ludwigtheo0815](https://github.com/Ludwigtheo0815)、[@rebarshop-24](https://github.com/rebarshop-24) 和[@nweishar](https://github.com/nweishar).
- **医生维护。** 长数据库检查显示进度并响应Ctrl+C，等待已在进行的工作完成清理后再退出。中断后重新运行 Doctor 以完成修复。当可选的更新历史记录检查不可用时，Doctor 还可以继续。 Doctor 还让清理工作在关闭前完成，从而避免关闭期间出现 Windows 崩溃风险。 [维护指导](/cli/doctor/sqlite-maintenance)、[#162213](https://github.com/openclaw/openclaw/pull/162213)、[#163608](https://github.com/openclaw/openclaw/pull/163608) [@steipete](https://github.com/steipete)，来自 [@fenglanhua](https://github.com/fenglanhua) 和 [@ringbe-cyber](https://github.com/ringbe-cyber). [5d7fa8e](https://github.com/openclaw/openclaw/commit/5d7fa8e9fa04a0202407891ba598b117908db3a8) 的报告。
- **会话存档修复。** Doctor 可以导入被较旧迁移记录阻止的会话并重试中断的存档修复。丢失的文件副本保留标记以供恢复，并保留原始数据库内容。 Doctor 还尝试恢复维护完成后停止的托管网关。回滚 OpenClaw 不会撤消已提交的存档更改。 [#164867](https://github.com/openclaw/openclaw/pull/164867)，作者：[@steipete](https://github.com/steipete)，报告者：[@hshs38033-cmd](https://github.com/hshs38033-cmd)； [#165854](https://github.com/openclaw/openclaw/pull/165854)，作者：[@RomneyDa](https://github.com/RomneyDa) 和 [@Olli0103](https://github.com/Olli0103)，来自 [@A1fred-AI](https://github.com/A1fred-AI) 的报告和调查， [@mpquemel](https://github.com/mpquemel)、[@goncalonc](https://github.com/goncalonc) 和 [@steipete](https://github.com/steipete).
- **插件安装记录。** 升级遇到损坏的旧插件元数据会保留原始记录及其有效安装条目。已经丢失的数据仍然需要备份，并且单独的未解决的注册表刷新问题可能会覆盖保留的条目；不要使用刷新作为有保证的恢复步骤。 [#161485](https://github.com/openclaw/openclaw/pull/161485)，作者：[@steipete](https://github.com/steipete)，报告者：[@aniruddhaadak80](https://github.com/aniruddhaadak80).
- **隔离的数据库。** 打开会话现在遵循现有的损坏隔离区。受影响的安装可能会失去只读访问权限，直到修复或恢复成功为止；保留数据库及其 WAL 文件并遵循 [ 恢复指南](/reference/database-schemas/integrity-and-recovery#a-database-is-quarantined-after-integrity-verification-failed)。 [#161783](https://github.com/openclaw/openclaw/pull/161783)，作者：[@SunnyShu0925](https://github.com/SunnyShu0925)，[@steipete](https://github.com/steipete) 报告，[@Patrick-Erichsen](https://github.com/Patrick-Erichsen). 验证
- **重新启动恢复。** 如果自动分类修复了拒绝的网关重新启动，OpenClaw 会尝试再次启动。失败的重试，或者已安装的分类处理程序拒绝或无法完成，现在可以退出并出现错误。前台和容器部署需要外部重启策略才能从该退出中恢复。 [#160173](https://github.com/openclaw/openclaw/pull/160173)，作者：[@steipete](https://github.com/steipete)，报告者：[@dh-js](https://github.com/dh-js).
- **Monterey 服务命令。** 在受影响的 macOS 12 安装上，当 OpenClaw 确定这样做是安全的时，网关停止、重新启动和更新命令可以从独立的终端窗口运行。未修复的较旧更新程序可能仍需要 [one-time 停止、更新和启动序列 ](https://github.com/openclaw/openclaw/pull/163317)。 [#163317](https://github.com/openclaw/openclaw/pull/163317)、[#165935](https://github.com/openclaw/openclaw/pull/165935) 由 [@NovaUnboundAi](https://github.com/NovaUnboundAi)、[@xXG0DLessXx](https://github.com/xXG0DLessXx) 和[@RomneyDa](https://github.com/RomneyDa).
- **非常旧的配置。** 已停用设置的更新错误现在通过 2026.9.5 和 `doctor --fix` 解释所需的中间升级。保持相同的配置文件和配置路径，并遵循 [ 旧版本升级指南 ](/install/updating#upgrading-very-old-versions)。 [#162150](https://github.com/openclaw/openclaw/pull/162150) by [@steipete](https://github.com/steipete).
- **September 数据库兼容性。** 从 9 月稳定版升级，使共享数据保持 2026.9.8. 使用的格式。已通过 10 月测试版转换为较新格式的数据无法在此版本中打开，并保持不变；此更新无法降级或修复它。 [#166959](https://github.com/openclaw/openclaw/pull/166959) by [@RomneyDa](https://github.com/RomneyDa)，早期的兼容性工作在 [#166026](https://github.com/openclaw/openclaw/pull/166026) 中[@RomneyDa](https://github.com/RomneyDa) 和 [@shakkernerd](https://github.com/shakkernerd).
- **Doctor 修复恢复。** 存档修复可以继续过去的空旧会话条目，并在中断后恢复保存的进度。 Doctor 还会重试失败的资源清理，并在清理安全后恢复网关，同时仍报告错误。 [ 状态迁移指南](/cli/doctor/state-migrations)、[ed472c0](https://github.com/openclaw/openclaw/commit/ed472c065b53fbecc342b549882b6eba41db2ec2)、[fab3a66](https://github.com/openclaw/openclaw/commit/fab3a6622e20d76fb3e850854372e44479a9dd71)，作者：[@RomneyDa](https://github.com/RomneyDa)，与合著者[@steipete](https://github.com/steipete) 和 [@victor-gurbani](https://github.com/victor-gurbani) 对 Doctor 和 Claude CLI 进行维修。
- **较旧的 ACP 会话。** 即使原始会话文件已移至存档中，升级也会保留较旧的 ACP 会话设置。 [16398dc](https://github.com/openclaw/openclaw/commit/16398dcb4a1d3b2fdb96d2206a82074825f3754d) by [@RomneyDa](https://github.com/RomneyDa).
- **Windows 网关发现。** 属于不相关的 Windows 计划任务的不可读启动器不再仅仅因为该任务正在运行而阻止网关发现。通过单个 BAT 文件启动的一些自定义网关仍然可能未被检测到。 [#166299](https://github.com/openclaw/openclaw/pull/166299)，作者：[@RomneyDa](https://github.com/RomneyDa)，源代码：[@steipete](https://github.com/steipete).

## <a id="messaging"></a> 消息传递

- **Telegram Control UI.** 要在 Telegram 中打开 OpenClaw 的迷你应用程序，请在与机器人的私人聊天中发送 `/controlui`。 `/dashboard` 现在属于会话仪表板。按照 [ 迁移指南 ](/channels/telegram/mini-app#upgrading-from-dashboard) 替换旧的快捷方式并获得新的按钮。访问需要在机器人所有者设置中输入数字 Telegram ID；如果您依赖通配符或用户名，请要求管理员添加它。 [#161369](https://github.com/openclaw/openclaw/pull/161369) by [@mmaps](https://github.com/mmaps)，命令分离为 [@joshavant](https://github.com/joshavant).
- **iMessage 回复。** OpenClaw 可以在普通的 iMessage 对话中写完答案，但从未发送。受影响的回复现已发送。 [#163742](https://github.com/openclaw/openclaw/pull/163742)，合著者 [@VACInc](https://github.com/VACInc)、[@Kimiyu-186](https://github.com/Kimiyu-186) 和 [@steipete](https://github.com/steipete).
- **Discord 任务结果。** 委托任务可以在您的 Discord 线程中发布其答案，但仍然显示为失败，因为它没有发送进一步的回复。 OpenClaw 现在可以识别已交付的答案。通过 Webhook 发送的回复也使用分配给您的线程的 Webhook 和身份。 [#163756](https://github.com/openclaw/openclaw/pull/163756)，作者：[@MertBasar0](https://github.com/MertBasar0)，报告者：[@stuart-minion-ai](https://github.com/stuart-minion-ai)，登陆者：[@obviyus](https://github.com/obviyus).
- **Discord 运行状况检查。** 当 Discord 活动或语音组件无法加载时，可以继续进行配置和运行状况检查。 [f489f0f](https://github.com/openclaw/openclaw/commit/f489f0f62adee590e0d68ff75df0143a6015f41f)。
- **取消排队的消息。** 如果取消仍在等待处理的消息，则已经在进行中的回复可以完成而不是卡住。 [单独的未解决问题](https://github.com/openclaw/openclaw/pull/164230#issuecomment-5968104212)可以让待处理的插件工作在您重置或删除对话时继续进行。 [#164230](https://github.com/openclaw/openclaw/pull/164230) by [@vincentkoc](https://github.com/vincentkoc).
- **Google Chat 和 Slack 线程。当启用线程时，** Google Chat 回复会保留在其原始线程中，即使键入指示器失败也是如此。当没有请求其他目标时，来自 CLI- 支持的代理的 Slack 回复也会保留原始线程。 [Google 聊天指导](/channels/googlechat)、[松弛线程指导](/channels/slack/threads-and-sessions)、[#136689](https://github.com/openclaw/openclaw/pull/136689) by [@ScientificProgrammer](https://github.com/ScientificProgrammer) 和[@obviyus](https://github.com/obviyus)，经[@danieljimz](https://github.com/danieljimz)验证； [#160751](https://github.com/openclaw/openclaw/pull/160751) 由 [@maxpuppet](https://github.com/maxpuppet) 和 [@obviyus](https://github.com/obviyus).
- **Feishu 附件。** 带字幕发送的文件或在 Feishu/Lark 帖子中一起发送的文件以文档形式到达代理，而不是消失或被误认为是视频。 [#151896](https://github.com/openclaw/openclaw/pull/151896)，由 [@gokay-ai](https://github.com/gokay-ai) 和 [@obviyus](https://github.com/obviyus) 报告和诊断，[@WhitenessTiger](https://github.com/WhitenessTiger).
- **Discord 后续消息。** 等待的 Discord 消息不再阻止同一通道中的较新消息到达回复队列。您的[队列模式](/concepts/queue)决定如何处理更正和后续操作；跨不同发件人的排序仍然是一个单独的限制。 [fe28b2c](https://github.com/openclaw/openclaw/commit/fe28b2c18f41f220e26c69f9311cb3328beeadac) by [@steipete](https://github.com/steipete).
- **长语音回复。** 在受影响的多代理设置中，自动语音摘要使用回复代理的提供商访问权限，而不是失败和剪辑答案。该代理仍需要已配置的 [ 摘要模型 ](/tools/tts/output) 的凭据。 [#161454](https://github.com/openclaw/openclaw/pull/161454)，作者：[@drakeo338](https://github.com/drakeo338) 和 [@obviyus](https://github.com/obviyus)，报告者：[@aounakram](https://github.com/aounakram).

## <a id="automations-and-scheduling"></a> 自动化和调度

- **计划作业和正在进行的聊天。** 达到时间限制的旧计划作业可能会停止同一会话中的较新对话并删除其对工具的访问权限。 [ 报告的问题 ](https://github.com/openclaw/openclaw/issues/163568) 已修复。 [#163704](https://github.com/openclaw/openclaw/pull/163704)，感谢 [@jayzhou2309](https://github.com/jayzhou2309) 的修复，[@AXEG0](https://github.com/AXEG0) 的报告，[@ekinnee](https://github.com/ekinnee) 和[@MasterSwords1](https://github.com/MasterSwords1) 用于调查，[@obviyus](https://github.com/obviyus) 用于验证和着陆工作。
- **启动后台作业。** 修复了一个启动问题，该问题可能会在计划作业或技能研讨会审核开始时冻结聊天或断开 Web 界面连接。这适用于使用代理配置的工作区的作业，包括压缩较旧的聊天历史记录时。他们的 [ 文件访问权限仍然仅限于任务文件夹 ](/plugins/architecture#plugin-metadata-snapshot-and-lookup-table)。当目录刷新缓慢时，计划作业还可以使用现有模型信息继续进行。 [#164049](https://github.com/openclaw/openclaw/pull/164049) by [@steipete](https://github.com/steipete)； [#161132](https://github.com/openclaw/openclaw/pull/161132)，作者：[@jayzhou2309](https://github.com/jayzhou2309)，[@Flakedict](https://github.com/Flakedict) 报告，[@obviyus](https://github.com/obviyus). 验证
- **编辑计划作业。** 代理可以从模型格式化计划作业更新的受支持错误中恢复，而不是重复失败并保留旧消息。 [#158543](https://github.com/openclaw/openclaw/pull/158543)，作者：[@carlosjarenom](https://github.com/carlosjarenom)，[@louria](https://github.com/louria) 报告，[@obviyus](https://github.com/obviyus). 验证
- **中断的一次性作业。** 重新启动后，中断的一次性计划作业可以再次运行，即使其第一条消息已到达，因此您可能会收到重复的消息。 [#166959](https://github.com/openclaw/openclaw/pull/166959)。

## <a id="plugins-and-integrations"></a> 插件和集成

- **模型更改和插件恢复。** 切换模型可以重用已经运行的大型插件，而不是再次复制它们并冻结请求。失败的插件重新加载可以恢复健康的模型访问和回复，而无需重新启动，并且丢失的上下文引擎插件可以使用 [ 内置后备 ](/concepts/context-engine)。初始加载仍然会阻塞；恢复不成功仍需要重新加载或重启。 [#161267](https://github.com/openclaw/openclaw/pull/161267)，作者：[@obviyus](https://github.com/obviyus)，报告者：[@cmrstudio56](https://github.com/cmrstudio56)； [8abe351](https://github.com/openclaw/openclaw/commit/8abe351bf40fe16f6b134ab348cad9a1b381a754) by [@sahilsatralkar](https://github.com/sahilsatralkar)； [#161023](https://github.com/openclaw/openclaw/pull/161023) by [@Patrick-Erichsen](https://github.com/Patrick-Erichsen).
- **macOS 上的 Bun 下的插件。** 当复制较大的依赖项时，会加载 iMessage 等插件，并遇到 Bun 的错误文件描述符错误macOS。 [#159403](https://github.com/openclaw/openclaw/pull/159403)，作者：[@sunlit-deng](https://github.com/sunlit-deng)，报告者：[@hannesrudolph](https://github.com/hannesrudolph)，后续工作：[@steipete](https://github.com/steipete).
- **MCP 连接。** 远程 MCP 插件不再阻止本机会话启动，因为 OpenClaw 为它们提供了不必要的本地工作目录。来自 MCP 服务器的 HTTP 错误也避免了受影响的 Node 26 崩溃路径。 [#162376](https://github.com/openclaw/openclaw/pull/162376) by [@Patrick-Erichsen](https://github.com/Patrick-Erichsen)； [66c7c35](https://github.com/openclaw/openclaw/commit/66c7c35c35c7de9411ea4b38218b4a591e365096) by [@RvsL](https://github.com/RvsL).
- **Tool 搜索指导。** 如果代理尝试通过 [Tool Search](/tools/tool-search) 使用可用的仅直接工具，该错误会解释如何直接调用它，而不是将代理发送回无结果的搜索。 [#161055](https://github.com/openclaw/openclaw/pull/161055)，作者：[@obviyus](https://github.com/obviyus)，报告者：[@jgs-jeeves](https://github.com/jgs-jeeves).
- **Bundled MCP 连接。从 Claude 和 Codex 捆绑导入的** MCP 服务器使用其配置请求的连接类型，而不是错误地回退到另一个传输。 [#166200](https://github.com/openclaw/openclaw/pull/166200)。
- **MCP 登录更改。** 当服务器更改其登录提供程序时，后台刷新会保留保存的凭据。显式登录可以向新提供商注册；带有过时回调的未使用注册也可以被替换。 [#166341](https://github.com/openclaw/openclaw/pull/166341)，贡献者包括 [@RomneyDa](https://github.com/RomneyDa)、[@Patrick-Erichsen](https://github.com/Patrick-Erichsen)、[@steipete](https://github.com/steipete) 和[@vincentkoc](https://github.com/vincentkoc).

## <a id="security-and-privacy"></a> 安全与隐私

- **Windows MXC 沙箱.** 可选的 [MXC 沙箱](/plugins/reference/mxc) 可以在兼容的 Windows 计算机上启动和运行工具，而无需旧的 Windows服务。如果您选择自己的 MXC 可执行文件，请将其更新为记录的要求或切换回捆绑副本，然后重新启动网关。成功启动仍然可以警告隔离度降低。将秘密保留在命令参数和环境值之外，因为允许检查主机上进程的人员可以读取它们。 [#158303](https://github.com/openclaw/openclaw/pull/158303)，感谢[@paulcam206](https://github.com/paulcam206).
- **请求在配对计算机上进行检查。**插件[输入策略](/plugins/hooks#choose-a-hook)现在可以在OpenClaw在配对计算机上执行请求之前拒绝请求。策略错误也会阻止请求。这些检查涵盖 OpenClaw 作业，而不是 Codex 或 Copilot，并且仅查看网关上可用的提示和历史记录。如果策略需要在配对计算机上添加说明或技能上下文，请改为使用受支持的运行程序在本地运行作业。阻止请求不会删除对话中已保存的文本。 [#164270](https://github.com/openclaw/openclaw/pull/164270) by [@steipete](https://github.com/steipete).
- **秘密轮换和恢复。** 替换或导入 [credential](/cli/secrets) 会保留其现有保护和允许的主机，除非您显式更改它们。 Doctor 还将恢复的网关令牌存储在秘密存储中，而不是将其复制到配置中。该恢复需要[交互式确认](/gateway/doctor/gateway-and-services)，即使有`--yes`；较早的纯文本副本不会被清除。 [#160926](https://github.com/openclaw/openclaw/pull/160926)，由 [@zachisfine](https://github.com/zachisfine)、[@yetval](https://github.com/yetval) 和 [@steipete](https://github.com/steipete) 组成； [#162372](https://github.com/openclaw/openclaw/pull/162372)，作者：[@steipete](https://github.com/steipete)，报告者：[@waynegault](https://github.com/waynegault).
- **代理到代理凭据。** A2A 连接拒绝缺少环境变量的令牌，而不是接受或发送占位符文本。提供丢失的变量并重新加载或重新启动 OpenClaw 以恢复连接。 [521ae23](https://github.com/openclaw/openclaw/commit/521ae2352ba13f1b63249b3d13945223eff39308) by [@eleqtrizit](https://github.com/eleqtrizit).
- **MCP 登录。** OAuth 登录和令牌刷新拒绝将凭据发送到另一个源的重定向。如果自定义提供程序现在因拒绝而失败，请配置直接令牌或注册端点。普通 MCP 资源重定向保留其现有行为。 [#138263](https://github.com/openclaw/openclaw/pull/138263)，作者：[@mmaps](https://github.com/mmaps)，之前的工作和合著者为 [@hansraj316](https://github.com/hansraj316).
- **导出批准。** 诊断和轨迹导出即使在提示传递到私人聊天时也会保留其指定的批准设备。其他仅审批设备无法审批绑定命令；管理员绕过仍然存在。 [#125663](https://github.com/openclaw/openclaw/pull/125663) by [@RomneyDa](https://github.com/RomneyDa).

## <a id="quality-of-life-improvements"></a> 生活质量改善

- **委托任务启动。** 云会话可以以较长的分配开始，而不会缩短任务，并且可见子会话在以后的轮次中保留自己的 [worktree](/gateway/sandboxing/workspace-access)，而不是使工作区检查失败。 [#159459](https://github.com/openclaw/openclaw/pull/159459)、[#162308](https://github.com/openclaw/openclaw/pull/162308)，来自 [@steipete](https://github.com/steipete). 的贡献
- **委派任务完成。** 家长收到完整的新 CLI- 支持的子代理答案，而不是缩短的前缀。即使完成通知被暂停，已完成的子树也会释放容量，并且相同模型的重试保留允许的后续委派。旧的被截断的答案不会被修复。 [#162843](https://github.com/openclaw/openclaw/pull/162843)，作者为 [@zyz619963502zyz](https://github.com/zyz619963502zyz)，诊断为 [@holgergruenhagen](https://github.com/holgergruenhagen)； [#162368](https://github.com/openclaw/openclaw/pull/162368)，作者：[@armstrongsam25](https://github.com/armstrongsam25)，报告者：[@davidcittadini](https://github.com/davidcittadini)，均经过 [@obviyus](https://github.com/obviyus) 验证； [#163032](https://github.com/openclaw/openclaw/pull/163032) by [@stackingrockss](https://github.com/stackingrockss).
- **会话维护命令。** 无效的重置目标在清除主对话之前被拒绝。压缩丢失的会话现在会报告错误，因此依赖于成功的脚本必须检查会话是否存在或处理该错误。 [#161533](https://github.com/openclaw/openclaw/pull/161533) by [@steipete](https://github.com/steipete).

## <a id="other-bug-fixes"></a> 其他错误修复

- **Windows 会话存储。** 通过 Windows 文件夹链接（例如联结）访问其数据库时，创建会话不再失败。 OpenClaw 识别不同的路径指向同一数据库，包括等效的 Windows 长路径拼写。 [bec0cfd](https://github.com/openclaw/openclaw/commit/bec0cfd9a21a1e6d5900fd0ac859c23f56b45d87)，作者：[@cestercian](https://github.com/cestercian)，合著者 [@RomneyDa](https://github.com/RomneyDa)； [#162332](https://github.com/openclaw/openclaw/pull/162332)，作者：[@steipete](https://github.com/steipete)，来自 [@zhyx1996](https://github.com/zhyx1996)、[@ngominhduc263](https://github.com/ngominhduc263) 的报告和诊断， [@oxen-horse](https://github.com/oxen-horse)、[@wuwo2119](https://github.com/wuwo2119)、[@dapangkai11](https://github.com/dapangkai11) 和 [@ignamiranda](https://github.com/ignamiranda).
- **不会退出的命令。** 修复了 Node 问题，该问题可能会使命令在打印所有输出后继续运行。该解决方法还涵盖网关服务、挂钩中继和 macOS 节点工作线程。某些命令可能需要更长的时间，高级覆盖可以绕过修复；请参阅 [ 节点兼容性指南](/install/node-compatibility#v8-compiler-settings)。 [#163788](https://github.com/openclaw/openclaw/pull/163788) by [@steipete](https://github.com/steipete).
- **配对计算机上的会话。**发送例行状态更新时，配对的计算机可能会显示为不可用，从而导致其他问题[在那里运行的会话](/nodes/session-hosting)停滞或失败。更新网关修复了此中断。请求还会等待工作人员重新连接，而不是冻结计算机的OpenClaw主机及其其他工作人员。[#164087](https://github.com/openclaw/openclaw/pull/164087) by [@steipete](https://github.com/steipete)； [#160812](https://github.com/openclaw/openclaw/pull/160812) by [@RileyJJY](https://github.com/RileyJJY)和[@altaywtf](https://github.com/altaywtf)， 报道者[@aniruddhaadak80](https://github.com/aniruddhaadak80).
