_2026 年 6 月 30 日发布。_

我们听到了反馈。 v2026.6.11 专注于使 OpenClaw 感觉不太可靠的粗糙边缘，修复了错误回复、发送卡住、重新连接、模型设置失败和更安全的管理默认设置。

## <a id="highlights"></a> 亮点

### <a id="channel-delivery-reliability"></a> 渠道交付可靠性

跨[Telegram](/channels/telegram)、[WhatsApp](/channels/whatsapp)、[Matrix](/channels/matrix)、[Google Chat](/channels/googlechat)、 [iMessage](/channels/imessage)、[Feishu](/channels/feishu) 和 [Mattermost](/channels/mattermost)、回复、命令、排队消息和附件不太可能被丢弃、重复、错误路由或附加到错误的对话。

### <a id="provider-and-model-recovery"></a> Provider 和模型恢复

[模型选择](/providers/models)和设置在目录、凭据、流、超时、压缩或回退出错时更清晰地恢复。受影响的 [OpenAI](/providers/openai)、[OpenRouter](/providers/openrouter) 和 [OpenCode Go](/providers/opencode-go) 配置现在可以更一致地报告或从故障中恢复，而不是给用户留下陈旧的选择或停滞的请求。

后续修复[快速模式](/tools/thinking#fast-mode-%2Ffast)改善其在受影响的提供商和后备路径中的行为；自动快速模式本身在此版本中并不新鲜。

### <a id="session%2C-memory%2C-and-trust-continuity"></a><a id="session-memory-and-trust-continuity"></a> 会话、内存和信任连续性

[Sessions](/concepts/session)、[compaction](/concepts/compaction)、[memory](/concepts/memory) 和 [QMD-backed memory](/concepts/memory-qmd) 在长时间运行的工作中更一致地保留预期的对话和有用的上下文，重新连接、升级和转录修复。当代理需要恢复正确的上下文或功能时，[工具搜索](/tools/tool-search)也表现得更可靠。

- Native Windows螃蟹箱水合现在自动选择所需的Windows守护进程作业，避免运行失败或错误路由，同时保持WSL2和显式作业覆盖不变。 [d5d9a82](https://github.com/openclaw/openclaw/commit/d5d9a8256d6bc2ff8d699152923357bd61c606c1) 感谢 @vincentkoc.
- 设置本地代理头像的人可以通过将工作区相关文件保留在 2 MB 以下来避免丢失图像，而 HTTP（S） 和数据 URI 头像不受该限制。 [#78884](https://github.com/openclaw/openclaw/pull/78884) 相关 [#65312](https://github.com/openclaw/openclaw/issues/65312)。感谢 @wangjieweb3-design、@nyx-nocturna.
- OpenClaw 的默认代理指令现在要求代理在提出自定义构建之前检查是否有合适的免费或开源解决方案，同时仍然允许在更适合时进行自定义工作。 [#86608](https://github.com/openclaw/openclaw/pull/86608) 感谢 @cablackmon.
- Plugin 作者现在可以在 `subagent_ended` 事件上使用记录的 `targetSessionKey` 将它们与相应的生成进行匹配，而不是依赖于未发出的 `agentId` 或 `childSessionKey` 字段。 [#95191](https://github.com/openclaw/openclaw/pull/95191) 相关 [#95186](https://github.com/openclaw/openclaw/issues/95186)。谢谢@ken-jo，@mahaohao-ch.
- ClawHub技能链接在OpenClaw文档和展示卡现在打开规范的所有者限定页面，并安装示例使用复制就绪`openclaw skills install @owner/<slug>`参考而不是旧的裸线路线。[#95972](https://github.com/openclaw/openclaw/pull/95972)谢谢@patrick-erichsen.

### <a id="tools-and-scheduled-work"></a> 工具和预定工作

[预定作业](/cli/cron)和内置[工具](/tools/index)现在可以更一致地完成、重试、报告故障并保留其预期输入。对 [ 插件 SDK 运行时 ](/plugins/sdk-runtime) 的改进还使工具支持的扩展在加载、返回结果或运行计划工作时更加可靠。

<Accordion id="sources-and-contributors-12" title="来源和贡献者">

- 使用 `deleteAfterRun` 的隔离 cron 作业现在会在完成后删除其临时会话和副本，包括禁用交付的运行、减少陈旧文件、累积上下文和手动清理。 [#84794](https://github.com/openclaw/openclaw/pull/84794) 相关 [#84707](https://github.com/openclaw/openclaw/issues/84707)。感谢 @bottenbenny、@turbotheturtle.
- 各个计划作业现在可以使用自己的回退模型，在禁用回退的情况下运行，或者通过 CLI 返回正常的回退继承，而不需要操作员编辑较低级别的有效负载数据。 [#93369](https://github.com/openclaw/openclaw/pull/93369) 相关 [#90302](https://github.com/openclaw/openclaw/issues/90302)。感谢 @849261680、@walliiee.
- Cron 历史记录现在可以可靠地查找作业 ID 包含额外周围空格的条目，并在嵌套或空白 ID 创建无法安全读回的日志记录之前拒绝它们。 [#93567](https://github.com/openclaw/openclaw/pull/93567) 感谢 @alix-007、@vincentkoc.
- 添加或删除 cron 作业不再导致另一个已经因丢失其挂起运行而发生的重复作业。 [#94323](https://github.com/openclaw/openclaw/pull/94323) 感谢 @yetval.
- Word、PowerPoint 和 Excel 文档读取和写入现在使用预期的 `.docx`、`.pptx` 或 `.xlsx` 路径，而不是因虚构扩展而失败。 [#95805](https://github.com/openclaw/openclaw/pull/95805) 相关 [#93326](https://github.com/openclaw/openclaw/issues/93326)。感谢 @bhnan、@lzyyzznl、@vincentkoc、@xzh-icenter.
- 浏览器自动化用户保留相同的参考丰富的快照，包括紧凑结果中的有用分支，在快照生成期间减少不可避免的处理。 [#96072](https://github.com/openclaw/openclaw/pull/96072) 感谢 @vincentkoc.
- 修复了Windows上的超时命令和中断的核心更新，有时会导致子进程运行，因此OpenClaw可以在取消、超时或更新清理后更可靠地停止整个进程树。 [a192b2e](https://github.com/openclaw/openclaw/commit/a192b2ea52b3166a7d190bf5f60f3feb030306bb) 谢谢 @vincentkoc.
- Windows 用户在解压 ZIP 下载（例如 ripgrep）时不太可能看到代理管理的工具安装失败，因为 OpenClaw 现在使用内置的 Windows 提取程序，而不是依赖于 PATH 查找。 [a5fde91](https://github.com/openclaw/openclaw/commit/a5fde9119c9c50685a392bff078a2f76a03d749d)
- Windows 设置和运行时检查现在通过使用受信任的 System32 解析器而不是依赖于意外的 PATH 条目，更可靠地找到所需的工具。 [d3b4444](https://github.com/openclaw/openclaw/commit/d3b44442f6c8bedd765dc20a06316d3420b5d854) 谢谢 @vincentkoc.
- 使用 `timeoutMs: 0` 创建的 SDK 运行现在可以保持请求的零超时，而无需不需要的客户端看门狗。 [2bdcc83](https://github.com/openclaw/openclaw/commit/2bdcc8314d3fce9ee2d0300759cd6a1d9bb45a7d) 感谢 @vincentkoc.
- Stalled OpenClaw 命令现在可以可靠地停止，即使调用者提供极大的执行或空闲输出超时也是如此。 [1425bb3](https://github.com/openclaw/openclaw/commit/1425bb3a03189813787194c23b8a38518166005a) 谢谢 @vincentkoc.
- 给定极大超时设置的命令现在使用安全最大值，而不是失败，因为运行时无法安排请求的等待。 [66b94ba](https://github.com/openclaw/openclaw/commit/66b94ba577b8836a4afa7cb59cd1a749bf2a8d68)
- Provider 特定工具 allow/deny 设置现在与 OpenClaw 的医生警告更加一致，包括提供程序别名、模型特定密钥、OpenRouter-style 模型 ID 或格式错误的策略条目的配置。 [8f2882f](https://github.com/openclaw/openclaw/commit/8f2882f94affbe5e89994ae175fdaf7304d7b392)
- SDK 应用程序现在在终端工具失败或被阻止时收到 `tool.call.failed`，而不是误导性的完成事件，因此现有的故障处理可以正确反应。 [#95383](https://github.com/openclaw/openclaw/pull/95383) 感谢 @ly-wang19.
- 修复了当识别的作业字段带有无害的尾随空格到达时，cron 添加和更新请求被拒绝的问题，因此可以保存计划，而无需放松对不明确或不安全输入的检查。 [#95674](https://github.com/openclaw/openclaw/pull/95674) 相关 [#95407](https://github.com/openclaw/openclaw/issues/95407)。感谢 @nassiel、@zw-xysk.
- Codex 子代理监控可处理大量子代理和转录文件，减少不必要的扫描，同时较旧的转录文件名格式继续像以前一样解析。 [#96085](https://github.com/openclaw/openclaw/pull/96085) 感谢 @vincentkoc.
- 修复了当运行程序和守护程序使用不同的主目录时，本机 Windows 螃蟹盒水合卡住或丢失切换，因此两者都可以找到相同的作业状态并停止文件。 [f354889](https://github.com/openclaw/openclaw/commit/f354889efa1c8bafca9304767afba2c270add549) 感谢 @vincentkoc.
