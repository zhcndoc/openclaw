# v2026.10.2

AI 代理和工具可以将这些发行说明读取为 [plain Markdown](https://raw.githubusercontent.com/openclaw/openclaw/main/CHANGELOG/2026.10.2.md)。

OpenClaw 2026.10.2 修复了从 2026.10.1 和 Doctor 修复升级期间的错误，解决了丢失或重复回复的问题，并帮助长时间对话继续进行，并修复了大型工具输出中的凭据屏蔽问题。

**发布规模：** 80 个拉取请求、12 个直接提交和 107 个贡献者。

## <a id="installation-and-onboarding"></a> 安装和入门

- 安装过程中的 **Node。** 恢复安装使用所选的兼容 Node 运行时 OpenClaw，即使旧系统 Node 在 PATH 中排在第一位，也避免了误导性的包脚本版本错误。请参阅 [ 节点设置指南](https://docs.openclaw.ai/install/node)。 [#164677](https://github.com/openclaw/openclaw/pull/164677)，感谢 [@steipete](https://github.com/steipete) 和 [@jarvisnextgeneration20-lang](https://github.com/jarvisnextgeneration20-lang).

## Web UI

- **仪表板回复。** 当后台标题工作之前阻止聊天时，聊天可以在每日或空闲重置后回复。委托和等待的后台命令也避免了两次产生最终答案。 [#162689](https://github.com/openclaw/openclaw/pull/162689)，[#166362](https://github.com/openclaw/openclaw/pull/166362)，感谢[@ericcaiwx-star](https://github.com/ericcaiwx-star)，[@dimonnld](https://github.com/dimonnld)， [@OmniScaleMatt](https://github.com/OmniScaleMatt)、[@gloria0021](https://github.com/gloria0021)、[@obviyus](https://github.com/obviyus) 和 [@shakkernerd](https://github.com/shakkernerd).
- **Dictation.** 握住麦克风并释放它不再过早停止录制。您可以继续说话，然后点击“停止”以插入文字记录。 [#166843](https://github.com/openclaw/openclaw/pull/166843)，感谢 [@alfredjbclaw](https://github.com/alfredjbclaw) 和 [@obviyus](https://github.com/obviyus).
- **打开并重新连接聊天。** 发现可用的工具可以重用已运行的兼容大型插件，避免可能冻结聊天和其他请求的重复加载。 [#167374](https://github.com/openclaw/openclaw/pull/167374)，感谢[@jalehman](https://github.com/jalehman).
- **键入停止命令。** 在连接的非全局聊天中，`/stop` 会清除排队的后续操作以及活动工作，因此等待消息不会立即重新启动代理。 “停止”按钮和离线重播仍然仅停止特定的运行。请参阅 [ 聊天取消指南 ](https://docs.openclaw.ai/web/control-ui/chat)。 [#167860](https://github.com/openclaw/openclaw/pull/167860)，感谢 [@masatohoshino](https://github.com/masatohoshino) 和 [@steipete](https://github.com/steipete).

## <a id="updates-and-maintenance"></a> 更新和维护

- **从 2026.10.1.** 升级从已发布的稳定版 2026.10.1 进行的首次升级可避免更换软件包后出现清理错误。 Windows 升级也通过了旧更新程序无法再调用的最终插件检查。 [#168849](https://github.com/openclaw/openclaw/pull/168849)，[#169031](https://github.com/openclaw/openclaw/pull/169031)，感谢[@RomneyDa](https://github.com/RomneyDa).
- **Windows 更新检查。** Windows 更新不再仅仅因为其启动器启动方式而拒绝有效更新。备份检查还可以识别同一文件夹的短名称和不同字母大小写。 [#166530](https://github.com/openclaw/openclaw/pull/166530)，[#168968](https://github.com/openclaw/openclaw/pull/168968)，感谢[@steipete](https://github.com/steipete)，[@wqj11a](https://github.com/wqj11a)， [@H0Nm4M1suZu](https://github.com/H0Nm4M1suZu) 和 [@RomneyDa](https://github.com/RomneyDa).
- **Update cleanup.** 已修复的 CLI 在清理已成功的更新时不再报告丢失模块错误。较旧的 CLI 在首次升级期间仍然会显示该错误；使用新安装的`openclaw update status`检查结果。请参阅 [ 更新指南](https://docs.openclaw.ai/cli/update)。 [#165233](https://github.com/openclaw/openclaw/pull/165233)，感谢[@steipete](https://github.com/steipete).
- **更新和修复报告。** 在保存的历史记录中确认成功的更新不再仅仅因为 OpenClaw 无法显示其结果而显得失败。可选配置后备通知现在显示为警告。修复报告还指出已配置的仍处于停止状态的聊天帐户。使用 `openclaw health --json` 调查这些账户；请参阅 [ 维修指南 ](https://docs.openclaw.ai/cli/update/repair-and-recovery)。 [#169037](https://github.com/openclaw/openclaw/pull/169037)，[#165539](https://github.com/openclaw/openclaw/pull/165539)，感谢[@steipete](https://github.com/steipete)，[@kvnloo](https://github.com/kvnloo)， [@RomneyDa](https://github.com/RomneyDa) 和 [@Patrick-Erichsen](https://github.com/Patrick-Erichsen).
- **容器文件复制。** 当容器阻止文件克隆时，更新可以复制文件字节。受影响的2026.9.7安装需要手动安装npm修复版本，之后的更新才能使用修复。保持本机文件系统保护启用并遵循 [ 恢复步骤](/cli/update/repair-and-recovery)。 [#165257](https://github.com/openclaw/openclaw/pull/165257)，感谢 [@steipete](https://github.com/steipete)、[@MrJanvar](https://github.com/MrJanvar)、[@rybing7](https://github.com/rybing7) 和[@Mohl](https://github.com/Mohl).
- **工作空间头像。** 更新检查不再拒绝工作空间内有效的绝对头像路径。较旧的更新程序可能仍需要简单的工作区相对路径（例如 `avatar.png`），直到更新为止。 [#164638](https://github.com/openclaw/openclaw/pull/164638)，感谢 [@nitinjwadhawan](https://github.com/nitinjwadhawan)、[@vincentkoc](https://github.com/vincentkoc) 和 [@BottaniCals](https://github.com/BottaniCals).
- **更换容器后的Doctor。** 更换已退出的容器后，Doctor可以等待先前网关的锁定到期并继续修复。更新也避免了Doctor自己的工作造成的错误的“正在进行离线维护”拒绝。如果 Doctor 报告存在活动网关，请按照 [Doctor 恢复指南 ](https://docs.openclaw.ai/cli/doctor/recovery) 中的停止说明进行操作。 [#165355](https://github.com/openclaw/openclaw/pull/165355)，[#165417](https://github.com/openclaw/openclaw/pull/165417)，感谢[@steipete](https://github.com/steipete).
- **Linux 修复检查。** 未更改的数据库上的时间戳更改不再导致错误更新或恢复拒绝。缓慢的本地数据库检查还可以避免在 Doctor 停止网关进行维护之前出现错误的服务管理器超时。 [#165775](https://github.com/openclaw/openclaw/pull/165775)，[#168161](https://github.com/openclaw/openclaw/pull/168161)，感谢[@steipete](https://github.com/steipete)，[@donquiche61](https://github.com/donquiche61)， [@naturecurly](https://github.com/naturecurly)、[@dreamkeeper](https://github.com/dreamkeeper)、[@wangmiao0668000666](https://github.com/wangmiao0668000666)、[@clockthunder](https://github.com/clockthunder)、[@honghongxinxi-zhb](https://github.com/honghongxinxi-zhb)、 [@jayzhou2309](https://github.com/jayzhou2309)、[@obviyus](https://github.com/obviyus) 和 [@Tosko4](https://github.com/Tosko4).
- **较旧的会话历史记录。** Doctor 可以继续修复剩余的会话文件，同时保持当前对话标签和活动聊天完好无损。有争议的原件被保存以供恢复；警告或受保护的存档并不意味着历史记录已导入或可以安全删除。 [329857b](https://github.com/openclaw/openclaw/commit/329857b21e9f01fcd5a399384d4f5231ce6371cd)、[80117e8](https://github.com/openclaw/openclaw/commit/80117e8cb0c2440e399b3e791b2726adc1644f56)，感谢 [@steipete](https://github.com/steipete) 和 [@coolcoolwcr](https://github.com/coolcoolwcr).
- **剩余的迁移文件。** Doctor可以存档已删除频道帐户的旧发件人列表并继续修复。内存索引锁定文件也会停止触发健康数据库的重复恢复警告。配置帐户的损坏文件和真正的恢复保留仍然需要注意；请参阅 [ 迁移指南](https://docs.openclaw.ai/cli/doctor/state-migrations)。 [#167651](https://github.com/openclaw/openclaw/pull/167651)、[#166517](https://github.com/openclaw/openclaw/pull/166517)，感谢 [@steipete](https://github.com/steipete)、[@oshunter](https://github.com/oshunter) 和[@noelff](https://github.com/noelff).
- **拒绝维护后重新启动。** 如果更新发现 OpenClaw 已是最新版本，但停止网关进行无法继续的维护，则可以在恢复安全后重新启动服务。维修仍然报告故障。您自行停止的服务或因数据面临风险而停止的服务将保持停止状态。 [#166548](https://github.com/openclaw/openclaw/pull/166548)，感谢 [@steipete](https://github.com/steipete) 和 [@Shirleyyyhk](https://github.com/Shirleyyyhk).

## <a id="messaging"></a> 消息传递

- **启动期间回复。** 消息可以等待自己的座席完成启动，而已经准备好的座席则继续独立应答。 [#168826](https://github.com/openclaw/openclaw/pull/168826)，感谢 [@steipete](https://github.com/steipete)、[@xiaozishan](https://github.com/xiaozishan) 和 [@obviyus](https://github.com/obviyus).
- **Telegram 预览。** 部分回复在其替换被延迟或拒绝时保持可见。接受替换后，旧的预览将被删除，即使最终发送失败，也会保留有用的文本。请参阅 [ 流媒体指南](https://docs.openclaw.ai/channels/telegram/messaging)。 [#164649](https://github.com/openclaw/openclaw/pull/164649)，感谢 [@jayzhou2309](https://github.com/jayzhou2309)、[@obviyus](https://github.com/obviyus) 和 [@jmar5439](https://github.com/jmar5439).
- **Telegram 发送失败。** 由于未解决的帐户所有权而在本地阻止的回复会显示准确的失败通知，而不是不确定的传递警告。所有权设置可能仍需要修正；请参阅 [ 频道所有权指南](https://docs.openclaw.ai/gateway/doctor/config-migrations#channel-ownership-during-an-update)。 [#167470](https://github.com/openclaw/openclaw/pull/167470)，感谢 [@obviyus](https://github.com/obviyus) 和 [@mgr-nick](https://github.com/mgr-nick).
- **Feishu 流媒体。** 可以跳过过时的等待预览，因此完成的答案不会等待每个早期版本。 [#166610](https://github.com/openclaw/openclaw/pull/166610)，感谢[@rudycelekli](https://github.com/rudycelekli)，[@feie22](https://github.com/feie22)，[@cas1per](https://github.com/cas1per)， [@L-Trump](https://github.com/L-Trump)、[@xiaobao-k8s](https://github.com/xiaobao-k8s) 和 [@csxjihk](https://github.com/csxjihk).
- **代理之间的消息。** 重播的消息保留原始发件人标签，包括当一个代理转发另一发件人的文本时，因此接收代理会在以后的回合中保留该上下文。 [#169130](https://github.com/openclaw/openclaw/pull/169130)，感谢[@RomneyDa](https://github.com/RomneyDa).

## <a id="memory"></a> 内存

- **通过工具搜索调用内存。** 当代理要求分数截止或结果限制时，通过工具搜索支持的内存搜索不再失败。 [#158632](https://github.com/openclaw/openclaw/pull/158632)，感谢 [@masatohoshino](https://github.com/masatohoshino)、[@obviyus](https://github.com/obviyus) 和 [@he-yufeng](https://github.com/he-yufeng).
- **完成回复前的摘要。** 当长时间对话需要摘要时，OpenClaw [ 在回答帮助程序结果或跟进批准之前摘要其历史记录](/concepts/compaction)，无需更改所选模型。 [#163117](https://github.com/openclaw/openclaw/pull/163117)，感谢 [@SunnyShu0925](https://github.com/SunnyShu0925)、[@steipete](https://github.com/steipete)、[@AXEG0](https://github.com/AXEG0) 和[@obviyus](https://github.com/obviyus).
- **应答期间的更正。** 使用 [ 持久上下文引擎 ](https://docs.openclaw.ai/concepts/context-engine)，在应答运行时发送更正不再导致已完成的交换被排除在代理存储的对话上下文之外。 [#168394](https://github.com/openclaw/openclaw/pull/168394)，感谢 [@steipete](https://github.com/steipete) 和 [@robertoronderosjr](https://github.com/robertoronderosjr).

## <a id="models-and-providers"></a> 模型和提供商

- **Provider 压缩。** 合格的直接 OpenAI 响应和 Anthropic API-key 聊天现在默认缩短与提供商管理的检查点的长时间对话。 Anthropic 在提供商拒绝较早的检查点后，聊天可以在下一轮恢复。 OpenAI 手册 `/compact` 的成本可能比本地摘要更高，因为它处理更多未缓存的输入；请参阅 [compaction](/concepts/compaction) 和 [OpenAI 选项 ](https://docs.openclaw.ai/providers/openai/advanced) 了解路由限制、回退和退出。 [#168164](https://github.com/openclaw/openclaw/pull/168164)，感谢[@obviyus](https://github.com/obviyus).
- **模型冷却期间的压缩。** 工作配置的回退可以在配额失败后主凭证冷却时总结长时间会话，而无需更改所选会话模型。显式压缩模型覆盖保持准确；请参阅 [ 压实指南 ](/concepts/compaction)。 [#166459](https://github.com/openclaw/openclaw/pull/166459)，感谢 [@steipete](https://github.com/steipete) 和 [@hawkit](https://github.com/hawkit).
- **Claude CLI 压缩。** 自动后转压缩与 Claude Code 保持一致，避免不必要的 Anthropic API-key 错误并保留本机对话连接。手册`/compact`是一个单独的路径；参见[CLI后端指导](https://docs.openclaw.ai/gateway/cli-backends)。 [#162066](https://github.com/openclaw/openclaw/pull/162066)，感谢[@rogeriochaves](https://github.com/rogeriochaves)，[@llmsommelier](https://github.com/llmsommelier)，[@RomneyDa](https://github.com/RomneyDa)， [@ajmtrz](https://github.com/ajmtrz)、[@MaShAn1027](https://github.com/MaShAn1027)、[@Jeehut](https://github.com/Jeehut) 和 [@Oldrich333](https://github.com/Oldrich333).
- **Long Claude CLI 回复。** 修复了已完成的 Claude CLI 任务中丢失的最终报告，并有许多流更新。 [#153545](https://github.com/openclaw/openclaw/pull/153545)，感谢[@zhangguiping-xydt](https://github.com/zhangguiping-xydt)，[@methylester](https://github.com/methylester)，[@obviyus](https://github.com/obviyus)， [@VACInc](https://github.com/VACInc)、[@aaajiao](https://github.com/aaajiao)、[@telbus](https://github.com/telbus)、[@aoclaw-glitch](https://github.com/aoclaw-glitch)、[@aikohoshinoai-prog](https://github.com/aikohoshinoai-prog) 和[@RTapiador](https://github.com/RTapiador).
- **Claude CLI 历史记录。** 导入历史记录可避免重复消息和转发输入，并保留发送消息的人员。已识别的后台指令不再看起来像您编写的消息，而大型工具结果显示为工具活动。更新后的 [CLI 指南 ](https://docs.openclaw.ai/gateway/cli-backends) 解释了这些显示更改并确认存储的转录本保持不变。 [#163521](https://github.com/openclaw/openclaw/pull/163521)、[#166080](https://github.com/openclaw/openclaw/pull/166080)、[#168851](https://github.com/openclaw/openclaw/pull/168851)，感谢[@rogeriochaves](https://github.com/rogeriochaves)、[@llmsommelier](https://github.com/llmsommelier)、[@RomneyDa](https://github.com/RomneyDa)、[@Marvinthebored](https://github.com/Marvinthebored)、[@Peetiegonzalez](https://github.com/Peetiegonzalez)、 [@IndySweeney](https://github.com/IndySweeney)、[@agierror](https://github.com/agierror) 和 [@Heighte](https://github.com/Heighte).
- **Long ChatGPT 订阅回复。** 超过 HTTP 的长 ChatGPT 订阅回复可以完成，而不会被流数据总量中断。单个流式更新的大小仍然受到限制。在通过响应 WebSockets 进行的本机交互式聊天中，如果在回复开始后重用的连接过期，OpenClaw 可以从保存的对话中恢复并继续回答。 [#166853](https://github.com/openclaw/openclaw/pull/166853)、[#167063](https://github.com/openclaw/openclaw/pull/167063)，感谢 [@jackten](https://github.com/jackten) 和 [@steipete](https://github.com/steipete).
- **Codex 会话启动。** 使用后台终端关闭空闲线程不再阻塞稍后的回合。可以取消停滞的启动等待并尊重其请求预算。 [#166693](https://github.com/openclaw/openclaw/pull/166693)，感谢[@jalehman](https://github.com/jalehman).
- **Codex 提供程序错误。** 工具工作后提供程序故障在恢复建议中仍然可见，而不是看起来只是停止。已完成的操作不会重复，并且显式停止仍然意味着取消。 [#165488](https://github.com/openclaw/openclaw/pull/165488)，感谢[@steipete](https://github.com/steipete).
- **代码模式任务。** 长代码模式任务在模型重用较早的请求编号时可以继续使用工具。 Node- 命令错误还解释了如何在目标计算机上运行 shell 命令。 [#165210](https://github.com/openclaw/openclaw/pull/165210)，感谢[@steipete](https://github.com/steipete).
- **OpenAI 工具兼容性。** OpenAI 回复不再仅仅因为启用的插件或 MCP 工具在其输入规则中包含受影响的模式而失败，即使未使用该工具也是如此。请参阅 [ 高级提供商指南 ](https://docs.openclaw.ai/providers/openai/advanced)。 [#166999](https://github.com/openclaw/openclaw/pull/166999)，感谢 [@scs0209](https://github.com/scs0209)、[@adamjgmiller](https://github.com/adamjgmiller) 和 [@obviyus](https://github.com/obviyus).
- **本地模型回复。** 具有严格聊天完成模板的模型可以在先前导致消息格式错误的后台通知后继续回复。 [#167309](https://github.com/openclaw/openclaw/pull/167309)，感谢 [@jlapenna](https://github.com/jlapenna) 和 [@steipete](https://github.com/steipete).
- **自定义基岩路线。** 使用自定义基岩提供程序 ID 的请求在联系 AWS 之前不再失败，并使用该路线的配置区域。请参阅 [Bedrock 指南](/providers/bedrock) 和 [ 自定义提供商设置](https://docs.openclaw.ai/gateway/config-tools/custom-providers)。 [#164406](https://github.com/openclaw/openclaw/pull/164406)，感谢 [@Ayushdevo](https://github.com/Ayushdevo)、[@obviyus](https://github.com/obviyus) 和 [@kai-ocean-kurt](https://github.com/kai-ocean-kurt).
- **Local llama.cpp setup.** 安装程序在下载模型文件之前检查服务器是否可以运行，并在不能运行时解释替代方案。托管 macOS 二进制文件需要 13.3 或更高版本；较旧的 Mac 可以通过 [ 本地模型服务配置 ](/gateway/local-model-services) 使用可用的现有或兼容的自定义服务器。 [e0de414](https://github.com/openclaw/openclaw/commit/e0de4147026d54096ace25a4785fa30fb50db575)，感谢 [@NovaUnboundAi](https://github.com/NovaUnboundAi)、[@xXG0DLessXx](https://github.com/xXG0DLessXx) 和 [@VACInc](https://github.com/VACInc).
- **加载已保存聊天的模型。** 在加载模型列表时，从已保存会话目录继续对话或更改聊天设置不再无限期挂起。超时允许您重试，而无需离开部分创建的聊天或稍后应用拒绝的设置更改。批量设置更改仍会单独报告每个聊天的结果。请参阅 [ 会话控制指南 ](/gateway/protocol/rpc-session-control)。 [#166089](https://github.com/openclaw/openclaw/pull/166089)、[#166376](https://github.com/openclaw/openclaw/pull/166376)，感谢 [@ericcaiwx-star](https://github.com/ericcaiwx-star)、[@steipete](https://github.com/steipete) 和[@dprev](https://github.com/dprev).
- **启动期间模型列表发生更改。** 启动检查和执行之间的模型列表更新不再导致报告的拒绝启动聊天或计划作业。 [#168410](https://github.com/openclaw/openclaw/pull/168410)，感谢[@RomneyDa](https://github.com/RomneyDa).
- **回退和保存的消息。** 自动回退可以在第一次尝试发送后到达另一个提供程序，而不是在重试开始之前失败。您保存的消息保持不变。代理之间的消息在首次传送和稍后重播时也会保留相同的文本和发件人上下文。 [9def9c1](https://github.com/openclaw/openclaw/commit/9def9c191a7d2947194259f010658d83870bbfec)、[36f6305](https://github.com/openclaw/openclaw/commit/36f630504df528ad70675238f90e4021cfcea6e0)。
- **Claude 历史记录缓存。** 在大型文档、图像或工具交换后，Claude 仍然可以重用符合条件的缓存的早期对话历史记录。 Bedrock 还选择所选模型和配置文件支持的缓存持续时间。请参阅 [ 提示缓存指南](https://docs.openclaw.ai/reference/prompt-caching)。 [#168042](https://github.com/openclaw/openclaw/pull/168042)，感谢[@steipete](https://github.com/steipete).
- **对话历史记录和缓存。** 重新打开的聊天保留模型最初看到的相同的缩短的工具结果文本。当帮助者私下报告时，浏览器聊天可以继续重用缓存的对话文本，并且 Claude 缓存早期历史记录，而无需稍后消失的临时指令。请参阅 [ 提示缓存指南](/reference/prompt-caching)。 [#168392](https://github.com/openclaw/openclaw/pull/168392)，感谢[@steipete](https://github.com/steipete).

## <a id="automations-and-scheduling"></a> 自动化和调度

- **Codex 最大思考。** 计划和 webhook 轮次在所选模型支持时遵循现有的最大思考设置，而不是默默地使用其默认工作。 [#165444](https://github.com/openclaw/openclaw/pull/165444)，感谢[@Oldrich333](https://github.com/Oldrich333).
- **重启后的条件检查。** 重启后第一个计划的脚本检查不再重新加载已运行的插件，避免导致超时并导致其他网关工作停止。请参阅 [ 日程指南 ](https://docs.openclaw.ai/automation/cron-jobs/schedules)。 [#166991](https://github.com/openclaw/openclaw/pull/166991)，感谢 [@67-luck](https://github.com/67-luck)、[@steipete](https://github.com/steipete) 和 [@lucianosmori](https://github.com/lucianosmori).
- **手动启动的作业。** 接受的自动化可以在开始它的聊天轮结束后继续使用其允许的工具。它使用作业的已保存权限，禁用或删除作业仍会停止其工作。 [#168037](https://github.com/openclaw/openclaw/pull/168037)，感谢[@obviyus](https://github.com/obviyus).
- **Home 通知。** 创建多个聊天不再填充 Home 的通知队列，并为每个聊天添加单独的通知。最近的新聊天内容共享一个摘要，为 Home 的下一个回合或心跳留下提醒和其他通知的空间。参见[主页指南](/concepts/main-session#what-flows-into-the-main-session)。 [#168239](https://github.com/openclaw/openclaw/pull/168239)，感谢[@steipete](https://github.com/steipete).

## <a id="browser-and-computer-use"></a> 浏览器和计算机使用

- **托管浏览器选项卡。** 在共享选项卡限制下，本地管理的浏览器清理优先于最近使用的会话选项卡之前的未跟踪页面和旧页面。仍可以删除最早的符合条件的会话选项卡。 [#166666](https://github.com/openclaw/openclaw/pull/166666)，感谢 [@ruel225](https://github.com/ruel225)、[@obviyus](https://github.com/obviyus) 和 [@vokaplok](https://github.com/vokaplok).

## <a id="plugins-and-integrations"></a> 插件和集成

- **插件批准等待。** 受影响的插件工具可以在现有响应窗口中等待您的批准，而不是因为停滞而提前取消。未答复的请求仍然会过期；请参阅 [ 权限请求指南](https://docs.openclaw.ai/plugins/plugin-permission-requests)。 [#161821](https://github.com/openclaw/openclaw/pull/161821)，感谢 [@fransqaas](https://github.com/fransqaas) 和 [@obviyus](https://github.com/obviyus).
- **长工具对话。** 受影响的上下文引擎插件在工具运行时将较旧的历史记录保留在模型的可用空间内，从而避免报告的上下文限制故障。超大的新工具产量仍然可以超出限制。 [#166120](https://github.com/openclaw/openclaw/pull/166120)，感谢 [@ruel225](https://github.com/ruel225)、[@steipete](https://github.com/steipete) 和 [@igs-rogenlo](https://github.com/igs-rogenlo).
- **Codex 模型发现清理。** 超时模型发现会释放废弃的后台进程，同时活动同级工作可以完成，从而防止累积内存使用的来源。后期工作可以开始更换；请参阅 [Codex 恢复指南](/plugins/codex-harness-runtime/recovery)。 [#168365](https://github.com/openclaw/openclaw/pull/168365)，感谢 [@steipete](https://github.com/steipete) 和 [@609NFT](https://github.com/609NFT).

## <a id="security-and-privacy"></a> 安全与隐私

- **凭证屏蔽。** 内置屏蔽不再错过跨长工具输出分割的已识别凭证。长文本或重复文本还可以避免报告的屏蔽冻结和堆栈溢出，并且在现有规则下减少处理工作。 [#161480](https://github.com/openclaw/openclaw/pull/161480)、[#166701](https://github.com/openclaw/openclaw/pull/166701)，感谢 [@eleqtrizit](https://github.com/eleqtrizit) 和 [@steipete](https://github.com/steipete).
- 通过秘密代理执行的 **HTTPS 命令。使用秘密出口代理的** HTTPS 命令不再无法通过新生成的证书进行严格的证书检查，包括 macOS 上受影响的 Python 命令。更新后，重新启动网关并启动新命令。保持证书验证启用。保留的旧调试代理证书未更改，并且仍然可能无法通过严格检查。 [f1cd78c](https://github.com/openclaw/openclaw/commit/f1cd78c7ec954542db26ee965adae4fb8baab309)，感谢 [@steipete](https://github.com/steipete)、[@vortexopenclaw](https://github.com/vortexopenclaw) 和 [@A1fred-AI](https://github.com/A1fred-AI).

## <a id="quality-of-life-improvements"></a> 生活质量改善

- **配置错误。** 当帮助程序无法启动时，配置检查会报告实际的启动错误和受影响的文件，而不是不相关的 `trim` 错误。 [#165373](https://github.com/openclaw/openclaw/pull/165373)，感谢 [@steipete](https://github.com/steipete) 和 [@nnljl2003](https://github.com/nnljl2003).
- **文件和控制台日志。** 在文件日志和 JSON 控制台输出中屏蔽机密使用较少的临时内存，具有相同的屏蔽规则和输出。 [#167943](https://github.com/openclaw/openclaw/pull/167943)，感谢[@steipete](https://github.com/steipete).

## <a id="other-bug-fixes"></a> 其他错误修复

- **引用的 Windows 命令。Windows 节点上的** 命令通过支持的命令包装器保留带有空格的多字参数、URL 和可执行路径。 [#158160](https://github.com/openclaw/openclaw/pull/158160)，感谢 [@Dimitri-lcht](https://github.com/Dimitri-lcht)、[@igs-rogenlo](https://github.com/igs-rogenlo)、[@steipete](https://github.com/steipete) 和[@kassol](https://github.com/kassol).
- **Rosetta 工作树和进程检查。** 在 Apple 芯片上的 Rosetta 下运行的英特尔 OpenClaw 使用 Git 进行工作树，并避免崩溃的本机进程检查。需要经过检查的维护仍然需要原生arm64 Node。 [#165088](https://github.com/openclaw/openclaw/pull/165088)，感谢[@steipete](https://github.com/steipete).
- **Helper 答案。** 使用 ACP 或共享 CLI 后备的帮助程序将其完整的新答案传递回主代理，包括长报告的结尾和正确任务的答案。延迟的旧结果也停止替换新接受的答案。请参阅 [ 公告指南 ](https://docs.openclaw.ai/tools/subagents/announce)。 [#165800](https://github.com/openclaw/openclaw/pull/165800)，[#166139](https://github.com/openclaw/openclaw/pull/166139)，感谢[@yetval](https://github.com/yetval)，[@steipete](https://github.com/steipete)， [@holgergruenhagen](https://github.com/holgergruenhagen)、[@potterdigital](https://github.com/potterdigital)、[@Leli1024](https://github.com/Leli1024)、[@zyz619963502zyz](https://github.com/zyz619963502zyz)、[@Yun-0000](https://github.com/Yun-0000) 和[@michaeljgood71](https://github.com/michaeljgood71).
- **助手结果后回复。** 当助手的交付截止日期到期时，主代理可以继续处理助手的结果，而不会丢失其最终回复。正常任务时间限制和停止仍然适用；请参阅 [ 切换指南 ](/concepts/subagent-yield-handoff)。 [#164282](https://github.com/openclaw/openclaw/pull/164282)，感谢 [@Oldrich333](https://github.com/Oldrich333) 和 [@obviyus](https://github.com/obviyus).
- **后台工具。** 在后台工具成功完成后，任务不再因停止而被取消，即使下一个模型响应达到其输出限制也是如此。请参阅 [ 队列指南 ](https://docs.openclaw.ai/concepts/queue)。 [#166997](https://github.com/openclaw/openclaw/pull/166997)，感谢 [@SunnyShu0925](https://github.com/SunnyShu0925)、[@steipete](https://github.com/steipete)、[@hannesrudolph](https://github.com/hannesrudolph) 和[@hippoley](https://github.com/hippoley).
- **E较早的图像。** 使用可用的图像解码器，请求中会忽略损坏的图像，因此文本后续操作和重新打开的对话可以继续。丢失的旧图像也会收到中性注释，而不是拒绝助理先前检查的指示。 [#166564](https://github.com/openclaw/openclaw/pull/166564)，[#166165](https://github.com/openclaw/openclaw/pull/166165)，感谢[@jayzhou2309](https://github.com/jayzhou2309)，[@steipete](https://github.com/steipete)， [@mirasrael](https://github.com/mirasrael) 和 [@nogikeyaksh](https://github.com/nogikeyaksh).
- **后续轮次的对话上下文。** 通过提示挂钩或替换提示添加到消息的上下文现在会在后续轮次和重新打开聊天后保留在该消息中，而可见聊天会保留原始文本。助手完成后的回复也会保留主要对话的说明，从而减少对受影响的本地模型的重复提示处理。 [#167938](https://github.com/openclaw/openclaw/pull/167938)、[#167898](https://github.com/openclaw/openclaw/pull/167898)，感谢 [@steipete](https://github.com/steipete)、[@Eragim](https://github.com/Eragim) 和[@apalmiere](https://github.com/apalmiere).
- **Stopped 节点工作程序。** 强制停止节点工作程序可以停止幸存的子进程，并在验证清理后释放其插槽以供以后工作。请参阅 [ 后台进程指南 ](https://docs.openclaw.ai/gateway/background-process)。 [#168746](https://github.com/openclaw/openclaw/pull/168746)，感谢 [@steipete](https://github.com/steipete)、[@aniruddhaadak80](https://github.com/aniruddhaadak80) 和 [@linhongyu510](https://github.com/linhongyu510).
