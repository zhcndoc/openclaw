# v2026.9.8

AI 代理和工具可以将这些发行说明读取为 [plain Markdown](https://raw.githubusercontent.com/openclaw/openclaw/main/CHANGELOG/2026.9.8.md)。

OpenClaw 2026.9.8 修复了代理之间丢失的回复，减少了运行多个 Codex 代理时的内存使用，并解决了更新失败和 Windows 启动问题。

**发布规模：** 43 个拉取请求、12 个直接提交和 8 个贡献者。

## Web UI

- **更新后的浏览器选项卡。** 如果您在更新期间使 OpenClaw 的捆绑 Web 界面保持打开状态，则该选项卡可以继续使用其旧文件加载视图。这些文件只是暂时保留，因此较旧的选项卡可能仍需要重新加载；请参阅 [ 保留限制 ](/web/control-ui/development)。 [#163478](https://github.com/openclaw/openclaw/pull/163478)，向后移植 [#163090](https://github.com/openclaw/openclaw/pull/163090) 和 [#163099](https://github.com/openclaw/openclaw/pull/163099)，贡献来自[@vincentkoc](https://github.com/vincentkoc).
- **会话分配。** 将指针移到“分配给...”上，然后按 Enter 键现在会打开菜单，而不会意外地将会话分配给某人。 [#163467](https://github.com/openclaw/openclaw/pull/163467)，向后移植 [#161393](https://github.com/openclaw/openclaw/pull/161393)，由 [@RomneyDa](https://github.com/RomneyDa) 和[@vincentkoc](https://github.com/vincentkoc).
- **无声回复帮助。** 20 种现有语言的帮助文本现在解释了客服人员可以在何处保持沉默。静音设置适用于群聊； OpenClaw 内的直接聊天和工作请求需要回复。 [#163409](https://github.com/openclaw/openclaw/pull/163409)，使用 [#162942](https://github.com/openclaw/openclaw/pull/162942) 的翻译，并有 [@vincentkoc](https://github.com/vincentkoc). 的贡献

## <a id="updates-and-maintenance"></a> 更新和维护

- <a id="update-recovery-sources"></a>**更新恢复。** 修复更新现在会保留您允许和启用的插件。新的 Doctor 运行可以完成待处理的升级确认并清除已完成工作的警告。对于 Windows 2026.9.4 恢复，请先备份并按照 [ 单独终端恢复说明 ](/cli/update) 使用原始服务帐户和安装设置。 [#162959](https://github.com/openclaw/openclaw/pull/162959)，由 [@RomneyDa](https://github.com/RomneyDa) 向后移植，由 [@VACInc](https://github.com/VACInc)、[@obviyus](https://github.com/obviyus) 和[@ericcaiwx-star](https://github.com/ericcaiwx-star).
- <a id="platform-update-sources"></a>**Windows 更新。** 如果 Windows 简要报告安装文件正在使用，更新程序将重试。如果仍然无法替换它们，则会将已安装的软件包保留在原处。较旧的更新程序无法在更新过程中获得此修复；如果第一次升级失败，请按照 [ 更新指南 ](/cli/update) 进行操作。 [#163074](https://github.com/openclaw/openclaw/pull/163074)，由 [@RomneyDa](https://github.com/RomneyDa) 向后移植，由 [@fuller-stack-dev](https://github.com/fuller-stack-dev) 和 [@obviyus](https://github.com/obviyus). 完成
- **macOS 更新。** 通过 npm 更新现在可以处理同一安装的两个不同路径，包括 npm 已删除旧文件但尚未替换它们的时刻。 [#163481](https://github.com/openclaw/openclaw/pull/163481)，向后移植 [#163479](https://github.com/openclaw/openclaw/pull/163479)，由 [@vincentkoc](https://github.com/vincentkoc). 完成
- **Starting OpenClaw.** 直接启动或在容器中启动现在可以防止两个副本同时使用相同的保存数据。 Windows 启动还可以避免缓存文件夹的路径太长时卡住。 [来源和鸣谢](#update-recovery-sources)。
- **停止 OpenClaw.** 当内存同步没有工作要做时，关闭可以完成，同时仍然允许完成已经正在进行的写入。 [来源和鸣谢](#platform-update-sources)。
- **数据库维护。** 当另一个操作短暂导致数据库繁忙时，维护重试。 [更新演练](/install/updating)避免不必要的数据库副本并保持每条记录的ID不变。 [更新恢复源和积分](#update-recovery-sources)、[平台更新源和积分](#platform-update-sources)。
- **更改连接设置。** 当您 [更改连接设置](/gateway/configuration/hot-reload) 时，已经进行的工作可以完成，前提是用户仍然具有访问权限。删除访问权限仍然会停止该工作。更改登录方式或者OpenClaw监听连接的方式仍然需要重启；请参阅 [ 代理设置指南](/gateway/trusted-proxy-auth)。 [#163174](https://github.com/openclaw/openclaw/pull/163174)，由 [@RomneyDa](https://github.com/RomneyDa) 从 [#160909](https://github.com/openclaw/openclaw/pull/160909) 反向移植。

## <a id="messaging"></a> 消息传递

- **代理之间的回复。** 当一个代理向另一个代理寻求帮助时，结果会返回给请求者一次。 [OpenClaw](/concepts/messages)内部的工作必须返回结果或继续工作，而不是默默结束。自定义工作流程必须明确处理返回结果并请求后续消息； `REPLY_SKIP` 和 `ANNOUNCE_SKIP` 不再隐藏回复。 [Doctor更新了旧设置](/gateway/doctor/config-migrations)，在群聊中保持沉默。 [来源和鸣谢](#platform-update-sources)。
- **重新加载和唤醒后回复。** 修复了重新加载或唤醒计算机后通道看起来已连接但无法再发送回复的情况。该问题是通过 Matrix 报告的。 [#163504](https://github.com/openclaw/openclaw/pull/163504)，向后移植 [#163268](https://github.com/openclaw/openclaw/pull/163268)。感谢上游作者 [@scotthuang](https://github.com/scotthuang) 和贡献者 [@vincentkoc](https://github.com/vincentkoc).
- **Telegram cleanup.** Doctor 可以将旧 Telegram 连接留下的已确认的空文件移动到存档中。它会留下非空或不确定的文件以供审查，并在移动失败时保留原始文件。 [来源和鸣谢](#update-recovery-sources)。
- **Telegram 预览。** 修复了对已替换任务的 Telegram 回复预览的后期编辑。 [来源和鸣谢](#update-recovery-sources)。

## <a id="skills"></a> 技能

- **刷新技能。** 在基于 Unix 的系统上，从只读安装复制的技能现在可以在沙盒工作区和 Claude CLI 会话中刷新。复制的文件夹不再阻止刷新，因为它们继承了原始文件夹的限制。 [来源和鸣谢](#update-recovery-sources)。

## <a id="models-and-providers"></a> 模型和提供商

- **GPT-6.1 Sol.** 此版本中对 [GPT-6.1 Sol](/providers/openai/models) 的支持仍不完整。这些改变都是为之准备的。 [#161400](https://github.com/openclaw/openclaw/pull/161400)、[#163132](https://github.com/openclaw/openclaw/pull/163132)，由 [@RomneyDa](https://github.com/RomneyDa). 向后移植
- **Windows.** 上的本地模型当所需的 Microsoft 文件丢失时，托管 llama.cpp 安装程序可以将它们添加到本地模型服务器旁边，以便它可以启动。如果启动仍然失败，请重新运行安装程序或手动配置兼容服务器。 [#163093](https://github.com/openclaw/openclaw/pull/163093) 及其向后移植 [#163128](https://github.com/openclaw/openclaw/pull/163128)，均由 [@RomneyDa](https://github.com/RomneyDa). 提供
- **Codex 内存使用。** 运行多个 [native Codex 代理](/plugins/codex-harness) 使用较少的重复内存。 OpenClaw 会一直等到需要代理的对话列表，然后再启动该列表的后台进程，并在兼容的情况下共享设置。用于跟踪 [ 保存的 shell 环境 ](/tools/exec) 的内存也是有限的。 [更新恢复源和积分](#update-recovery-sources)、[平台更新源和积分](#platform-update-sources)。
- **Anthropic 后台工作。** 修复了在收集后台命令、其他代理或工作流程的结果之前 Anthropic 对话卡住或完成的情况。 [来源和鸣谢](#update-recovery-sources)。

## <a id="browser-and-computer-use"></a> 浏览器和计算机使用

- **桌面应用程序访问。** 如果您将 [Codex 计算机 Use](/plugins/codex-computer-use) 与 API 密钥一起使用，则检查对桌面应用程序的访问不会再停止并请求不相关的浏览器登录。控制浏览器仍然需要自己登录。 [来源和鸣谢](#windows-session-sources)。

## <a id="security-and-privacy"></a> 安全与隐私

- **本地连接检查。** HTTPS 检查 OpenClaw 是否正在本地运行，现在遵循托管代理设置，并验证服务器的证书是否与您在每个连接上配置的证书相匹配。 [来源和鸣谢](#update-recovery-sources)。
- **日志中的秘密。** 修复了当 OpenClaw 在 Bun 上运行时，未隐藏长且格式异常的日志条目中的秘密的情况。 [来源和鸣谢](#platform-update-sources)。

## <a id="other-bug-fixes"></a> 其他错误修复

- <a id="windows-session-sources"></a>**Windows.** 上已保存的对话修复了阻止 Windows 用户打开已保存对话或准备计划代理任务的错误。 [#162931](https://github.com/openclaw/openclaw/pull/162931)，作者为 [@RomneyDa](https://github.com/RomneyDa)，向后移植 [#160075](https://github.com/openclaw/openclaw/pull/160075) [#157067](https://github.com/openclaw/openclaw/issues/157067) 和 [#159339](https://github.com/openclaw/openclaw/issues/159339)。它还包括 [#162467](https://github.com/openclaw/openclaw/pull/162467) 的桌面应用程序访问修复以及诊断工作区恢复时更清晰的消息。
- **修复对话历史记录。** 修复在遵循长链链接对话时不再崩溃。它保留历史记录并将每个记录附加到正确的会话。 [来源和鸣谢](#update-recovery-sources)。
