v2026.8.2 在 Control UI 上添加了一个“主页”按钮，可在您正在处理的任何内容旁边打开您的个人主页代理，而不是让您离开它以开始另一个对话。它还带来了 Linux 桌面伴侣、无需切换页面即可启动的后台会话、无需运行网关即可保持可用的浏览器控制、Control UI 的四种新外观，以及针对回复、语音、更新和恢复的长尾修复。

**发布规模：** 784 个拉取请求、10 个直接提交和 134 个贡献者。

## <a id="installation-and-onboarding"></a> 安装和入门

安装和首次运行设置现在可以更好地保留人们已经做出的系统和模型选择。 Linux 和 macOS 恢复路径故障更加清晰，引导式设置通过重新连接保留选定的代理和模型，并且无需将人员发送到终端即可查看、安装和验证所需的运行时插件。

<AccordionGroup>

<Accordion id="installing-and-updating-openclaw" title="安装和更新 OpenClaw">

现在安装将遵循每个系统实际开始的路径。 Fedora 和其他受影响的基于 RPM- 的 Linux 系统可以保留其发行版拥有的 Node 软件包，而 OpenClaw 选择满足其 SQLite 要求的托管运行时，并且 shell 安装程序再次暴露需要从中恢复的 npm 错误支持过时的启动器和安装目录。在 macOS 上，安装和重新启动在重定位一次失败后停止，并指向应用程序副本而不是循环。 Linux 网关安装在写入 root 拥有的配置或凭据之前还会拒绝不安全的 sudo 到 root 设置，而无需更改真正的 root 安装或普通 sudo 生命周期命令。

更新使更多的工作安装保持完整。 pnpm-owned 安装在更新程序交接期间保留在 pnpm 中，中断的软件包生命周期工作可以在新软件包启动之前完成，并且强化的 npm 主机可以在不启用不相关软件包脚本的情况下进行更新。 Doctor 现在会在考虑旧的最后一次正确的副本之前迁移可读的活动配置，从而在仍然需要回退恢复时保留被拒绝的字节。 ClawDock 帮助程序已停用，因此现有用户需要自行删除帮助程序源代码行，并移至记录的 Docker Compose 和 OpenClaw CLI 命令，并保留其部署状态。

<Accordion id="guided-setup-and-provider-sign-in" title="引导式设置和提供商登录">

首次运行设置现在等待刚刚配置的内容变为现实。模型设置通过重新连接保留所选模型，保持挂起状态直到保存的设置处于活动状态，并在正在运行的网关尚未准备就绪时显示实际恢复原因。引导式 CLI 设置仅在步骤实际属于一个步骤时才请求代理，并在流程的其余部分中保留该选择，并且允许人们在不需要时添加代理而无需复制凭据。

当模型需要运行时插件时，macOS 入门和 Control UI 可以显示插件来自何处以及它请求哪些功能，请求明确批准，安装它，并在同一流程中验证模型。拒绝或取消会使配置的模型保持不变并停止尝试。当原始回调被证明未发送时，Mac 用户还可以在同路由重新连接后完成 ChatGPT 登录、取消停滞的提供商登录或退出登录，而没有后期结果接管替换尝试。

## <a id="the-new-web-ui"></a> 新网UI

当同时进行多个对话时，[Control UI](/web/control-ui) 更易于使用。新会话可以在后台启动，主页可以保留在屏幕上已有的工作旁边，消息和草稿更可靠地保持其位置，较长的历史记录可以减少重复的工作，四个可选主题使工作区更容易创建您自己的工作区。

<AccordionGroup>

<Accordion id="starting-and-composing-conversations" title="开始和撰写对话">

现在，当您停留在设置页面并准备其他内容时，新会话可以在后台开始，然后在准备就绪时从其完成通知中打开。普通文件夹和新存储库仍然可用，而无需假装它们支持工作树，项目和签出选择可以在临时发现失败中幸存下来，并且启动进度不断前进，而不是隐藏更新的工具或批准活动。从“新会话”的非焦点部分键入也会将第一个可打印字符发送给作曲家。

在 iPhone 上，当连接的网关和操作员访问支持时，模型、工作量、权限、上下文、附件、技能、连接器和工具控件现在位于 Composer 中。排队的消息与发送前检查的设置保持绑定，旧的或陈旧的队列条目停止检查，Control UI 提示通过准备、完成和重新加载保持一个可见的标识。选择文本可以打开可编辑的旁聊草稿，而无需将旁白问题添加到主要历史记录中。

<Accordion id="messages-and-context-that-keep-their-place" title="保留其位置的消息和上下文">

排队、中断和取消的输入现在返回到被接受的点，而不是下降到较新的回复以下，并提示 Control UI 已经通过刷新、分页和重新安装完成了停留。跨会话消息显示它们来自哪个对话并链接回该对话，而长时间对话耗尽空间后的恢复可以在被取代的工作之前保留最新的活动文本请求。

围绕这些切换的命令界面也更简单。如果没有兼容性别名，手动对接和焦点命令将消失，并且 `/session unbind` 现在是分离绑定对话而不结束其代理会话的受支持方法。

## <a id="updates-and-maintenance"></a> 更新和维护

现在，更新会保留更多的工作安装，并在出现问题时留下更清晰的恢复路径。医生可以与托管网关协调支持的离线修复，繁忙的系统提供状态，Control UI 请求更多运行空间，恢复消息保留有用的编辑细节，而不会将不确定的工作变成错误的成功。

<AccordionGroup>

<Accordion id="updates-that-preserve-a-recovery-path" title="保留恢复路径的更新">

自动更新现在可以在重新连接、重新加载、禁用检查、一次性安装和托管服务切换时保留其选择的通道和最终结果。无人值守安装仍然仅限于托管网关服务，而前台网关将保持运行状态，直到您自己遵循停止、更新和启动路径。

当无法检查服务所有权时，启用重新启动的更新也会拒绝替换文件，当可以恢复失败的更新时保留回滚信息，并且如果会话迁移不完整，则在声明成功之前停止。安装较新的软件包不再在该版本实际运行之前迁移共享状态，尽管已被受影响的软件包更改的数据库仍然需要兼容的备份还原，并且这些路径都没有将整个更新转变为一个可逆事务。现在可以在选定的网关停止后预览和删除经过验证的旧版迁移原始文件，但该清理是明确且不可逆的，因为它会永久删除旧安装可能用于回滚的文件。

<summary>来源和完整变更列表</summary>

<Accordion id="doctor-repairs-and-state-migration" title="医生维修和状态迁移">

Doctor 现在可以通过停止匹配的托管网关、完成支持的修复、检查结果并重新启动同一服务来明确拥有更多离线修复工作的所有权。它可以恢复受支持的旧审批和数据库，在迁移过程中保留有效的计划作业和当前语音呼叫设置，并解释在修复无法完成时哪些原始材料仍然可用。

<Accordion id="gateway-responsiveness-and-shutdown" title="网关响应和关闭">

现在，在重命名会话、打开历史记录、列出任务页面、检查计划工作或同时运行多个代理轮次时，繁忙网关花费更少的时间重复工作。大型会话列表保留更少的内存，异常分支的历史不再重复相同的祖先工作，并且有界运算符请求在返回可重试的重载结果之前有更公平的机会启动。

<Accordion id="recovery-messages-and-operator-diagnostics" title="恢复消息和操作员诊断">

## <a id="security-and-privacy"></a> 安全与隐私

现在，一些较低级别的保护措施失效得更早，泄露的信息也更少。超大的 MCP 响应和事件在解析之前受到限制，例行诊断将 ClawDock 凭据保留在外，长期秘密编辑在其支持的大小内保持安全，可选图像组件移动到修补的依赖项版本而不强制执行。

<AccordionGroup>

<Accordion id="runtime-and-dependency-safeguards" title="运行时和依赖性保护">

网关集成现在在解析超大 MCP HTTP 响应或单个 SSE 事件之前拒绝它，而健康的长期流可以继续超过该总量。 ClawDock 检查将凭证值和前缀排除在普通诊断之外，并且编辑处理接受的长秘密而不会崩溃。

可选的图像解码现在使用修补的 Sharp 0.35.4 和 libheif 1.23.2 组件，而不强制使用 Sharp。独立的 `@openclaw/memory-lancedb` 安装仍然可以通过其可选的 Transformers 路径解析较旧的 Sharp，因此依赖性修复不应被解读为普遍覆盖。 Bun 1.4 网关连接还使用已安装的 npm WebSocket 接收器。
